= officework 0.5.0-beta.7

日本語: link:RELEASE.ja.adoc[RELEASE.ja.adoc]

To try it: `pip install --pre officework`

This release came out of published forms again. Three of them went through
officework into PDF and were read beside the PDF each office publishes in the
same place: the National Tax Agency's liquor tax overview, and the Cabinet
Office's aptitude survey form and interview record.

Column widths matched after the last release, so this time the vertical
measurements did not. The same document ran one or two pages longer than
theirs, and lines drifted downward.

== Line height comes from the font

**Every line was 6.4mm, whatever the font and the size.** Word and LibreOffice
both decide it in two steps: the font gives a natural height, then the
paragraph's setting overrides it. We now do the same two steps.

**A substituted font's vertical metrics do not match the original.** Ume Mincho
is 1.0000em where MS Mincho is 1.292em. The widths were matched; the heights
were not. Line advance is now looked up under the original font's name. Names
that are not in the table fall back to the face installed on the machine, the
way LibreOffice does it — OS/2 usWinAscent plus usWinDescent plus the hhea line
gap.

**A line height given in points was turned into a multiplier.** `w:lineRule`
`exact` and `atLeast` state the height itself. Dividing them by the 6.4mm
constant only worked while that constant was the line height, so they are
carried as a height in points now.

The survey form goes from six pages to five, matching the reference. Its body
advance is 15.50pt against the reference's 15.54pt.

== Paragraph styles are applied

A docx carries its own style definitions. We were overlaying the bundled
template's heading definition on top of them, so the interview record's
headings — 20pt, centred, blue in the file — came out at our template's 16pt,
left aligned and black.

When the document defines the style itself, that definition wins. Otherwise the
template is used as before. The `w:basedOn` chain is followed.

Size works the same way: the survey form's body is 12pt in the file and we set
it at 11pt, because the body style's `w:sz 24` was not being read.

== Inline images sit on the line

A drawing in a docx lives inside a run, so it is part of the text flow. We drew
images below the paragraph, so a heading's image dropped to its own line and
the heading could not be centred together with it.

An image at the start of a paragraph is now placed to the left of the first
line's text, and the line grows when the image is taller than the text.

**Transparent images came out as grey squares.** The PNG alpha channel was
being dropped. It is now written as a separate stream and referenced as a soft
mask, which is what the PDF format asks for.

== Text box insets

The inset was hardcoded at 1.5mm on the left and every box was centred
vertically. DrawingML's defaults are 0.1in left and right, 0.05in top and
bottom, anchored to the top. A file that states `lIns` and friends is followed.

== Borders

* **A merged cell was drawing borders through its middle.** A merge is one
  cell, so only its outline is drawn
* **Diagonal borders are drawn.** Across a merge, one line spans the whole
  merge

== Opening and saving leaves the original alone

**Tabs were appearing at the start of lines.** A paragraph's tab stop
definitions were being read as tab characters. Eight paragraphs of the survey
form changed text on a save.

**A drawing's stored copy was cut short.** In a docx that starts with a byte
order mark, the offsets used to slice the original XML are three bytes out. The
interview record is such a file, and opening and saving it produced XML that no
longer parsed.

**The styles relationship was written twice.** In a docx whose styles part is
not called `styles.xml` — the interview record's is `styles2.xml` — we added
our own on top. A package may only carry one relationship of that type.

== The Python API answers like openpyxl and python-docx

A test was written that walks every public property of the originals and
compares the answers with ours. Nobody picks the list, so it grows whenever the
originals grow. Its first run found that we were filling in defaults where the
file states nothing.

**Bold, italic, underline and strikethrough have three values now.** A docx
writes on, off, and says-nothing as three different things. We collapsed the
last two into `False`, which hid whether the run inherits from its style.
`None` now means the file says nothing. On save, a run that was explicitly
turned off is written back that way.

**Paragraph alignment, line spacing, indents and spacing work the same.** They
return `None` when the file states nothing.

**Run boundaries survive reading.** Word splits runs even when the formatting
is identical, and we joined them on read, so run-level formatting was invisible
from Python. Joining is now the editing side's job.

**A first-line indent given in characters is resolved with the paragraph's own
size.** One character is 240 twips in a 12pt paragraph and 210 in a 10.5pt one;
we always used 10.5pt.

**A cell with no format of its own reports the workbook's default font.** It
used to report `None`, which reads as "this cell has no font".

`ws.merged_cells` was added. It iterates "B2:C3" strings and supports `in`,
`len()` and `str()`.

A paragraph's style now reaches its base style, its font and its paragraph
format (`p.style.base_style`, `p.style.font.size`,
`p.style.paragraph_format`).

== Other changes

* A cell's inner padding is Excel's two pixels
* A single trailing space no longer gets a line of its own
* Numbered list markers follow what the document states
* A shape's fill colour is no longer used as its text colour
* Fitting to one page allows for the tallest row, so the last row is no longer
  pushed off

== Internal changes

`kumihan::Document` gained `style_matome`, which resolves a style definition
through its `w:basedOn` chain and returns `None` when the document has no such
definition.

`InlineImage` now records where in the paragraph's text it sits.

A differential test against openpyxl and python-docx was added. It walks every
public property of the originals and compares them with ours.
