= officework 0.5.0-beta.3

日本語版: link:RELEASE.ja.adoc[RELEASE.ja.adoc]

To try it: `pip install --pre officework`

== Pagination now follows Word's rules

When saving a docx we now write the line height into the file. Without it the
program that opens the file applies its own default. Word's "single" line is
about 1.15× the font size; ours is 6.4mm for 10.5pt text, which is 1.73×. The
same document therefore broke onto a different number of pages.

We also fixed a defect where the bottom of the last line spilled into the
margin. Pagination looked only at the baseline, not at the descender, so the
last line hung 1.4mm below the text area.

Checked with a 200-paragraph document. Before the fix we produced 5 pages and
the other program produced 3; now **both produce 6 pages and break at the same
places** (page 1 ends at line 38, page 2 at 78, page 3 at 118, page 4 at 158).

One caveat: we checked against LibreOffice, because we have no copy of Word
here. The line height we write is the same value Word uses, so it should break
identically in Word, but we have not seen it on a real machine.

== Caught up with what openpyxl and python-docx can do

We compared the engine (`pip install officework`) against the API surface of
openpyxl and python-docx. It is now at 100%.

[cols="2,1"]
|===
|Compared against |Result

|openpyxl Workbook / Worksheet / Cell |100%
|python-docx Document / Paragraph / Run / Table |100%
|Chart types openpyxl can write |11 / 11

|===

All eleven chart types are available: bar, line, area, pie, doughnut,
projected pie, radar, scatter, bubble, stock (high-low-close) and surface. In a
projected pie chart we also draw the leader lines between the pie and the bar.

We ran 24 sample scripts from a published article series through both the
original libraries and officework, compared the output, and fixed the
differences we found in real documents. The largest was `ws["A1"]`: the
original returns a cell, and we were returning a value.

== Shapes in documents

You can now place shapes in a docx (`python-docx` can only place pictures).
Call `d.add_shape("roundRect", 25, 80, 40, 25, fill="DDE7F0", text="Approved")`
with the shape name, position and size. Rectangle, rounded rectangle, ellipse,
arrow, diamond and line are built in, each with fill, outline, text inside,
rotation, opacity and a drop shadow.

Coordinates and sizes are millimetres from the top-left of the page. They are
written as DrawingML, so Word and LibreOffice open them as **shapes you can
select and edit** — not as a flattened picture. They survive open-and-save, and
you can put them on any page, not just the first.

Grouped shapes are written as a real group (`grpSp`), so Excel and Word treat
them as one object.

You can also select and drag shapes on the writer screen.

== No unusable buttons left in the ribbon

There are no buttons that do nothing when pressed, and no greyed-out buttons,
in either writer or calc. In beta.2 there were 14.

Bring forward, send backward, align, group, merge shapes, protect workbook
structure and page break preview all work now.

== Other changes

* Save a page as an image (`save("page.png")`). The default is 150 dpi; pass
  `dpi=300` for print resolution
* Formatting applied to part of a cell's text (bold on a few characters, say)
  no longer disappears when you save
* The spreadsheet app can protect the workbook structure and individual
  ranges. **No password is set** — we do not pretend to hold something we do
  not. Both are written into the xlsx, so Excel honours them
* The spreadsheet screen switches between page break preview and normal view
* Translucent fills, such as a highlighter pen, now show on screen and in PDF
* Freehand pen strokes reach the paper (highlighter under the text, pen on top)
* Screen wording and template translations tidied up across 15 languages

== Under the hood

Not visible to users, but this release added a **regression check that compares
rendered pages as images**. It lays out sample pages, renders them, stores a
fingerprint, and checks that the same input still produces the same picture.

We built it because the numeric tests kept passing while the appearance broke.
Six of the defects fixed in this release were invisible until we opened the
output and looked, or counted pixels: images and watermarks missing from the
page, rounded rectangles drawn square on paper, shadows and opacity ignored on
paper, shape outlines drawn at half width on screen, pen strokes never reaching
the paper, and the last line spilling into the margin.
