= officework 0.5.0-beta.8

日本語: link:RELEASE.ja.adoc[RELEASE.ja.adoc]

To try it: `pip install --pre officework`

The last release was about one measurement, the height of a line. This one is
wide instead of deep. The spreadsheet learned four hundred functions and every
preset shape, equations are typeset by the engine itself, a document's paper
belongs to its section, and the two apps share one ribbon.

The engine is what ships. `pip install officework` installs it and nothing
else; the apps are not distributed yet.

== Four hundred functions, and a dialog to find them

**The function list is 404 entries.** Statistics, finance, engineering,
database and the distribution family were the gaps, and they are filled:
IPMT through XIRR, the incomplete gamma and beta distributions, ACOSH through
MDETERM, the *B trio and the array constants (`{1,2;3,4}`) that formulas need
to read them.

Every documented function now takes every argument Excel takes. Where we
accepted three arguments and Excel accepted five, the two extra ones did
nothing; they work now.

**Insert Function has Excel's classic shape.** A category on the left, the
function list, the description, and the argument fields with a running result.
The function manual is generated from the same material the dialog shows, so
the two cannot drift apart.

== Every preset shape draws

**All 187 shapes in the DrawingML specification now draw from the
specification's own definitions.** Before, a shape we did not recognise came
out as a rectangle. Braces draw as braces, connectors are read, and the screen
and the printed page share one table of shapes, so they cannot disagree.

A shape anchored to two cells now takes its size from those cells, which is
what the anchor promises: widen a column and the shape widens with it.

== Equations are typeset by the engine

**Python and TeX are no longer needed.** Equations are set by typst and mitex,
both compiled into the engine. Write LaTeX, press Enter, and the formula is
drawn with the same maths font TeX uses. Japanese inside a formula
(`\text{売上}`) comes out in the document's own font.

**A Word or Excel equation now opens as a formula.** OMML is read into LaTeX,
covering the same elements LibreOffice's own reader handles, so an equation
from Word prints instead of vanishing. Excel keeps its equations inside a text
box; those are read the same way.

Pictures on a spreadsheet are printed too. They were in the model and never
reached the page, which is also why an equation could not print.

== The paper belongs to the section

**Pages are stacked, one sheet after another, and that is the ordinary view.**
The separate "print layout" mode is gone. Paper size, orientation, margins and
columns now apply to the section the caret is in, so one document can hold an
A4 portrait section and an A3 landscape one.

In AsciiDoc this is written the way asciidoctor-pdf writes it, with the
`page-*` attributes.

== One ribbon

writer and calc now show the same buttons. The only difference is which target
comes first: a cell in calc, a character in writer. A button that does not
apply is not shown greyed out; it is not shown.

== Word documents come closer to the original

* A paragraph border knows which side it draws, and the page draws it
* A hanging indent hangs
* A table cell obeys its own alignment, horizontal and vertical
* A page break inside a run breaks the page, and two of them break twice
* A text box is set the way the file says
* Bold text is one run of glyphs, not one run per character
* Blank pages are not printed
* A right-aligned number sits at the right edge of its merge
* Print centring is read, and a blank line in a cell takes a line's height
* The baseline sits at the font's ascent, not at four fifths of the box

== The Python API runs the originals' own samples

**python-docx's sample script and openpyxl's sample script now run against
officework unchanged.** They were the measure, and what they exercised is what
was missing: `docx.shared`, `docx.enum`, `docx.styles`, the chart classes,
`RGBColor` passing python-docx's own type check, and `add_run` starting plain
the way python-docx starts it.

A misspelt attribute on `Doc`, `Book` or `Sheet` is refused instead of silently
doing nothing.

== The agent

The consult pane is an agent: it calls tools, shows its loop, and writes and
runs Python macros in a sandbox, with errors going back to it. AI destinations
are named and switchable, and the model is shown as one of four states.

== The manuals

* Every button has a command page: 256 of 256
* English versions for the index, the two tutorials, the button table and the
  docx/xlsx comparison
* The booklets are rewritten as plain sentences, one thing per sentence
* A function manual, generated from the dialog's own material
* The `=df()` manual, written before the function existed

== Other changes

* `=df()` defines a table column once, XLOOKUP searches by bisection, and INDEX
  takes areas
* Lists, protection, arrows, filters, CSV and the sandbox do what their pages say
* A list style makes a list, and the file carries the numbering to prove it
* The conversation leaves a record beside the book, and comes back
* Attribute references stay as text, and links and cross references are read the
  way Asciidoctor reads them

== Internal changes

`kumihan` gained `omml`, which turns OMML into LaTeX, and `suushiki`, which
typesets LaTeX into a PNG. Both formats reach them: docx through `ooxml` and
xlsx through `sheet`.

`kumihan::Paragraph` gained `line_pt`, `first_line_chars`, `border` and
`align_itta`; `CharFormat` gained a three-valued `itta` so that "stated off"
and "not stated" stay apart.

The shape table moved out of the drawing code into the specification data, and
`paper` reads the same table the screen does.
