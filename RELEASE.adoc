= officework 0.5.0-beta.6

日本語: link:RELEASE.ja.adoc[RELEASE.ja.adoc]

To try it: `pip install --pre officework`

This release came out of published forms again. Four of them went through
officework into PDF and were read beside the PDF each office publishes in the
same place: the National Tax Agency's liquor tax overview and consumption tax
tables, the Ministry of Internal Affairs' wage statistics, and the Cabinet
Office's interview record.

The loudest problem in the last release was tables running off the paper. It
had two separate causes and both are fixed.

== Column widths match Excel

**The five-pixel padding was counted twice.** What xlsx stores for a column is
how many digits of the standard font fit in it, and the cell's inner padding is
already inside that number. Adding it again made every column 1.3mm too wide,
which compounds across a wide table. The liquor tax overview went from 21 pages
to 12.

**The digit width was fixed at seven pixels.** It depends on the font and its
size: seven for MS Mincho at 10.5pt, nine for Arial at 12pt. It is measured from
the workbook's own standard font now. The wage statistics table uses Arial 12pt,
so its columns had been 22% too narrow.

**Fit-to-page was applied when nobody asked for it.** That setting only counts
when the fit-to-page mark is present; otherwise Excel uses the scale. The
consumption tax sheets carry both a scale of 78% and a fit of two pages wide,
and using the second works out at 83.7% — larger, not smaller — which pushed
the sheet onto an extra column of paper.

**A table's right edge is no longer counted as content.** Many forms draw the
right edge of a table as the *left* border of the next column. Counting that
column added a sheet of paper. Four of the liquor tax workbook's five sheets are
drawn that way.

== Numbers stay inside their cell

**A missing font is replaced by one with the same widths.** Before, only the
class was preserved — mincho stayed mincho. MS Mincho gives all 95 half-width
characters the same width; IPAex Mincho, which was standing in for it, is
proportional and sets a digit 24% wider. In a table of figures the columns ran
into each other.

Ume Mincho, Ume Gothic, Ume P Mincho and Ume P Gothic match the four MS faces
character for character. Century maps to C059, and Arial, Times New Roman,
Calibri, Cambria and Courier New to the fonts drawn to match them.

**Text is measured with the font that will draw it.** Every half-width
character had been assumed 0.55em and every other 1.0em, whatever the font.
That assumption decided right alignment, where a line wrapped, and whether the
text fit at all.

**A number that does not fit is filled with #.** As Excel does. Text may spill
into an empty neighbour; a number may not, because a number with its digits cut
off still reads as a number.

== The whole cell format is read

Of 25 fields, 11 were being read. Everything that shows on paper is read now.
The two left out are sheet protection.

* **Indent** — one step is three spaces, not one full-width character, and a
  right-aligned cell indents from the right
* **Vertical alignment** — was never read; everything sat on the bottom. Merged
  cells now sum their height too, so a heading merged down several rows no
  longer lands at the bottom of the merge's first row
* **Stacked text** — narrow column headings stack downward instead of running
  into the next column. Rotation from 0 to 180 degrees prints as well
* **Shrink to fit** — shrinks the type rather than overflowing, and does not
  apply to a cell holding more than one line
* **Underline, strike, subscript, italic** — printed. Italic slants only by the
  angle the font declares, so a font without an italic face stays upright
* **All eighteen pattern fills** — every one had been a flat wash of the
  foreground colour, which turned a light shading into solid black. The colours
  blend by the pattern's weight now
* **Gradient fills** — filled with the two stops blended

== Pictures appear

**WMF pictures are drawn.** Two of the three pictures in the Cabinet Office's
interview record form are Windows Metafiles, which the image decoder could not
read, so they were dropped. A metafile is a list of lines and fills rather than
a picture, so it is drawn as such and **does not go soft when enlarged**.

The PDF writer can now handle curves, clipping and dash patterns.

== Other changes

* Document parts are located through their relationship type rather than their
  conventional name, so a docx that names them differently still opens
* The right-click menus go through the translation table
* An edit no longer copies the whole sheet for undo. On a 200,000-cell sheet
  that was 33ms per edit; it is 36µs
* The styles panel shows the same headings on every face

== Under the hood

The PDF writer has a path: move, line, cubic curve, close, filled and stroked,
with a dash pattern and a clip. The clip belongs to one path, so adding
something in the middle of a list cannot leave it switched on.

Font substitution looks for a width-compatible partner first. Every partner is
freely licensed, and none is bundled.
