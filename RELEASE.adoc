= officework 0.8.0 and aiseed office 0.1.0-alpha.6

日本語: link:RELEASE.ja.adoc[RELEASE.ja.adoc]

To try it: the engine installs with `pip install officework`. The app (aiseed
office) is on https://github.com/aiseed-dev/officework/releases[GitHub Releases].

This is the engine release after 0.7.0 and the app release after
0.1.0-alpha.5.

**This release fills forms.** A resume, an application or a notification is a
form with marks where the values go, and the values are a small table book of
their own. officework puts the values in and prints the form, to PDF, xlsx,
docx or PNG, or hands the pages to another program to draw. The forms and the
data are both plain text (AsciiDoc), so a person and a program can both read
and write them.

The rest is the same job as before: open the docx and xlsx you were sent the
way Word and Excel open them. This time that meant pictures and shapes: which
one is on top, and how a picture that fills a shape is stretched and cut.

**Plenty is still broken.** There is a list of what we know about below.
Please report what breaks at
https://github.com/aiseed-dev/officework/issues[the GitHub issues].

== Filling forms

A form is a table book or a Word document whose cells and paragraphs hold
marks such as `{氏名}` or `{学歴・職歴.3.内容}`. The data is a table book of
names and values, and tables of rows. The whole contract, with every mark, is
in link:docs/en/forms-manual.adoc[the forms manual].

[source,python]
----
from officework import sheet, doc

form = sheet.Book.open("履歴書-厚労省.form.adoc")
data = sheet.Book.open("履歴書.sheet.adoc")
b = sheet.Book.fill(form, data)
b.save("履歴書.pdf")          # .xlsx and .png work too
b.missing                     # names the form asks for that the data lacks
b.bessi                       # tables carried on to a 別紙

d = doc.Doc.fill_form(doc.Doc.open("届出.docx"), data)
d.save("届出.pdf")            # .docx works too
----

What filling does:

* a mark the data does not answer becomes empty, so the rows a resume
  prepares beyond the data stay blank. A name the data does not hold at all is
  usually a slip, so `fill` warns about it and lists it in `missing`
* `{年齢}` is worked out from the birth date and the date
* `{日付.元号}` and `{日付.和暦年}` give the Japanese era and the year in it;
  the first year of an era is 元, as official forms write it
* `{通勤時間.時間}` and `{通勤時間.分}` take the numbers from a value such as
  `1時間10分`
* `{性別:男・女}` circles the option the data names. The circle is measured
  from where the page sets the characters, and it is a shape of the book, so
  the PDF, the xlsx and the draw list all have it
* `{区分=開業}` gives ■ when the data names that option and □ otherwise
* rows the form has no room for are carried on to a 別紙 sheet (or, in a
  document, a 別紙 after a page break), in the form's own columns and widths
* a shape can be a picture field: the photo the data names goes inside the
  shape's box, keeping its proportions
* in a Word form, a blank of underlined spaces (`{氏名}＿＿＿＿`) keeps its
  length, and a mark Word split across formatting runs is still read

The resume forms made with this (the Ministry of Health, Labour and Welfare's
example and the JIS one) are published separately, in the aiai repository,
with the scripts that make them.

== The draw list

`Book.draw_list()` and `Doc.draw_list()` return the pages as data (version
0.1): points from the top left, one list of items in the order the PDF draws
them, the fonts by name and file, and pictures in base64. Text carries its
baseline and its top, so a program that places text by its top, such as a
Flet canvas, computes nothing. For a filled form the pages also list the
fields, one per data item, with their rectangles, so a program can put an
input over a field, write the edit back with `data.set_field(name, value)`,
fill again and redraw.

`sample/drawlist/pil_draw.py` draws a draw list with Pillow alone, and
`sample/drawlist/flet_form.py` shows and edits a form on a Flet canvas.

== Writing forms from Python

What a program that makes forms needs:

* `Book.save("x.adoc", attributes=[…])` writes a book as AsciiDoc, with its
  pictures as files in `images/` beside it, and `Book.save_look` writes its
  look as a template
* `Book.fonts_used`, `replace_fonts` and `set_default_font`
* `Sheet.set_shape` changes a shape's field, text or font; `margins_mm` and
  `print_scale` can be read and set, and `default_row_height` read
* `Book.fields()` lists the cells of a form that hold marks

== Pictures and shapes

* **Pictures and shapes stack in the order the file gives**, the first at the
  bottom (ECMA-376 Part 1 20.5.2.35 and 19.3.1.45). The spreadsheet screen
  drew every picture under every shape, and the printed page drew them the
  other way round, so a photo in a white frame could be hidden by its frame
* **A picture that fills a shape is stretched to its fill rectangle** and cut
  to the shape's box (`a:stretch/a:fillRect`, ECMA-376 20.1.8.30). In Word's
  restaurant brochure the photo on the first page was drawn at the size of its
  box; it is now 381.9 × 579.4 pt, and Word prints it at 382.1 × 579.4 pt
* **A drawing behind the text goes under the text and its pictures**
  (`behindDoc`, ECMA-376 Part 1 20.4.2.3). The brochure's dark panels hid a
  photo and two icons
* a picture keeps its offset inside its cell in xlsx, and a shape held by two
  cells is written back held by them (`twoCellAnchor`), so it follows the rows
  around it
* on a sheet printed as more than one band of columns, a shape goes on the
  page of the band its cell is in

== PDF and PNG

* a PDF embeds only the fonts its text is set in. The filled resume went from
  89 KB to 73 KB
* PNG is laid out as the PDF is, with the same fonts, so the two match
* an AsciiDoc table line of more than 16 columns (`[cols=…]`) is read whole,
  and a cell spanning both ways is written as AsciiDoc writes it (`3.2+|`)

== The app (aiseed office 0.1.0-alpha.6)

**A ribbon settings file makes the app an edition for one kind of work.**
`~/.config/officework/ribbon.toml` names the app (the window title), picks the
tabs after File and their order, and picks the buttons on a tab. Tabs and
buttons that are not listed are only hidden: a macro's `xw.press` still
presses them, and removing the file brings the full ribbon back. A tab name
the ribbon does not know makes a new tab for your own Python buttons. The
macro manual shows an edition for correcting documents an AI wrote:

[source,toml]
----
name = "Correcting documents"
tabs = "Home, Insert, Layout, Collaboration, View"
----

On the spreadsheet screen, pictures and shapes now stack as the file says, so
a filled resume shows its photo inside its frame. On the document screen, a
picture that fills a shape is stretched and cut as on paper, and drawings
behind the text stay behind it.

== What is still broken

The room Word keeps for a header that holds nothing is the one we could not
pin down. Three templates want two empty paragraphs' worth of it and six want
none, and nothing in the files separates them, so we keep none. The numbers
are in `engine/src/tests.rs` and in the design note.

Known gaps in the engine:

* a table set to automatic width is not widened to fit its content
* a floating table anchored to the page or the margin is placed in the body
  flow
* a double rule counts its full width toward the row height, but only one line
  is drawn
* an empty paragraph left after a table is not carried to the next page, so a
  form that Word prints on two pages comes out on one
* a header built out of a table draws the text in its cells but not its rules
* Word puts a 14pt line of MS PGothic in two grid lines. We measure it with
  the line spacing of MS Mincho, so the two fonts are not told apart
* an embedded Excel object reserves its space and stays blank
* a vertical cell stacks its characters one by one without rotating them
* a font the machine does not have is laid out with the substitute's widths,
  so lines break differently
* on the spreadsheet side, 24 of the 55 collected workbooks differ from Excel
  in page count. 19 of them come out shorter than Excel's
* HTML written from an AsciiDoc document does not yet match Asciidoctor's HTML
  exactly
* EMF pictures are not drawn (the logo of Word's restaurant brochure is one).
  WMF pictures are
* a picture that fills a shape other than a rectangle is cut to the shape's
  bounding box, not to its outline
* Word's restaurant brochure prints on three pages, Word's on two. Its table
  is wider than the page's text, and how Word narrows it is not known yet
* the Flet canvas cannot clip, so `flet_form.py` cuts a stretched picture with
  Pillow, and draws it uncut when Pillow is not installed

Known gaps in the app:

* the PDF written from the document screen (the PDF button) still goes
  through an older writer. It leaves out shapes, floating pictures and the
  panels behind the text, sets the text in the screen's font, and embeds
  whole fonts: a two-page report came to 10 MB, where the engine's PDF of the
  same file is 32 KB. The engine's PDF (`Doc.save("x.pdf")`) has all of them

* a font with no bold face of its own (MS Mincho, for one) stays regular on
  the editor screen
* the editor screen does not follow `w:titlePg`, a header of its own on the
  first page of a section. It draws the same header on every page
* the Windows `setup.exe` is not signed yet. Windows shows "Windows protected
  your PC"; open "More info" and run it from there
* Python is not bundled. Macros and heavy aggregation run on the Python
  already on the machine

== Internals

The engine lays a form out once, and the screen, the PDF and the draw list all
come from that layout. Where the layout set a field's characters is kept, so
a circle and a field's rectangle land on the printed characters.

The resume forms, their sample data and the script that makes them moved out
of this repository into aiai. The Flet sample stays here, for in-house systems.
