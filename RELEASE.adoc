= officework 0.9.0 and aiseed office 0.1.0-alpha.7

日本語: link:RELEASE.ja.adoc[RELEASE.ja.adoc]

To try it: the engine installs with `pip install officework`. The app (aiseed
office) is on https://github.com/aiseed-dev/officework/releases[GitHub Releases].

This is the engine release after 0.8.0 and the app release after
0.1.0-alpha.6.

**This release fills templates made in Word and Excel as they are.** A
template needs no marks of ours: in Excel, the data names a cell by its
address or by a defined name, and in Word, a mail merge field or a mark such
as `{氏名}` says where a value goes. Only the values change; every other part
of the file is copied as it was.

**In the app, an .adoc is edited as its text, beside the pages it makes**, and
the document screen shows each page as a picture of the printed page.

The rest is the same job as before: draw the pages the way Word and Excel
print them. This time we compared the pages of filled templates with the PDFs
of Word for Mac and Excel for Mac, and fixed what differed. Where the ECMA-376
standard and Word disagree, we followed the standard.

**Plenty is still broken.** There is a list of what we know about below.
Please report what breaks at
https://github.com/aiseed-dev/officework/issues[the GitHub issues].

== Filling a template made in Word or Excel

The data is the same table book as for forms (the
link:docs/en/forms-manual.adoc[forms manual] describes it).

[source,python]
----
from officework import sheet, doc

data = sheet.Book.open("山田.sheet.adoc")
notes = sheet.Book.fill_template("履歴書.xlsx", data, "山田.xlsx")
missing = doc.Doc.fill_template("letter.docx", data, "yamada.docx")
----

In an Excel template:

* an item of the data's two-column table named with a cell address (`B5`,
  `履歴書!D9`) or with a name the template defines (Formulas > Name Manager)
  puts its value in that cell. Marks such as `{氏名}` in the cells are filled
  as well
* only the cells that change are written into the sheets. A text value goes
  in as text and a number as a number, and the cell keeps its format. Every
  other part (formats, theme, shapes, document properties) is copied as it
  was. On the Ministry of Health, Labour and Welfare's resume, four values
  change only `xl/worksheets/sheet1.xml`
* a shape named in Excel's name box after a data item (`写真`) takes the
  picture file the data gives, looked for in the data file's folder. The
  picture goes inside the shape, keeping its proportions, and the shape's own
  text gives way. PNG and JPEG pictures can be put in
* `notes` lists what cannot be put in this way: rows that would need a 別紙,
  a picture of another kind, a file not found

In a Word template:

* a mark such as `{氏名}` in the body, a header or a footer is filled, even
  when Word keeps parts of it in differently formatted runs. The value takes
  the format of the place the mark starts
* a mail merge field (Mailings > Insert Merge Field) named after a data item
  becomes its value as plain text, as in the document Word's mail merge makes
* only the text of the marks and the fields changes. Every other part of the
  file, and everything else in those parts, is copied as it was
* `missing` lists the names the data lacks altogether; they are filled with
  nothing and warned about, as `fill` does

Word's mail merge fields are also read when a docx is opened, filled by `fill`
and `fill_form` like marks, and written back as fields, so a mail merge
template survives being opened and saved.

Saving a docx no longer rewrites the parts nobody changed. A header or footer
that is unchanged is carried over as it was (a Word letter's header had lost
2 KB), and the settings and document properties are no longer linked twice.

== The pages, compared with Word and Excel

The pages are compared with the PDFs Word for Mac and Excel for Mac print.
Documents set in Meiryo UI are compared as copies set in Hiragino Sans or Yu
Gothic.

* Word's letterhead template, set in Hiragino Sans: every line's baseline is
  within 0.5pt of Word's
* Word's cover letter template (転職の送り状), set in Hiragino Sans: every
  line breaks where Word breaks it, and is within 1pt of Word's
* the Ministry's resume, read the Mac way (`platform="mac"`): the same 8 pages
  as Excel for Mac, with the column breaks within 0.2pt

What changed in Word documents:

* **kerning** (`w:kern`, ECMA-376 Part 1 17.3.2.19) was not read, and no
  letter was kerned. Recent Word templates ask for it in the document
  defaults. The layout now takes the face's kerning pairs, so Hiragino Sans
  W3 closes と and を by 0.03 em, as Word does. Text in capitals only, a
  document with a character grid and faces set at a fixed half-width pitch
  are not kerned
* **the edges a table names itself** (`w:tblBorders`, 17.4.39) have their
  width and colour. Every such edge was 0.5pt black. The bottom edge of a
  table also has its own width under the last row, and the text after the
  table starts below it
* **a run's own automatic colour** (`w:color w:val="auto"`, 17.3.2.6) is kept
  over the colour of its styles. The placeholders of Word's letterhead were
  grey here and black in Word
* **a style that names only a Latin theme font** leaves the East Asian font
  to its base style (17.3.2.26). The letterhead's name was measured in Arial
  and drawn in another face, so its underline stopped early
* the line height of Hiragino Sans W3 is 1.30 em and its baseline 1.03 em
  down, as Word draws it. The standard leaves the single line height to the
  application (17.3.1.33), so these values were measured in Word
* a bold letter in a face with no bold face (Hiragino, MS Mincho, MS Gothic,
  Century) advances 0.02 em further, as Word does. A half-width space does not
* the underline takes its place and thickness from the face's own figures
  (the `post` table). Word draws Latin faces this way; a face without the
  figures keeps the old place
* a line in a table cell is aligned between the left and right indents, and a
  picture in a cell is aligned with the text of its paragraph
* free-form shapes (`a:custGeom`) are drawn, and an inner outline cuts a hole.
  A linear gradient fill (`a:gradFill`) is drawn as a gradient
* a group sized by the page (`wp14:sizeRelH`) grows with it, and every shape of
  a group placed in a line is drawn
* a named highlight colour (`yellow`, `darkBlue`, …) has its colour, not black
* a see-through shape drawn with a path no longer leaves the rest of the page
  see-through
* the page pictures (PNG) draw the letters as the PDF does: the same face
  choice, underline, strikethrough, spacing and bold

What changed in Excel workbooks:

* a shape that runs over a page break is drawn on each page it reaches, cut to
  that page, as Excel prints it. It was drawn whole on its first page, out into
  the margin
* the full-width spaces (U+3000) at the end of a right-aligned cell do not
  count in its width. Those at the start still do
* a face named with 楷書 (regular script) falls back to a Mincho face, as
  Excel for Mac draws it, not to a Gothic one

Where the standard and Word differ:

* `w:overflowPunct` (17.3.1.21) lets 、 hang past the end of a line when the
  document says nothing. Word for Mac broke the line one letter earlier
  instead. We follow the standard
* the standard says only that an underline is "directly below" the letters
  (17.3.2.40). Word draws East Asian faces lower than their own figures, by
  no rule we could find. We use the face's figures

== The draw list

A text item may have `clip` (`[x, y, w, h]`), the part of the page it is cut
to. It is set on the text of a shape that runs over a page break.

== The app (aiseed office 0.1.0-alpha.7)

**An .adoc is edited as its text, beside the pages it makes.** The left side
holds the file's characters in a fixed-width face. The right side shows the
pages the text makes, laid out as the PDF is, and made again shortly after the
typing stops. Pressing a place on the pages puts the caret on the text it comes
from, and the pages follow the caret, with a yellow band on its line. Errors,
and markup the pages do not show, are listed above the pages with the file's
line numbers. Saving writes the characters back unchanged, so comments, blank
lines and line breaks stay. `sample/writer/07_早見表.adoc` shows each kind of
markup beside the pages it makes. To edit an .adoc on its pages as before, put
`adoc_code = "0"` in `~/.config/officework/settings.toml`.

**The document screen draws each page as a picture of the printed page.** The
pictures are made from the pages the PDF prints, so the changes above reach the
screen. On the screen, the cover letter template set in Hiragino Sans breaks
every line where Word does. A bold face made thicker, such as Hiragino Sans W3
in bold, is bold on the screen too, and a section's own first-page header
(`w:titlePg`) is followed. The caret and the selection sit on the letters of
the pictures. `page_pictures = "0"` in the settings keeps the older drawing.

**The PDF button writes the pages the screen shows.** A docx's PDF has its
shapes, floating pictures and the panels behind the text, and embeds only the
fonts it uses. The 32-page JST plan is 508 KB; it was about 10 MB. A print
template, this app's own documents and vertical text still go through the
older writer.

== What is still broken

These need Windows Word and Excel to settle, and we have not had them:

* the line height of Yu Gothic. Word for Mac draws 1.44 em; we use 1.5 em,
  measured earlier on another document
* where Word puts the underline of an East Asian face
* whether Windows Excel also leaves out the full-width spaces at the end of a
  right-aligned cell
* which way to read an xlsx saved on a Mac when nothing says. We read it the
  Windows way unless `platform="mac"` is given

Filling templates:

* a Word template takes text only. The circle of a choice mark, a picture and
  rows carried on to a 別紙 are not put in
* an Excel template does not take rows that need a 別紙, or pictures other than
  PNG and JPEG

Known gaps in the engine:

* a free-form shape whose path has an arc (`arcTo`) or a guide name is not
  drawn
* a gradient that follows the shape (`a:path`) is drawn in one colour
* a table set to automatic width is not widened to fit its content
* a floating table anchored to the page or the margin is placed in the body
  flow
* a double rule counts its full width toward the row height, but only one line
  is drawn
* an empty paragraph left after a table is not carried to the next page, so a
  form that Word prints on two pages comes out on one
* a header built out of a table draws the text in its cells but not its rules
* Word puts a 14pt line of MS PGothic in two grid lines. We measure it with
  the line spacing of MS Mincho, so the two fonts are not told apart
* an embedded Excel object reserves its space and stays blank
* a vertical cell stacks its characters one by one without rotating them
* a font the machine does not have is laid out with the substitute's widths,
  so lines break differently
* on the spreadsheet side, 24 of the 55 collected workbooks differ from Excel
  in page count. 19 of them come out shorter than Excel's
* HTML written from an AsciiDoc document does not yet match Asciidoctor's HTML
  exactly
* EMF pictures are not drawn (the logo of Word's restaurant brochure is one).
  WMF pictures are
* a picture that fills a shape other than a rectangle is cut to the shape's
  bounding box, not to its outline
* Word's restaurant brochure prints on three pages, Word's on two. Its table
  is wider than the page's text, and how Word narrows it is not known yet
* the Flet canvas cannot clip, so `flet_form.py` cuts a stretched picture with
  Pillow, and draws it uncut when Pillow is not installed

Known gaps in the app:

* on the side-by-side screen of an .adoc, the buttons that format selected
  text (bold, size, font) do not change the file. Write the markup in the text
  (`*bold*`)
* an .adoc edited on its pages (`adoc_code = "0"`) is not drawn as page
  pictures
* the list of markup the pages do not show is in Japanese on every language's
  screen
* the PDF button still uses the older writer for a print template, this app's
  own documents and vertical text
* the Windows `setup.exe` is not signed yet. Windows shows "Windows protected
  your PC"; open "More info" and run it from there
* Python is not bundled. Macros and heavy aggregation run on the Python
  already on the machine

== Internals

`tools/screen_compare.py` puts our pages beside Word's or Excel's PDF as
pictures and counts where they differ. It reads a docx or an xlsx, and
`--platform mac` reads an xlsx the Mac way. `tools/ms_pdf.py` waits for Word
to open a document before saving it as PDF.

The design note `docs/sekkei/sashikomi.ja.adoc` records the values measured in
Word, how Excel for Mac and Windows differ, and what was decided.
