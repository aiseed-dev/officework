= officework 0.5.0-beta.4

日本語版: link:RELEASE.ja.adoc[RELEASE.ja.adoc]

To try it: `pip install --pre officework`

This release is what one real document taught us. We took a notice form the
Cabinet Office publishes for download, converted it with officework, and
compared the result against the PDF the same office publishes beside it. Three
defects came out of that one file, and all three would show on any Japanese
office form of the same shape.

== Indents match the original

Three separate causes, all of them visible on the first page.

The left indent was rounded to steps of two full-width characters, so a
one-character indent came out as two and a three-character indent as four. That
form sets a left indent in 123 places. The paragraph now carries the exact
value from the file, and writes the same value back, so opening and saving no
longer moves the text.

Indents written as a character count — `w:leftChars` and its two siblings — were
ignored. This is what Japanese Word writes, and Word prefers it over the
measurement when a document has both. A document that uses only the character
form lost every indent.

Most of the indenting in that form is not a paragraph setting at all: it is
full-width spaces typed at the start of the line, which is how Japanese
business documents are usually laid out. We were dropping them, and when we
kept them we drew them at the width of an ASCII space — 3.48pt where 12pt was
called for. Nine of them put the addressee 76.7pt from where it belongs.

After the fix, 様 sits at 178.90pt against the reference PDF's 178.92, and
大臣 at 394.90 against 394.92.

== Text boxes made by other programs are printed

The same form has three contact panels — office, address, phone, email — and a
note beneath them. We printed none of them.

They were never lost. Anything we did not write ourselves was kept as the
original XML and copied back out on save, so the document survived a round
trip intact; it simply never reached the page. Word positions these boxes
relative to the flow of the text, so where they land is only known once the
document is laid out — the reading is now split so that the shape's size and
contents come from the XML and its position is resolved after layout.

Two things also had to change for the contents to be legible. We were reading
only the first line inside a box, which was enough for the single-line shapes
we write ourselves but dropped four of the five lines in each of these panels.
And the renderer drew whatever it had as one line, which ran each panel across
its neighbours.

== English is now British or American

English is one language on screen and two in documents, because the date order
splits by country and choosing one silently is wrong for the other half.

[cols="2,1,1"]
|===
|Language setting |Short date |Paper

|`en`, `en_US` |m/d/yyyy |Letter
|`en_GB`, `en_AU`, `en_IE`, `en_ZA`, `en_NZ` |dd/mm/yyyy |A4
|===

An English locale that names a country other than the US is treated as
British, because Australia, New Zealand, Ireland, South Africa and India all
write dd/mm/yyyy. An unrecognised one falls to the same side rather than
stopping.

This fixes a defect rather than only adding a choice. The date table held
British formats under the tag `en`, and US English mapped to that same entry,
so opening an American spreadsheet gave British date order. A docx now also
declares `en-GB` or `en-US` where it used to write a bare `en`.

== Other changes

* The right panel is now the project panel and the left one the agent panel,
  in all fifteen languages. The right panel called itself a file listing, which
  it stopped being when it gained create, rename and delete
* The sample scripts follow the engine's current API

== Under the hood

Not visible to users. Three checks had quietly stopped checking anything.

The ribbon parser's self-test sabotages the table six ways and expects each to
be caught. Five of the six carried a copy of a button's label, and the labels
became English in August, so those five had not modified anything since —
passing an unbroken file to the parser and reporting that the parser was blind.
Each case now finds its target in the file and fails loudly if the text did not
actually change.

The generator that produces the ribbon table could no longer reproduce it.
Regenerating would have greyed out nine buttons that work, all of them made
usable during beta.3. Fixing that surfaced a gap in the generator itself: it
could emit a greyed either-or button but had no way to emit a working one.

The Windows build check ran on Linux by cross-compiling, which stopped being
possible when polars arrived and brought C code with it. It runs on a Windows
machine now.
