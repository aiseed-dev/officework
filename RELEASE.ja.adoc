= officework 0.5.0-beta.9

English: link:RELEASE.adoc[RELEASE.adoc]

試すには: `pip install --pre officework`

前の版は横に広がりました。この版は深さです。Word の文書を「ファイルに書いて
あるとおり」に出すことに集中しました。表の書式、書式の既定、図形の色と位置、
そして字間です。数の見せ方は LibreOffice に合わせました。

直した所は、役所が公開している PDF と1つずつ突き合わせて確かめています。
判断に迷う所は、規格(ECMA-376)と LibreOffice の読み手の両方を見てから
決めました。

配っているのはエンジンです。`pip install officework` で入るのはエンジンだけで、
アプリはまだ配っていません。

== 表が、ファイルに書いてあるとおりに出ます

日本の事務は表で出来ています。表に掛かる決まりを1つずつ読むようにしました。

**表のスタイルが効きます。** python-docx が書く表は、スタイルの名前だけを
言って、色を1つも持ちません。見た目は `styles.xml` の `w:tblStylePr` に
あります。見出しの行、最初の列、1行おきの帯を、表自身の `w:tblLook` が選ぶ
とおりに当てます。

そのほかに読むようになった決まりです。

* 幅の割合(`w:tblW type="pct"`)。表が本文の幅いっぱいに広がります
* 表の左のインデント(`w:tblInd`)。Word の版で測り方が違うので、そこも
  分けています
* 見出しの行(`w:tblHeader`)。表が紙をまたぐと、次の紙でも見出しが出ます
* セルの余白(`w:tcMar` と `w:tblCellMar`)。セルごとの指定が表より強いです
* セルの斜線(`w:tl2br` / `w:tr2bl`)。記入しない欄に引く斜線です
* セルの中の均等割り付け(`w:tcFitText`)
* 段落のインデント。セルの中でも本文と同じに効きます

**行の高さが合いました。** セルの中の段落の空きを数えていませんでした。
表のスタイルが言う「段落の後 0」も、言っていないことと区別できていません
でした。

紙をまたぐ表で、字も罫線も無い色の帯が次の紙の頭に出ることがありました。
塗りを2度敷いていたためです。

セルが自分で持つ罫線は、開いて保存すると消えていました。記入欄の下線が
これです。書き出すようになりました。

== 書式の既定を、下から順に読みます

書式は5段の重なりです。アプリの既定、`w:docDefaults`、表のスタイル、段落の
スタイル、そして直接の書式です。下の2段を読んでいませんでした。

python-docx が書く文書は、直接の書式をほとんど持ちません。全部がスタイルに
あります。だから、この2段を読まないと 10.5pt で段落の空きも行間も無い文書に
なります。Word は 11pt、段落の後 10pt、行間 1.15 で出します。

箇条書きと題の下の罫線も、スタイルの中にあります。`w:numPr` を本文に書かず、
スタイルの名前だけで箇条書きにする文書が読めるようになりました。

== 紙の上の字が、原本に近づきました

**字間の指定が紙にも出ます。** 突き合わせに使った調査票の記入欄は、`w:spacing` に
-12 から -20 twip を書いて字を詰めています。組む側はその詰めを測って行を
折っていましたが、PDF は同じ書式の字をまとめて描くので、読む側は書体の送りで
字を並べていました。行が 11pt 伸びて、罫線と隣のセルの字に重なります。

測った結果です。役所が公開している PDF と、同じ字の行どうしを比べました。

|===
|文書 |行末の平均のずれ |1pt 以内に収まる行

|調査票(110 行) |9.01pt → 2.50pt |5 → 68
|告知書(141 行) |3.71pt → 2.54pt |5 → 83
|===

そのほかの直しです。

* 太字の太さを、字の高さの30分の1にしました。LibreOffice と同じ数です。
  前は 0.12mm の決め打ちで、大きい見出しが太く見えませんでした
* 段落の罫線のうち `w:between` を、LibreOffice が引く所に引きます
* 節の区切りだけを持つ段落には罫線を引きません。紙の頭に横線が出ていました
* 図形の色が、文書のテーマの配色から出ます。濃さの修飾(`lumMod` など)も
  解きます
* 図形の位置と大きさが、基準の全部の種類に従います。紙の中央に置いた枠が
  左上に寄ることがありました
* 塗らないと言っている図形(`<a:noFill/>`)を塗りません。1枚まるごと濃い青に
  なる文書がありました
* 自分で塗りを言わない図形は、スタイルの参照(`a:fillRef`)から色を取ります

== 数の見せ方を LibreOffice に合わせました

**書式を付けていないセルの数が、Excel と同じ字で出ます。** `=1.1-1` は
0.10000000000000009 ではなく 0.1 です。有効数字は15桁、2^53 より小さい整数は
整数のまま、指数が15以上か-15以下なら指数の形にします。どれも LibreOffice の
`doubleToString` と同じ決め方です。

**足し算と引き算が、Excel と同じ丸めをします。** `=1/3*3` は 1 です。
LibreOffice の `approxAdd` と `approxSub` と同じで、結果が桁を大きく落とす
ときだけ丸めます。

**列が狭いときは、桁を落としてから諦めます。** 前はすぐ `#####` にして
いました。1.2cm の列で `=1/3` は 0.3333、`=1/3*10000000` は 3E+06 と出ます。
これも LibreOffice と Excel の作法です。

== 検査を2つに分けました

公開の門と、普段の試験は別のものです。門が見るのは**配る物が壊れていないか**
だけで、配っていない物の赤は門になりません。

配る文書も一覧で決めるようにしました。`docs/engine-docs.txt` に19の径路を
書いてあり、道具が「実在するか」「日英の対が揃っているか」「PyPI の頁が
一覧の外を指していないか」を見ます。PyPI は同じファイルを2度受け取らないので、
上げた後では直せないためです。

docx と xlsx の中の札を全部数えて、読んでいない物を並べる道具も入れました
(`tools/tag_check.py`)。**わざと読まない物は、理由と一緒に書いてあります。**
表の札は、いま「読んでいない」一覧に1つも残っていません。

== AsciiDoc の読み書き(まだ配っていません)

Asciidoctor の読み方に合わせる作業を続けています。本家の試験の入力を記録して、
元の字と書き直した字の HTML を比べる道具を作りました。読める172頁のうち、
同じ HTML になるのが129頁です(前は114頁でした)。

箇条書き、説明つきの項目、2行の題、コメント行、属性行、引用の出どころが
往復するようになりました。表はセルの原文を持ち続け、その字を直すまで書き
替えません。

== 手引き

* 数式について「読めます・印刷できます」と書き直しました
* `fill` は知らない欄の名前を渡されたら断ります。手引きにもそう書きました

== 内部の変更

`kumihan::Table` に `width_pct` と `indent_mm` が増えました。`Cellbox` に
`mar_mm` と `fit_text`、`CellBorders` に斜線の2つが増えました。

`kumihan::Document` は、テーマの配色(`theme_colors`)と、文書の既定の空き
(`space_after_pt`・`line_spacing`)を持ちます。

`paper` の `Piece` は字間(`tc_pt`)を持ちます。PDF の `Tc` にそのまま渡します。
同じ書式の字を1つにまとめるとき、**字が続いていない所では切ります** — 均等
割り付けや両端揃えで配った空きが消えないようにするためです。
