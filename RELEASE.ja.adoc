= officework 0.8.0 と aiseed office 0.1.0-alpha.6

English: link:RELEASE.adoc[RELEASE.adoc]

試すには: エンジンは `pip install officework` で入ります。アプリ(aiseed office)は
https://github.com/aiseed-dev/officework/releases[GitHub Releases] にあります。

エンジンは 0.7.0 の次、アプリは 0.1.0-alpha.5 の次の版です。

**この版で、様式を埋められるようになりました。** 履歴書、申請書、届出は、値を入れる所に
印を置いた様式です。値は、それだけを書いた小さな表のブックに書きます。officework が
値を入れて様式を刷ります。出力は PDF、xlsx、docx、PNG のどれかです。ページをほかの
プログラムに渡して描かせることもできます。様式もデータも普通の文字(AsciiDoc)なので、
人もプログラムも読み書きできます。

そのほかは、これまでと同じ仕事です。受け取った docx と xlsx を、Word と Excel と同じに
開きます。今回は絵と図形でした。どれが上に来るか、図形を塗る絵をどう伸ばしてどう
切るか、の 2 つです。

**まだ直っていない所はたくさんあります。** 分かっている物を下に並べました。
壊れている所は https://github.com/aiseed-dev/officework/issues[GitHub の Issues] に
知らせてください。

== 様式を埋める

様式は、セルや段落に `{氏名}` や `{学歴・職歴.3.内容}` のような印を置いた、表のブックか
Word の文書です。データは、名前と値の表と、行の表を持つ表のブックです。印の全部と決まりは
link:docs/ja/forms-manual.adoc[様式の手引き]にあります。

[source,python]
----
from officework import sheet, doc

form = sheet.Book.open("履歴書-厚労省.form.adoc")
data = sheet.Book.open("履歴書.sheet.adoc")
b = sheet.Book.fill(form, data)
b.save("履歴書.pdf")          # .xlsx と .png にも書けます
b.missing                     # 様式が使うのに、データに無い名前
b.bessi                       # 別紙に続けた表

d = doc.Doc.fill_form(doc.Doc.open("届出.docx"), data)
d.save("届出.pdf")            # .docx にも書けます
----

埋めるときにすること:

* データが答えない印は空になります。履歴書がデータより多く用意した行は空のままです。
  データにまったく無い名前は書き間違いのことが多いので、`fill` が警告を出し、`missing` に
  並べます
* `{年齢}` は生年月日と日付から計算します
* `{日付.元号}` と `{日付.和暦年}` は、元号とその年を出します。元号の最初の年は、役所の
  様式と同じく「元」と書きます
* `{通勤時間.時間}` と `{通勤時間.分}` は、`1時間10分` のような値から数を取ります
* `{性別:男・女}` は、データが選んだ方を丸で囲みます。丸は紙に字が置かれた位置を測って
  描きます。丸はブックの図形なので、PDF にも xlsx にも描画の一覧にも入ります
* `{区分=開業}` は、データがその選択肢を選んでいれば ■、そうでなければ □ になります
* 様式に入りきらない行は、別紙のシートに続けます(文書では、改ページの後の別紙に続け
  ます)。列と幅は様式のものを使います
* 図形を写真の欄にできます。データが書いた写真を、縦横の比を保って図形の中に置きます
* Word の様式では、下線を引いた空白の欄(`{氏名}＿＿＿＿`)の長さが変わりません。
  Word が書式の区切りで分けた印も読みます

これで作った履歴書の様式(厚生労働省の様式例と JIS の様式)は、作るスクリプトと一緒に、
aiai のリポジトリで別に公開します。

== 描画の一覧

`Book.draw_list()` と `Doc.draw_list()` は、ページをデータで返します(版 0.1)。
長さはページの左上からの pt です。描く物は PDF が描く順に 1 つの並びにし、書体は名前と
ファイルで、画像は base64 で渡します。字はベースラインと上端の両方を持つので、Flet の
Canvas のように字を上端で置くプログラムは、計算をしなくて済みます。様式を埋めたページ
には、データの項目ごとの欄とその四角も並びます。欄の上に入力を置き、直した値を
`data.set_field(name, value)` でデータに書き戻し、埋め直して描き直せます。

`sample/drawlist/pil_draw.py` は Pillow だけで描画の一覧を描きます。
`sample/drawlist/flet_form.py` は、様式を Flet の Canvas に出して直せるようにします。

== Python で様式を作る

様式を作るプログラムが使う物です。

* `Book.save("x.adoc", attributes=[…])` はブックを AsciiDoc で書き、画像を隣の
  `images/` にファイルで置きます。`Book.save_look` は見た目をテンプレートとして書きます
* `Book.fonts_used`、`replace_fonts`、`set_default_font`
* `Sheet.set_shape` は図形の欄、文字、書体を変えます。`margins_mm` と `print_scale` は
  読み書きでき、`default_row_height` は読めます
* `Book.fields()` は、様式の中で印を持つセルを並べます

== 絵と図形

* **絵と図形は、ファイルに書かれた順に重ねます**。最初の物がいちばん下です
  (ECMA-376 Part 1 20.5.2.35、19.3.1.45)。表の画面はどの絵もどの図形の下に描き、
  紙はその逆だったので、白い枠の中の写真が枠に隠れることがありました
* **図形を塗る絵は、塗る四角(fill rectangle)へ伸ばし**、図形の四角で切ります
  (`a:stretch/a:fillRect`、ECMA-376 20.1.8.30)。Word の飲食店のパンフレットの
  1 頁目の写真は、図形の四角の大きさで描いていました。いまは 381.9 × 579.4pt で、
  Word は 382.1 × 579.4pt で刷ります
* **本文の後ろの図形は、本文とその中の絵の下に描きます**(`behindDoc`、ECMA-376
  Part 1 20.4.2.3)。パンフレットの濃い色の板が、写真 1 枚と絵 2 つを隠していました
* xlsx の絵は、セルの中のずらしを保ちます。2 つのセルで留めた図形は、2 つのセルで
  留めたまま書き戻すので(`twoCellAnchor`)、周りの行に合わせて伸び縮みします
* 列を分けて何枚かに刷るシートでは、図形はそのセルがある列の紙に載ります

== PDF と PNG

* PDF は、字を置いた書体だけを埋め込みます。埋めた履歴書は 89KB から 73KB になりました
* PNG は PDF と同じ組み方と書体で組むので、2 つがそろいます
* AsciiDoc の表で 16 列を超える `[cols=…]` の行を全部読みます。縦にも横にもまたがる
  セルは、AsciiDoc と同じ形(`3.2+|`)で書きます

== アプリ(aiseed office 0.1.0-alpha.6)

**リボンの設定ファイルで、アプリを 1 つの仕事のための版にできます。**
`~/.config/officework/ribbon.toml` で、アプリの名前(ウィンドウのタイトル)、ファイルの
後ろに出すタブとその順番、タブに並べるボタンを決めます。書かなかったタブとボタンは
隠れるだけです。マクロの `xw.press` はそれも押せ、ファイルを消すと元のリボンに戻り
ます。リボンが知らない名前のタブを書くと、自分の Python のボタンのための新しいタブに
なります。マクロの手引きに、AI が作った書類を直すための版の例があります。

[source,toml]
----
name = "書類を直す"
tabs = "ホーム, 挿入, レイアウト, 共同編集, 表示"
----

表の画面では、絵と図形をファイルの順に重ねるので、埋めた履歴書の写真が枠の中に
出ます。文書の画面では、図形を塗る絵を紙と同じに伸ばして切り、本文の後ろの図形は
後ろのままにします。

== まだ直っていないこと

突き止められなかったのは、**何も持たないヘッダーに Word が取る場所**です。空の段落
2 つぶん取るのが合う型紙が 3 件、取らないのが合う型紙が 6 件あり、ファイルの中に
分かれ目がありません。いまは取らない方にしています。測った値は
`engine/src/tests.rs` と設計の記録にあります。

エンジンで分かっている穴です。

* 幅を「自動」にした表で、列の幅を中身に合わせて広げることはまだできません
* 用紙や余白を基準にして浮かぶ表は、本文の流れに置きます
* 二重線の太さは行の高さに数えますが、線を描くのは1本のままです
* 表の後ろに残った空の段落を、次の頁へ送りません。Word が2頁目を出す様式が1頁に
  なります
* ヘッダーの表は、セルの中の字を出しますが、罫線は引きません
* ＭＳ Ｐゴシックの 14pt の行を、Word は行グリッド2つに置きます。こちらはＭＳ 明朝と
  同じ行送りで測っているので、この2つを分けられません
* 埋め込まれた Excel の表は、場所だけ空けて中身は白いままです
* 縦書きのセルは1字ずつ積みますが、字の向きは変えません
* 機械に入っていない書体は、代わりの書体の幅で組むので、行の折れ方が変わります
* 表計算は、集めた 55 枚のうち 24 枚で紙の枚数が Excel と違います。19 枚はこちらが
  少ない枚数です
* AsciiDoc で書いた文書の HTML は、Asciidoctor の HTML と完全には一致しません
* EMF の絵は描けません(Word の飲食店のパンフレットのロゴがそうです)。WMF の絵は描けます
* 四角でない図形を塗る絵は、図形の形ではなく、図形を囲む四角で切ります
* Word の飲食店のパンフレットは、Word が 2 頁、こちらは 3 頁です。表の幅が本文より広く、
  Word がそれをどう縮めるかはまだ分かっていません
* Flet の Canvas は切り抜きができないので、`flet_form.py` は伸ばした絵を Pillow で
  切ります。Pillow が入っていなければ、切らずに描きます

アプリで分かっている穴です。

* 文書の画面から書き出す PDF(PDF のボタン)は、まだ古い書き手を通ります。図形、浮かぶ
  写真、本文の後ろの板が出ず、字は画面の書体になり、書体を丸ごと埋め込みます。2 頁の報告書が
  10MB になり、同じファイルをエンジンで PDF にすると 32KB です。エンジンの PDF
  (`Doc.save("x.pdf")`)には、どれも出ます

* 太字の書体を持たない書体(ＭＳ 明朝など)は、編集画面では普通の字のままです
* 編集画面は、節の先頭の頁だけ別のヘッダーを使う指定(`w:titlePg`)に従いません。
  どの頁にも同じヘッダーを出します
* Windows の `setup.exe` はまだ署名していません。「WindowsによってPCが保護されました」
  が出るので、詳細情報から実行してください
* Python は同梱していません。マクロと重い集計は、機械に入っている Python で動きます

== 内部の変更

エンジンは様式を一度だけ組み、画面、PDF、描画の一覧はその組んだ結果から作ります。
欄の字を置いた位置を残すので、丸と欄の四角が刷った字の上に来ます。

履歴書の様式、見本のデータ、様式を作るスクリプトは、このリポジトリから aiai へ移し
ました。Flet の見本は、企業の中のシステムで使えるので、ここに残しました。
