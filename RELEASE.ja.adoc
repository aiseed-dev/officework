= officework 0.5.0-beta.8

English: link:RELEASE.adoc[RELEASE.adoc]

試すには: `pip install --pre officework`

前の版は、行の高さという1つの寸法の話でした。この版は逆で、横に広がりました。
表計算が400を超える関数と、すべての図形を覚えました。数式はエンジン自身が
組むようになりました。用紙は文書ではなく節が持つようになりました。writer と
calc のリボンは1つになりました。

配っているのはエンジンです。`pip install officework` で入るのはエンジンだけで、
アプリはまだ配っていません。

== 関数が404個になりました

**関数の一覧は404個です。** 足りなかったのは統計・財務・エンジニアリング・
データベースと、分布の一族でした。IPMT から XIRR まで、不完全ガンマ関数と
ベータ関数、ACOSH から MDETERM まで、末尾が B の3つ、そしてそれらを書くのに
要る配列定数(`{1,2;3,4}`)が入りました。

手引きに載っている関数は、Excel が取る引数を全部取るようになりました。
こちらが3つしか受け取らず Excel が5つ受け取る関数では、後ろの2つが何もして
いませんでした。効くようになりました。

**関数の挿入のダイアログが、Excel と同じ形になりました。** 左に分類、関数の
一覧、説明、引数の欄と計算の途中の結果です。関数の手引きは、このダイアログが
出すのと同じ材料から作ります。片方だけが古くなることがありません。

== すべての図形が描けます

**DrawingML の187種類の図形が、仕様書の定義そのものから描けるようになりました。**
前は、知らない図形は四角で出ていました。大かっこは大かっこで、コネクタも
読みます。画面と紙は同じ図形の表を見るので、食い違いません。

2つのセルに留めた図形は、そのセルから大きさを取るようになりました。列の幅を
広げると図形も広がります。留め方が約束しているとおりです。

== 数式はエンジンが組みます

**Python も TeX も要らなくなりました。** 数式は typst と mitex が組みます。
どちらもエンジンの中に入っています。LaTeX を打って Enter を押すと、TeX と
同じ数式の書体で組まれます。数式の中の日本語(`\text{売上}`)は文書の書体で
出ます。

**Word や Excel の数式が、式として開くようになりました。** OMML を LaTeX に
読みます。扱う要素は LibreOffice の読み手と同じです。Word の数式が消えずに
印刷されます。Excel は数式をテキストボックスの中に持ちますが、そちらも同じ
ように読みます。

表計算に貼った画像も印刷されるようになりました。模型には在るのに紙に出て
いなかったもので、数式が出なかった理由もこれです。

== 用紙は節が持ちます

**紙を1枚ずつ積んで見せるのが普通の表示になりました。** 「印刷レイアウト」の
切り替えは無くしました。用紙・向き・余白・段組みは、カーソルのある節に効き
ます。1つの文書の中に、A4 縦の節と A3 横の節を置けます。

AsciiDoc では asciidoctor-pdf と同じ書き方(`page-*` の属性)で書きます。

== リボンは1つです

writer と calc が同じボタンを出すようになりました。違うのは対象の順だけです。
calc はセルが先、writer は字が先です。使えないボタンはグレーで出すのではなく、
出しません。

== Word 文書が原本に近づきました

* 段落の罫線が、どの辺を引くかを知り、紙もそれを引きます
* ぶら下げインデントがぶら下がります
* 表のセルが、自分の揃え(横も縦も)に従います
* 段落の途中の改ページで頁が変わります。2つあれば2回変わります
* テキストボックスの組み方が、ファイルの指定どおりになりました
* 太字が1つのまとまりで出ます。1文字ずつではありません
* 何も無い頁は印刷しません
* 右揃えの数値が、結合したセルの右端に付きます
* 印刷の中央揃えを読みます。セルの空行も1行分の高さを取ります
* ベースラインが、行の高さの5分の4ではなく書体のアセントに来ます

== Python の API が、本家の見本をそのまま動かします

**python-docx の見本と openpyxl の見本が、書き替えなしで動くようになりました。**
この2つを基準にしたので、足りなかった物がそのまま出ました。`docx.shared`、
`docx.enum`、`docx.styles`、グラフのクラス、python-docx 自身の型の検査を通る
`RGBColor`、そして python-docx と同じく書式を持たずに始まる `add_run` です。

`Doc`・`Book`・`Sheet` の属性の綴りを間違えると、黙って何もしないのではなく
断るようになりました。

== エージェント

相談のパネルがエージェントになりました。道具を呼び、その繰り返しを画面に出し、
Python のマクロを書いてサンドボックスで走らせます。誤りはそのまま返します。
AI の宛先には名前を付けて切り替えられます。モデルの状態は4つのうちどれかで
出ます。

== 手引き

* ボタン1つに1枚の手引きが揃いました。256枚のうち256枚です
* 一覧・実例で覚える2冊・ボタンの対応表・Word / Excel との違いに英語版が
  付きました
* 冊子を普通の説明文に書き直しました。1つの文には1つのことです
* 関数の手引きが、ダイアログと同じ材料から作られるようになりました
* `=df()` の手引きを、関数を作る前に書きました

== そのほかの変更

* `=df()` で表の列を1度だけ定義できます。XLOOKUP は二分探索で探し、INDEX は
  領域を取ります
* 一覧・保護・矢印・フィルター・CSV・サンドボックスが、手引きに書いてある
  とおりに動きます
* 一覧のスタイルが一覧を作ります。番号はファイルに残ります
* 相談の記録がブックの隣に残り、開き直すと戻ります
* 属性の参照は字のまま残ります。リンクと相互参照は Asciidoctor と同じ順で
  読みます

== 内部の変更

`kumihan` に `omml`(OMML を LaTeX に直す)と `suushiki`(LaTeX を PNG に組む)
が入りました。docx は `ooxml` から、xlsx は `sheet` から、どちらもここを通ります。

`kumihan::Paragraph` に `line_pt`・`first_line_chars`・`border`・`align_itta` が
増えました。`CharFormat` の `itta` は3つの値を持ち、「指定して切ってある」と
「何も指定していない」を分けます。

図形の表を描画のコードから仕様の定義データへ移しました。`paper` は画面と同じ
表を読みます。
