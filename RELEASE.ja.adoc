== 表計算が、Excel と同じ答えを出します

**関数の一覧は404個です。** 統計・財務・エンジニアリング・データベースと
分布の一族が入りました。手引きに載っている関数は、Excel が取る引数を全部
取ります。配列定数(`{1,2;3,4}`)も書けます。

**関数の挿入のダイアログが、Excel と同じ形です。** 左に分類、関数の一覧、
説明、引数の欄と計算の途中の結果です。関数の手引きはこのダイアログと同じ
材料から作るので、片方だけ古くなることがありません。

**数の見せ方を LibreOffice に合わせました。** 書式を付けていないセルの
`=1.1-1` は 0.1 です。有効数字は15桁、2^53 より小さい整数は整数のまま、
指数が15以上か-15以下なら指数の形にします。`=1/3*3` は 1 です
(`approxAdd` と `approxSub` と同じ丸め)。列が狭いときは、桁を落としてから
`#####` にします。

列の幅が Excel と同じ幅になり、数字が隣の欄にはみ出さなくなりました。
セルの書式は、表示形式・罫線・塗り・配置・書体を全部見ます。

== Word の文書が、書いてあるとおりに刷れます

**表の決まりを1つずつ読みます。** 表のスタイル(`w:tblStylePr` の条件・帯・
見出しの行・最初の列)、幅の割合、左のインデント、見出しの行の繰り返し、
セルの余白、セルの斜線、セルの中の均等割り付け、段落のインデントです。

**書式の既定は5段の重なりです。** アプリの既定、`w:docDefaults`、表の
スタイル、段落のスタイル、直接の書式。下の2段を読んでいませんでした。
python-docx が書く文書は直接の書式をほとんど持たないので、この2段が無いと
別の見た目になります。

**字間の指定が紙にも出ます。** `w:spacing` で字を詰めた原稿を、詰めたまま
刷ります。前は書体の送りで並べていたので、行が伸びて罫線に重なりました。

そのほかに直した所です。

* ページ割りが Word の決まりに合いました(行の高さをファイルに書きます)
* 段落スタイルの見た目が効きます。箇条書きと題の罫線もスタイルから来ます
* 行の高さを書体から出します。ベースラインは書体のアセントに来ます
* 段落の罫線が、どの辺を引くかに従います。`w:between` は LibreOffice と
  同じ所に引きます
* 太字は1つのまとまりで出て、太さは字の高さの30分の1です
* 開いて保存しても、原本の部品はそのまま残ります

役所が公開している PDF と、同じ字の行どうしを比べた数字です。

|===
|文書 |行末の平均のずれ |1pt 以内に収まる行

|調査票(110 行) |9.01pt → 2.50pt |5 → 68
|告知書(141 行) |3.71pt → 2.54pt |5 → 83
|===

== 図形と、画像と、数式

**DrawingML の187種類の図形が、仕様書の定義そのものから描けます。** 前は
知らない図形が四角で出ていました。色は文書のテーマの配色から出し、濃さの
修飾(`lumMod` など)も解きます。位置と大きさは、基準の全部の種類に従います。

他のソフトで作ったテキストボックスも刷れます。表計算に貼った画像も刷れます。
2つのセルに留めた図形は、そのセルから大きさを取ります。

**数式はエンジンが組みます。** Python も TeX も要りません。typst と mitex が
入っています。Word と Excel の数式(OMML)は LaTeX に読むので、消えずに
刷れます。

== 用紙は節が持ちます

紙を1枚ずつ積んで見せるのが普通の表示になりました。用紙・向き・余白・段組みは
カーソルのある節に効きます。1つの文書の中に A4 縦の節と A3 横の節を置けます。

== Python の口が、本家の見本をそのまま動かします

**python-docx の見本と openpyxl の見本が、書き替えなしで動きます。**
`docx.shared`・`docx.enum`・`docx.styles`、グラフのクラス、python-docx 自身の
型の検査を通る `RGBColor` が入りました。`Doc`・`Book`・`Sheet` の属性の綴りを
間違えると、黙って何もしないのではなく断ります。

xlwings の書き味(`from officework import calc as xw`)も同じままです。

== まだ直っていないこと

**アプリは配っていません。** `pip install officework` で入るのはエンジンだけ
です。画面はソースから組めます(README の「組む」)。

エンジンで分かっている穴です。

* 表の列の幅に `w:gridCol` を使います。Word がセルごとの `w:tcW` を使う
  文書では、折り返しが1字ずれることがあります
* 入れ子の表は、外の表の外に出して本文の流れに置きます
* 表計算の頁割りが原本と合わない帳票があります。国税庁の課税状況の2つは、
  原本の8頁と7頁に対して11頁と12頁になります
* 図形のスタイルの参照(`a:fillRef`)は色だけを取ります。テーマの並びが
  グラデーションでも単色で塗ります
* AsciiDoc の読み書きは**まだ配っていません**。Asciidoctor の頁で比べると、
  読める172頁のうち129頁が同じ HTML です

== 内部の変更

`kumihan` に `omml`(OMML を LaTeX に直す)と `suushiki`(LaTeX を組む)が
入りました。図形の表は描画のコードから仕様の定義データへ移し、画面と紙が
同じ表を読みます。

公開の門と普段の試験を分けました。門が見るのは配る物が壊れていないかだけ
です。配る文書は `docs/engine-docs.txt` の一覧で決めます。docx と xlsx の
札を全部数えて、読んでいない物を理由つきで並べる道具も入れました
(`tools/tag_check.py`)。
