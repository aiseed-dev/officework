= officework 0.7.0 と aiseed office 0.1.0-alpha.5

English: link:RELEASE.adoc[RELEASE.adoc]

試すには: エンジンは `pip install officework` で入ります。アプリ(aiseed office)は
https://github.com/aiseed-dev/officework/releases[GitHub の Releases] から落とします。

エンジンは 0.6.0 の次の版です。アプリは 0.1.0-alpha.4 の次の版です。やることは前の版と
同じです。**受け取った Word の文書と Excel のブックを、Word や Excel と同じように表示して、
同じ紙に刷ります。**

この回は Word のテンプレートを 1 件ずつ見ていきました。Word で開き、officework で開き、
刷った頁を並べ、違う行を 1 つ見つけ、OOXML で何と書いてあるかを確かめて、決めを直す。
下に書いた物はすべてこのやり方で出てきた物で、見つけたときに測った値をコードのそばに
書いてあります。

確かめ方も1つです。同じファイルを Word と officework で開いて、刷った物を並べます。
役所が公開している様式 288 枚と、Word が配っているテンプレートで、これを毎日回しています。

**まだ直っていない所は多くあります。** 下に「まだ直っていないこと」として書きました。
壊れている所は https://github.com/aiseed-dev/officework/issues[GitHub の issue] へ
書いてください。

== 受け取った Word の文書が、Word と同じ紙に収まります

**役所が公開している様式 288 枚のうち、Word と頁数が合うのは 272 枚です。** 前の版では
270 枚でした。

この回に見つけた決めです。どれも Word の PDF で測って確かめました。

* 前の段落の「後の空き」と次の段落の「前の空き」は足しません。大きい方だけが間の空きに
  なります。`w:doNotUseHTMLParagraphAutoSpacing` を持つ文書だけは足します
* 行の中のベースラインは書体の上がりの所です。行の倍率が 1 より小さいときは上がりも
  縮み、1 を超えて増えた分はベースラインの下に付きます
* 表は、その表が入っている節の行長で組みます。文書の行長ではありません
* 頁の番号は、その節の決め(`w:pgNumType w:start`)で振ります。目次の節が 0 から
  始まる文書は、その次の枚に 1 と刷ります
* 1 枚に収まる表の行は、残りに入らなければ行ごと次の頁へ送ります。割るのは 1 枚に
  収まらない行だけです
* 頁の頭に来た段落は、自分の「前の空き」をそのまま置きます
* 段落の罫線の `w:space` は、線を引く側にだけ空きます。前は上下 2 回ぶん足していました
* 表スタイルの帯は字を大文字にできます(`w:tblStylePr` の `w:caps`)
* 本文の中の絵は、その行が載った頁に刷ります
* 固定の行の高さは、保存しても固定のままです
* 見出しは次の段落と離れず、段落の 1 行だけが頁の境に残りません。表のセルの中でも同じです
* 番号付きの箇条書きは `w:numFmt` の形で振り、間にほかの段落を挟んでも続きます

前の版(0.6.0)で直した所です。

* 表の行は、上の罫線の太さの分だけ高くなります。太さは `w:sz` から取り、二重線は3倍、
  三重線は5倍として数えます
* 表は次の行が始まる位置から始まり、表の後の文は表の下端から始まります。この1つだけで
  12 枚の頁数が合いました
* 縦に結合したセルが足りない高さは、またがる行に均等に配ります
* 節の1頁目だけ別の余白を使えます(`w:titlePg`)
* 空の段落の大きさと書体は、段落記号の書式(`w:pPr/w:rPr`)から取ります
* 行の高さの「最小値」(`w:trHeight`)は、セルの中身の下限として使います。セルの余白は
  その上に足します
* セルの余白は、辺ごとに表の既定と混ぜます
* 罫線がセルの側にしか書かれていない表でも、縦の罫線を引きます
* 行の高さが行グリッドの間隔をほんの少し超えるときは、グリッド1つに収めます。超え方が
  0.1pt までなら収まったものとして扱います
* 頁区切りと節の区切りの間に空の段落しか無いときは、頁を1回だけ改めます。前は2回
  改めて、ヘッダーだけの頁が出ていました
* ヘッダーとフッターが表でできているときも、セルの中の字を出します。Word のテンプレートは
  日付・題・頁番号を1行の表に入れるので、そこが白いままでした

== 書体の選び方を Word に合わせました

**1つのファイルに複数の書体が入っている形式(.ttc)から、名前で指定された書体だけを
取り出します。** 前は先頭の書体で測っていたので、ＭＳ Ｐゴシックの全角の空白が広くなり、
Word とは違う所で行が折れていました。

* テーマの書体が日本語の字を持たないとき、その日本語はＭＳ 明朝で描きます
* 文書の既定がテーマの欧文の書体を指すとき、欧文の既定もテーマから取ります
* 行の高さは書体の `hhea` の値から取ります
* 大文字で表示する指定(`w:caps`)と、スタイルが持つ文字の間隔を読みます
* 半角と全角の幅をそろえる設定(`w:balanceSingleByteDoubleByteWidth`)があるときは、
  日本語の書体の半角を 0.5em で送ります

== 図形と写真が、置いた所に出ます

* 文字の回り込みをしない写真は、指定された位置に置きます
* 写真だけの段落は、写真の高さの行になります。残りの高さに入らない写真は、次の頁の
  上の余白から始まります
* 帯・線・囲み・グループなどの図形を描きます。表のセルの中に置かれた図形も描きます
* 文字を持たない図形は本文より先に描き、テキストボックスは本文の後に描きます

見本の報告書(`sample/事業のご報告.docx`)は、2 頁とも Word と同じ頁割りになりました。
行の位置は Word との差が 0.7pt 以内で、2つのグラフの位置は Word と同じです。

== 目次を刷る前に作り直します

Word は印刷のたびに `TOC` のフィールドを作り直します。ですからファイルに入っている
頁番号と見た目は、前に刷ったときの物です。こちらも同じようにしました。文書を 1 回組んで
頁を出し、`PAGEREF` にその見出しが載った頁を答え、もう 1 回組み直します。項目は
`TOC 1`・`TOC 2` のスタイルで組みます。保存されている run が名乗る文字スタイルは、
Word も使わないからです。

Word の事業計画書のテンプレートでは、目次が Word の「2」に対して「1」、字の大きさが
Word の 10pt に対して 13pt でした。

== Word のテンプレートも刷れます

Word が「新規」の一覧で配っているテンプレートを集めて、同じ比べ方をしました。
事業計画書 `e22e6b47` は Word が 20 頁のところ 23 頁でしたが、20 頁になり、
どの頁も Word と同じ行から始まります。

履歴書のテンプレートは、1 頁目の 38 行すべてが Word との差 0.2pt 以内に収まります。

== Excel のブックが、Excel と同じ紙に収まります

**既定の文字の大きさは 11pt、既定の行の高さは 18.75pt です。** 画面と紙とファイルの
3つで同じ値を使います。

* 列の幅は、ファイルが指定した書体の数字の幅を、Windows の Excel と同じく 96dpi の
  画素で数えます。Mac で作ったブックは、アプリの設定か
  `Book.open(path, platform="mac")` で、Mac の数え方(72dpi)で開けます
* 行の高さは、手で決めた高さの印(`customHeight`)が無くても読みます。ECMA-376 の
  とおりです。保存しても、自動で決まった高さは自動のまま残します。高さと余白を
  ポイントの整数に切り捨てるのは、Mac の数え方で開いたときだけです
* 罫線は Excel と同じ太さで印刷します。100% のときに細線 1pt、中線 2pt、太線 3pt で、
  拡大縮小の率も掛けます。極細線は 0.12pt です
* テキストボックスは、テーマの色と明るさの加減、破線、段落ごとの行、書体を読みます
* 縦方向の中央揃え、既定の列の幅、JIS の B4 と B5 の紙に従います
* 紙に収める拡大縮小の率は、Excel と同じく1パーセントきざみの整数にします
* セルの中で行を重ねるときの間隔を Excel に合わせました
* 空白のセルを読む数式は 0 を返します

書き出した xlsx を Excel が開けなかった所も直しました。テーマの部品と関連付けの
食い違い、Excel が知らないエラーの値、列全体と行全体の参照(`A:B`・`1:3`)です。

役所が公開しているブック 55 枚で、Excel の PDF と比べています。完全に一致した物は
1 枚から 5 枚になりました。

== 日付と時刻にタイムゾーンを持たせられます

**セルに、タイムゾーン付きの日時を入れられます。** セルにはその場所の時刻を表示し、
2 つの日時の引き算では、実際に過ぎた時間を計算します。

----
=ZONED("2026-10-01 10:00", "Asia/Tokyo")           出発(東京の時刻)
=ZONED("2026-10-01 04:30", "America/Los_Angeles")  到着(ロサンゼルスの時刻)
=(B3-B2)*24                                        飛行時間 10.5 時間
=TO_ZONE(B3, "Asia/Tokyo")                         到着を東京の時刻で
----

保存されるのは数式なので、xlsx でも AsciiDoc でもタイムゾーンが戻ります。xlsx の
セルの値には、そのタイムゾーンの時計の時刻を書きます。Excel で開いた人にも、
再計算するまでは正しい時刻が見えます。

`ZONED` と `TO_ZONE` は Rust で書いたカスタム関数です。カスタム関数は、これまで
どおり Python でも書けます。Python の関数は、タイムゾーン付きの `datetime` を受け取り、
返せます。`NOW()` と `TODAY()` はブックのタイムゾーンの時刻を返します。ブックの
タイムゾーンは、別の物を指定して開かない限り、パソコンの設定です。

== Python から使う所

**大きな表はデータフレームで扱えます。** 数万行の表をセル1つずつ読む必要はありません。

[source,python]
----
t = s.tables["テーブル1"]
t.schema()                    # 行数と、列の名前と型
t.head(2)                     # 見出しと先頭の2行
t.query("SELECT 月, SUM(金額) AS 計 FROM テーブル1 GROUP BY 月")
t.frame(sql, limit=200)       # 同じ答えを polars の DataFrame で
----

問い合わせの言葉は SQL です。`t.frame()` を使うには polars を入れてください。

`xw.press("bold")` は、リボンのボタンを押したのと同じことをします。`xw.ui_state()` は、
いま開いている物とステータスバーの字を返します。

`Doc.open` は `.adoc` も読み、`save("報告.adoc")` で書けます。

`Book.open` は、ファイルを作った Excel を `platform="windows"` か `"mac"` で、
時計の時刻のタイムゾーンを `time_zone` で受け取ります。`Book.time_zone` で
ブックのタイムゾーンを読み書きできます。

タイムゾーン付きの日時のセルは、`officework.sheet` でも `officework.calc` でも、
`zoneinfo` のタイムゾーンを持つ `datetime` で返ります。polars の DataFrame では、
タイムゾーンが 1 つの列はそのタイムゾーンの列に、混ざった列は UTC の列になります。

Mac で `officework.calc` が動いているアプリにつながるようになりました。前はアプリを
違うフォルダーで探していました。

openpyxl に合わせた細かい直しも入りました。`sheet_state` と `paper_size`、データの
入力規則を足した後で範囲を足せること、1つのセルだけの結合が何もしないこと、経過時間の
表示形式が `timedelta` を返すことです。

== アプリ(aiseed office 0.1.0-alpha.5)

**画面はセクションを 1 つずつ見せます。** Word の文書は節で書かれていて、節は用紙・
ヘッダーとフッター・頁番号の付け方が変わる所です。窓の下のタブで選ぶと、その節の紙だけを
見せます。表計算がシートを選ぶのと同じです。スクロールもその中で止まり、キャレットが別の
セクションへ移ると画面もついて行きます。

ヘッダーとフッターを画面のどの頁にも描きます。その頁が使う部品と、その頁の番号です。
行の中のタブは描かなくなったので、目次の点線が紙と同じ所で止まります。

表計算の画面も、文章の画面と同じく、ブックが指定した書体を登録するようにしました。
ＭＳ 明朝などの Office の書体が、その書体で表示されます。テキストボックスは、画面でも
その字の大きさと書体で表示します。

表計算の詳細設定で、xlsx の開き方を選べます。ファイルを作った Excel(Windows か Mac)、
日付の起点、タイムゾーンです。

上に書いた Word と Excel の一致は、アプリの表示と印刷にもそのまま効きます。

リボンの並びと名前は Euro-Office のままにしています。ファイルの読み書きと印刷を
Word・Excel に合わせることを先にするためです。

== まだ直っていないこと

突き止められなかったのは、**何も持たないヘッダーに Word が取る場所**です。空の段落
2 つぶん取るのが合う型紙が 3 件、取らないのが合う型紙が 6 件あり、ファイルの中に
分かれ目がありません。いまは取らない方にしています。測った値は
`engine/src/tests.rs` と設計の記録にあります。

エンジンで分かっている穴です。

* 幅を「自動」にした表で、列の幅を中身に合わせて広げることはまだできません
* 用紙や余白を基準にして浮かぶ表は、本文の流れに置きます
* 二重線の太さは行の高さに数えますが、線を描くのは1本のままです
* 表の後ろに残った空の段落を、次の頁へ送りません。Word が2頁目を出す様式が1頁に
  なります
* ヘッダーの表は、セルの中の字を出しますが、罫線は引きません
* ＭＳ Ｐゴシックの 14pt の行を、Word は行グリッド2つに置きます。こちらはＭＳ 明朝と
  同じ行送りで測っているので、この2つを分けられません
* 埋め込まれた Excel の表は、場所だけ空けて中身は白いままです
* 縦書きのセルは1字ずつ積みますが、字の向きは変えません
* 機械に入っていない書体は、代わりの書体の幅で組むので、行の折れ方が変わります
* 表計算は、集めた 55 枚のうち 24 枚で紙の枚数が Excel と違います。19 枚はこちらが
  少ない枚数です
* AsciiDoc で書いた文書の HTML は、Asciidoctor の HTML と完全には一致しません

アプリで分かっている穴です。

* 太字の書体を持たない書体(ＭＳ 明朝など)は、編集画面では普通の字のままです
* 編集画面は、節の先頭の頁だけ別のヘッダーを使う指定(`w:titlePg`)に従いません。
  どの頁にも同じヘッダーを出します
* Windows の `setup.exe` はまだ署名していません。「WindowsによってPCが保護されました」
  が出るので、詳細情報から実行してください
* Python は同梱していません。マクロと重い集計は、機械に入っている Python で動きます

== 手引き

writer の手引きに、受け取った docx を刷るときに Word と同じに扱う設定の一覧と、まだ
違う所の一覧を足しました。Python の手引きには、文書をブロックで読み書きする書き方、
`.adoc` の読み書き、表をデータフレームで扱う書き方を足しました。Mac に Microsoft Office が
入っていれば追加の書体は要らないことも書きました。

== 内部の変更

画面と紙が、同じ処理で組まれます。文書を組み立て、文字ごとの書体を決め、紙面に並べる
までが1つにまとまりました。PNG も同じ処理を使うので、画面・PDF・PNG の3つで同じ書体に
なります。

手元の Word と Excel を基準にする道具が入りました。docx と xlsx を Word・Excel に
開かせて PDF にし、行の位置と字を比べます。数式の答えも Excel から取ります。開いた文書は
その都度閉じ、閉じられなければ止まります。

役所の様式を集める道具、Word のテンプレートを集める道具、頁数を集計する道具を `tools/`
に入れました。
