= officework 0.9.0 と aiseed office 0.1.0-alpha.7

English: link:RELEASE.adoc[RELEASE.adoc]

試すには: エンジンは `pip install officework` で入ります。アプリ(aiseed office)は
https://github.com/aiseed-dev/officework/releases[GitHub Releases] にあります。

エンジンは 0.8.0 の次、アプリは 0.1.0-alpha.6 の次の版です。

**この版で、Word と Excel で作ったテンプレートに、そのまま値を入れられるようになりました。**
テンプレートに、こちらの印を置く必要はありません。Excel では、データにセルの番地か定義した
名前を書きます。Word では、差し込み印刷のフィールドか `{氏名}` のような印が、値を入れる所を
示します。変わるのは値だけで、ファイルのほかの部分は元のまま写します。

**アプリでは、.adoc をコードで直し、その横にできるページを出すようになりました。**
データの .adoc は、名前を書いた Word や Excel のテンプレートに値を入れた姿を出します。
Word と Excel のファイルは、印刷するページの形で、見るだけで開きます。

そのほかは、これまでと同じ仕事です。ページを、Word と Excel が印刷するのと同じに描きます。
今回は、値を入れたテンプレートのページを Word for Mac と Excel for Mac の PDF と比べて、
違う所を直しました。ECMA-376 の規定と Word が違う所は、規定に従いました。

**まだ直っていない所はたくさんあります。** 分かっている物を下に並べました。
壊れている所は https://github.com/aiseed-dev/officework/issues[GitHub の Issues] に
知らせてください。

== Word と Excel のテンプレートに値を入れる

データは、様式と同じ表のブックです(書き方は link:docs/ja/forms-manual.adoc[様式の手引き]に
あります)。

[source,python]
----
from officework import sheet, doc

data = sheet.Book.open("山田.sheet.adoc")
notes = sheet.Book.fill_template("履歴書.xlsx", data, "山田.xlsx")
missing = doc.Doc.fill_template("送付状.docx", data, "山田.docx")
----

Excel のテンプレートでは、次のようにします。

* データの 2 列の表の項目に、セルの番地(`B5`、`履歴書!D9`)か、テンプレートで定義した
  名前(数式 > 名前の管理)を書くと、そのセルに値が入ります。セルにある `{氏名}` などの印も
  埋まります
* 値が変わるセルだけをシートに書きます。字は字として、数は数としてセルに入り、セルの書式は
  残ります。ほかの部分(書式、テーマ、図形、文書の情報)は元のまま写します。厚生労働省の
  履歴書に 4 つの値を入れると、変わるのは `xl/worksheets/sheet1.xml` だけです
* 図形に、Excel の名前ボックスでデータの項目と同じ名前(`写真`)を付けておくと、データに
  書いた画像のファイルがその図形の中に入ります。ファイルはデータのファイルと同じフォルダーから
  探します。画像は縦横の比を保って図形の中に置き、図形の中の字は消します。入れられる画像は
  PNG と JPEG です
* `notes` には、この形で入れられなかった物が並びます。別紙の要る行、ほかの種類の画像、
  見つからないファイルです

Word のテンプレートでは、次のようにします。

* 本文、ヘッダー、フッターの `{氏名}` のような印を埋めます。Word が印の字を書式の違う部分に
  分けていても見つかります。値は、印の始まる所の書式で入ります
* データの項目と同じ名前の差し込み印刷のフィールド(差し込み文書 > 差し込みフィールドの挿入)は、
  値の字になります。Word の差し込み印刷で作った文書と同じです
* 変わるのは、印とフィールドの字だけです。ファイルのほかの部分と、その部分の中のほかの所は、
  すべて元のまま写します
* `missing` には、データに 1 つも無い名前が並びます。その印は空になり、`fill` と同じように
  警告が出ます

差し込み印刷のフィールドは、docx を開いたときにも読みます。`fill` と `fill_form` は印と
同じように埋めます。保存するとフィールドのまま書くので、差し込み印刷のテンプレートを開いて
保存しても壊れません。

docx を保存するときに、誰も変えていない部分を書き直さなくなりました。変わっていない
ヘッダーとフッターは元のまま写します(Word の手紙のヘッダーが 2KB 減っていました)。
設定と文書の情報へのリンクを 2 回書くこともなくなりました。

== ページを Word と Excel に合わせる

ページは、Word for Mac と Excel for Mac が印刷した PDF と比べました。メイリオ UI の文書は、
書体をヒラギノ角ゴシックか游ゴシックに替えた写しで比べました。

* Word のレターヘッドのテンプレート(ヒラギノ角ゴシック):どの行も、ベースラインが Word と
  0.5pt 以内です
* Word の転職の送り状のテンプレート(ヒラギノ角ゴシック):どの行も Word と同じ所で折れ、
  位置は Word と 1pt 以内です
* 厚生労働省の履歴書を Mac の読み方(`platform="mac"`)で読むと、Excel for Mac と同じ
  8 ページになります。列の境目の差は 0.2pt 以内です

Word の文書で直したことです。

* **カーニング**(`w:kern`、ECMA-376 Part 1 17.3.2.19)を読んでいなかったので、字を詰めて
  いませんでした。最近の Word のテンプレートは、文書の既定でカーニングを指定しています。
  いまは書体の値で字の組み合わせを詰めます。ヒラギノ角ゴシック W3 では、Word と同じく
  「と」と「を」の間を 0.03em 詰めます。大文字だけの字、文字グリッドのある文書、半角を
  決まった幅で並べる書体は詰めません
* 表そのものの罫線(`w:tblBorders`、17.4.39)に、太さと色が付きました。これまでは
  どれも 0.5pt の黒でした。表の下の辺も、最後の行の下に自分の太さを持つようになり、
  表の後ろの字はその下から始まります
* 字に直接付けた「自動」の色(`w:color w:val="auto"`、17.3.2.6)を、スタイルの色より
  先にしました。レターヘッドのプレースホルダーは、こちらでは灰色、Word では黒でした
* 欧文のテーマの書体だけを指定したスタイルは、和文の書体を元のスタイルから受け継ぎます
  (17.3.2.26)。レターヘッドの名前は Arial の幅で組み、別の書体で描いていたので、下線が
  途中で切れていました
* ヒラギノ角ゴシック W3 の 1 行の高さを 1.30em、ベースラインを行の上から 1.03em にしました。
  Word が描く値です。1 行の高さは規定がアプリに任せているので(17.3.1.33)、Word で測りました
* 太字の書体を持たない書体(ヒラギノ、ＭＳ 明朝、ＭＳ ゴシック、Century)を太字にすると、
  Word と同じく 1 字ごとに 0.02em 広げます。スペースは、半角も全角も広げません
* 下線の位置と太さは、書体が持つ値(`post` 表)を使います。Word は欧文の書体をこう描きます。
  値を持たない書体は、これまでの位置のままです
* 表のセルの中の行は、左と右のインデントの間でそろえます。セルの中の画像は、その段落の字と
  一緒にそろえます
* フリーフォームの図形(`a:custGeom`)を描き、内側の輪郭は穴にします。線形のグラデーション
  (`a:gradFill`)は、グラデーションで塗ります
* ページの大きさに合わせるグループ(`wp14:sizeRelH`)は、ページに合わせて広げます。行の中に
  置いたグループは、中の図形を全部描きます
* 名前で指定した蛍光ペンの色(`yellow`、`darkBlue` など)が、黒ではなくその色になりました
* **文字の透かし**を、Word と同じに描きます。ファイルが決めた箱(ヘッダーの中の VML の図形、
  ECMA-376 Part 4 19.1.2)に、ファイルのとおりに回して色を付け、本文の下に描きます。字は、
  箱から内側の余白を引いた大きさに伸ばします。測った 3 つの透かしで、字の広がりは Word と
  0.2pt 以内です。前は、決まった 60pt で本文の上に描いていました
* ページの色(`w:background`)が、エンジンの描くどのページにも付きます。PDF、PNG、描画の
  一覧です
* パスで描く半透明の図形の後ろで、ページのほかの物まで半透明になることがなくなりました
* ページの画像(PNG)は、PDF と同じに字を描きます。書体の選び方、下線、取り消し線、
  文字の間隔、太字が PDF と同じです

Excel のブックで直したことです。

* 改ページをまたぐ図形は、Excel と同じく、届くページのそれぞれに、そのページの範囲で
  切って描きます。これまでは最初のページに丸ごと描き、余白にはみ出していました
* 右揃えのセルは、文の終わりの全角スペースを幅に数えません。文頭の全角スペースは数えます
* 名前に「楷書」がある書体は、ゴシックではなく明朝で代えます。Excel for Mac と同じです

規定と Word が違った所です。

* `w:overflowPunct`(17.3.1.21)は、指定が無ければ「、」を行末からはみ出させてよい、と
  しています。Word for Mac は、はみ出させずに 1 字前で折りました。こちらは規定に従います
* 規定は、下線を「字の高さのすぐ下」とだけ書いています(17.3.2.40)。Word は和文の書体の
  下線を、書体が持つ値より下に引きます。決まりは見つかりませんでした。こちらは書体の値を
  使います

== AsciiDoc と書体

* 誤りと、ページに出せない書き方の一覧は、下の行に線を引く見出し(setext の見出し)の後でも、
  ファイルの行の番号を出します
* 一覧は、同じ種類を 1 つのファイルで 1 回だけ、出た回数と一緒に並べます
  (「字下げの段落(literal) × 3(3 行目ほか)」)。Python の `Doc.unsupported` も同じ数を返します
* macOS の確認の画面を待って止まる書体のフォルダー(Group Containers の中の Office の
  クラウドの書体)は、2 秒待って飛ばします。前は書体を探す処理が止まり、字を組む物が全部
  止まりました
* `save_look` は、書式の違う部分を持つセルを、いちばん長い部分の大きさで書きます。
  全部の部分が同じ大きさのときも同じです

== 描画の一覧

字に `clip`(`[x, y, w, h]`)が付くことがあります。字はその範囲で切って描きます。
改ページをまたぐ図形の字に付きます。

== アプリ(aiseed office 0.1.0-alpha.7)

**Word と Excel のファイルは、見るだけで開きます。** 値はデータから入れるので、アプリは
ファイルを見せるだけで、変えません。docx は、印刷と同じ姿のページで開きます。スクロール、
拡大、検索、コピー、PDF の書き出しはできます。入力、文書を変えるボタン、保存は断ります。
xlsx は、文書の画面で、印刷するページの形で開きます。
`~/.config/officework/settings.toml` に `docx_edit = "1"` や `xlsx_edit = "1"` と書くと、
前のように直せます。

**データの .adoc は、名前を書いた Word や Excel のテンプレートに値を入れます。** 名前と値の
表でデータを書いた .adoc の頭に、`:template: 送付状.docx`(または .xlsx)と書きます。右には、
値を入れたテンプレートを、PDF と同じ組み方で出します。データに無い名前は、ページの上に
出します。PDF のボタンはそのページを書き出します。名前を付けて保存で .docx か .xlsx を
選ぶと、値を入れたテンプレートを書きます。ファイルのほかの部分は元のままです。

**.adoc は、コードを直し、その横にできるページを出します。** 左にはファイルの字を等幅の
書体で出します。右には、その字から作ったページを、PDF と同じ組み方で出します。入力を
止めて少したつと、ページを作り直します。ページを押すと、左のその字へカーソルが移ります。
ページはカーソルについてきて、カーソルの行に黄色の帯が付きます。誤りと、ページに出せない
書き方は、ファイルの行の番号と一緒にページの上に並べます。保存すると字をそのまま書くので、
コメント、空行、行の切れ目は残ります。`sample/writer/07_早見表.adoc` を開くと、書き方と
出来上がりを並べて見られます。前のようにページの上で直すときは、
`~/.config/officework/settings.toml` に `adoc_code = "0"` と書きます。

**文書の画面は、どのページも印刷したページの画像で出します。** 画像は PDF に刷るページから
作るので、上に書いた直しが画面にも出ます。ヒラギノ角ゴシックに替えた転職の送り状は、画面でも
どの行も Word と同じ所で折れます。ヒラギノ角ゴシック W3 の太字のように、太字の書体が無い
書体を太くした字も、画面で太字になります。節の先頭のページだけ別のヘッダーを使う指定
(`w:titlePg`)にも従います。カーソルと選択は、画像の字の上に置きます。設定に
`page_pictures = "0"` と書くと、前の描き方に戻ります。

**PDF のボタンは、画面に出ているページを書き出します。** docx の PDF に、図形、浮かぶ写真、
本文の後ろの板が出ます。書体は使った物だけを埋め込みます。32 ページの JST の計画書は
508KB になりました。前は約 10MB でした。.adoc、印刷のテンプレート、縦書きも、エンジンの
書き手で書くようになりました。前の書き手は使いません。

**.adoc の字を壊さないようにしました。** コードとページを並べた画面を見直すと、保存で字を
AsciiDoc の書き手に通してしまう道が見つかりました。書き手に通すと、どの行の後にも空行が
入ります。見つかった道は、ほかのタブへ移って戻ったとき、開けなかったファイルがあったとき、
落ちたときの控え、拡張子を書かずに名前を付けて保存したときです。どれも直しました。
この画面では、字に効く操作だけが動きます。表、画像、見た目を付ける操作は、ボタンでも
キーでもソケットでも、断って理由を出します。保存では、ファイルの CR LF の改行と、最後に
改行が無いことを保ちます。コードから書き出す docx は、コードから作った文書で書きます。

見えなくなったページの画像は GPU に返し、見ている所の近くのページだけを持ちます。長い
文書をスクロールしたり直したりしても、メモリーが増え続けなくなりました。

== まだ直っていないこと

次のことは、Windows の Word と Excel が無いと決められません。まだ確かめていません。

* 游ゴシックの 1 行の高さ。Word for Mac は 1.44em で描きます。こちらは、前に別の文書で
  測った 1.5em を使っています
* 和文の書体の下線を、Word がどこに引くか
* 右揃えのセルの終わりの全角スペースを、Windows の Excel も数えないか
* Mac で保存した xlsx を、指定が無いときにどちらの読み方にするか。いまは、
  `platform="mac"` が無ければ Windows の読み方です

テンプレートに値を入れるときの穴です。

* 表のブックの AsciiDoc(`.sheet.adoc`)は、まだ表の画面で開きます。値を入れるテンプレートの
  横には出ません
* Excel のテンプレートに入らなかった物の知らせは、どの言語の画面でも日本語で出ます
* Word のテンプレートには、字だけが入ります。選択肢の丸、画像、別紙に続ける行は入りません
* Excel のテンプレートには、別紙の要る行と、PNG と JPEG 以外の画像は入りません

エンジンで分かっている穴です。

* 円弧(`arcTo`)や計算式の名前を使うフリーフォームの図形は描きません
* 図形の形に沿うグラデーション(`a:path`)は、1 色で塗ります
* 幅を「自動」にした表で、列の幅を中身に合わせて広げることはまだできません
* 用紙や余白を基準にして浮かぶ表は、本文の流れに置きます
* 二重線の太さは行の高さに数えますが、線を描くのは1本のままです
* 表の後ろに残った空の段落を、次のページへ送りません。Word が2ページ目を出す様式が
  1ページになります
* ヘッダーの表は、セルの中の字を出しますが、罫線は引きません
* ＭＳ Ｐゴシックの 14pt の行を、Word は行グリッド2つに置きます。こちらはＭＳ 明朝と
  同じ行送りで測っているので、この2つを分けられません
* 埋め込まれた Excel の表は、場所だけ空けて中身は白いままです
* 縦書きのセルは1字ずつ積みますが、字の向きは変えません。縦書きの文書でも、括弧を縦用の
  形に変えません
* 機械に入っていない書体は、代わりの書体の幅で組むので、行の折れ方が変わります
* 表計算は、集めた 55 枚のうち 24 枚で紙の枚数が Excel と違います。19 枚はこちらが
  少ない枚数です
* AsciiDoc で書いた文書の HTML は、Asciidoctor の HTML と完全には一致しません
* 透かしの字は、透かしが名前を書いた書体ではなく、こちらの最初の書体で描きます。箱は Word と
  合いますが、字の形は違います
* EMF の絵は描けません(Word の飲食店のパンフレットのロゴがそうです)。WMF の絵は描けます
* 四角でない図形を塗る絵は、図形の形ではなく、図形を囲む四角で切ります
* Word の飲食店のパンフレットは、Word が 2 ページ、こちらは 3 ページです。表の幅が本文より
  広く、Word がそれをどう縮めるかはまだ分かっていません
* Flet の Canvas は切り抜きができないので、`flet_form.py` は伸ばした絵を Pillow で
  切ります。Pillow が入っていなければ、切らずに描きます

アプリで分かっている穴です。

* Windows の `setup.exe` はまだ署名していません。「WindowsによってPCが保護されました」
  が出るので、詳細情報から実行してください
* Python は同梱していません。マクロと重い集計は、機械に入っている Python で動きます

== 内部の変更

`tools/screen_compare.py` は、こちらのページと Word や Excel の PDF を画像で並べ、
違う所を数えます。docx と xlsx を読みます。`--platform mac` を付けると、xlsx を Mac の
読み方で読みます。`tools/ms_pdf.py` は、Word が文書を開き終わるのを待ってから PDF に
します。Word や Excel がダイアログ(フォルダーの使用の許可など)を出したときは、時間切れまで
待たずに、ダイアログの名前を出して止まります。

設計の記録 `docs/sekkei/sashikomi.ja.adoc` に、Word で測った値、Excel for Mac と
Windows の違い、決めたことを書きました。
