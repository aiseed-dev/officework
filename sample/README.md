# sample — 公開できるサンプル

「開いて・直して・刷る」を試すための帳票と文書。**中身はすべて架空**
(実在の様式・人名・社名は入っていない)。templates/ が「ブック=業務アプリ」の
見本なのに対し、こちらはただの普通の書類。

```bash
./target/release/calc  sample/見積書.xlsx
./target/release/writer sample/報告書.docx
```

## calc 用(xlsx)

- **見積書.xlsx** — 結合(表題)・罫線・表示形式(¥#,##0)・式(数量×単価、
  SUM・ROUND)・印刷範囲(A4 縦)。数量や単価を打ち直すと合計まで
  再計算される。ファイル > 印刷で PDF にすると印刷範囲どおりに出る
- **出納帳.xlsx** — 前行を引き継ぐ残高の式・条件付き書式(残高が1万円を
  割ると塗って知らせる — 最終行で実際に発動している)・セルのコメント・
  タイトル行の繰り返し
- **成績表.xlsx** — AVERAGE・MAX・COUNTIF(">=80")と条件付き書式
  (80点以上を塗る)
- **売上台帳.xlsx** — ピボットの試し場。月×区分×品名の36行入り。
  挿入 > ピボットテーブルを挿入(行=区分、列=月、値=金額)がすぐ試せる。
  できたピボットの上にカーソルを置くと「ピボットテーブル」タブが現れ、
  結合・入力規則などのボタンが灰色になる(文脈タブとロック)。オートフィルタや
  並べ替えの「拡張しますか」の試し場としても使える

## writer 用(docx)

- **報告書.docx** — 見出しの階層・表・本文。参考資料 > 目次 を押せば
  見出しから目次ができる
- **送付状.docx** — 右揃え(日付・差出・敬具)と中央揃え(表題・記)の定型
- **議事録.docx** — 見出し+表(開催情報)+決定事項

## writer の見どころ(sample/writer/)

**日本語一級とうちだけの機能**を実際に使った見本。docx なので Word でも
LibreOffice でも開ける(4件とも実際に開けることを確認済み)。
生成スクリプトは Rust の例 — python-docx では素直に書けないもの(ルビ・縦書き・
記入欄・均等割付)を含むため:

```bash
cargo run -p ooxml --example gen_writer_samples   # sample/writer/*.docx を作り直す
./target/release/writer sample/writer/01_日本語の組版.docx
```

- **01_日本語の組版.docx** — ルビ(組版・禁則処理)、均等割付(項目名を
  端から端まで)、ドロップキャップ、箇条書き、英文のハイフネーション、
  コメント。レイアウト > 列の挿入 で2段に組み直せる
- **02_縦書きの手紙.docx** — 縦書き(右の列から左へ)。句読点とかぎ括弧が
  縦用の形になり、ルビも縦で振れる。ホーム > テキスト方向 で横書きへ戻せる
- **03_申込書.docx** — 表+記入欄(コンテンツコントロール)。氏名・メール・
  電話・ドロップダウン(参加する回)・チェック(☐☑)・署名。欄は薄い箱で
  見え、中は普通に打てる。保護タブの「保護」で読み取り専用にして配れる
- **04_月次報告.docx** — 見出しの階層・ヘッダー・フッターのページ番号・
  表・段落の帯・コメント・しおり(相互参照の的)。参考資料 > 目次 で
  ページ番号つきの目次ができる
- **検印欄マクロ.py** — writer のマクロ(プラグイン > マクロ)の見本。
  開いている文書の末尾に検印欄(承認・確認・担当)の表を足す。台本の
  `d` は python-docx の文書で、変更は1手として入る(Ctrl+Z で戻る)。
  単体でも `python 検印欄マクロ.py 文書.docx` で試せる
- **05_道具くらべ.docx** — ボタンを順に押して試すための紙。書式の見本行・
  しおり・図表番号・コメント・表が1枚に入っている。
  **この5件は試験の材料でもある** — writer の試験
  (`cargo test -p writer menu_run`)が5件すべてを開いて、
  リボンのボタンを全部おし、落ちないこと・未配線が無いことを確かめる

## エンジンだけの見本(pip install officework — アプリ不要)

PyPI から入れたエンジンを、この見本の帳票・文書で試す6本。
どれも**このフォルダで実測してから置いてある**:

```bash
pip install officework
cd sample
python3 差し込み.py       # 見積書に宛名と数量を差し込む
python3 量産.py           # 宛先ごとの見積書を3通つくる
python3 集計.py           # 売上台帳を読んで区分ごとに集計
python3 差し替え.py       # 報告書の字句を置き換える
python3 表の吸い上げ.py   # 報告書の表を CSV に
python3 点検.py           # フォルダ中の帳票の「読めない部品」を数える
```

**xlsx(書く・読む)**

- **差し込み.py** — 見積書.xlsx の宛名(A3)と数量(C12)を差し替えて保存。
  罫線・結合・表示形式(¥#,##0)は据え置き。読み直すと式が計算済み —
  金額(F12)から消費税・合計(F18)まで追従している
- **量産.py** — 見積書を型紙に、宛先3件ぶんを回す(openpyxl の定番仕事を
  書式を壊さずに)。1通ごとに合計(F18)を読んで確かめる
- **集計.py** — 売上台帳.xlsx(36行)を `values()` で一気に読み、区分ごとに
  合計(総計 214,120円)。込み入った集計はここから polars / pandas へ

**docx(直す・吸い上げる)**

- **差し替え.py** — 報告書.docx の `replace()`(run の書式を保つ置換)と
  表の読み。python-docx と違い、理解できない部品を書き直さない
- **表の吸い上げ.py** — 文書の中の表(4行)を CSV に。報告書から数字を
  拾って集計へ回す入口

**受け取った帳票の門**

- **点検.py** — フォルダの xlsx / docx を全部開いて `unsupported` を数える
  (この見本のフォルダは「きれい 13 本 / 気になる 0 本」)。黙って部品を
  落とさないエンジンだから成り立つ検品

## 表計算が正本(小さな団体の見本)

**サーバーを持たない団体の形。** 上のカタログは商品マスタをサーバーに置くが、
数人の会にサーバーは無い。**正本は人が calc で直す1枚の表**で、そこから
案内も注文書も作る。実在の種苗の会のサイトでは 200 品目の在庫が手書きの
HTML で保たれ、在庫の言い方が4通りに割れていた — **手で保つ表は必ずこうなる。**

```bash
pip install officework
python3 sample/在庫から配り物.py
```

作られる物:

- **種の在庫.xlsx** — 正本。人が calc で開いて在庫数を直す
- **種のカタログ.html** — お客が見る頁。**在庫の言い方は在庫数から作る**ので
  割れようがない(0 なら品切れ、5以下なら残りわずか、空欄なら販売予定)。
  JavaScript は無し・分類の開閉は `details` だけ
- **種の注文書.xlsx** — 印刷して FAX で送れる注文用紙。A4・印刷範囲つき・
  見出しの行が2枚目以降にも出る。番号は `0000` の書式で 0001 と並ぶ

表を直して、もう一度走らせるだけ。**手で HTML を触らない。**

### 受注のほう(注文書が返ってきてから)

```bash
python3 sample/注文を受ける.py
```

- **種の注文書_記入済み.xlsx** — 返ってきた注文書の代わり(実物では FAX か
  メールで届く)
- **種の受注台帳.xlsx** — 受けた行を**足すだけ**。過去の受注は動かさない
- **種の納品書.docx** — 差し込みは Python がやる(writer の差し込みの
  機能はまだ無い)

**断ることを黙ってしない。** 在庫より多い注文・品切れ・まだ販売していない品は
受けず、どの行をなぜ受けなかったかを画面にも納品書にも書く。ここを黙って
通すと、台帳と在庫と現物が別々のことを言い出す。在庫は受けた分だけ引かれる
ので、`在庫から配り物.py` を回し直せばカタログが追従する。

この見本を書いて実際に走らせたときに見つけたエンジンの穴は
docs/sekkei/python.ja.md の「見本を書いて見つけた穴」に置いた。

### 写真の台帳(1シートに1枚)

```bash
pip install officework Pillow
python3 sample/写真の台帳.py
```

**原本をそのまま埋める。** xlsx は zip で JPEG は既に圧縮済みなので、
フォルダに置いても台帳に入れても合計はほとんど変わらない(実測: 原本
3,001KB → 台帳 2,994KB)。**なら1つのファイルに収まるほうがよい** —
台帳と写真が離れて片方だけ無くなる、が起きない。

**1シートに写真1枚**(発注者 2026-08-15)。小さく並べても写真は見えず、
見えない台帳は見ない台帳になる。1枚目が一覧(目次)で、以降は写真ごとに
1シート。**シートの耳がそのまま索引**になる。

撮影日と画素は **EXIF から取る**ので人に打たせない。人が書くのは
「場所」と「覚え書き」だけ。Pillow は**あれば使う** — 無ければ EXIF は
読めないとその場で言う。

**写真と台帳は追跡に入れていない**(台本が作り直す)。他の見本の xlsx は
手で組んだ小さい物なので追跡しているが、実物大の JPEG は別。

**欄は写真の上に置く**(発注者 2026-08-15)。開いてすぐ書ける所に無いと
書かれない。写真は下 — 見るのは後、書くのが先。

途中で「足したシートだと日付が出ない」と誤診した。**シートのせいではなく、
前の配置(欄を写真の右)で写真が欄を覆っていた**だけだった。欄を上に移したら
同じシートで正しく出た。**浮かんだ写真は下の欄を隠す** — oneCellAnchor は
セルの上に置く物なので、欄と重ねない置き方にすること。

### 月に一度の便り(客の台帳)

```bash
python3 sample/月の便り.py
```

- **会員申込.html** — JS なしの申込の頁。**申込が同意の証跡になる**
- **客の台帳.xlsx** — 名前・メール・住所・最後の注文・**案内可**・
  **同意した日**・**同意の取り方**・**断った日**
- **便りの下書き/*.eml** — 一人ずつの下書き。メールの道具でそのまま開ける

**送らない。** 作るのは下書きまでで、送るのは人。数百通を勝手に出す道具には
しない(一度出た物は取り消せない)。

**法を道具で守る**(特定電子メール法): 同意の無い人・**証跡の無い人**・
断った人には**作らない**(外した人と理由を必ず言う。見本では3件が3つの
違う理由で外れる)。差出人の氏名・住所と受信拒否の連絡先は台本が
末尾に付けるので**書き忘れが起きない**。中身と経緯は
docs/from-pokemaru.ja.md。

## 注文書付きカタログ(writer 用・サーバー連携の見本)

- **カタログ.docx** — 分類ごとの見出し+商品表(36品目)、巻末に注文書の
  ページ。writer で開いて 参考資料 > 目次 を押せば、ページ番号つきの
  目次ができる
- **商品マスタの正本はサーバー、docx は生成物**という分業の見本:

```bash
python3 sample/catalog_server.py           # マスタを配る(127.0.0.1:8765)
.venv/bin/python sample/gen_catalog.py     # サーバーから取って作り直す
```

サーバー側は価格改定と新商品(37品目)を持っているので、作り直すと
カタログが追従する。**繋がらなければ、そう言ってから**同梱の見本データで
作る(黙って古いままにしない)。追跡に入っているのは同梱データ版。

### Web でも配る(JS なしの HTML)

同じサーバーが同じ商品マスタから **JS なしの HTML** も出す(1ソース多形態):

- `GET /catalog.html` — カタログ。**商品はカードで陳列** — 絵(サーバーが
  SVG を生成。ボールペンはインクの色まで見える)・品名・値段が一目。
  検索(`?q=テープ`)、分類の開閉(details/summary)、札を選んで
  **「選んだ商品を比べる」** → サーバーが比較表を組み、いちばん安い列に
  印を付ける。どれも実行コードなしの「動き」の見本
- `GET /compare?c=A-101&c=…` — 比較表(上の form の行き先)
- `GET /img/品番.svg` — 商品の絵。**実物では販売者が用意した画像
  (写真等)を置いて配るだけ** — この見本では画像ファイルが無くても
  動くよう、代役の絵をその場で生成している
- `GET /order.html` — 注文書のフォーム。**記入して「注文を送る」だけ** —
  form の POST は JavaScript 以前からの素の仕組みで、JS は一切無い
- `POST /order` — フォームからも、注文書.xlsx の @送信(JSON)からも受ける。
  偽の品番の行は受けず、どの行を受けなかったかを言う

writer の HTML 読み(SEKKEI「JS なしの閲覧と記入」)が入るまでは、普通の
ブラウザが仮の閲覧手段。入ったらこの2ページがそのまま検証相手になる。
サーバーの Python は管理者が別途配る — 文書と一緒に旅をしない。

- **注文書.xlsx** — カタログの受け側(calc 用)。品番を打つと品名・単価が
  右の H〜J 列(品番マスタの写し)から VLOOKUP で引かれ、金額・小計・
  消費税・合計まで式で埋まる。品番の欄には入力規則(候補はマスタの写し)。
  手続きは隣の **更新.py・送信.py**(手続きはブックからは動かない —
  ブックが運ぶのは帳票と関数だけ)。中身を確かめて
  `~/.config/office/plugins/` へ置く(1機械1回)。
  以後データ > Python のパネルで:
  - `@更新` — マスタの写しをサーバーの正本と入れ替える(価格改定・
    新商品に追従し、金額は再計算される)
  - `@送信` — 品番と数量の入った行を JSON でサーバーへ送る
    (受付番号が返る)

  開いただけでは何も実行されない。実行は毎回の明示の操作(plugins は
  自分で据えたコードなので、網も普通に使える — 置く前に読むのが門)。
  式の入った行を増やすときは既存の行を Ctrl+C → Ctrl+V で写す。

## e-shop の試作 — Word で店を書く(eshop.py)

「販売者が Word で店を書き、プラグインが店を開く」の一本道の実証
(SEKKEI「e-shop」の節。本実装は writer のプラグインになる予定):

```bash
.venv/bin/python sample/eshop.py        # カタログ.docx → 商品マスタ.csv
python3 sample/catalog_server.py        # 店が開く(CSV があれば自動で読む)
```

- **店の正本は文書。** 品を足す・値を直すのは writer(または Word)で
  カタログ.docx を直し、上の2つを回し直すだけ — Web の知識は要らない。
  分類は見出し、商品は表(品番/品名/説明/単価)から取る。記入欄など
  商品表でない表は飛ばす
- 商品マスタ.csv は生成物なので追跡しない(正本は文書)
- 注文は店の /orders に溜まる — 下の**受注台帳.xlsx**が引き取る

## 受注台帳.xlsx — 販売管理(calc 用)

e-shop の受け側の帳面。**空で出荷**され(台帳は記録 — 見本の記録は
持たない)、店に溜まった注文を引き取って行を刻む:

- まず隣の **取り込み.py** を据え付ける(1機械1回): 中身を確かめて
  `~/.config/office/plugins/取り込み.py` へ(手続きはブックからは動かない —
  ブックが運ぶのは帳票と関数だけ。templates/ の問い合わせ台帳の取り込みと
  同名なので、同じ機械で両方使うならどちらかを別名で置く —
  @名前 はファイル名がそのまま)。以後、
  データ > Python で **`@取り込み`** — 新しい注文だけを追記する
  (取込済の件数を K2 に控えるので、何度押しても重複しない)。
  品名・単価は**その時のマスタの値**で刻む(台帳は記録なので式で
  引き直さない)。金額は式(数量×単価)、右上に売上合計(=SUM)
- **発送済**の列はチェックボックス(空白キーで ☑/☐)
- 売上の集計は calc の既存道具がそのまま効く: **ピボットテーブル**
  (社名別・品番別の売上)、**小計**、**並べ替え・絞り込み**
- 開いただけでは何も実行されない。実行は毎回の明示の操作+サンドボックスの中

## 作り直し

サンプルは生成物。直すのは生成側で、ファイルを直接直さない。

```bash
cargo run -p sheet --example gen_samples   # xlsx 6件+手続きの .py 3件
.venv/bin/python sample/gen_docs.py        # docx 3件(要 python-docx)
.venv/bin/python sample/gen_catalog.py     # カタログ.docx
```

どれも検査つき: xlsx は pysheet で開いて式の値を、docx は
`ooxml --example rtall` で往復(本文一致・注記0)を確かめてある。
