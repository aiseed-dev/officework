= officework

_元は英語版(link:README.adoc[README.adoc])です。こちらは日本語訳です。_

Microsoft の Excel と Word は閉じた世界です。
データも、見た目も、コードも、1つのファイルの中に閉じ込められています。
officework はそれをほどいて、**データ・テンプレート・Python・AI を自由に使えるようにした Office** です。

4つを、それぞれ独立させました。

* *データ* — 文書は AsciiDoc(`.adoc`)、表も同じ字のままの形(`.sheet.adoc`)で持てます。どの道具でも読めて、差分も取れます。xlsx / docx は受け渡しの形式として、書式ごと壊さずに読み書きします
* *テンプレート* — 文書の見た目は本文から分けました。同じ本文が、テンプレートを替えるだけで別の姿になります
* *Python* — コードはブックにも文書にも載せません。`.py` を置けば、セルの式``=倍(A1)``・リボンのボタン・一覧から呼べます。VBA の代わりはこれで、「開いた瞬間に他人のコードが走る」事故が仕組みの上で起きません
* *AI* — 決まった AI を抱き合わせません。OpenAI 互換の API を話す相手なら、手元のモデルでも何でも繋げます。アプリの中から AI に相談できますし、MCP を登録すれば、AI に頼んで動いているアプリを操作させることもできます

エンジンは `pip install officework` で単体でも入ります: xlsx / docx を書式ごと壊さずに読み書きし、openpyxl・python-docx・xlwings の書き味を継いでいます。
自動化の結果を目で確かめ、手で仕上げ、起動中のブックを Python から直に操れます。

アプリは **officework の1本**です。
フォルダを開いて、文書も表も同じウィンドウのタブで編集します。
中の編集画面は2つで、名前があります: 文書編集が *writer*、表計算が *calc* です。
どちらで開くかは、ファイルの名前で決まります。

* *writer*(文書 — `名前.adoc`)— AsciiDoc の視覚エディタ。原稿を見たまま直し、画面・PDF・HTML・docx に出す。docx は受け渡しの形式で、開いて見る・adoc にすることはできる(link:docs/writer-manual.ja.adoc[writer の手引き])
* *calc*(表 — `名前.sheet.adoc`)— 式も計算する表計算。xlsx も開いて、直して、保存できる(link:docs/calc-manual.ja.adoc[calc の手引き])

閉じて開き直すと、前回開いていたフォルダとファイルとタブが戻ります。

== なぜ作ったか — 秘密の資料と AI

Microsoft 365 の Copilot のような組み込みの AI は、答えを作る前に会社の全部のデータ(メール・文書・会議・チャット)を検索して材料にします(RAG と呼ばれる仕組みです)。
AI は既存のアクセス権を守りますが、実際の会社では長年の共有設定が乱れていて、機密ファイルが「誰でも読めるのに、深くて見つからない場所」に埋もれています。
今までは、見つからないことが実質の守りでした。
横断検索の AI が入ると、その守りは消えます。
権限の大掃除・機密ラベル・漏えい防止・監査の監視を続けない限り、知るべきでない資料が要約に混ざって出てきます。
つまり、全社の RAG は管理がついていかず、秘密事項を安心して扱えません。

officework は逆の設計です。

* AI が見るのは、いま開いているフォルダとファイルだけです。全社の索引を作りません
* 繋ぐ AI は自分で選びます。手元のモデルを選べば、データはこの機械から出ません
* ブックも文書もデータだけを運びます。コードは運びません

== いま出来ること

要点だけを書きます。
全部の一覧はlink:docs/writer-manual.ja.adoc[writer の手引き]とlink:docs/calc-manual.ja.adoc[calc の手引き]にあります — 手引きには、いま動くことだけを書いています。

* *writer(文書)* — 縦書き・ルビ・均等割付までの日本語組版。記入欄(申込書を作って、保護して、配れる)・目次・変更履歴・コメント・描画・途中で紙が変わる印刷・PDF。docx は開いて保存しても壊れません
* *calc(表)* — 約185の関数(動的配列も)と再計算・循環参照の検出。複数シート・ピボットテーブル・条件付き書式・入力規則・グラフ(裏方は matplotlib)・ソルバー・保護と暗号化・PDF。xlsx も同じく壊れません

リボンの並びは Euro-Office に合わせてあります(乗り換える人が場所を覚え直さずに済むように)。
*まだ出来ていないコマンドはグレー表示で並んでいます* — できないものを、できるように見せません。

**VBA 型のマクロはありません。
ブックはコードを運びません。
**ブック(.sheet.adoc / .xlsx)はデータだけ、コードは .py — 別々のファイルです。
自作のコードは``~/.config/officework/plugins/`` に .py で置きます。
手続きなら `@名前` で実行、関数なら `=倍(A1)` のような普通の式でセルから呼べます(関数名は日本語でもかまいません)。
受け取ったブックにコードは入っていないので、**「開いた瞬間に他人のコードが走る」という事故が、仕組みの上で起きません。
**詳しくは link:docs/calc-manual.ja.adoc[calc の手引き]。

== 手に入れる

やりたいことに応じて3つの道があります。

*PyPI から。* これが主な配り方で、*0.4.0 からはアプリも一緒に入ります*。

[source,console]
----
$ pip install officework      # エンジン・橋・MCP、そしてアプリ
$ officework                  # 前回のフォルダとファイルを開いて立ち上がる
----

0.4 までの wheel は、アプリが `officework-calc` / `officework-writer` の2本に分かれています。

wheel は Linux と Windows で約 36MB(mac は2つの CPU 分が入るのでもう少し大きくなります)。
*この道がいちばん手間がかかりません* — pip が置いたファイルには mac の quarantine も Windows の Mark of the Web も付かないので、Gatekeeper も SmartScreen も出ません。
Python の同梱も要りません。

[NOTE]
====
*Linux だけ、機械の側に要る物があります*(pip では入れられません):
`sudo apt install libxkbcommon0 libxkbcommon-x11-0 libxcb1 libxcb-xkb1 libfontconfig1 fonts-noto-cjk`
足りなければ `officework` がその場で名前を挙げて教えます。
mac と Windows は素で動きます。
====

*インストーラ — まだ公開していません。* 包む仕組みは出来ていて、出来上がるのはこの3つです(どれも Python 3.14 を同梱)。
ただしまだリリースしていません。

== 自分で足した物の置き場

足す物は全部この1つのフォルダに入ります。
どの OS でも同じ場所です(Windows は `%USERPROFILE%\.config\officework`)。

----
~/.config/officework/
├── funcs/         セルから呼ぶ関数:  =倍(A1)
├── ribbon/        リボンのボタンになるマクロ
├── plugins/       一覧から選ぶマクロ
├── records/       記録した操作(下書き。そのままでは走りません)
├── .venv/         足したパッケージ(matplotlib、polars など)
└── settings.toml  言語、キーの割り当て
----

このフォルダを VS Code で開けば、エディタが `.venv` を自分で見つけます。
マクロとパッケージを同じ場所にしているのはそのためです。
パッケージが足りないときは、アプリがそのままコピーできるコマンドを表示します。

== 組む

必要なもの: Rust(1.80以降)、日本語のフォント、Linux なら Wayland か X11。

Debian/Ubuntu では、ビルドに次のパッケージも要ります(CI と同じ一覧):

[source,bash]
----
sudo apt install libxkbcommon-dev libxkbcommon-x11-dev libxcb1-dev \
  libxcb-xkb-dev libfontconfig1-dev cmake clang pkg-config
----

[source,bash]
----
cargo build --release

./target/release/officework                    # 前回の姿で開く(初回はフォルダを選ぶ)
./target/release/officework sample/報告書.docx  # 同梱のサンプル(中身は架空)
./target/release/officework sample/見積書.xlsx  # 表も同じアプリで開く
----

開発用に writer / calc を単体で組んだ実行ファイルも残っていますが、配るのは officework だけです。

初回のビルドは、画面ライブラリ GPUI(Zed エディタと同じもの)を取ってきて組むので時間がかかります。
2回目からは速くなります。

=== フォント

*同梱していません。* 書体は文書側の設定なので、docx/xlsx に書かれている書体名をこの機械に入っているフォントから探します。
見つからなければ、日本語を表示できる別のフォントで代用します。

[source,bash]
----
OFFICE_FONT=/path/to/font.ttf ./target/release/officework   # 明示して指定する
----

`fonts-noto-cjk` か `fonts-ipaexfont` が入っていれば動きます。

=== 校正(writer のレビュー > 校正)

英語の綴りは辞書だけで見ます(`/usr/share/dict/words` など)。
日本語の誤変換・表記ゆれは辞書では見つからないので、**手元で動くAI モデル**に聞きます。
宛先はこう指定します:

[source,bash]
----
OFFICE_HOST=127.0.0.1 OFFICE_PORT=8000 OFFICE_MODEL=... ./target/release/officework
----

OpenAI 互換の API(`/v1/chat/completions`)を話すサーバーなら何でも構いません。
*繋がらなければ「校正できません」と出ます* —黙って「指摘なし」にはしません。

校正はコマンドラインからも単体で使えます:

[source,bash]
----
cargo run --release --bin office-spell -- 文書.txt
cargo run --release --bin office-spell -- --furigana 原稿.txt
----

== Python との分業

**見ながら整える仕事はアプリ、データを作る・絵を描く仕事は Python。
**グラフ・SmartArt・方程式・ピボット・ソルバーまでボタンがありますが、裏で働くのは Python(matplotlib・polars・scipy)です。
込み入った分析はそのまま polars・statsmodels で。

*エンジンだけなら PyPI から入ります。アプリは要りません。*

[source,console]
----
$ pip install officework
----

**MCP サーバ**も付いています。
AI に、動いているアプリを操らせられます:

[source,console]
----
$ pip install "officework[mcp]"   # あとは officework-mcp を AI 側に登録する
----

読み書き・書式・自動調整・保存の8つだけを渡します。
同じ橋を使うので決まりも同じ — このパソコンの中だけで、TCP は開きません。

*別のアプリの中にも入ります。* Electron 製の表計算link:https://github.com/genspark-ai/genoffice[genoffice] は、xlsx の読み書きを別プロセスの助手に任せる作りです。
その助手をこのエンジンに差し替えられます — *genoffice 側のコードは1行も変えず*、環境変数を1つ設定するだけ。
12 あるコマンドのうち 11 を officework が受け持ちます(保存も含む。
`.xls` の取り込みだけ未実装)。
手順と「何を差し替えて、何を差し替えていないか」はlink:docs/engine.ja.adoc[エンジンの説明]へ。

openpyxl と違い、罫線・結合・列幅・図形を保ったまま値を差し込めます。

[source,python]
----
from officework import sheet

b = sheet.Book.open("様式7.xlsx")
b["提案見積書"]["A30"] = "日本フネン株式会社"   # 書式はそのまま残る
b.save("out.xlsx")
print(b.unsupported)   # 読めなかった部品の一覧(空なら全部読めた)
----

docx も同じです。
python-docx は理解できない部品を書き直してしまいますが、こちらは原本を正として変えた所だけ書き戻すので、様式・ヘッダー・図形・変更履歴が壊れません。

[source,python]
----
from officework import doc

d = doc.Doc.open("報告書.docx")
print(d.unsupported)               # 読めなかった部品の一覧(空なら全部読めた)
d.replace("旧社名", "新社名")       # 段落の中の書式はそのまま
d.fill("宛先", "日本フネン株式会社") # 名前つき記入欄に差し込む(writer で付けた名前)
d[3].text = "差し替え"              # 見出しの段は見出しのまま、寄せも1行目の字下げも残る
print(d.tables[0][1][2].text)      # 表・行・セル
d.save("out.docx")
----

帳票に差し込むなら `replace()` を使ってください。
文字ごとの書式(太字・色など)を残したまま置き換えるので、太字の項目名の隣に普通の値が入る形が崩れません。
`.text` への代入は段落を丸ごと書き替える大づかみな道具で、文字の書式は段落の先頭のものに揃います。

起動中の calc を外から操ることもできます(こちらはアプリを起動しておく必要があります):

[source,python]
----
from officework import calc as xw   # xlwings 流の Book / Range
----

橋は Python の専用ではありません。
アプリはソケット(`$XDG_RUNTIME_DIR/officework/officework.sock`)を開いていて、JSON を1行書くと JSON を1行返します。
JSON を書ければ、どの言語のどのアプリからでも繋げます — MCP サーバもこのソケットの客の1つです。
任意のコードを走らせる命令は置いていません。
ソケットを開くのは Linux と macOS だけです。Windows では作りません。

[source,console]
----
$ echo '{"cmd":"ping"}' | nc -q 1 -U $XDG_RUNTIME_DIR/officework/officework.sock
{"ok":true,"app":"officework","showing":"doc","version":"0.1.0-alpha"}
----

コードを書く人向けの説明は link:docs/python-manual.ja.adoc[Python の手引き] にあります —*範囲⇄配列のやり取り*(values() と1セルずつの書き込み)、=PY の2次元リストとスピル、writer マクロの `d`、サンドボックスの中の約束、まで、実際に動かして確かめた内容つきです。

== 構成

----
engine/     kumihan — 組版の核(行組み・禁則・字幅・紙面の座標)
ooxml/      docx の読み書き
sheet/      xlsx の読み書き、式の計算、書式(styles.xml)
ops/        ブックの操作の言葉と受け口(開く・読む・書く — Python もアプリも同じ意味で使う)
pyrun/      Python を実行する仕組み(サンドボックス・時間制限)
lang/       言語ごとの処理(訳の表・校正・ふりがな)。画面なしで動く
paper/      紙面を PDF へ写す
face/       画面の部品のうち、絵を描かない部分(ファイルの一覧・前回の姿)
ui/         gpui との結線(入力・IME・リボン)
writer/     文書の編集画面
calc/       表の編集画面
officework/ アプリの本体(タブと、2つの編集画面の入れ物)
pysheet/    Python から使う部分(pip install officework → officework.sheet / officework.doc)
sidecar/    genoffice に載せるときの別プロセス
----

**画面も紙も、同じ紙面を別の面に写すだけ**です。
だから画面と印刷が食い違いません。

== 各国語版

*画面の言語は実行時に切り替えられます。* 14言語を同梱: ja(既定)・en・de・es・fr・id・it・ko・pt・ru・tr・vi・zh・zh-tw。

[source,bash]
----
OFFICE_LANG=en ./target/release/officework      # 一時的な上書き
# 恒久には ~/.config/officework/settings.toml に:
#   language = "en"
----

*画面全体が切り替わります* — リボンも、ステータスバーの文言も、ダイアログも。
どの言語も**全部の文言が訳されています** — 訳に欠けのある言語は、そもそも登録できない作りです。

訳の数をここに書かないのはわざとです。
*数は増え続けるので、書けば古くなります。* 代わりに `cargo test` の中に検査があり(`lang/tests/i18n_soroi.rs`)、英語に未訳が無いこと・使われなくなった訳が残っていないこと・**13言語が同じキーを持つこと**を毎回確かめます。
前はこの検査を手で実行する決まりだったので誰も実行せず、未訳が173句まで溜まっていました — **思い出して実行する検査は、検査ではありません。
**設定ページもあります: ファイル > 詳細設定 で、いまの言語・書体・校正の宛先・Python の経路が見え、言語を順に切り替えられます(選んだその場で画面が切り替わります)。

標準のリボンの語は Euro-Office 本家の訳から、残りの文言は Claude による機械翻訳で、言語ごとに Microsoft Office の用語に合わせてあります。
en と ja は目を通してあります —*ほかの言語は、母語話者の校閲を歓迎します。*

言語を足すのは1コマンドです — `ui/gen_lang.py` が訳すべき文の一覧(`ui/i18n/keys.json`、番号つきの ja/en 対訳)を出し、訳を``ui/i18n/<locale>.json`` で受け取って、表の生成から登録までやります。
訳に欠けや不備のある言語は登録を断ります:

[source,bash]
----
python3 ui/gen_lang.py --todo     # 材料を出す
python3 ui/gen_lang.py nl         # ui/i18n/nl.json から生成・登録
python3 ui/gen_lang.py --check    # 登録済み全言語を検査
----

言語ごとの癖(組版・校正のやり方)は `lang` クレートの `Language` にまとめてあります。
新しい言語の癖は、これを1つ実装すれば済みます。
