# マニュアルの決まり

管理するのは**利用者向けの冊子の日本語と英語の対**だけ
(docs/ja/ と docs/en/)。英語版が原本、日本語版が訳です。
文体・構成の型・例の作法は docs/sekkei/manual-kakikata.ja.adoc
(書き方の手引き)にある — 新しい頁や冊子を書く前に読む。

**仕様はマニュアルだけに書きます。** 実装は
マニュアルを読んで作られるので、コード化できる内容(選択肢の全部・
既定・範囲と単位・押した後に起きること・断るときの文言・Python の API)を
漏らさず書く。目安は「この頁だけを読んで、実装と試験が作れるか」。
簡潔にするために動きの中身を省かない — 省いてよいのは経緯と内輪の
事情だけ。

流れは1本: 決める → マニュアルの頁に書く(未実装の印)→ 実装 →
検査が頁と実物を突き合わせる → 印を実装済みへ。**仕様を SEKKEI に
書かない**(SEKKEI に書くのは、決める前の検討と決めの経緯の2つだけ)。
画面に出ない内部の設計は**開発者マニュアル**(docs/dev/README.ja.adoc)に、
いまの状態として書く。挙動や構造を変えたら、利用者マニュアルと同じ規則で、
同じ回に直す。

## 本当のことだけを書く

1. **挙動を変えるコミットは、同じ回でマニュアルの該当箇所も直す。**
   直しきれない新機能の追記は遅れてよいが、遅れは下の「追随待ち」に
   一行で控える。黙って古いままにしない
2. **できることだけ書く**(リボンの灰色と同じ方針)。「〜できます(予定)」は
   書かない
3. **動かして確かめてから書く。** 例のコード・数値・選択肢は、この機械で
   実物に当てて確かめてから書く(python-manual と同じく、全部この機械で確かめる)

## commands/ だけは逆 — 手引きが先、実物が後

ボタン1つに1枚。あることは見せて、**状態で言う**。状態は3つだけ:

- **実装済み**(いま使えます)
- **未実装**(まだ使えません)
- **廃止予定**(なくす予定です。行き先を書く)

ダイアログの選択肢はこの1枚に書く(調べは docs/sekkei/dialog-parameters.ja.adoc)。

## 英語と日本語の対(英語が原本、日本語が訳)

- 各冊子の頭に原本と訳の断りを書く(既存の冊子の書き方に合わせる)
- 両言語とも直すのが原則。急ぐときは英語を先に直し、日本語は追随待ちへ —
  **どちらか一方だけが直っている状態を規則の外に置かない**

## 書き方 — 利用者の目で

- **一覧(docs/ja/README.adoc)も利用者の物。** 管理の話・決めた人・日付の
  注記を書かない。経緯は docs/sekkei/ へ
- 用語は Excel / Word と Euro-Office の**両方を引いて見比べてから**選ぶ
  (どちらにも誤訳や癖がある — 順に機械的に落ちない)。迷ったら「使う人が
  ヘルプや検索で探す言葉はどちらか」。独自の機能は両方とも参考にできない —
  普通の言葉で名前を決めてから使う(決めるのは発注者)
- 言葉づかいは普通の日本語で(`python3 tools/kotoba_list.py` が、Excel と Word の用語と役所の文書に無い言葉を一覧にする。合否は出ないので、読んで決める)

## 生成した節は手で直さない

キーの一覧・すべての操作・対応表は道具が起こす。ずれたら**手元で検査を
回せば自分で直る** — 直った分をコミットに入れる。CI は直さずに落とすので、
入れ忘れはそこで分かる。

## Excel のヘルプの使い方

Excel のヘルプからは、使う人が知っている仕事の一覧として、構成だけを借ります。
**文章は写しません。** 書いた物は from-excel にまとめます(仕事ごとに、ここでの
やり方か、やらない理由を書きます)。

## 出す前の検査(全部回す)

```
python3 tools/kotoba_list.py           # 言葉づかい(一覧。読んで決める)
python3 tools/manual_uchiwa_check.py   # 内輪の注記(見る対象に入っているかも確かめる)
python3 tools/command_docs.py          # コマンドの手引きの枚数と状態
python3 tools/api_taiou.py             # 対応表と実物のずれ
python3 tools/sunset_check.py          # 廃止語
ruby -I vendor/asciidoctor/lib vendor/asciidoctor/bin/asciidoctor -o /dev/null <触った.adoc>
```

最後の asciidoctor の検査は、`vendor/asciidoctor` がある機械でだけ回せます
(この Mac には 2026-09-24 の時点でありません)。回せなかったときは、報告にそう書きます。

新しい冊子を足したら、docs/ja/README.adoc の一覧と manual_uchiwa_check の
見る対象の両方に足す。

## 置き場の地図

- 設計(なぜ)は SEKKEI.adoc と docs/sekkei/。実装の在庫は
  docs/guide-tsukiawase-2.ja.adoc。どちらも作る側の資料で、利用者向けの
  一覧(docs/ja/README.adoc)には載せない
- docs/ に残っている corpus・engine・pysheet-gokan・mac-signing も作る側の物。
  **ファイルの場所は動かさない** — PyPI の README など公開済みのリンクが
  刺さっている
- docs/articles/ は公開用の書き物で、この決まりは掛からない。その時点の
  事実と見立てを残す物なので、挙動が変わっても遡って直さない(直すのは
  マニュアルの方)。発注者の一人称で書く
