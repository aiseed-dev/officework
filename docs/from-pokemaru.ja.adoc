= 産直のプラットフォームから来た人の手引き(蒸留の台帳を兼ねる)

2026-08-15 起こし(発注者「無肥料、自然栽培農家を対象に、calc で管理して、ポケマルを蒸留したらどうでしょうか」)。

**ポケットマルシェで生産者がやっている仕事の並びを教師**にして、「あの仕事はここではこうやる(またはやらない、なぜなら)」を書く。
文章も画面も写さない —*課題の並びだけが教師*(Excel のヘルプ・ONLYOFFICE のガイドを蒸留したのと同じ流儀。
規則は docs/README.ja.adoc)。

== 先に、蒸留できない物を言う

*2つある。集客と、運賃。* どちらもソフトでは代わりにならない。
ここを「できる」と書いたら、この repo でいちばん嫌う嘘になる。

*集客* — プラットフォームの本体の値打ちは「客を連れてくる」こと。

*運賃*(発注者 2026-08-15「個人でホームページを作るよりも運賃の値引き交渉ができます」)— これは集客より地味だが、**毎回・全部の荷物に効く**ので効き目は大きい。
個人が数箱を出すのと、何千の生産者の荷物をまとめて出すのとでは、運送会社から出てくる数字が違う。
ポケマルはヤマトの自動伝票発行を持ち、伝票の発行手数料は 1 配送 87 円(税別)。

*どれだけ効くかは測っていない。* 「手数料 23% より大きい」と書きたくなるが、値引きの率も箱の単価も分からないので**書かない**。
分かっているのは「個人より安い運賃が適用される」という向きだけ。
実際の生産者に運賃の実額を見せてもらうまでは、ここに数字を入れない。

=== ただし、運賃の梃子の正体は「量」

だから道具にできることはある — *量をまとめるのは会でもできる*。
JA や産直の会が昔からやってきたことで、要るのは交渉に出す数字:

[NOTE]
====
どの地域へ・どの大きさで・冷蔵か常温か・月に何箱。
====

これは**表計算の仕事**そのもの。
officework が出せるのは「値引き」ではなく**交渉に持っていく表**で、そこは正直に分けて書く。
数人の会でも、実在の種苗の会のように農家リストを持つ集まりなら、まとめる相手は既にいる。

だから officework は**プラットフォームの代わりではない**。
位置づけはこう:

[NOTE]
====
*リピーターが付いて、客と直接やりとりするようになった生産者が、
手数料を払わずに、客の名簿を自分の手元に置いたまま続けるための帳場。*
====

数字で言うと、ポケマルの販売手数料は *23%*(2024-04-01 に 20% から改定)。
3,000 円の品なら 690 円がプラットフォームへ行く。
*初めての客にはその値打ちがある*(連れてきてもらったのだから)。
**二度目からの客にも同じだけ払い続けるか**が、この道具の問い。

置き換える相手はポケマルではなく、**その手前の実態**でもある — 取引先はExcel か手帳、出荷の記録は伝票の控え、進捗は担当者の記憶、という状態。

== なぜ無肥料・自然栽培を的にするか

* *採れ高が読めない*(自然任せ)→ 在庫が毎日動く → 手で頁を直していられない
* *品目が多くて少量* → カタログの自動生成が効く(種の見本は 26 品目、実在の種苗の会は 200 品目)
* *説明が要る*(なぜ高いか・なぜ形が不揃いか)→ 写真と覚え書きが売り物の一部
* *客が固定*(リピーター中心)→ 名簿を自分で持つ値打ちが高い
* *自家採種をする* → 種の交換の台帳と地続き

== 印の読み方

* *同じ* — 同じ作法がそのまま通じる
* *違う形* — 道具の形は違うが、同じ仕事がここの道でできる
* *まだ無い* — 未実装。隠さない
* *作らない* — 設計判断。理由を一行で書く
* *蒸留できない* — ソフトでは代わりにならない。*できると書かない*
* *該当なし* — プラットフォームがあるから要る仕組み。直販では要らない
* *当面は手で* — 仕掛けは作らないと決めた物。*書く場所だけ用意する*。手で追えなくなったら作る(先に作ると、使われない仕掛けが残る)

=== 月1のメールが、この商いに合う理由

* *チャットは要らない。* メールと電話が既にあり、二重に持つと客が困る
* *月1なら書ける。* 週1は続かず、年1では忘れられる。畑が動く周期にも合う
* *在庫が正本だから、書く手間が小さい* — 今月出せる物は表から出る。人が書くのは畑の一言だけ(そこは AI にも下書きさせられる)
* *返信が注文になる。* 別の入口を作らずに済む

=== 会員登録で同意をもらう(2026-08-15 発注者)

発注者「会員登録してもらえばいいのでしょう」。
これが**オプトインの正面の答え**だった。
「取引関係にある者」の例外に寄りかからず、*申込をもらう*。

* 申込そのものが「*いつ・どうやって同意したか*」の証跡になる(法は同意を証する記録の保存を求めている)
* 名簿が**自分の手元にできる**。プラットフォームに持たれない
* *集客との接ぎ目にもなる* — プラットフォームで初めて出会った人に会員になってもらえば、二度目からは直接。手数料 23% への答えがここ
* 種の交換の会のように、**「会」の形が既にある集まり**とも噛み合う

`sample/月の便り.py` は JS なしの申込の頁(`会員申込.html`)を出し、申込を受けると台帳に「同意した日」「同意の取り方」ごと足す。

=== 法を道具で守る(特定電子メール法)

総務省・消費者庁のガイドラインの要点を、`sample/月の便り.py` はこう受ける:

* *同意の無い人には作らない*(台帳の「案内可」)
* *証跡の無い同意は同意でない。* 「案内可 ○」だけでは足りず、**「同意した日」と「同意の取り方」**が要る。無ければ作らない
* *外した人と理由を必ず言う*(「断ることを黙ってしない」と同じ作法)。見本では3件が3つの違う理由で外れる
* *断った人には二度と作らない*(台帳の「断った日」)
* *差出人の氏名・住所と受信拒否の連絡先を末尾に機械的に付ける*(表示義務)。台本が付けるので**書き忘れが起きない*

*これは法律の助言ではない。* 実際に出す前に、自分の商いの形で確かめること。

== 場を開く(研修・講座・交換会)

発注者「研修の開催でも同じものがつかえるでしょう」(2026-08-15)。
*言うだけでなく、同じ型で書けるかを実際に確かめた*(`sample/研修の受付.py`)。

[cols="1,1"]
|===
|物を売るとき |場を開くとき

|種の在庫 |*研修の一覧(定員が在庫)*
|在庫を引く |席を引く。満席なら断って理由を言う
|受注台帳 |参加者の名簿(足すだけ)
|注文書(A4・印刷範囲) |*受付表*(当日、紙で持つ。出欠は手で丸を付ける)
|月の便り |開催の案内(同じ客の台帳・同じ同意の縛り)
|納品書 |受講の案内・領収書(差し込み)
|===

*違ったのは3つだけだった*:

. *日時と場所がある*(在庫には無い属性)
. **当日の出欠**がある
. *満席のときキャンセル待ちに回す*(品切れは「また入ります」で済むが、席は日が決まっているので待つ形が違う)

それ以外は物を売るのと同じ道で通った。
*帳場が同じなら、売り物が物でも場でも変わらない* — 種を売る会が交換会や講座も開く、という実際の姿にそのまま合う。

会場で電池も電波も要らない紙の受付表が出せるのは、**画面と紙が一致する**この土台の効き目でもある。

== サイトは台帳の写し(2026-08-15 発注者)

発注者「栽培の記録も同じでしょう。
そこから、Web サイトができますね」。
*そのとおりだった* — `sample/サイトを作る.py` で通した。

----
種の在庫.xlsx   → tane.html(その日の在庫)
栽培の台帳.xlsx → hatake.html(畑の記録。新しい順)
研修の一覧.xlsx → kenshu.html(空き・満席)
                → moushikomi.html(会員申込。JS なしの form)
                → index.html
----

*人が直すのは xlsx だけで、HTML は一度も手で触らない。*

効き目がはっきり出たのが研修の頁で、*受付の台本が席を引いた結果の「満席」がそのままサイトに出る*。
台帳が1つだから、受付と頁がずれようがない。

実在の種苗の会のサイトは 200 品目の在庫を手書きの HTML で保っていて、在庫の言い方が4通りに割れていた。
*手で保つ頁は必ずそうなる。* 割れるのは人の不注意ではなく、正本が2つある(表と頁)ことの帰結。

台帳が無ければ**その頁を作らず、無いと言う**(黙って空の頁を置かない)。
JavaScript は使わない — 分類の開閉は `details`、申込は form の POST。
どちらも JS 以前からある素の仕組みで、電波の細い所でも古い機械でも動く。

=== 栽培の記録も同じ形だった

「1行が1件・足すだけ・消さない」の台帳。
**自然栽培では「何もしなかった」も記録**になる — 肥料も薬も入れないのだから、書けるのは見たことだけで、翌年の材料はそこにしかない。
作業の欄に「(何もせず)」と書ける形にした(見本 8 件のうち 2 件がそれ)。

写真とは**ファイル名で結ぶ**。
台帳の中に画像を持たない — 写真は写真の台帳の持ち物で、こちらはその名前を指すだけ。
