= 他人が書いた xlsx の目録(pyoffice の突き合わせ用)

*現物はこの repo に置かない。* 置き場は `~/xlsx-corpus/`(既定)。
ここに残すのは**目録**(出所・大きさ・sha256 の頭・何を試すための1枚か)と**突き合わせの結果**だけ。

*置かない理由は2つ。*

. *免許* — 他人の xlsx を Apache/AGPL のツリーに入れると配れなくなる。政府の統計は「出典を書けば使ってよい」形が多いが、**再配布と利用は別の話**で、目録から取り直せるなら現物を持ち歩く理由がない
. *個人情報* — 実物の台帳には人名・口座・単価が入る。*repo に入れたら消せない*

    # 取り直すcd ~/xlsx-corpus && curl -sSLO <目録の URL> # 通すcd ~/dev/officework OFFICEWORK\_PYTHON=<wheel を入れた仮想環境の python> \\ python3 tools/pyoffice\_diff.py ~/xlsx-corpus/\*.xlsx

== 何を狙って集めるか

*枚数ではなく書き手の幅。* 同じ Excel で作った台帳を 50 枚集めても、落ちる穴は1種類しか出ない。

* *Excel* — 新しい物と、古い `.xls` から変換した物の**両方*
* **LibreOffice Calc / Google スプレッドシート**の書き出し
* *ONLYOFFICE 自身*(向こうの読みと突き合わせるのだから外せない)
* **会計・給与ソフト**の書き出し(機械が書く xlsx は人が作る物と癖が違う)
* *統計の表* — 発注者 2026-08-09:「国は csv に移した物が多いので、**日銀などの外郭から**取るとよい。**統計局の過去のデータ**もよい」

==== ふりがなの連結(向こうの欠陥)

向こうは共有文字列の `<rPh>`(ふりがな)の中の `<t>` を、本文の `<t>` と**繋げて**返す。
`<si><t>実</t><rPh sb="0" eb="1"><t>ジツ</t></rPh></si>` が``実ジツ`` になる。
`年、年度、期` は `年、年度、期ネンネンドキ` になる。

**日本語の xlsx でふりがなの入っていない物のほうが珍しい**ので、これは向こうの実装が日本の帳票で必ず踏む欠陥。
officework は `phonetics` に別に持っていて本文を汚さない(SEKKEI の「日本語の xlsx の宝」)。

*突き合わせでは、この差は「うちの穴」に数えない。* 数え間違えるとやることの一覧が汚れる。

==== 1. シートの取り違えの**最小再現**ができた

`make_manysheets` / `lo_manysheets` が、日銀の 30 枚の帳面と**同じ壊れ方**を再現した。

==== 2. ✔ 条件付き書式の `expression`(数式で指定)を読めない [中]

`sheet/src/xlsx.rs:1283-1309` が読むのは cellIs / containsText / duplicateValues / top10 / aboveAverage / dataBar / colorScale / iconSet の 8 種。
*`expression` が無い。*

officework は黙って落とさず「条件付き書式(読めない種類。
保存で失われる)」と**報告している**(そこは正しい)。
しかし `=MOD(ROW(),2)=0` の縞模様は実物の帳票でいちばんよく使う条件付き書式で、*読めないでは済まない*。

*直した(2026-08-09)。* `CondKind::Formula` を足し、`expression` を読み・*効かせ*・書き戻す。
`make_cond` / `lo_cond` とも報告が消え、両方の書き手から``Formula("LEN(C2)>3")`` として同じに読める。

決めどころは**評価するか、運ぶだけか**。
**評価する**ことにした — 縞が出ないなら読めても仕方がない。
式は**範囲の左上を基準にした原文**で持ち、セルごとに左上からのずれだけ相対参照をずらして(`model::offset_refs`)その位置で解く。
`$` で固定した側は動かないので、`$D2="済"` の行まるごとの色分けも意図どおりに効く。

*ずらすのは解くときだけで、持っている原文は書き換えない。* 保存はいつも原文を返すので、*評価が外れてもファイルは減らない*。
解けない式・誤りは「当たり無し」へ倒す(見当違いの色を自信たっぷりに塗るほうが気付けない)。
範囲は 20,000 セルまで — 式は1セルずつ字句解析から解くので、列まるごとを毎回の描画で回せない。

*ついでに出た1件*: `parse_dxfs` が塗りを `bgColor` からしか読んでおらず、*openpyxl が書いた条件付き書式の色が全種類で黙って消えていた*(openpyxl は `patternType="solid"` + `fgColor` に書く。
Excel も同じ流儀を使う)。
規則は残って色だけ消えるので気付きにくい。
`rgb` を持っているほうを採るよう直した。

==== 3. *LibreOffice が書いた名前の定義が、全部死ぬ* [大に近い中]

`=SUM(名前つき)` が `make_arrays.xlsx` では `15.0` になるのに、*LibreOffice で焼き直した `lo_arrays.xlsx` では `#NAME?`* になる。
中身の `<definedName>` は同じ `式!$A$1:$A$5`。
違うのは**属性の数だけ**:

    openpyxl    <definedName name="名前つき"> LibreOffice <definedName function="false" hidden="false" name="名前つき" vbProcedure="false">

`sheet/src/xlsx.rs:1181` は``e.attributes().flatten().count() == known`` で「単純な名前か」を決めている。
*属性が1つでも余計に付いていたら素通し*(式から引けない)扱いになる。

`function="false"` も `hidden="false"` も `vbProcedure="false"` も**既定値**で、意味を何も足していない。
**LibreOffice はこれを全部の名前に書く。
**つまり *LibreOffice で保存された xlsx の名前つき範囲は、officework ではひとつも使えない*。
数を数えるのではなく、**既定でない値が付いているか**で見分けるのが正しい。

*直した(2026-08-09)。* `defined_name_plain` が属性の**意味**で見分ける。
真偽の属性は**偽なら無いのと同じ**、立っていたら(隠し名前・マクロ)今までどおり原文で持ち越す。
中身を持つ属性(`comment` 等)も、単純と見ると保存で黙って落ちるので原文へ回す。
`lo_arrays` の `式!F7` が `#NAME?` → `15.0` になり、corpus 24 枚すべてで名前が往復する。
試験は``既定値つきの名前が式から引ける`` / `隠し名前は原文のまま持ち越す`。

==== 4. キャッシュ値の無い式 — *決めが要る*(欠陥ではない)

openpyxl は式のセルに `<v>`(前回の答え)を**書かない**。

* *向こう*: 空を返す(ファイルに書いていないものは返さない)
* *うち*: 開いたときに計算して `165.0` を返す。CSE のスピル(`D3:D7`)もちゃんと広がる

**うちのほうが役に立つ**が、サイドカーとして「同じ答えを返す」を目標にするとこれは差として出続ける。
*どちらに寄せるかを決める必要がある*(設計 docs/sekkei/pyoffice.ja.adoc)。
当方の見立ては**うちに寄せる** — 空欄を返しても呼ぶ側は結局 `recalc_cells` を呼ぶので、最初から埋まっているほうが往復が減る。

=== 「使っている範囲」をどうするか(決めが要る)

向こうは `<dimension ref="A1:AL108">` の**宣言**を返す。

== 第4便: `expression` が着地した(2026-08-09)

条件付き書式の `expression` を `main` へ載せて、同じ 30 枚を通し直した。
*57,350 セル。× は 8 枚 → 6 枚。減った 2 枚はちょうど `lo_cond` と``make_cond``* で、どちらも ○ になった。

  ほかに 4 枚は △ — 向こうの欠陥と分かっている差だけ(うちの宿題ではない)

残る 6 枚は第3便の表のうち**決めが要る 2 種だけ**(使っている範囲 4 枚・キャッシュ値の無い式 2 枚)。
*欠陥として残っているものは無い。*

読みの側も直に確かめた。
`lo_cond` / `make_cond` のどちらも**「読めない種類」の報告が消え**、LibreOffice と openpyxl という別々の書き手から``Formula("LEN(C2)>3")`` として**同じに**読める。

*この 2 枚で `当たり 0 セル` は正しい。* C 列は「品目2」など**3文字**しか入っていないので `LEN(C2)>3` は偽になる。
*0 を見て「効いていない」と早合点しない* —ずらした式(`LEN(C3)>3`, `LEN(C4)>3`…)と各セルの値まで出して確かめた。
当たる側は試験(`数式で指定した縞模様が往復して効く`)が``MOD(ROW(),2)=0`` で A2/A4 が真・A1/A3 が偽・範囲外は偽まで押さえている。
