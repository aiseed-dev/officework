= WSL を使っているなら、逆にしませんか — Debian を土台にして、Windows を客にする

////

* 2026-09-20 時点の書き物。発注者(yniji)の一人称で書いてある
* 公開する前に、Debian 13 + GNOME Boxes + Windows 11 を手元で 1 度通して、
  「実際にやった」と書ける所だけ残す。通していない所は書かない
* 貼り付けるときはこの注記ごと消してよい

WSL を使っている人は、もう Linux で仕事をしています。エディターとターミナルと
Python は WSL の中で、Windows は「その外にある物」です。それなら、外と中を
入れ替えませんか、という話です。

Debian を PC の土台にして、Windows は仮想環境(GNOME Boxes)の中で動かします。
WSL の逆、というより、そもそも WSL は要りません。WSL は「Windows を土台に
したまま Linux を使う」ための物で、土台を Debian にすれば、その工夫ごと
要らなくなります。

== WSL で困っていたこと

私が WSL で困っていたのは、Linux が客であることから来る物ばかりでした。

* Windows の更新で再起動が来る。WSL の中で動かしていた物は止まる
* `/mnt/c` の向こうのファイルは遅い。Windows 側のエディターで開くか、
  WSL 側で開くかを、いつも考える
* メモリを `vmmem` が抱えて返さない
* Windows の側では、通知、Store、Copilot の誘いが続く。AI と仕事をしている
  間、これは全部割り込みです
* AI の道具(Claude Code など)は WSL の中で一番素直に動くのに、その結果を
  見るのは Windows の側、という往復

* Python で画面を作る Flet を、配れるアプリに組む(`flet build windows`)には
  Visual Studio 2022 の「C++ によるデスクトップ開発」が要る。数 GB です。
  Debian なら `apt install clang cmake ninja-build libgtk-3-dev` の 1 行です

* 組織の道具(認証、メール、会議、コードの置き場)を WSL の中に置いて動かし
  続けることはできない。WSL には cron も systemd も、Windows の更新を
  止める手も無い。土台が Windows のままなので、Windows の利用規約
  (サーバーとしての使用を認めない、接続は 20 台まで)もそのまま掛かる。
  Windows Server にすれば条項は外れるが、料金がコア数と人数で乗る

どれも「土台が Windows で、Linux が客」だから起きます。WSL を良くしても
解決しません。土台を替えると、全部が一度に消えます。

== 逆にすると

土台が Debian になります。ファイルもエディターもターミナルも AI の道具も、
全部が土台の側にあります。

Windows は GNOME Boxes の中で動く客になります。開くのは、Windows でしか
動く物を使う時だけです。

* 更新も再起動も、Windows の都合では来ません
* Windows の箱は写し(スナップショット)を取れます。何かを入れる前に戻せます。
  メールで届いた xlsm のマクロが動いても、箱の中で止まります
* メモリは Boxes に渡した分だけです。使わない時は箱を閉じます

== 「でも Word と Excel が」に答える

逆にしなかった理由の一番大きい物は、これだと思います。会社の書類は Word と
Excel のファイルで、Linux では同じに開かない。

officework は、ここを埋めるために作りました。受け取った docx と xlsx を、
Word と Excel と同じ頁数、同じ折れ方、同じ列幅で開いて、刷ります。役所が
公開している様式 288 枚で Word の PDF と比べていて、2026 年 9 月 19 日の
時点で 246 枚が頁数まで一致しています。同じファイルを両方で開いて並べれば、
誰でも確かめられます。

Debian には `.deb` で入ります。Python からは `pip install officework` で、
同じエンジンが使えます。

[source,console]
----
sudo apt install ./officework_0.1.0-alpha.3_amd64.deb
officework 見積書.xlsx
----

== 実際にやった手順

2026 年 9 月 20 日にやりました。詰まる所はありませんでした。

. Debian 13 の netinst の iso を落として、Rufus で USB に書く
. USB から起動して入れる。言語は日本語、デスクトップは GNOME
. `sudo apt install fonts-noto-cjk python3-pip python3-venv git gnome-boxes`
. Microsoft の頁から Windows 11 の ISO を落とす
. Boxes で「仮想マシンを新規作成」→ ISO を選ぶ → メモリ {n}GB、ディスク {n}GB
. Windows の入れ方は普通の PC と同じ。プロダクトキーは {控えた物を入れた / 「プロダクト キーがありません」で進めた}
. officework の `.deb` を Releases から落として `sudo apt install ./officework_0.1.0-alpha.3_amd64.deb`

かかった時間は {n} 時間で、そのうち待っていた時間がほとんどです。

(PC の機種とメモリ、Boxes に渡した量、Windows の認証をどうしたか、を
埋めてから公開する。Debian で様式が同じに開いている画面の写真を 1 枚
添える)

== 向かない人

* 会社が管理している PC の人。土台を替えられません
* GPU を Windows 側で使う人(CUDA、ゲーム)。仮想環境の Windows に GPU は
  渡せません(渡せる形もありますが、この記事の範囲を超えます)
* Windows でしか動く物を 1 日中使う人。客を 1 日中開けておくなら、逆にする
  意味が薄いです

== まとめ

WSL を使っている人は、もう半分は逆になっています。残りの半分は、土台を
替えるだけです。WSL を工夫して解決しようとしていた物の多くは、Debian を
本体にすると、工夫なしで消えます。Word と Excel のファイルが同じに開く
なら、替えない理由はほとんど残りません。
