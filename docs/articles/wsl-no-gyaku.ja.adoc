WSL を使っている人は、もう Linux で仕事をしています。エディターも
ターミナルも Python も WSL の中で動いていて、Windows はその外にある物です。

それなら、WSL は要りません。WSL は「Windows を土台にしたまま Linux を使う」
ための工夫です。土台を Debian にすれば、その工夫ごと要らなくなります。
Windows でしか動く物は、Debian の中の仮想環境(GNOME Boxes)で動かします。
PC は 1 台のままです。

私は 2026 年 9 月にこれをやりました。詰まる所はありませんでした。
Debian と、その中の Windows の仮想環境は、簡単に作れます。

開発系の人であれば、もう Windows を使うメリットはありません。そもそも
Web でしか開発していないでしょう。ブラウザ、ターミナル、エディター、
Python、Node、Docker は、全部 Linux の物です。Windows が足している物は
ありません。

== WSL では消えないこと

WSL をどれだけ良くしても消えない物が 4 つあります。どれも、土台が Windows
のままだから残ります。

*割り込み。* Windows の側では、通知、Store、Copilot の誘い、更新の催促が
続きます。更新の再起動が来れば、WSL の中で動かしていた物は止まります。
AI と仕事をしている間、これは全部割り込みです。AI は文字とファイルと
命令で仕事をするので、OS の画面はそもそも要りません。

*動かし続ける土台が無い。* 組織の道具(認証、メール、会議、コードの置き場)を
WSL の中に置いて動かし続けることはできません。WSL には cron も systemd も
無く、Windows の更新を止める手もありません。Jitsi は Linux の Docker
Compose でしか配られていません。入れるだけならできる物も、動かし続ける所で
止まります。

*利用規約。* Windows 10 / 11 のライセンス条項は、サーバーとして使うこと
(商用のホスティング、複数の利用者に同時に使わせること)を認めておらず、
接続できる機器も 20 台までです。組織の道具を Windows の PC で動かすのは、
技術の前に条項に触れます。

*料金。* 条項を外すには Windows Server が要りますが、その料金は今となっては
常識はずれの高額です。本体はコア数で課金され、そこに接続する人ごとの
CAL が乗ります。同じ仕事を Debian は無料でやり、入れ方と運用は AI が
教えてくれる時代に、この差を払う理由がありません。

Debian を本体にすると、この 4 つが一度に消えます。

== Windows を消すときに要ること

「でも Word と Excel が」という問題は、もうありません。Windows は箱の中に
残るので、Word と Excel もその中でそのまま動きます。失う物はありません。

要るのは、次の物です。

* *残す物の写し。* 書類と写真を USB か外付けのディスクに写す。Debian を
  入れると PC の中身は消える
* *Windows のプロダクトキー。* 箱の中の Windows に入れる。出ない PC も
  あり、その場合は認証なしで使う(壁紙に印が出るだけで動く)
* *箱に入れる物の一覧。* Windows でしか動く物(会計ソフト、特定のプリンターの
  道具)を書き出す。それ以外は箱に入れない
* *メモリとディスクの余裕。* 箱の Windows に 4GB と 64GB を渡すので、PC は
  メモリ 8GB 以上、ディスク 128GB 以上
* *Wi-Fi のパスワードと、プリンターの機種。* Debian は最初から印刷の仕組み
  (CUPS)を持っていて、ここ数年のプリンターはドライバー無しで刷れる
* *半日の時間。* 待っている時間がほとんど

それだけです。Word と Excel を Linux で開く道具は要りません。

== Flet が素直に動く

Python で画面を作る Flet は、Debian の上で一番素直に動きます。

* `pip install flet` と `flet run` で動く所は Windows と同じです
* 配れるアプリに組む(`flet build linux`)のに要る物は、apt の 1 行です。
  Windows では Visual Studio 2022 の「C++ によるデスクトップ開発」(数 GB)
  が要ります

[source,console]
----
sudo apt install clang cmake ninja-build pkg-config libgtk-3-dev
flet build linux
----

* 手元のファイルにも、cron にも、systemd にも、同じ Python から触れます。
  AI に書かせた画面を、そのまま動かし続けられます

AI に書かせて、動かして、直す、を Python 1 枚で回す道具なので、土台が
Debian になると、その回転が一番速くなります。

== Windows は箱の中で

Windows でしか動く物(会計ソフトなど)は、GNOME Boxes の中の Windows で
使います。開くのは、その物を使う時だけです。

* 更新も再起動も、Windows の都合では来ません
* 箱は写し(スナップショット)を取れます。何かを入れる前に戻せます。メールで
  届いた xlsm のマクロが動いても、箱の中で止まります
* メモリは箱に渡した分だけです。使わない時は箱を閉じます
* 様式のファイルは外(Debian)に置き、Windows には共有フォルダで見せます。
  記録は自分の側に残ります

== 実際にやった手順

2026 年 9 月 20 日にやりました。詰まる所はありませんでした。

. Debian 13 の netinst の iso を落として、Rufus で USB に書く
. USB から起動して入れる。言語は日本語、デスクトップは GNOME
. `sudo apt install fonts-noto-cjk python3-pip python3-venv git gnome-boxes`
. Microsoft の頁から Windows 11 の ISO を落とす
. Boxes で「仮想マシンを新規作成」→ ISO を選ぶ → メモリ {n}GB、ディスク {n}GB
. Windows の入れ方は普通の PC と同じ。プロダクトキーは {控えた物を入れた / 「プロダクト キーがありません」で進めた}
. `pip install flet` と `flet run` で、Python の画面が動くことを見る

PC は {機種}、メモリ {n}GB です。かかった時間は {n} 時間で、そのうち
待っていた時間がほとんどです。

== 向かない人

* 会社が管理している PC の人。土台を替えられません
* GPU を Windows 側で使う人(CUDA、ゲーム)。仮想環境の Windows に GPU は
  渡せません(渡せる形もありますが、この記事の範囲を超えます)
* Windows でしか動く物を 1 日中使う人。箱を 1 日中開けておくなら、替える
  意味が薄いです
