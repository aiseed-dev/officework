# 産直のプラットフォームから来た人の手引き(蒸留の台帳を兼ねる)

2026-08-15 起こし(発注者「無肥料、自然栽培農家を対象に、calc で管理して、
ポケマルを蒸留したらどうでしょうか」)。

**ポケットマルシェで生産者がやっている仕事の並びを教師**にして、「あの仕事は
ここではこうやる(またはやらない、なぜなら)」を書く。文章も画面も写さない —
**課題の並びだけが教師**(Excel のヘルプ・ONLYOFFICE のガイドを蒸留したのと
同じ流儀。規則は docs/README.ja.md)。

## 先に、蒸留できない物を言う

**2つある。集客と、運賃。** どちらもソフトでは代わりにならない。ここを
「できる」と書いたら、この repo でいちばん嫌う嘘になる。

**集客** — プラットフォームの本体の値打ちは「客を連れてくる」こと。

**運賃**(発注者 2026-08-15「個人でホームページを作るよりも運賃の値引き
交渉ができます」)— これは集客より地味だが、**毎回・全部の荷物に効く**ので
効き目は大きい。個人が数箱を出すのと、何千の生産者の荷物をまとめて出すのとでは、
運送会社から出てくる数字が違う。ポケマルはヤマトの自動伝票発行を持ち、伝票の
発行手数料は 1 配送 87 円(税別)。

**どれだけ効くかは測っていない。** 「手数料 23% より大きい」と書きたくなるが、
値引きの率も箱の単価も分からないので**書かない**。分かっているのは
「個人より安い運賃が適用される」という向きだけ。実際の生産者に運賃の実額を
見せてもらうまでは、ここに数字を入れない。

### ただし、運賃の梃子の正体は「量」

だから道具にできることはある — **量をまとめるのは会でもできる**。JA や
産直の会が昔からやってきたことで、要るのは交渉に出す数字:

> どの地域へ・どの大きさで・冷蔵か常温か・月に何箱。

これは**表計算の仕事**そのもの。officework が出せるのは「値引き」ではなく
**交渉に持っていく表**で、そこは正直に分けて書く。数人の会でも、実在の
種苗の会のように農家リストを持つ集まりなら、まとめる相手は既にいる。

だから officework は**プラットフォームの代わりではない**。位置づけはこう:

> **リピーターが付いて、客と直接やりとりするようになった生産者が、
> 手数料を払わずに、客の名簿を自分の手元に置いたまま続けるための帳場。**

数字で言うと、ポケマルの販売手数料は **23%**(2024-04-01 に 20% から改定)。
3,000 円の品なら 690 円がプラットフォームへ行く。**初めての客にはその値打ちが
ある**(連れてきてもらったのだから)。**二度目からの客にも同じだけ払い続けるか**
が、この道具の問い。

置き換える相手はポケマルではなく、**その手前の実態**でもある — 取引先は
Excel か手帳、出荷の記録は伝票の控え、進捗は担当者の記憶、という状態。

## なぜ無肥料・自然栽培を的にするか

- **採れ高が読めない**(自然任せ)→ 在庫が毎日動く → 手で頁を直していられない
- **品目が多くて少量** → カタログの自動生成が効く(種の見本は 26 品目、実在の
  種苗の会は 200 品目)
- **説明が要る**(なぜ高いか・なぜ形が不揃いか)→ 写真と覚え書きが売り物の一部
- **客が固定**(リピーター中心)→ 名簿を自分で持つ値打ちが高い
- **自家採種をする** → 種の交換の台帳と地続き

## 印の読み方

- **同じ** — 同じ作法がそのまま通じる
- **違う形** — 道具の形は違うが、同じ仕事がここの道でできる
- **まだ無い** — 未実装。隠さない
- **作らない** — 設計判断。理由を一行で書く
- **蒸留できない** — ソフトでは代わりにならない。**できると書かない**
- **該当なし** — プラットフォームがあるから要る仕組み。直販では要らない

## 出品(商品を並べる)

| プラットフォームでの仕事 | 印 | ここでの道 |
|---|---|---|
| 商品を登録する(品名・説明・価格) | 違う形 | **在庫の表(xlsx)が正本**。人は calc で数を直すだけ。`sample/在庫から配り物.py` |
| 写真を付ける | 違う形 | **1シートに1枚**の写真の台帳。原本のまま埋める(zip なので大きさはフォルダに置くのと変わらない)。`sample/写真の台帳.py` |
| 在庫を切らす・再開する | 違う形 | 在庫数を直して作り直すだけ。**在庫の言い方は数から作る**ので割れない(手で保つと「在庫あり!」「ありません。」「販売予定」に割れる — 実在の会で確認) |
| 客が見る頁 | 違う形 | 在庫から **JS なしの HTML** を生成。`sample/catalog_server.py` は分類の開閉・絞り込み・比較表まで実行コードなしで出す |
| 送料を品ごとに決める | まだ無い | 在庫の表に欄を足せば済む。まだ見本に無い |
| スマホから出品 | まだ無い | Flet のランチャー(デスクトップ+スマホ)が来たらここに載る(ayumi.ja.md) |

## 注文を受ける

| プラットフォームでの仕事 | 印 | ここでの道 |
|---|---|---|
| 注文が入る | 違う形 | 3つの道: **注文書(xlsx)を FAX かメールで返してもらう** / **JS なしのフォームから POST** / 電話を書き取る。`sample/注文を受ける.py` と `catalog_server.py` |
| 注文の一覧を見る | 違う形 | 受注台帳(xlsx)。**足すだけ** — 過去の受注は動かさない |
| 在庫を引く | 違う形 | 受けた分だけ引く。**断ることを黙ってしない** — 品切れ・販売予定・数が足りない、を理由ごとに言い、受けた分だけ台帳に載る |
| 注文をキャンセルする | まだ無い | 台帳に取消の行を足す形になるはず(消さない)。まだ見本に無い |
| 定期便・予約 | まだ無い | 自然栽培では「採れたら送る」が現実的なので、**予約の形が違う**はず。設計から要る |

## 発送

| プラットフォームでの仕事 | 印 | ここでの道 |
|---|---|---|
| 宛名を出す | 違う形 | 受注台帳から**差し込み**で宛名と納品書(docx)。`sample/注文を受ける.py` |
| 送り状を出す(ヤマトの自動伝票。1配送 87円) | **まだ無い** | **ここがいちばん効く空白。** ヤマト B2 クラウド等は CSV の取り込み口を持つので、受注台帳から送り状の CSV を出せば届くはず。**仕様は未確認** — 当たること |
| 送料を計算する | まだ無い | 地域・大きさ・クール便で変わる。表で持てば式で引ける |
| **安い運賃で出す** | **蒸留できない** | 梃子は**量**であって道具ではない。個人では届かない。ただし「会でまとめる」なら道はある — 下の行 |
| 運賃の交渉に出す数字を作る | まだ無い | 地域×大きさ×温度帯×月の箱数。**受注台帳から出せる**(集計と同じ道)。これが officework の持ち場 |
| 発送済みを記録する | 違う形 | 受注台帳の「発送」の欄。いまは「まだ」と書くだけ |

## 入金

| プラットフォームでの仕事 | 印 | ここでの道 |
|---|---|---|
| 代金の回収(客から) | **作らない** | **決済は持たない。** 金を預かる仕組みは免許と責任の話で、表計算の仕事ではない。銀行振込・現金・外部の決済への案内に留める |
| 売上金の振込(請求不要) | 該当なし | プラットフォームが預かるから要る仕組み。直販では最初から自分の口座に入る |
| 入金の突き合わせ | **まだ無い** | 通帳の CSV と受注台帳を突き合わせて「入金済/未入金」を付ける。**帳簿の仕事としてここが空いている** |
| 手数料 23% | 該当なし | 払わない。それがこの道具の値打ち |

## 客とのやりとり

| プラットフォームでの仕事 | 印 | ここでの道 |
|---|---|---|
| 購入者とチャットする | **作らない** | **やりとりの場は作らない。** メールと電話が既にあり、二重に持つと客が困る。officework は**やりとりの記録**を持つ側に立つ |
| やりとりを記録する | 違う形 | **客の台帳**(名前・メール・住所・最後の注文・案内可・断った日・覚え書き)。`sample/月の便り.py` が作る。**リピーター中心の商いでは名簿が資産** |
| 配信を断られる | 違う形 | 台帳の「断った日」。**入っていれば二度と下書きを作らない**(法の要求を道具で守る) |
| 自分専用のウォール・コミュニティ | **作らない** | 場を作るのはプラットフォームの仕事。うちは**そこへ出す材料**(写真・説明・案内)を作る側 |
| レビュー | **作らない** | 同上。ただし**いただいた言葉を台帳に控える**のは客の台帳の仕事 |
| 案内を出す(季節の便り) | 違う形 | **月に一度のメール**(発注者 2026-08-15「月1ぐらいのメールがいいかも」)。客の台帳+在庫から一人ずつ下書き(.eml)を作る。`sample/月の便り.py` |
| 一斉に送る | **作らない** | **送るのは人。** 台本が作るのは下書きまで — 数百通を勝手に出す道具にしない(一度出た物は取り消せない)。SMTP の設定も持たない |

### 月1のメールが、この商いに合う理由

- **チャットは要らない。** メールと電話が既にあり、二重に持つと客が困る
- **月1なら書ける。** 週1は続かず、年1では忘れられる。畑が動く周期にも合う
- **在庫が正本だから、書く手間が小さい** — 今月出せる物は表から出る。人が
  書くのは畑の一言だけ(そこは AI にも下書きさせられる)
- **返信が注文になる。** 別の入口を作らずに済む

### 法を道具で守る(特定電子メール法)

総務省・消費者庁のガイドラインの要点を、`sample/月の便り.py` はこう受ける:

- **同意の無い人には作らない。** 過去に買った人は「取引関係にある者」で
  オプトインの例外に当たりうるが、案内が主目的なら規制が掛かる。台帳の
  「案内可」が ○ の人だけを対象にし、**外した人と理由を必ず言う**
  (「断ることを黙ってしない」と同じ作法)
- **断った人には二度と作らない**(台帳の「断った日」)
- **差出人の氏名・住所と受信拒否の連絡先を末尾に機械的に付ける**(表示義務)。
  台本が付けるので**書き忘れが起きない**

**これは法律の助言ではない。** 実際に出す前に、自分の商いの形で確かめること。

## 帳簿

| プラットフォームでの仕事 | 印 | ここでの道 |
|---|---|---|
| 売上の集計 | 同じ | 受注台帳を読んで集計。`sample/集計.py` の形(polars / pandas へも渡せる) |
| 確定申告の材料 | まだ無い | 受注台帳+入金の突き合わせから、月別・品目別の表を出す所まで |
| 栽培の記録 | まだ無い | 播種・定植・収穫の台帳。**自然栽培では「何もしなかった」も記録**で、翌年の材料になる |

## 数えると

**同じ 2 / 違う形 15 / まだ無い 10 / 作らない 5 / 蒸留できない 1 / 該当なし 2。**

「違う形」が「まだ無い」を上回っているのは、今日(2026-08-15)一周を通した
成果がそのまま当たっているため。埋まっていないのは、**送り状・入金の
突き合わせ・客の台帳**の3つが芯で、どれも「注文の後」の仕事。

## 次にやるなら

1. ~~**客の台帳**~~ — **済**(2026-08-15。`sample/月の便り.py`)。
   月1の便りの下書きまで通した
2. **送り状の CSV** — 発送の手間がいちばん重い。ただし**仕様を当たってから**
   言うこと(ここに「できる」と書くのはまだ早い)
3. **運賃の交渉に出す表** — 地域×大きさ×温度帯×月の箱数。**会でまとめる**
   ときの材料。プラットフォームの梃子の正体が量である以上、ここを出せることは
   小さくない
4. **入金の突き合わせ** — 帳簿が閉じる

**やらないと決めた物を増やさない。** 決済・チャット・レビュー・コミュニティは
作らない。この4つを作り始めた瞬間、officework はプラットフォームの劣化版に
なる。うちは**帳場**であって、市場ではない。
