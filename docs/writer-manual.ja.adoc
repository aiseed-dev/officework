= writer の手引き

_元は英語版(link:writer-manual.adoc[writer-manual.adoc])です。こちらは日本語訳です。_

*この手引きは writer 0.2.0-alpha について書いています。* いま配っている0.1.0-alpha にまだ入っていない所には**(0.2.0-alpha で入ります)**と印を付けています。
印の付いた説明は、これからそう作る、という意味です。

officework の文書の編集画面の手引き。
*AsciiDoc の視覚エディタです。* 原稿(.adoc)を見たまま直せます。
処理系(asciidoctor など)の代わりではありません — 原稿を書くための道具です。

3つに分かれます。

[cols="1,1"]
|===
| |できること

|*表示* |開いた AsciiDoc は**全部そのまま見えます**(うちが意味を知らない塊も、字はそのまま出ます)
|*編集* |見たまま直せるのは**部分集合**です(「書き方の一覧」の 27 行)。ルビと記入欄はうちの拡張です
|*保存* |開いた原稿は**壊しません**。知らない塊は原文のまま返します
|===

うちが意味を知らない塊(註記 `NOTE:`・コードの塊 `----`・取り込み``include::`` など)は、*見えますが直せません*。
カーソルを置いて打つと、そう言って断ります。
直すときは原稿をテキストエディタで開いてください。

書き出しは画面・PDF・HTML・docx の4つです。
画面も書き出し先の1つなので、紙の姿でも原稿の姿でも書けます。

*docx は受け渡しの形式です。* 開いて見る・刷る・adoc 形式にすることはできますが、*docx のまま直して保存はしません*(0.2.0-alpha で入ります)。
直すのは adoc、渡すのは docx、という分担です。

Python から使うときは今までどおり docx を直して返せます(`from officework import doc`)。
画面で直さないだけです。

**押せるボタンは全部動きます(グレー表示は図形まわりの5つだけ)。全部の一覧は「すべての操作」にあります。
**docx をパスワードで包むボタンは外しました。
パスワード付きの docx を**開く**ことはできます。

3つの約束:

* *開いた原稿を壊さない。* うちが意味を知らない書き方も、字はそのまま返す。docx を開いたときは、スタイル・図形・理解しない部品を原文のまま持ち越す
* *どの操作も1手で戻せる。* 打鍵も IME の確定も貼り付けもペンの1本も配色の変更も、Ctrl+Z 一回で戻る
* *黙って落とさない。* 読めないもの・保存で失われるものはレポートとステータスバーで言う

試せる見本が link:../sample/README.md[sample/] にある — 特に``sample/writer/01〜05``(日本語の組版・縦書き・申込書・月次報告・道具くらべ)と``06_書き方の見本.adoc``(下の「書き方の一覧」を1枚にしたもの)。

== 画面

画面の枠はデスクトップ版の形。
**1段目**が保存・印刷・戻す・やり直しと文書名(未保存は \* 印。
この行が窓の取っ手)、**2段目**が白地のタブ(現在地は下線。
右端の 🔍 = 検索と置換)、**下端**がステータスバー — ページ n/m・文字数(日本語の実情に合わせ単語数ではなく**文字数**)・状態の文言・校正・ズーム。

* *ファイルタブは全面のページ* — 左のメニュー(新規作成・開く・URL を開く・最近開いた12件・保存・名前を付けて保存・印刷・保護する・詳細情報・ファイルの場所を開く・終了)と、右に「文書の情報」(統計と、docx のプロパティ = 作成者・タイトルなど。欄を押して打てば docProps に入り、Word でも見える)
* *左パネル*(表示タブ): 見出し / コメント / 検索 — 押すとその場所へ飛ぶ
* *右パネル*(表示タブ): 文字・段落・ページの設定盤(ボタンはリボンと同じ実体。入っているボタンは色が変わる)

タブの並び:*ファイル / ホーム / 挿入 / 描画 / レイアウト / 参考資料 / フォーム /ヘッダー・フッター / 共同編集 / 保護 / 表示 / マクロ*。

== 文字書式(ホーム)

*選択した字にだけ掛かる*(選択が空なら段落まるごと)。
太字・斜体・下線・取り消し線・上付き/下付き・文字色・蛍光ペン・書体(この機械のフォント一覧)・大きさ・大文字小文字・スタイルのクリア。

*ルビ*: 選択してホーム > ルビ。
ダイアログに読みを打つ(空で外す)。
基底の上に半分の大きさで組まれ、読みが親より長ければ等配で伸びる。
docx には``w:ruby`` で入り、Word / LibreOffice でも見える。
でんでん記法``{漢字|かんじ}`` の .md からも読める。

== 段落書式(ホーム)

* 揃え: 左・中央・右・両端、そして**均等割付** — 両端揃えとの違いは**最後の行まで**字間に配ること(項目名を端から端まで、の日本の様式の形。docx には `w:jc distribute` で入る)
* 箇条書き・段落番号(レベルは Tab / Shift+Tab)、インデント、行間(1.0→1.5→2.0)、段落の前で改ページ、背景色、囲み枠、ドロップキャップ
* 非表示文字の表示切り替え

== 縦書き(ホーム > テキスト方向)

押すたびに縦横が切り替わる。
右の列から左へ流れ、句読点・かぎ括弧・長音は縦用の形になり、ルビも縦で振れる。
docx には sectPr の``textDirection tbRl`` で入り、LibreOffice で開けることを確認済み。

初版の限界(正直に): 表・段組みは横のまま、英数字は1字ずつ縦に積む(横倒しはまだ)、明示の改ページは列送りに畳まれる。
見開き表示とは併せない。
見本: `sample/writer/02_縦書きの手紙.docx`。

== 見出し・目次・しおり・相互参照(参考資料)

* *見出し*: ホーム > 段落のスタイル(または参考資料 > テキストの追加で標準→見出し1→2→3 と回す)
* *目次 / 図表目次*: ページ番号は**印刷(PDF)と同じ折り方**で計算するので紙と食い違わない。変えたら「更新」で作り直す。docx には静的な本文として入る
* *図表番号*: 段落の下に「図 N」(採番は自動)
* *しおり*: ダイアログで追加・削除・移動。**相互参照**はしおりの「文字」か「ページ」を本文に挿す(うっすら網掛け=計算された値の印。docx にはREF / PAGEREF フィールドで入り、Word でも再計算できる)

== フォーム(記入欄・コンテンツコントロール)

フォームタブに10種: *テキスト・コンボボックス・ドロップダウン・チェックボックス・ラジオボタン・画像・メールアドレス・電話番号・複合・署名*。

* 欄は薄い箱で見え、中は普通に打てる(欄の中の編集は欄の中身として残る)
* チェックは同じボタン(または空白キー)で ☐⇄☑。コンボ・ドロップダウンはダイアログで選択肢をカンマ区切りで決め、同じボタンで次の候補へ回る
* docx には `w:sdt`(コンテンツコントロール)で入り、Word で開ける。うちだけの種類(メール・電話・複合・署名)は tag に `jo:*` の印
* *保護タブの「保護」と組み合わせると配布用の様式になる* — 読み取り専用にして配り、受け取った側は欄だけ記入する。見本: `sample/writer/03_申込書.docx`

== 表・画像・挿入

* *表*: 挿入 > 表の挿入(3×3)。セルの中で編集、Tab で隣へ。セル結合された表は読み・表示・保存・PDF 対応(結合を作る UI はまだ無い)
* *画像*: PNG・JPEG・SVG(SVG は高精細 PNG に変換)。docx の部品ごと保存され Word でも見える
* *図形・SmartArt(9形)・グラフ・テキストアート*:ボタンの裏で Python(matplotlib 等)が描いて画像として貼る
* *方程式*: 挿入 > 方程式で小窓が開き、*LaTeX を打って Enter *(例: `\frac{a+b}{2}`)。組むのは Python — TeX が入っていればそちらで(行列の列まで揃う)、無ければ matplotlib。**絵と LaTeX の原文が二枚組**でdocx に入るので、Word では絵として見え、writer で開き直せば式として直せる。組めない式は理由を言って断る
* *テキストボックス*: 1×1 の表(枠の中に文字)
* *ファイルからのテキスト*: .txt / .md / .docx を差し込む

== 描画(ペン・蛍光ペン・消しゴム)

紙の上をドラッグ。
線は**ページに固定**(本文を編集しても動かない)、1筆が undo の1手。

*筆は画像(SVG)として保存されます。* 本文の隣の `images` フォルダに入り、本文からは `image::` で指されます。
ですので HTML にも PDF にも docx にも出て、後から画像として消せます。
前は docx にしか残らず、adoc で保存すると消えていました。

保存すると、*線は本文の流れの中の絵になります。* 引いた高さのすぐ上の段落の後ろに入りますが、紙の上の左右の位置は残りません。
何枚の絵にしたかは状態行に出ます。

== レイアウト

* 用紙(A4→B5→A3)・向き・余白(20/12/30mm)・段組み(1→2→3段)・行番号・ページ色・透かし(斜めの薄い字。Word でも見える)・ハイフネーション(欧文を音節で折る)
* *配色の変更*: 6種を巡回(標準・藍・緑・臙脂・藍+生成りの紙・墨+灰の紙)。見出しの字の色と紙の色が組で変わり、**その時の値で塗る**のでテーマ部品なしで Word でも同じ色に見える。Ctrl+Z で1手で戻る

== ヘッダー・フッター

ダイアログで編集(全ページ共通)。
ページ番号・ページ数は印として入り、紙(PDF)で各ページの実番号になる。
日付は挿した時点の**固定の文字**(開くたびに変わるフィールドにしない — 事務書類の事故のもと)。

== HTML — JS なしの閲覧と記入

*Web の文書を writer で読む・記入する・刷る。*

* *開く*: .html ファイル、または ファイル > *URL を開く*(http/https)。見出し・段落・リスト・表・画像・ルビ・form が紙面に組まれる —読めない要素はレポートへ。リンクは**起点のホストの中だけ**辿れる
* *JS は実行しない*(読み飛ばしてレポートに言う)。JS 前提のページは動かない — 読めないものは読めないと言う
* *記入と送信*: form の欄(input / select / textarea)が記入欄になり、送信は GET / POST の普通の往復。返ってきた文書がまた紙面になる
* *ページの Python*(`<script type="py">`)は**開いても実行されない**。明示の操作で、Python in Calc と同じサンドボックスの中でだけ回る
* 開いた HTML は docx で保存・PDF で印刷できる(HTML では保存しない —互換は書式の境界で守る)
* 受入サンプル: `sample/html/`(01〜10)、動く相手は``python3 sample/catalog_server.py`` のカタログと注文書

== 共同編集タブ — サーバー無し、全部ファイル越し

共有フォルダに置いた文書で、そのまま効くツール:

* *共同編集モード*: ロック(`.~lock.文書.docx#`)の持ち主を名前で確認し、先客が去っていれば編集権を取り直す。先客がいる間は上書き保存が止まる(早い者勝ちの編集権+後の人は読むだけ、という正直な形)
* *コメント*: 段落単位で追加・削除・表示切替(docx の comments.xml。Word で吹き出しに見える)。*adoc 形式では、隣の控えファイルか git のどちらでも持てます*(0.2.0-alpha で入ります)。git を使う人はレビューの仕組みで足り、使わない人には隣の控えがあります
* *変更履歴*: 記録の開始/停止。記録中は変わった段落の左に橙の棒。docx で書き出すと Word の本物の変更履歴(挿入・削除・著者つき)になる。*adoc 形式では git の差分で見られます*(本文はテキストなので、どこが変わったかがそのまま読めます)
* *チャット*: 文書の隣のチャットファイル(`文書.docx.chat.txt`)へ名前付きで追記。生放送ではない — ファイル越しの伝言
* *バージョン履歴*: 上書き保存のたびに `.jo-history/` へ控え(9世代)。選ぶと**名前のないコピー**として開く — 戻すなら自分で同じ名前で保存(黙って書き戻さない)

== 保護タブ

* *保護*: 読み取り専用の入切(docx の documentProtection と往復 — Word でも保護に見える)。*パスワードは掛けない・掛けた振りもしない*。効き目は本物: 打鍵も文書を変えるボタンもブロックし、見る・刷る・検索は通す
* *暗号化*: パスワード付きで送られてきた docx は**開けます**(パスワードを聞きます。*Agile = AES-256* も古い *AES-128* も読めます。msoffcrypto-tool との相互検証済み)。**掛けるボタンはありません。**writer が保存するのは adoc で、zip ではないので包めないためです
* *デジタル署名*: 隣に置く署名ファイル(`文書.docx.sig`、Ed25519。署名の鍵は``~/.config/officework/sign.key`` に自動生成)。改ざん検知と名前の証明が実体 — Word の署名欄に出る方式ではない(そう言う)

== 表示タブ

ナビゲーション(左パネル)・ページに合わせる / 幅に合わせる / 100% /拡大・縮小・*印刷レイアウト(紙を1枚ずつ積んで見せる — 節で紙の大きさが変わる文書はこの表示で違いが見える。編集の表示は続きの連続表示のまま)*・*複数ページ(見開き — 画面だけ。印刷は1ページずつ)*・ダークモード(周りだけ暗く、紙は白のまま)・ルーラー(mm)・ツールバー / ステータスバー / 左右パネルの表示切替。

== 左右のパネルと、外側のアイコンの柱

パネルの外側にアイコンの柱が立っています。
押すと面が替わります:

* *左*: 見出し / コメント / 検索 / AI
* *右*: 設定(いる場所)/ ページ(文書ぜんぶの決め)

絵の上に指を置くと名前が出ます。
パネルは**場所を取ります**(紙に重なりません)。

== 右パネル「設定 — いる場所を直す」

*いる場所に追従します。* 表の中にカーソルがあれば表の面が、段落に数式や画像があればその面が、いちばん上に出ます(下の 文字・段落・ページ もそのまま残ります — 表の中でも字は太字にしたいので)。

* *表*(表の中にいるとき): 行数×列数といまの位置を出し、*上に行 / 下に行 / 行を消す / 左に列 / 右に列 / 列を消す*。最後の1行・1列は消しません(表ごと消すのは別の操作)
* *数式*(段落に式があるとき): 原文(LaTeX)を出し、「式を直す」でその原文を欄に載せて開きます。*打ち直しになりません*
* *画像*(段落に絵があるとき): 大きさ(mm)と、小さく / 大きく
* *文字*: 太字・斜体・下線・取消・大きさ・書体・色・書式を消す
* *段落*: 揃え・行間・字下げ・箇条書き・番号・背景・囲み
* *ページ*: 向き・用紙・余白・段組み・縦書き

パネルは**場所を取ります**(紙に重なりません)。
中身が縦に伸びたら巻けます。

== AI — 左パネルで相談する

*AI のボタンは、左パネルの会話にまとまっています。* 11 個のボタン(要約・書き直す・敬語にする・…)は、**左パネルの会話**に置き換わっています — 「この段落を敬語にして」と打てば済み、ボタンでは作れない頼み方もできるからです。

開き方: *表示タブ > ナビゲーション*(左パネル)→ タブの *AI*。

* **選んでいる所が相談の相手**になります(選んでいなければ全文)
* *直した文は見せてから入ります。* 「入れる」を押すと、選んでいればその所を置き換え、選んでいなければカーソルの後ろへ。どちらも**Ctrl+Z 一手**で戻せます
* 文を直さない頼み(書き方の相談)は、そのまま答えます

*タブに残った2つ*(会話では代われない仕事):

* *ホーム > ふりがな* — 入るのが普通の字ではなく**ルビの書式**だから
* *マクロ > マクロを書く* — 置き場に .py を置く仕事だから(自動では走らせません。読んで確かめてから実行)

**宛先の選び方**は ファイル > 詳細設定 の「AI の宛先」にあります。
使えない宛先なら**その場で理由**を言います。

== 校正(レビュー系)

英語の綴りは機械の辞書、日本語の誤変換(以外/意外)・表記ゆれは**ローカルのモデル**に聞く(宛先は OpenAI 互換``OFFICE_HOST`` / `OFFICE_PORT` / `OFFICE_MODEL`。ネットワークの外に出ない)。モデルの作り話は通さず、*繋がらなければ「校正できません」と出る* —黙って「指摘なし」にしない。ルビの自動付与も同じモデルの資産(文脈で読みを選ぶ — 読みが割れる語 561種の実際に確かめたに基づく)。

画面なしのツール: `office-spell 文書.txt`(終了コード 0=無し 1=あり2=読めない 3=検査しきれず)、`--furigana`、`--washi`。

== マクロタブ

* *一覧*: `~/.config/officework/plugins` の .py を並べ、選ぶと走る(サンドボックスの中)。青空注記・EPUB などの拡張はここに足していく選ぶと**サンドボックス(bubblewrap)の中の Python** が文書のコピーを直し、結果が1手として入る(Ctrl+Z で戻る)。スクリプトには `d` = python-docx の文書が変数される。*コードは文書には載せない*(docx に実行コードを入れない — xlsx と方針が違うのは、python-docx という公共財が既にあるから)

**走らせられるのは置き場の .py だけです。
**置き場の外の .py を選ぶ口は閉じました。
外から受け取った物は、置き場に置いてから一覧で選びます —**置く手が1つ挟まる**のが門です。

* *マクロの書き方* — 名前つき記入欄(`fill`/`extract`)・雛形(`render`)・速さの作法・AI に書かせる話はlink:macro-manual.ja.adoc[マクロの手引き]に

== 文書は2種 — adoc 形式と、受け取った docx

writer は2つの形式を扱います。
*どちらで開いているかで、できることが変わります。* いまどちらかは、画面の下の行に `adoc` / `docx` と出ます。

[cols="1,1,1"]
|===
| |adoc 形式 |docx 形式

|本文 |何が書いてあるか(見出し・強調・引用・表) |本文の中に書式も混ざる
|書式 |*別のファイル*(隣の .toml)が持つ |本文が持つ
|書式の変え方 |名前を付けて、その名前を使い回す |その場に直に掛ける
|保存 |.adoc と .toml の2つ |.docx 1つ(原本の部品はそのまま)
|===

どちらが良いという話ではありません。
**受け取った docx は今までどおり**開いて直して返せます。
何も変わりません。

=== なぜ分けたか

Word にもスタイルはあったが、直接書式(この行だけ太字12pt)が同じくらい簡単だったので誰も使わず、文書が書式の泥に沈んだ。
*設計で防ぐ* —ネイティブ文書では、見た目を直に変える道より**名前を付ける道の方が楽**にする。

== ネイティブ文書(.adoc)

ファイル > 開く で `.adoc` を選ぶ。
中身は普通の字で、こう書かれている:

[source,asciidoc]
----
= 月次報告
:template: 社内標準

== まとめ

売上は前月比で*伸びた*。詳しくはfootnote:[東京と大阪の合計]。

* 東京
* 大阪
----

* `= 題名` / `:template: 名前` が頭
* *見た目は1つも入らない。* 大きさも色も書体もテンプレートの側

書き方の一覧は次の節にあります。

=== 1つのファイルに文書を何枚も

同時に送る請求書の原稿をまとめて保存する、という使い方のために、1つの `.adoc` に文書を何枚も入れられます。
切れ目は `= 題名` です — 題名が何度も出てくれば、その数だけ文書が入っています。
2枚以上入っているファイルを開くと、画面の下に文書のタブが出ます(表のシートのタブと同じ位置・同じ動きです)。
検索と置換の「探す範囲」で「このファイル」を選ぶと、いまの文書を見終えたら次の文書へ回ります。

=== 保存すると、書き方が揃います

writer は保存のときに、**1つの文を1行**にして書きます。
文の終わりは `。`!` `?` です。欧文は `.`` の後ろが空白と大文字のときだけ切ります(``Dr. Smith`` や ``example.com/a.b` では切りません)。

こうすると、1文だけ直したときに、git の差分にその1文だけが出ます。
段落をまるごと1行で書いていると、どこを直したのか読めません。

開くときは、続いている行を1つの段落に戻します。
ですので、*画面の見え方は変わりません*。

**他所からもらった .adoc を開いて保存すると、行の切れ目が変わります。
**文章は1文字も変わりませんが、差分は大きく出ます。
中身を比べたいときは、保存の前後ではなく、開いた画面で見てください。

=== 書き方の一覧

同じ1つのことを、本文の書き方・リボンのボタン・Web の形の3つで並べた表です。
*どれも同じものを指しています。* 本文を手で書いても、ボタンで作っても、出来上がりは同じです。

[cols="1,1,1,1"]
|===
|したいこと |本文の書き方 |リボンのボタン |Web の形(HTML)

|表題 |`= 表題` |右パネルのスタイル > 表題 |`<h1 class="title">`
|見出し 1 |`== 見出し` |ホーム > 段落のスタイル > 見出し1 |`<h2>`
|見出し 2 |`=== 見出し` |ホーム > 段落のスタイル > 見出し2 |`<h3>`
|見出し 3 |`==== 見出し` |ホーム > 段落のスタイル > 見出し3 |`<h4>`
|段落 |そのまま書く |ホーム > 段落のスタイル > 標準 |`<p>`
|引用 |`____` で挟む |右パネルのスタイル > 引用 |`<blockquote>`
|箇条書き |`* ` で始める |ホーム > 箇条書き |`<ul>` と `<li>`
|段落番号 |`. ` で始める |ホーム > ナンバリング |`<ol>` と `<li>`
|太字 |`*太字*` |ホーム > 太字 |`<strong>`
|斜体 |`_斜体_` |ホーム > 斜体 |`<em>`
|上付き文字 |`x^2^` |ホーム > 上付き |`<sup>`
|下付き文字 |`H~2~O` |ホーム > 下付き |`<sub>`
|ふりがな |`ruby:漢字[かんじ]` |ホーム > ルビ |`<ruby>` と `<rt>`
|スタイル(段落) |`[.名前]` を段落の前の行に |右パネルのスタイル |`class="st-名前"`
|スタイル(文字) |`[.名前]#字#` |右パネルのスタイル |`<span class="st-名前">`
|ハイパーリンク |`https://例.jp[表示する字]` |(まだありません) |`<a href="…">`
|脚注 |`footnote:[注の文章]` |参考資料 > 脚注 |番号と末尾の一覧をリンクで結ぶ
|ブックマーク |`[[名前]]` を段落の前の行に |参考資料 > ブックマーク |段落の `id="名前"`
|相互参照 |`<<名前>>` |参考資料 > 相互参照 |`<a href="#名前">`
|表 |`\|===` で挟み、行ごとに ``\|``区切り |挿入 > 表の挿入 |`<table>` と `<td>`
|セルの結合(横) |`2+\|` |(まだありません) |`colspan="2"`
|セルの結合(縦) |`.2+\|` |(まだありません) |`rowspan="2"`
|図 |段落をまるごと `image::images/図1.png[]` に |挿入 > 画像を挿入 |`<img>`
|数式 |段落をまるごと `stem:[x^2]` に |挿入 > 方程式を挿入 |`<img>`(元の式も残る)
|改ページ |`<<<` |挿入 > 区切り |印刷のときだけ改ページ
|記入欄 |`field:名前[表示する名前,種類]` |フォーム > テキストフィールド |`<input>` `<select>` `<textarea>`
|見出し 4・5 |`=====` `======` |ホーム > 段落のスタイル |`<h5>` `<h6>`
|等幅 |`` ``字`` `` |右パネル > スタイル > 等幅 |`<code>`
|ラベル付きリスト |`項目:: 値` |右パネル > スタイル > 説明のリスト |`<dl>` `<dt>` `<dd>`
|註記 |`NOTE: 文` |右パネル > スタイル > 註記 |`<p class="st-註記">`

*本文に書かないもの。* 下線・取り消し線・フォントの色・蛍光ペンの色・フォント・フォントサイズ・行間・配置・罫線と、*ページの飾り*(ヘッダー・フッター・透かし・ページの色・縦書き)は、本文ではなくテンプレートに書きます。
ヘッダーとフッターの中の `{ページ}` `{ページ数}` は、その頁の数字になります。
リボンのこれらのボタンを押すと、右のスタイルの面が開きます。
Web の形では CSS になります。

*表題は本文の1行目になります。* `= 表題` は画面にも紙にも出て、その場で直せます。
同じ字が文書の情報(ファイル > 詳細情報のタイトル)にも入るので、docx にすると Word の文書のプロパティにも出ます。
見た目はテンプレートの「表題」で決めます。

*数式は開いたときに組みます。* 本文が持っているのは元の式(LaTeX)だけです。
組むのは Python なので、TeX が入っていればそちらで、無ければ matplotlib で組みます。
組めない式があれば数を言います。

*本文には入らないもの。* 目次と図表目次は、押したときに作られる字です(本文の書き方はありません)。
Web に書き出すと `nav` にまとまります。
コメント・ペン・変更履歴は docx だけの機能です。

図を入れたときは、本文の隣に `images` フォルダが出来て、その中に絵が入ります。
本文は絵の場所を指しているだけなので、*本文と `images` は一緒に運んでください*。

記入欄の種類は、書かなければ1行の文字です。
ほかに `複数行` `チェック` ``日付```メール` `電話` `画像` `署名` `選ぶ:A|B` `打てる選ぶ:A|B` が書けます。
ボタンで入れた欄は種類ごとに同じ名前が付くので、2つ以上入れるときは**フォーム > 名前**で名前を変えてください(送られる側はこの名前で受け取ります)。

=== テンプレート(見た目の元)

書式のファイルは**フォルダに1つ**置きます。
同じフォルダの文書は、名前を書かなくてもそれを使います。

[cols="1,1,1"]
|===
|置き方 |書き方 |使われるもの

|フォルダに1つ(ふつう) |何も書かない |同じフォルダの `テンプレート.toml`
|文書ごとに変える |本文の頭に `:template: 社内標準` |`社内標準.toml` を *文書の隣 → `~/.config/officework/templates/`* の順に探す
|===

**書いてあるほうが強い**ので、`:template:` があればそちらが使われます。
どちらも無ければ同梱の既定です。

=== 画面を原稿の姿にする

adoc 形式の文書は、**書くための原稿**です。
紙の姿で見ることも、原稿の姿で書くこともできます。
フォルダの `テンプレート.toml` にこう書くと、画面が原稿の姿になります。

[source,toml]
----
[組み方]
横幅 = "可変"     # 紙の幅ではなく窓の幅で組む
区切り = "なし"   # ページに折らない(1本の流れ)
----

窓を広げれば行が長くなり、ページの区切りは出ません。
*本文は1文字も変わりません* — 紙にするときは印刷用のテンプレートが A4 に組みます。

=== 様式(升目)を作る

申請書・稟議書のような**升目の書類**は、本文に表として書きません。
**中身はラベル付きリスト、升目はテンプレート**という分け方にします。

本文の頭で、どの様式を使うかを言います。

[source,asciidoc]
----
= 休暇申請書
:様式: 申請書

申請日:: 2026年8月18日
部署:: 総務課
氏名:: 山田太郎
----

テンプレート:

[source,toml]
----
[様式.申請書]
行 = [
  { 升 = ["申請日"],        幅 = [30, 70] },
  { 升 = ["部署", "氏名"] },
]
----

同じ本文が、画面と紙では升目、Web では表、docx でも表になります。
*中身と升目は名前で結びます*(項目の名前と升の名前)。
順番では結びません — 項目を1つ足しただけで全部ずれるからです。

*升目に無い項目・項目の無い升目は、そう言います。* 黙って落とすと、空欄の申請書が出来上がります。
文書を開いたときに状態行に出ます。

`幅` は百分率です。
1つの升は「項目の名前」と「値」の2つの枠になるので、上の例では名前が 30 パーセント、値が 70 パーセントになります。
書かなければその行の枠を等分します。

=== 書き出し先ごとに書式を変える

同じ本文を、画面・Web・紙で違う見え方にできます。
**書式のファイルを書き出し先の数だけ置くだけ**です。

[cols="1,1"]
|===
|書き出し先 |使うファイル

|画面と保存 |`テンプレート.toml`
|Web の形で書き出す(HTML) |`テンプレート-web.toml`
|印刷(PDF) |`テンプレート-印刷.toml`
|===

*混ざりません。* 一度に効くのは1枚だけで、無ければ `テンプレート.toml` に落ちます。
どれを使ったかは書き出したときに画面の下の行に出ます。

*アプリの形にしたいときも Web と同じ道です。* `テンプレート-web.toml` に``[送り先]`` を書けば、記入欄が送れる申込用紙になります。

`テンプレート-印刷.toml` を置くと、**画面と紙の見え方が変わります。
**置かなければ今までどおり同じです — 変えるかどうかは置いた人が決めます。

[source,toml]
----
[文書]
大きさ = 11

[ページ]
用紙 = "A4"
余白 = 25
ヘッダー = "社内資料"
フッター = "- {ページ} / {ページ数} -"
透かし = "社外秘"
ページの色 = "FFFDF5"
縦書き = false

[スタイル.本文]
字下げ = 1          # 1行目を1字下げる(日本語の本文の作法)
行間 = 1.5

[スタイル.見出し1]
大きさ = 20
太字 = true
色 = "1B6E3C"
後の空き = 8
----

スタイルに書けるものは、いまはこの12個です。
**必要なら足します**が、足すときは通る道が全部揃っていることを確かめます(揃っていないと「書いたのに効かない」が残ります)。

[cols="1,1"]
|===
|字に効く |段落に効く

|大きさ・書体・太字・斜体・下線・色 |背景色・揃え・字下げ・前の空き・後の空き・行間
|===

**書式の入れ子は3段**です。
`[文書]` の書体と大きさが土台で、その上に段落のスタイル、いちばん内側が文字のスタイル(`[.名前]#字#`)です。
内側が勝ちます。
スタイルが別のスタイルを継ぐ書き方(Word の「基準にするスタイル」)はありません — 継ぐ鎖があると、その色がどこから来たのか誰にも言えなくなります。

*AI に書かせるのがいちばん楽*(「役所に出す様式で」「社内報告書らしく」)。
テキストなので、AI が読み書きでき、人が差分を読める。

壊れているテンプレートは、**どこが悪いかを言って**同梱の既定に落ちる —黙って落ちると直す手がかりが無い。

==== 配られたテンプレートは書き替わりません

テンプレートは、**書式を決める人が作って配るもの**です。
役所の様式・社内の書式規程・学会の体裁は、書く人ではなくその人の持ち物です。

書式を直すと、書き先はいつも**開いている文書の隣**になります。
元が別の場所(`~/.config/officework/templates/` の中や同梱の既定)だったときは、

[NOTE]
====
この文書だけの写しを /…/社内標準.toml に作りました。配られた
/home/…/templates/社内標準.toml は変えていません
====

と出ます。
*この文書だけが写しの方を見るようになります。* 配った人が元を直しても、この文書には届かなくなるので、直してもらうときは元を直す人に頼んでください。

=== 見た目を変えたいとき

大きさ・書体・色・蛍光ペン・下線・打ち消しを押すと、直には掛からず、*右のスタイルの面が開きます*。
そこで、

* 一覧から**選ぶ**(すでにあるスタイルを着る)
* **なし**を押す(いま着ているスタイルを外す)
* *新しく作る*(見た目に名前を付けて、テンプレートに入れる)

のどれかを選びます。
名前を決めるとテンプレートにスタイルが入り、その名前を持つ所が一度に変わります。

* **字を選んでいれば字に、選んでいなければ段落に**掛かります
* 字に付いたスタイルは `[.名前]#字#` として保存されます
* 強調(太字・斜体)・上付き・下付きは**意味なので封じません**。そのまま効きます

=== 右パネルのスタイルの面

表示 > 右パネル → 柱の3つ目。
いまの段落が着ているスタイルと、選べる一覧が出る。
押すと着替え、字の大小はそこで直す — **直るのはテンプレート**なので、同じスタイルの所が一度に変わる。

=== Web と発表の組み方

テンプレートに1節足すと、*同じ本文が別の姿で組まれる*。
直すのはテンプレートだけで、本文(.adoc)は1文字も変わらない。

Web(1本の流れ):

[source,toml]
----
[組み方]
横幅 = "可変"     # 紙の幅ではなく窓の幅で組む
区切り = "なし"   # ページに折らない
----

発表(1節=1枚):

[source,toml]
----
[組み方]
区切り = "節"     # 見出し1(== …)ごとに1枚
跨ぎ = false      # 段落が枚を跨がない
----

* 節の頭で必ず紙を改めるので、**見出し1 が1枚の表題**になる
* `跨ぎ = false` は、枚の境に掛かった段落を丸ごと次の枚へ送る。1段落で1枚に収まらないときはそのまま(送っても直らないので諦める)
* 枚として1枚ずつ見るには 表示 > *印刷レイアウト*
* *PowerPoint は要らない* — 発表もテンプレートの1種

=== Web の形で書き出す(HTML)

ファイル > *Web の形で書き出す(HTML)*。
本文が HTML、テンプレートが CSS になります。

[source,html]
----
<style>
body { font-family:"Noto Sans CJK JP"; max-width:42em; margin:0 auto }

=== GitHub に置くとそのまま読める

GitHub は `.adoc` `.asciidoc` `.asc` のファイルを**そのまま組んで見せます**(asciidoctor を使っています)。
writer で書いた原稿をリポジトリに置けば、書き出しをしなくても読める形になります。
README を `README.adoc` にしても同じです。

*テンプレートは効きません。* 見た目は GitHub 側のものになります。
色や書体を決めたいときは、HTML で書き出して GitHub Pages などに置いてください。

本家にある書き方(見出し・表・箇条書き・脚注・相互参照・`image::`・``stem:``など)は、そのまま思ったとおりに出ます。
うちだけの書き方 —ふりがな `ruby:` と記入欄 `field:` — は字がそのまま出ますが、この2つを使う文書を GitHub で見せることはまず無いはずです。

=== 記入用紙にする(HTML の form)

本文に記入欄を書き、テンプレートに送り先を書くと、**そのまま使える申込用紙**になります。

本文:

----
= 見学の申し込み

field:name[お名前]
field:kind[参加区分,選ぶ:一般|学生]
field:day[希望日,日付]
field:note[ご要望,複数行]
----

テンプレート:

[source,toml]
----
[送り先]
宛先 = "https://example.jp/uketsuke"
送り方 = "post"
ボタン = "申し込む"
----

種類は、書かなければ1行の文字です。
ほかに `複数行` `チェック` ``日付```メール` `電話` `画像` `署名` `選ぶ:A|B` `打てる選ぶ:A|B` が書けます。

* 角括弧の中は「表示する名前」で、コロンの前が「送られる名前」です
* *送り先が無ければ form にしません。* 押しても何も起きない用紙を作らないためです

== 受け取った docx を adoc 形式にする

ファイル > *adoc 形式にする(本文と書式を分ける)*。

docx は本文と書式が1つのファイルに混ざっています。
これを**2つのファイルに分けます**。

[cols="1,1,1"]
|===
| |中身 |ファイル

|本文 |何が書いてあるか。見出し・段落・箇条書き・表 |`文書.adoc`
|書式 |どう見せるか。書体・大きさ・色・余白 |`文書の型.toml`
|===

*書式は無くなりません。* 同じ見た目の段落をまとめて1つの書式にし、名前を付けて書式のファイルへ移します。
本文の側にはその名前だけが残ります。

名前の付き方はこうです。

* いちばん数の多い見た目が「*本文*」になります
* docx の側で「見出し1」などと名乗っている段落は、*その名前を引き継ぎます*
* 名乗っていない見た目には「*見た目1*」「*見た目2*」という仮の名前が付きます。中身を見て名前を決めるわけではないので、*後から自分で分かりやすい名前に変えてください*(右のスタイルの面から直せます)

=== なぜ分けるのか

* *同じ書式の所が一度に直ります。* 「見出し1」を直せば、その名前を持つ所が全部変わります
* *同じ本文が別の姿になります。* 書式のファイルを差し替えるだけで、紙にもWeb にも発表用にもなります
* *中身だけを比べられます。* 本文は普通の文字ファイルなので、git で差分が読めます

=== 気をつけること

* *戻せないので、押したときだけ変わります。* 押すまで docx は docx のままです(原本の部品もそのまま残ります)
* *段落ごとの書式に収まらない所は落ちます。* 1つの段落の中で1語だけ色が違う、といった場合です。*その数を必ず言います* — 「何も失っていない」と嘘はつきません。強調・脚注・リンク・ルビは残ります
* 押した後は保存先が `.adoc` になります

== フォルダから探す

ファイル > *フォルダから探す*。
指定した場所を辿って、複数のファイルを串刺しで探す。

* *.docx の中身も探せる* — 一度 txt に落とす必要がない
* 普通の字(.txt / .md / .adoc / .py / .csv …)もそのまま
* `*.txt` の形で名前を絞れる(`;` で複数)
* 場所は**開いている文書の隣**が既定(前に選んだ場所があればそちら)
* 隠しフォルダは辿らない。多すぎるときは途中で止め、*止めたと言う*

当たりはファイルごとに、行番号つきで並ぶ。
選ぶと**下に前後が出るだけで、開かない**。
開くのは下の**「読み込み」**を押したとき — 見て、これだと分かってから開くので、押し間違いで文書が入れ替わらない。

== 印刷(PDF)と保存

* ファイル > 印刷で PDF。ヘッダー・フッターの実番号・透かし・ページ色・ペン・縦書きごと写る
* *画面と紙は、同じにも違うようにもできます。* `テンプレート-印刷.toml` を置けば紙だけ別の姿になり、置かなければ画面のままが紙になります
* *数える所は必ず紙で数えます。* 目次・図表目次・相互参照のページ番号と、ヘッダーのページ数は、画面が何枚に見えていても**紙の枚数**です。「3ページ」と書いてあるのに紙の3ページに無い、が起きません
* *Ctrl+S は adoc で保存します*(先客のロックがあれば止まります)。本文だけが書かれ、書式はテンプレートの側です
* *docx は「書き出す」で作ります。* テンプレートの書式は docx のスタイルの定義として書かれるので、Word で開いても見た目が付きます。Word 側で「スタイルを直せば同じ所が一度に変わる」も効きます。本文の側には見た目を焼き付けません。フォルダに `テンプレート-docx.toml` があれば、docx だけそちらの書式で書き出します
* 書き出しても、*原稿の保存先は adoc のままです。* そのあとの Ctrl+S はdocx ではなく adoc を保存します
* 開いた docx を**その場で直して返すことはしません**(0.2.0-alpha で入ります)。直すなら「adoc 形式にする」を押してから作業し、docx で書き出します

== グレー表示は5つだけ

グレー表示になっているのは、レイアウトタブの**図形まわりの5つ**だけです —
前面へ移動・背面へ移動・配置・グループ化・図形を結合。
図形を扱う機能はまだ入っていないので、押せない形で場所だけ取ってあります。

「できないものを、できるように見せない」ためで、灰色のボタンは押しても
何も起きません。表計算の側も同じ扱いです。

残る正直な限界は各章に書いたとおり(縦書きの初版の限界、変更履歴の個別採否、セル結合を作る UI など)。
