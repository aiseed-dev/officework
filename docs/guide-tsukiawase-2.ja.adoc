* ✔(2026-08-08、続報で改訂)*結合の確認をやめ、左上以外の値は消す* —発注者2段: 「どうして警告を出すのか」→確認を廃止。「呑まれた値がモデルに残るのは困る」→*左上以外の中身は消す*(書式は残す)。残すと見えない値が SUM などの式に効いて帳票が静かに嘘をつく。消しても Ctrl+Z 一発で戻るから確認は出さない — 状態行で「左上以外の値は消しました — Ctrl+Z で戻せます」と言うだけ。SUM が隠れ値を数えないこと・Ctrl+Z で戻ることまで試験で固定。さらに(発注者 2026-08-08): **左上が空白なら、読み順で最初の中身を左上へ移してから**消す(「B1 に題があるのに A1 から選んで結合」で題が消えない)。横方向は行ごとに同じ扱い。文字列の全連結は見送り —数や式が混ざると合成でデータが化ける(発注者も「複雑になるか」)。移すときは**書式ごと**(発注者 2026-08-08「書式は値があった場所の書式。中央揃えにしない」)— 「セルの結合」は揃えを含めて一切触らず、中央を掛けるのは「結合して中央に配置」だけ

== 第4便: リボン全ボタンの実機一巡(2026-08-08 `tools/ribbon_sweep.py`)

*台帳では見つからない種類の欠陥がある。* ここまでの台帳は本家のヘルプと画面を読んで作ったので「無い機能」しか拾えない。
185 の命令のうち 176 は実装済みで、もう不足より**壊れ**のほうが危ない。
そこで実機で全ボタンを押す道具を置いた(`tools/ribbon_sweep.py`)。
見るのは4点:

. 落ちない
. 押して何かが起きる(一覧・パネル・状態行・中身のどれかが変わる)
. 一覧が開いたら**押したボタンの真下**に出ている
. Esc で閉じ、閉じたあとキーが効く(= 焦点が格子に戻っている)

判定は画素比べでなく rpc(`ribbon` / `ui_state`)で読む。
しくじった時だけ撮る。

=== 見つかったもの

* ✘ *取り消し(2026-08-08)。「リボンを押すと焦点が外れて Esc が効かない」は存在しない不具合だった。* 点検の道具が窓に **X の入力焦点**を与えていなかったので、Esc が別のアプリへ飛んでいただけ。`window.focus` を足す細工を一度入れたが、外しても Esc は効くと確かめて戻した。*道具の側の欠陥を製品の欠陥として報告した* — 焦点・重なり・前の操作の残りは、実機の点検で真っ先に疑う
* ✔(2026-08-08)*一覧が押したボタンでなく選んでいるセルの下に出る*(発注者報告)。ボタンの場所を描くときに控え、その真下に出す
* ✔(2026-08-08)**セルのスタイルの一覧だけ位置が直書き**で、どのボタンから開いても左端に出ていた。一巡点検が数値で捕まえた
* ✔(2026-08-08)*条件付き書式を Esc で閉じると、押した覚えのない親の品書きが出る* — `a_cancel` の `||` が短絡して子だけ閉じていた。親を通らずに開いた子はまとめて閉じる(`menu_direct`)
* ✔(2026-08-08)*前の一覧の注記が次の一覧の見出しに残る* — 書体の一覧に「ピボット 1/4 …」が出た。`pick_note` は16箇所で立つのに消すのは2箇所だけだった

=== 誤報を生む型(この道具を使うときに疑うこと)

一巡の最初の版は**しくじり 20 件以上を報告したが、大半は道具の側の欠陥**だった。
順に踏んだ落とし穴:

. *X の入力焦点を与えていない* → Esc が他のアプリへ行き「Esc が効かない」。打鍵の前に必ず `set_input_focus`。窓を前面にも出す(重なっていると撮った絵に相手の中身が写る)
. *共有の実行時ディレクトリの socket に繋いだ* → 発注者が動かしているcalc に話しかけた。必ず自分の `XDG_RUNTIME_DIR` の socket を使う
. *ボタンの位置を段の頭で一度しか読まない* → 出たり消えたりするボタンがあるので座標が古くなり、隣を叩いてその結果を無実のボタンのせいにする。押すたびに引き直す
. *ボタンの場所の控えが段をまたいで貯まる*(製品側の欠陥でもあった)→前の段のボタンが残る。描くたびに捨てる
. *空のブックで回す* → 書式のボタンが効いても差が出ず全部「無反応」
. *前のパネルを片付けない* → 後続が軒並みおかしくなる。ボタンごとに素の状態へ戻し、戻せなければ立て直す

=== 当てになる検査とならない検査(2026-08-09 で線を引いた)

*既定で見るのは「落ちない」と「一覧の位置」だけ。* 位置は rpc から数で読むので当たる — 実際に直書き6箇所を捕まえた。

「押して何か起きたか」と「Esc で閉じるか」は `--strict` に隔離した。
手では効く zoom-in を「無反応」と言い、長く回すと Esc の判定が崩れる。
原因を7回追って道具の欠陥を6つ潰したが、まだ残っている。
*当たらない検査は無いより悪い*(緑を信じられなくなるうえ、本物が雑音に埋もれる)。

=== この道具の限界

* *文字入力は試験できない。* 合成キーは IME を通らない。割り当て(Esc など)は効くので、そちらは見られる
* 段の見出しの場所は目分量。切り替わったかは rpc の `tab` で必ず確かめる
* 「押して何も起きない」の判定は、あらかじめ中身のあるセルを選んでおく必要がある。空のセルだと書式のボタンが効いても差が出ない

== pyoffice の突き合わせが落とした穴(2026-08-09 `tools/pyoffice_diff.py`)

genoffice のサイドカーが返す欄と `sheet` のモデルを並べて出た件。
ガイドの読み合わせではなく**他所の実装との突き合わせ**なので、ここに別立てで置く。

* ✔(2026-08-09: `Sheet::freeze`(`FreezePane { frozen_rows, frozen_columns }`)を足し、`sheetView > pane` を読み書きした。`sheetViews` は `rtl` のときだけでなく**常に**書くので、右から左と固定枠が同じ枠に同居する。`showGridLines` / `showFormulas` / `zoomScale` も併せて往復させた — いずれも `Option` で持ち、*原文に無かったものは書き足さない*(触っていない帳票の差分を増やさない)。掴んで動かす分割(`state="split"`)は固定ではないので撥ねる。*calc も繋いだ* — `App::frozen` は画面の状態でモデルに触れていなかったので、ファイルが固定と言っていても固定なしで開き、calc で固定してもファイルに載らなかった。`freeze_from_book`(開いた直後)と `freeze_into_book`(書く直前)で往復させる。数え方は 1対1。*併せて見つかった地雷: `sheetView` を `Event::Empty` でしか見ていなかった* — Excel は `<selection/>` や `<pane/>` を抱えた Start で書くので、実物の xlsx では *`rtl` すら読めていなかった*。両方の枝から読むようにした) *[大] 固定枠(ウィンドウ枠の固定)を読まないし書かない* — `sheet/src/xlsx.rs:3104` は `sheetViews` を **`rtl` のときだけ**書き、`pane` は読み書きのどちらにも出てこない。Excel で見出し行を固定した台帳をcalc で開いて保存すると、*固定が黙って消える*。台帳・様式では見出しの固定は既定に近いので、乗り換えの一発目で気付かれる種類の欠陥。併せて `sheetView` の他の属性(`showGridLines` / `zoomScale` / `showFormulas`)も同じ理由で落ちている
