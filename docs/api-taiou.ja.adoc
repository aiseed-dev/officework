= 対応表 — メニュー・API・python-docx・openpyxl

引くための1枚です。同じ操作を4つの言い方で探せます。

*並びは画面のメニューのまま*です。ファイル・ホーム・挿入…の順に、
押すボタンがそのまま行になります。探すときは、画面で押している場所を思い出してください。

*分類はオブジェクト*です。`officework` が触るのは `.adoc` の1つの模型なので、
文書と表で分けません(2026-08-24 発注者)。
`Doc` `Paragraph` `Run` `Table` `Cell` `Sheet` `Book` `Section` `Comment` のどれかです
(記入欄はまだ独立した物になっておらず、`Doc` が持っています)。

`A / B` と2つ書いてある行は、*いま呼び方が2つある*という意味です。
95 行のうち 21 行がこの形で、**寄せる仕事が残っている所**です。

*印は4つです。*

[cols="^1,1,3"]
|===
|印 |数 |意味

|✅ |70 |*実装した。* 専用の呼び方があります
|✍ |19 |*書けば済む。* 専用の口は作りません — 書き方をその行に出してあります
|(空) |22 |*まだ。* 作らないと決めたのではありません。**ここが仕事の一覧**です
|❌ |3 |*実装しない。* 決めた物だけで、理由をその行に書いてあります
|===

**空欄1つでは、できるのか・まだなのか・やらないのかが分かりません。**
印を見れば、その行で何が起きているかが分かります。

*「書けば済む」がいちばん大事な列*です。専用の呼び方が無くても、
いまある口を組み合わせれば書けます。*操作できるかどうかと、専用の口があるかどうかは別*です。

そして**書ければ、関数で包めば API になります**。
`officework` に足すのを待たずに、*ご自分で名前を付けて使えます*。
よく使う物はパッケージにして、職場に配れます
(link:python-manual.ja.adoc[Python の手引き]の「パッケージを足す」)。

* `officework` の*呼び方*を引く
* python-docx / openpyxl の*覚えている書き方*から、こちらの書き方を引く
* 同じ操作を、*本家の2つがどう呼んでいるか*を見比べる

*列は「うち・本家」の組を2つ並べてあります。*
左の2列が文書(`officework` と python-docx)、右の2列が表(`officework` と openpyxl)です。
隣どうしを見れば移し替えが分かり、左右を見比べれば文書と表の違いが分かります。

本家の側は実際に呼んで確かめた名前です(python-docx 1.2.0 / openpyxl 3.1.5)。

// api:taiou:start(この間は tools/api\_taiou.py --write が書く)
1行が1つのボタンです。*並びは画面のメニューのまま*です。

*`officework` は `.adoc` を触る1つの模型*なので、文書と表で分けません。
代わりに**どのオブジェクトの物か**を出します。
`A / B` と2つ書いてある所は、*いま呼び方が2つある*という意味です。

空いている所(—)は、その道がありません。

この節は `tools/api_taiou.py` が起こします。手で直さないでください。
