= Calculating by column

_日本語版(secondary): link:../ja/df-manual.adoc[df-manual.adoc]_

*Status: implemented.*

A formula normally belongs to one cell. This booklet describes `df`, which
lets one formula belong to a whole column. Read it if you keep a table
where every row is worked out the same way, such as a quotation, an order
book, or a ledger.

== What it does

You write the formula once, and the column is filled.

Take a sales table with a Price column and a Quantity column. The Amount
of every row is Price times Quantity. Today you write that formula in one
cell and copy it down every row. With `df` you write it once.

    =df(Sales[Amount] = Sales[Price] * Sales[Quantity])

The table then has an Amount column.

[cols="2,1,1,1"]
|===
|Item |Price |Quantity |Amount

|A4 copier paper |420 |30 |12600
|Toner |8900 |2 |17800
|Folder |180 |50 |9000
|===

Three things follow from writing it once.

You read one formula instead of ten thousand. When the same formula is
copied into ten thousand cells, a single row that someone edited by hand
does not stand out. One formula per column is read once and checked once.

Add a row and the column fills itself. You do not copy the formula down
again.

The formula names the columns instead of the cells. `Sales[Price]` says
what the value is. `C2` says only where it sits.

== How to write it

The form is one equals sign inside `df`.

    =df(<table>[<column>] = <formula>)

The left side names the table and the column that is being defined. The
right side is the formula for that column. Inside the formula you refer to
other columns of the same table by the same `<table>[<column>]` form.

You can put the formula in any cell of the sheet. The left side already
names the table, so the definition reads the same wherever it sits. The
table is a table object on that sheet (one made with Format as Table).

The cell you wrote it in shows the names of the columns it defines. It
shows `Sales[Amount]`, or `Sales[Amount], Sales[Tax]` when two columns are
defined. The values go into the table.

If the table has no such column, it is added at the right edge of the
table. The column name is written in the header row and the table range
grows by one column. If the column already exists, every row of it is
filled with the value of the formula. Whatever was in that column, values
or formulas, is replaced by the values of the definition.

== It is a definition, not a write

`=df(Sales[Amount] = Sales[Price] * Sales[Quantity])` says "the Amount of
Sales is Price times Quantity". It does not copy a value into cells that
happen to be somewhere else.

This is why the formula can sit anywhere. A cell formula that reaches out
and overwrites a distant table would be hard to find later. A definition
belongs to the column it names.

The square bracket form is Excel's structured reference, so it is written
the way you already know. The one difference is that putting it on the
left of the equals sign defines the column.

== Several definitions at once

Separate them with commas.

    =df(Sales[Amount] = Sales[Price] * Sales[Quantity],
        Sales[Tax]    = Sales[Amount] * TaxRate)

Both columns are added to the table.

== Names you define yourself

A value that is not a column can be given a name, and the name can be used
in the formula.

    =df(TaxRate = 0.1,
        Sales[Tax] = Sales[Amount] * TaxRate)

A defined name can be used in the formulas of the same `df`. It cannot be
used in an ordinary cell formula or in a `df` written in another cell.

== The order of calculation

The order is worked out from what depends on what. It is not the order you
wrote the definitions in.

    =df(Sales[Tax]    = Sales[Amount] * 0.1,
        Sales[Amount] = Sales[Price] * Sales[Quantity])

Tax is written first and Amount second, but Tax needs Amount, so Amount is
calculated first. The answer is the same either way round.

== When it is refused

*The same column defined twice.* If two definitions name `Sales[Amount]`,
neither is used and the cell shows an error. The message names the column
and both places, so you can go and delete one.

*A loop.* If Amount needs Tax and Tax needs Amount, the cell shows an
error. The message names the columns in the order they depend on each
other, so you can read where the loop closes.

*A table or column that does not exist.* The cell shows an error naming
the part that was not found.

*No room for the new column.* If the column just right of the table holds
a value or a formula, the column cannot be added. The message names the
column and the column letter that is not free.

*A definition that uses a failed column.* A definition whose formula reads
a column that failed for one of the reasons above is not used either. The
message names that column.

Error messages name columns, not cell addresses. `Sales[Amount]` is the
thing you wrote, so it is the thing the message talks about. Only the
message for a double definition also gives the two cell addresses, so you
can choose which one to delete.

The messages are in Japanese. These are the forms they take:

[cols="1,2"]
|===
|Case |Message

|Defined twice |`売上[金額] を2回定義しています(F1 と F3)`
|Loop |`定義が循環しています(売上[金額] → 売上[税額] → 売上[金額])`
|No such table |`表 仕入 が見つかりません`
|No such column |`売上[原価] が見つかりません`
|No room for the column |`売上[金額] を足す場所(D 列)が空いていません`
|Uses a failed column |`売上[税額] は、エラーになった 売上[金額] を使っています`
|===

== What a formula can hold

The right side takes the same things as an ordinary cell formula: numbers,
text, cell references, functions, and columns of the same table. A column
of the same table is read as the value in the current row. `Sales[Price]`
is the price in row 2 while row 2 is being worked out.

`df` shows the names of the columns it defined in its cell. The result of
`df` cannot be passed to another function.

== The same thing in Python

A definition becomes one `with_columns` call, one for one.

[source,python]
----
import polars as pl

売上 = pl.DataFrame({
    "Item": ["A4 copier paper", "Toner", "Folder"],
    "Price": [420, 8900, 180],
    "Quantity": [30, 2, 50],
})
売上 = 売上.with_columns((pl.col("Price") * pl.col("Quantity")).alias("Amount"))
----

A defined name becomes an ordinary Python variable.

[source,python]
----
TaxRate = 0.1
売上 = 売上.with_columns((pl.col("Amount") * TaxRate).alias("Tax"))
----

The whole sheet is a set of "name = formula" and "table[column] = formula"
definitions, and the order they run in comes from the dependencies alone.
That is the spreadsheet's own way of recalculating, widened from cells to
columns and names.

== Two things not settled yet

Both will be settled against the ledger sample when it is built. Until
then, writing them is refused with an error message.

*Running totals inside a formula.* A ledger has a balance column, which is
the running total of the amounts above it. Which summaries can appear
inside a `df` formula, and how they are written, is not decided. For now,
a summary function such as `SUM` or `AVERAGE` on the right side is refused
with `df の中の集計はまだ使えません(売上[累計] の SUM)`.

*Looking a value up in another table.* Writing
`Journal[AccountName] = Accounts[Name]` needs a rule for which key joins
the two tables. That rule is not decided. For now, a column of a table
other than the one on the left side is refused with
`別の表の列はまだ引けません(科目表[名前])`.
