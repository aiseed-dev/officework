= SNS の受け持ち(方針と投稿の下書き)

作業用の文書です。利用者向けのマニュアルではありません。
投稿の文面は利用者が読むので、docs/ の手引きと同じ言葉の決まりで書きます
(CLAUDE.md の「言葉づかい」)。

== 受け持ち

SNS 担当(Claude)がすること:

* 投稿の文面を英語と日本語で書き、この文書に置く
* 投稿に使う写真を、リポジトリにある物(web/assets)か、自分で作った文書から用意する
* 出す前の確認(下の一覧)を通す
* 反応(不具合の報告、質問)への返事の下書きを書く

発注者がすること:

* アカウントを持ち、投稿のボタンを押す(push と同じで、外に出す操作は発注者がします)
* 報酬や募集の条件のように、お金と人に関わる決めを下す

== 決め

. **動いている物だけを書きます。** 手引きと紹介ページ(web/main.py)と同じ決めです。「〜できます(予定)」は書きません。これから作る物は「作っています」と書きます。
. **数字には日付を付けます。** 例:「2026 年 9 月 19 日の時点で 288 枚のうち 246 枚」。数字は SEKKEI.adoc の突き合わせの記録(「docx の Word 比較」の回ごとの集計)と紹介ページ(web/main.py)の数字と同じ物を使います。
. **写真に使えるのは、自分の文書と、役所が公開している様式だけです。** Word のテンプレート(web/gallery の物)は Microsoft の著作物なので、試験に使うだけで、写真にも投稿にも出しません(SEKKEI.adoc「Word のテンプレートを英語版と日本語版で全部通す」)。
. **英語が先です。** 発注者の決め(2026-09-19)「日本に訴えるよりもまず世界に訴えた方がいい」に従い、英語の投稿を先に出し、日本語は同じ内容を後から出します。
. **売りは 1 つです。** 「受け取った docx と xlsx を、Word と Excel と同じに開いて刷る。同じファイルを両方で開けば誰でも確かめられる」。機能の数や AI の話は、この売りの後に添えます。
. **秘密の値と人の情報は出しません。** 様式を送ってくれた人の名前は、本人が認めた場合だけ、docs/corpus-docx.ja.adoc に書く形で残します。投稿には出しません。
. **同じ言葉の決まりで書きます。** 比喩や造語を使いません。Word と Excel のヘルプの言葉を使います。

=== Discord の Flet 日本語チャンネル

Flet を使う人の場所なので、Flet の話を先に書き、製品の話は 1 行に留めます。
コードは web/ にあるので、リンクは GitHub の web/ です。紹介ページが公開されたら URL を足します。

1 つ目(自己紹介と、ページの作り):

----
はじめまして。Word と Excel のファイルを同じに開いて刷るアプリ(aiseed office)を作っていて、その紹介ページを Flet で作りました。

Python のファイル 1 枚(200 行ほど)です。サーバーでは flet run --web を systemd で動かし、nginx から 127.0.0.1:8550 へ渡しています(WebSocket を通すために Upgrade と Connection のヘッダーを付けています)。

コードと動かし方はここにあります。
github.com/aiseed-dev/officework/tree/main/web
----

2 つ目(日本語の書体の手当て。同じことで困る人がいるので、先に出してもよい):

----
Flet の Web で、「、」「。」が字の中央に寄って出る件です。

Flutter は日本語の書体を持たず、字ごとに Google の Noto から補います。どの Noto(日本語・簡体字・繁体字・韓国語)で補うかはブラウザの言語設定で決まり、アプリからは指定できません。日本語以外の設定のブラウザで開くと、繁体字用の字形になります。

手当てとして、assets/index.html(Flet の index.html の写し)で、Flutter が動き出す前に navigator.language を ja にしています。足したのは 1 か所です。
github.com/aiseed-dev/officework/blob/main/web/assets/index.html

Flet の版を上げたら index.html を写し直す必要があるので、Flet 側に言語を指定する設定があれば、この手当ては要らなくなります。
----

== テスター向けの 1 枚の手引き(下書き)

募集の投稿からリンクする 1 枚です。公開する場所は紹介ページ(office.aiseed.dev)か、リポジトリの docs/ です。

----
= 手元の様式で確かめる手順

1. aiseed office を入れます(Mac・Windows・Linux)。
   github.com/aiseed-dev/officework/releases

2. お使いの様式(docx)を、Word と aiseed office の両方で開きます。

3. 次の 3 つを送ってください。
   - Word の画面の写真 1 枚
   - aiseed office の画面の写真 1 枚
   - それぞれの頁数

4. 違って見えた所があれば、一言で書いてください(例:「表の 2 列目が広い」)。

5. 違いがあったときだけ、そのファイルを送ってください。
   個人情報や社外秘が入っている物は、空の様式か、中身を書き換えた物にしてください。
   送っていただいたファイルは、直す確認に使い、認めていただいた場合は比べる集めに入れます。

送り先: {GitHub の Issues か、メール}
----

== 出す前の確認

投稿を出す前に、この順で見ます。

. 書いてあることは、いま動いている物か(手引きに載っているか)
. 数字に日付が付いているか。数字は SEKKEI.adoc の突き合わせの記録と同じか
. 写真は自分の文書か、役所の公開の様式か(Word のテンプレートではないか)
. 人の名前、ファイルの中身、秘密の値が写っていないか
. リンク先は開くか(紹介ページは公開後だけ)
. 言葉づかいは普通か(CLAUDE.md の表の言葉が入っていないか)
. 英語は 280 字、日本語は 140 字を目安に収まっているか

== 発注者に決めてもらう物

* Discord の Flet 日本語チャンネルに、紹介ページの公開前に出すか(コードは GitHub にあるので、公開前でも出せます)

* 紹介ページ(office.aiseed.dev)の公開の日。公開までは投稿のリンクは GitHub にします
* アプリの配布の書き方。README.ja.adoc は「配布はしていません」、紹介ページは「試験公開」で Releases へ案内しています。投稿はどちらに合わせるか。合わせた方に README も直します
