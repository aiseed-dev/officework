= 連載「AI ネイティブな仕事の作法 — ソフトウェア開発編」の直し方(まとめ)

2026-09-20 の話し合いから。作業は Web サイト用の Opus のセッションがやる。
元の文書: docs/sekkei/ai-kakumei-shita-kara.ja.adoc(主張のまとめ)、
docs/articles/ai-ni-makaseru-server.ja.adoc(会社の人への 1 枚)。

== 1. 表紙で 1 番目にする

aiseed.dev の表紙で、この連載を 1 番目に置く。隣に道具(aiseed office)と
入口(Flet の会、普通の人の会、Windows の 1 枚、Debian の 1 枚、WSL の記事)を
並べる。

== 2. 自立編の頭に「AI の PC」の章を足す

会社の人への 1 枚をそのまま章にする。AI に専用の PC を 1 台渡す。Debian に
して、画面(GNOME)も入れて動かしたまま。公開の Web と社内の道具と AI の作業を
1 台で兼用。AI にルートを渡す(壊れたら初期化)。初期化で戻らない物だけ人が
持つ(鍵と認証、外でやる操作、書類の写し)。公開の側と AI の側は別の利用者。
AI は複数入れて相互監視(別の会社の AI、見張る側には作った物と基準だけ)。
費用は、開発が 100 + 100 か 100 + 20 ドル、運用が 20 + 20 で月 1 万円以内。
SIer を雇うのと同じことが月 20 ドルほど。サーバーは安い物でよい。

置く場所は自立編の 2-01(Microsoft と Google から自立する)の次。以降の章は
全部この PC の上でやる形になる。

== 3. 自立編の各章を、AI に読ませて実行できる仕様書にする

各章に 3 つを足す。

* 確かめ方。章の終わりに「これができていれば済み」(ログインできる、メールが
  届く、会議に入れる)
* 人が持つ物。その章で人が渡す値(ドメイン、鍵、パスワード)と、AI が「やる
  前に言う」操作
* 確かめた版と日付。道具の版が上がれば手順が変わる

AI のいるサーバーで「2-03 を読んで、そのとおりにやって」と言えば動く形が
目標。

== 4. 転換編に「AI 革命は下から」の章を足す

docs/sekkei/ai-kakumei-shita-kara.ja.adoc の 18 の主張を、発注者の一人称で、
その順で 1 章にする。現場を本来の姿に戻す、情シスは要らず現場に人を増やす、
部署から始める、稟議なしでできる所から、上からは必ず失敗する、ウクライナの
例(侵攻を受けて守っている側であることを書く)、経営者には細かな問題を見る
時間が無い、中心が持てば抑圧・下が持てば解決、だから AI は革命を起こす。

== 5. 2-05「文書を取り戻す」に足す

いまは OnlyOffice Docs で書かれている。aiseed office が様式の一致で使い物に
なった時点で、aiseed office に替えるかは発注者の決め。足す話は、原稿は文字
(adoc)で持ち、git に入れるのは原稿だけでデザインは入れない、adoc 形式での
データ交換が重要になってくる、の 2 つ。

== 6. 書き方

普通の言葉。1 文に 1 つ。比喩と造語を使わない。根拠の無い文を足さない
(発注者の言葉と確かめられる証拠だけ)。数字は日付付き。どちらの側かを
言わない中立の書き方をしない。
