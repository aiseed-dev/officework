# SEKKEI — 日本語

設計の正本の一部(なぜ作るか・校正・辞書・K4(縦書き/ルビ/均等割付)・右横書き)。2026-08-08 に SEKKEI.md から部屋割りで
**純移動**した(文言は変えていない)。書き込みの規則は SEKKEI.md の頭を見よ。

## 校正 — ローカルの Command A+(`ui/src/proof.rs`)

日本語の「スペルチェック」は綴りの話ではない。実際に起きるのは**誤変換**(以外/意外)・
**表記ゆれ**(問合せ/問い合わせ)・送り仮名・重複表現で、辞書式では検出できない。
だから中身にモデルを使う。**これは「AI機能」ではなく、校正という普通の機能の実装手段** —
だからリボンに AI タブは作らず、レビュー > 校正 に置く。

- 宛先は 127.0.0.1 のローカルサーバ(OpenAI互換 `/v1/chat/completions`)。
  **基幹網は外に出ない**ので、閲覧の分離設計と矛盾しない。
  `JO_PROOF_HOST` / `JO_PROOF_PORT` / `JO_PROOF_MODEL` で差し替え
- Command A+ はオープンウェイト(migration-kit DESIGN.md でローカルAIとして採用済み)。
  ただし大型なので相応の GPU メモリが要る(同 DESIGN.md の注記)
- **モデルの作り話は通さない**: `found` が本文に実在しない指摘は捨てる
- **サーバが居なければ「校正できません」と出す。** 黙って「指摘なし」にしない
  (利用者が「誤りが無い」と受け取ってしまうため)

## なぜこれを作るのか — 英語は解放された。日本語は解放されなかった

英語の綴り検査は**公共財になっている**。この機械で確かめた:

    hunspell-en-us は システムパッケージ。
    依存元: libenchant-2-2, task-gnome-desktop, task-kde-desktop,
            task-xfce-desktop, task-mate-desktop, task-lxqt-desktop …
    語彙: SCOWL(Kevin Atkinson)・Moby lexicon・Princeton WordNet

**誰も英語を正しく綴るために Microsoft に金を払っていない。** 辞書は誰でも同梱できる。

日本語には対応物が無い。`/usr/share/hunspell/` に ja は無く、`apt-cache search hunspell`
にも日本語の辞書は出てこない。だから日本語の校正は、Word の校正・ATOK・Just Right! を
買うしかなく、いまそれがクラウド(Copilot)へ移りつつある。

**これは誰かの怠慢ではなく、構造。**

| | 誤りの正体 | 辞書で解けるか |
|---|---|---|
| 英語 | 綴り誤りは**辞書に無い語**になる (`recieve`) | 解ける → 公共財になった |
| 日本語 | 誤変換は**辞書に有る語**になる (「以外」/「意外」) | 解けない → 企業のものであり続けた |

ふりがなも同じ。「後」の読みは辞書に書けない(文脈で変わる)。
実測: 青空文庫5作・ルビ14,994箇所で、**読みが割れる語が561種**。

**オープンウェイトのモデルは、日本語にとっての hunspell になれる。**
hunspell が英語にしたこと(誰でも同梱できる・金を払わない・手元で動く)を、
日本語でやる。それがこのソフトの存在理由であり、
**言語の正しさの土台を一社から借りている状態を終わらせる**ということ。

## 辞書は答えではなく絞り込み(2026-08-02 に測り直した)

「英語は辞書で足りる」は**不正確だった**。辞書が答えられるのは
「この語は一覧にあるか」までで、**無い語が誤りかどうかは答えられない**。

    『高慢と偏見』 123,688語 → 辞書に無い語 312種 (0.25%)
    AMDの技術文書   2,114語 → 辞書に無い語  74種 (3.50%)

    例: Bennet, Bingley, Bakewell, Annesley … / DeepSeek, Docker, Franka, LangChain …

**全部、正しい語。** 辞書だけだと『高慢と偏見』に2,251件の「綴り誤り」を報告する。

だから配置はこうなる。**辞書は前置きの濾過器**で、残った未知語だけモデルに訊く
(固有名詞か、誤りか)。組み込みの固有名詞リストは誤魔化しなので、判定に置き換えた。

    英語  : 辞書が 99.7% を落とす → 0.25% だけがモデルに届く
    日本語: 辞書が何も落とせない  → 100%  がモデルに届く

**これが「日本語にGPUが要る」の定量的な意味**であり、同時に推論の最適化でもある
(一番速い推論は、動かさない推論)。同じ処理の流れで、濾過器の効きだけが違う。

判定の規則: **迷ったら name。** 正しい語を「誤り」と言う害の方が、
誤りを見逃す害より大きい。判定できなければ「綴り誤り」ではなく**未知語**として出し、
判定できなかったことを `skipped` に残す。一度判定した語は覚えて二度訊かない。

## 校正は office の一部。別ブランドで配らない

hunspell が英語で勝ったのは**誰でも同梱できたから**だが、それを可能にしたのは
**免許**であって、別売りのパッケージではない。だからこちらは
**aiseed office(仮称)として配り、校正はその中の機能**にする。
別ブランドの製品を増やさない。

**AGPL なので、単体で切り出して配りたい人は配れる。** こちらがやる必要はない。

`office-spell` と `furigana-bench` は残すが、これは**製品ではなく道具**である。
理由は1つで、**画面を開かずに回せないと測れない**から —
青空文庫17,000作品の命中率も、Radeon 上の推論速度も、窓越しには測れない。

    office-spell 文書.txt        指摘を出す(標準入力も可)
    office-spell -l              語だけ(hunspell -l と同じ形)
    office-spell --washi         第1候補を振った本文を pywashi の記法で出す

終了コードで区別する — **0=指摘なし 1=指摘あり 2=入力が読めない 3=検査できなかった部分がある**。
3 が要るのは、モデルが居ないときに 0 を返すと
「終了コード0 = 問題なし」と受け取られるため。**黙って「指摘なし」にしない**を
コードの形で守る(`Report::may_say_clean()`)。

固有名詞は一般の英語辞書に載らない(実際に `Radeon` → `Radon` と直された)。
hunspell と同じくユーザ辞書 `OFFICE_DICT_USER` で受ける。

## 日本語の辞書 — 「答え」ではなく「濾過器」(2026-08-10 発注者「日本語の辞書も作れないか」)

作る。ただし**英語の辞書とは役割が違う**。↑の「辞書は答えではなく絞り込み」を
日本語側で実装する話であって、あの節を覆すものではない。

**答えの辞書は作らない。** 「以外」も「意外」も正しい語なので、語を何万積んでも
どちらが正しいかは判定できない。ここは構造であって、辞書の量では動かない。

**作るのは濾過器と規則。** いま日本語側の濾過器は**空**で、100% がモデルに届く。
英語は辞書が 99.7% を落としている。**ここを埋めるのが辞書の仕事**で、判定は
モデルに残したままでよい(「一番速い推論は、動かさない推論」)。

### 副産物のほうが大きい — **モデルが無くても指摘が出る**

いまの日本語の校正は、モデルが居なければ**何も出ない**(正しくは「校正できません」と
言って終わる)。下の 1〜3 は**辞書と規則だけで判定でき、モデルを要らない**。
GPU の無い機械でも日本語の校正が動き出す — 存在理由(「言語の正しさの土台を
一社から借りている状態を終わらせる」)に、いちばん近い一歩はここ。

### 作る順(この順を崩さない)

| | 何を見るか | 拠り所 | モデル |
|---|---|---|---|
| 1 | **表記ゆれ** 問合せ/問い合わせ が同じ文書に混在 | **文書の中だけ**。辞書すら要らない | 要らない |
| 2 | **重複表現** 頭痛が痛い・まず最初に・各位様 | 有限の一覧(自前で書く) | 要らない |
| 3 | **送り仮名** 行なう/行う | 内閣告示「送り仮名の付け方」 | 要らない |
| 4 | **同音異義語の濾過器** | ペア表 | **判定はモデル。辞書は印を付けるだけ** |

**1 が最初。** 辞書が要らず、文書の中で閉じ、誤検出の当たりも付けやすい。
**4 が本命だが最後。** 効きを数で出す土台(青空文庫の実測)を先に用意する。

### 決めごと

1. **種別を増やさない。** `lang/src/check.rs` の `Kind::Notation`(表記ゆれ)・
   `Kind::Okurigana`(送り仮名)は**既にある** — モデルの `why` を分類するために
   作った受け皿。辞書側もそこへ入れる。利用者から見て「モデルが言ったのか辞書が
   言ったのか」で語彙が変わるのはおかしい
2. **外部の辞書ファイルに依らない。** 1〜3 は同梱データか規則で閉じる。
   `/usr/share/dict/words` のような外部依存を日本語側に増やさない
   (2026-08-10 の CI で、英語の辞書とフォントが無くて赤になったのを踏んだ)
3. **内閣告示は使える。** 法令・国の告示は著作権の保護の外(著作権法13条)。
   「送り仮名の付け方」「常用漢字表」はそのまま典拠にできる。
   **民間の校正基準や社内表記ルール集を写さない** — そこは免許が別
4. **許容を誤りにしない。** 送り仮名には本則・許容・例外がある。
   「行なう」は許容で、誤りではない。**規則があるからといって断定しない**
5. **黙って「指摘なし」にしない**(既存の掟)。辞書だけで見た範囲と、モデルに
   訊けなかった範囲を分けて言う。終了コード 3(検査できなかった部分がある)は
   辞書が通っただけでは消えない
6. **誤検出は見逃しより重い**(既存の掟「迷ったら name」)。表記ゆれは引用と
   固有名詞で必ず誤る。**混在を報告するだけで、どちらが正しいとは言わない**

### 測り方

効きは**数で**出す。青空文庫の実測基盤(`lang/src/ja/aozora.rs`)が既にあるので、
4 の濾過器は「何 % をモデルに送らずに済んだか」を出してから広げる。
1〜3 は「実物の文書で誤検出が何件出たか」。**当たらない検査は無いより悪い。**

### 1「表記ゆれ」を入れた(2026-08-10。`lang/src/ja/notation.rs`)

**モデルが居なくても指摘が出るようになった。** `office-spell` を繋がらない宛先で
回すと、表記ゆれだけが出て**終了コードは 3 のまま**(モデルに訊けなかった範囲は
残っているので 0 にも 1 にもしない)。副産物のほうが大きい、と書いた所が形になった。

    1   表記ゆれ  問合せ      → 問い合わせ  [辞書]
    11  表記ゆれ  問い合わせ  → 問合せ      [辞書]
    4 件の指摘(ただし 日本語の校正(モデルに繋がりません…))   終了コード 3

**対称に2件出す。** 「問合せ→問い合わせ」だけを出すと直す先を指したことになる
(決めごと6)。互いを指させれば、断定していないことが目で見える。

#### 束ね方 — 骨格キー

送り仮名の揺れは形が決まっている。**漢字の骨は動かず、間と後ろの仮名だけが変わる。**
だから送り仮名を落とした骨(問合せ・問い合わせ・問合わせ → `問合`)で束ね、
束の中に書き方が2通り以上あれば混在と見る。形態素解析は要らない。

#### **骨格キーだけでは束ね過ぎた。** 実測して歯止めを足した

これは机の上では出てこなかった。骨格キーと「送り仮名は前から落ちる」だけの
最初の版を**この repo の日本語文書(26万字)に掛けたら 64 件**出て、
**大半が誤り**だった。青空文庫711作品を掛けると更に別の型が出た。

| 束ね過ぎの型 | 実際に出た例 | 足した歯止め |
|---|---|---|
| 活用の途中で切る | 取り込み/取り込(む) | 語の後ろに助詞でない仮名が続けば捨てる |
| 助詞で語を繋ぐ | 新製品発売/新製品**を**発売 | 送り仮名になる仮名(い段・え段)だけを繋ぎに認める |
| サ変名詞の活用 | 発売/発売**し**・確認/確認**し** | 漢字と漢字の**間**の送り仮名を要求する |
| 形容詞+名詞の句 | 若者/若**い**者・青空/青**き**空・同様/同**じ**様 | 送り仮名が い・じ・き で終わり、かつ最後の漢字が誰も送り仮名を持たないなら句と見る |
| 助詞の顔をした活用語尾 | 召し上/召し上**がる** | が・か・で の次が活用語尾なら捨てる |
| 歴史的仮名遣い | 思ひ出/思ひ出し・立ち給/立ち給ひし | ひ・ぢ・ぴ を送り仮名から外す |

**漢字1字の語は扱わない。** 上げる/上る のような別語を束ねてしまうし、
行う/行なう は 3(内閣告示)の担当。**骨格は漢字2字から。**

#### 測った結果

| コーパス | 大きさ | 指摘 | 密度 |
|---|---|---|---|
| `sample/` の実物の帳票・文書 10点 | 3,170字 | **0件** | — |
| この repo の日本語文書 17点 | 263,154字 | **11件** | 1件/24,000字 |
| 青空文庫 711作品 | 11,103,529字 | **298件**(出た作品 90) | 1件/37,000字 |

**当たり**: この repo の 11 件のうち**真は5件**(取消線/取り消し線・切替/切り替え・
一巡点検/一巡り点検・表示切替/表示切り替え・問合せ/問い合わせ)。
偽の6件は**全部おなじ1組**(置換/置き換え)が6文書に出た物で、
**語の組で数えれば 6 組中 5 組が真**。青空文庫は抽出68種を手で判定して**真41/偽27**。

文語と歴史的仮名遣いの分だけ青空文庫のほうが悪い。**的は現代の事務文書**なので
この差は想定どおりだが、数として残す。

#### 残っている誤検出は1種類 — 骨格が同じで**読みが違う**漢語と和語

置換(ちかん)/置き換え(おきかえ)、独身/独り身、溺死/溺れ死、通夜/通り夜。
切替(きりかえ)/切り替え と**構造がまったく同じ**なので、字面では切り分けられない。
分けるには常用漢字表の音訓が要る — **内閣告示なので使える**(決めごと3)が、
それは 3〜4 の仕事なので**いまは混在として出す**。断定していないので害は止まる。

見落とす側も書いておく。**問合せ先/問い合わせ先は出ない**(末尾が送り仮名を
持たない名詞なので、形容詞の歯止めに当たる)。引渡し/引き渡しました も出ない。
**誤検出は見逃しより重い**の側に倒した結果で、承知の上。

#### 引用と固有名詞をどうしたか — **鉤括弧を外さない**

決めごと6が言うとおり、引用の契約文言と本文とで送り仮名が違うのは正当に起こる。
だが**「」を除いてから掛けても、この repo の26万字で指摘は 11 件のまま動かなかった**
(1件も減らず、増えもしない)。日本語の「」は引用より**強調と用語の括り**に使う
ほうが圧倒的に多く、外すと真の指摘を落とすだけになる。だから**外さない**。
実例も出た — writer.ja.md の「置換」は Word の釦の名(固有名詞)である。
**混在として出し、どちらが正しいとは言わない**という決めごと6が、そのまま歯止めになる。


### 2〜4 の作り方を決めた(2026-08-10 発注者「3〜4 もやってしまいましょう」)

1(表記ゆれ)が形になったので残りを決める。**当初「3 と 4 は常用漢字表の音訓を
共通の土台にできる」と見ていたが、調べたら外れ**だった。`lang` に音訓の表は無く、
ふりがなは全てモデルに訊いている(`ja/furigana.rs` は候補の組み立てと解釈だけ)。
**3 と 4 に共通の土台は要らない。それぞれ独立に作れる。**

音訓の表が要るのは別件 — 1 に残った誤検出(置換(ちかん)/置き換え(おきかえ)の型)を
消すときだけ。**そのために表を起こすかは、4 が済んでから決める。**

#### 2 重複表現(`Kind::Wording`)

有限の一覧で足りる。頭痛が痛い・まず最初に・各位様・後で後悔・約〜程度。
**一覧は自分で書く** — 民間の校正基準を写さない(決めごと3)。

難しいのは語彙ではなく**許容の線引き**。「まず最初に」は重言だが日常的に使われ、
断定すると煩い。**指摘は出すが「誤り」と言わない**(1 と同じ作法)。

#### 3 送り仮名(`Kind::Okurigana`)

内閣告示「送り仮名の付け方」。**本則・許容・例外の3段があり、許容を誤りにしない**
(決めごと4)。行う/行なう はどちらも通る — **通則6の許容**であって誤りではない。
だから 3 が出せる指摘は狭い:

- **本則から外れ、許容にも無い形**(申込む→申し込む の類)
- **1つの文書の中で本則と許容が混在**している(これは 1 の仕事と重なる)

**狭くてよい。** 送り仮名を機械が断定すると、正しい文章に指摘が出て信用を失う。

#### 4 同音異義語の濾過器 — **これだけ性質が違う**

1〜3 は**指摘を出す**が、4 は**指摘を出さない**。モデルへ送る量を減らすのが仕事で、
出口は `Kind::Conversion`(誤変換)だがそれを決めるのはモデルのまま。

    いま      : 全文がモデルへ行く(辞書が何も落とせない)
    4 が入ると: 同音異義語を含む文だけがモデルへ行く

**表は音訓から計算しない。** 熟語の読みは連濁・音便で組み立てが効かない
(「一段」いちだん / 「値段」ねだん)。**紛らわしい組を直に書く** —
以外/意外、保証/保障/補償、対象/対照/対称、機会/機械、追求/追及/追究。
数百組で実務の大半を覆う。設計の「ペア表」はこの意味。

**効きは数で出す。** 「何 % の文をモデルに送らずに済んだか」を測ってから広げる。
測る土台は `lang/corpus/`(青空文庫)と `sample/`。**測る前に表を太らせない** —
表が大きいほど濾過器は効かなくなる(全部の文が何かに引っかかる)。

#### 進め方

**2 と 3 を先に、4 は後。** 2・3 はモデル無しで指摘が増える(利用者にすぐ効く)。
4 は流れを変えるので、1〜3 で `lang` の形が落ち着いてから触る。

### 2 と 3 を入れた(2026-08-10。`ja/wording.rs`・`ja/okurigana.rs`)

**1〜3 が揃った。モデルの居ない機械で出せる日本語の指摘は、これで3種類。**

| | 大きさ | 1 表記ゆれ | 2 重複表現 | 3 送り仮名 |
|---|---|---|---|---|
| `sample/` の実物の帳票・文書 10点 | 3,170字 | 0件 | **0件** | **0件** |

#### 3 送り仮名 — **狭い。狭いことが正しい**

内閣告示「送り仮名の付け方」は**本則・許容・例外の3段**なので、
「規則に無い=誤り」とは言えない。出せるのは2つに絞った:

- **本則でも許容でも例外でもない形**(少い→少ない、珍らしい→珍しい)18組。ここだけ直す先を言う
- **本則と許容が同じ文書に混ざっている**(行う と 行なう)16組。**どちらが正しいとは言わない**

**「行なう」は誤りではない**(通則1の許容)。「申込む」も誤りではない(通則6の許容)。
決めごと4のとおり、許容を誤りにしていないことは試験で縛った。
**「大い」は一覧に入れない** — 「大いに」は通則5の例外で正しいため。

青空文庫の686件は**戦前の表記**(新らしい121・珍らしい112・少い92…)で、
1973年の告示より前の文章だから出て当たり前。**的は現代の事務文書**で、そちらは
257,526字で**0件**。文脈を見て確かめた誤検出は1種類だけで、直した:

> 「腰かけに穴が**明いた**」は動詞の**明く**であって、形容詞の「明るい」ではない。
> 直後が「た/て」なら見送る。これで青空文庫の28件が落ち、残る9件は全部
> 形容詞(「明い昼中」「月が大きく明い」)だった。

熟語の一部も拾わない — 「ご説**明い**たします」「代**表す**る」「銀**行う**んぬん」は、
**前が漢字なら熟語**として見送る。

## 表オブジェクトと右横書き — 方針変更(2026-08-04 発注者)

**改訂: 表オブジェクトは「持たない」から「持つ」へ。** 範囲に変換・
サイズ変更は表そのものが無いと成り立たない(名前の付いた範囲を外す・
広げる、という仕草)。`sheet::model::TableDef`(名前・範囲・見出し/合計/
縞々/最初/最後/フィルタ)を持ち、`xl/tables/tableN.xml` + worksheet の
tableParts + rels + Content_Types と往復する。**見た目は書式のまま** —
表を外しても帯や縞々は残る(Excel と同じ。「書式は据え置き」の掟にも合う)。
表を減らしたときは部品も宣言も消す(残すと Excel が「壊れている」と言う)。

**改訂: 右から左を「日本の事務では使わない」と言わない。**
日本語も右から書くことがある(右横書き — 昔の看板・横額・のれん)。
- **シートの方向**(`Sheet.rtl` ↔ sheetView rightToLeft): 列を右から
  並べる。実装は `visible_cols()` を逆順にする一点だけ — 描画も当たり
  判定もこの関数を通るので、見える場所と掴む場所がずれようがない
- **文字の向き**(`CellFormat.rtl_text` ↔ alignment readingOrder="2"):
  セルの中を1字ずつ右から並べる。**日本語の右横書きのための実装**で、
  ラテン文字の bidi(双方向)は扱わない — そう言って出す

## 日本語一級(K4)— 均等割付・ルビ・縦書き(2026-08-04 発注者「やってみて」)

紙面が**1字=1セル(x_mm 持ち)**なのが効いた — 3つとも「セルの置き方」の
話に落ちる。描画側は置かれた座標のとおりに出すだけ。

- **均等割付** = `Align::Distribute`。docx の `w:jc distribute` と往復
  (いままで両端揃えに丸めていた)。行の余りを字間に等配し、**最後の行も
  配る**(両端揃えとの違い)。描画は「同じ書式の連なりを1本で描く」を
  **x が飛んだら切る**よう改良 — 画面・PDF とも座標が正
- **ルビ** = `CharFormat.ruby: Option<String>`。field と同じ場所に持つ —
  run の切り貼り(分割で降ろす・同型は合流)の道具立てがそのまま効く。
  組版は基底の上(行送りの黄金比の余白の中)に**半分の大きさの行**
  (from_body=false)を置く。狭ければ中付きで等配、広ければ中央から
  はみ出す(基底を広げる詰めは残件)。docx は `w:ruby`(rubyPr/rt/
  rubyBase)と往復。基底が行で割れると読みが両方に付く(残件)。
  UI はホームの「ルビ」ボタン → パネルで読みを打って Enter(空で外す)
- **縦書き**(実装済み 2026-08-04): docx は sectPr の
  `w:textDirection w:val="tbRl"` と往復。組みは**変換方式** —
  行長 = 紙の縦の使い幅で普通に(横に)組み、できた行を
  「行 k → 右から k 本目の列」へ写す(fold_columns と同じ考え方)。
  Line.y_mm に列の x、Cell.x_mm に上からの距離を持たせ、Sheet に
  vertical の旗 — 描く側(画面・PDF)は旗を見て1字ずつ置く。
  約物は写すときに縦用の字形(、→︑ 。→︒ ー→縦棒 「」→﹁﹂ など)へ
  置換。ASCII の横倒しは初版ではしない(1字ずつ縦に積む)と正直に言う。
  クリック・キャレット・選択の当たり判定も旗で転置済み(キャレットは
  横棒)。実装は Line を変えず Sheet に vert_x(行ごとの列の x)を持たせた
  — 全指定 literal を割らない。ホームの「テキスト方向」で入切。
  初版の約束(status でも言う): 表・段組みは縦にならない、ASCII は
  1字ずつ縦に積む(横倒しはまだ)、変換下線は出ない、
  明示の改ページは列送りに畳まれる。LibreOffice が開けることを実地確認済み



Linux 前提で作ってきたが、**Mac 版も作る**。同じ writer / calc の移植なので
「新しいバイナリは作らない」の掟には触れない。ソースで裏を取った現状:

- **自作コード(engine / ooxml / sheet / lang / paper / ui / writer / calc)に
  OS の分岐は一つも無い**(`cfg(target_os)` 不使用)。素の Rust
- フォント探索(`engine/src/font.rs`)は最初から `/Library/Fonts`・
  `/System/Library/Fonts`・`~/Library/Fonts` を見る。ttc も読めるので
  ヒラギノはそのまま拾える見込み
- GPUI は Zed の母国が Mac(Metal)。GPU 描画・IME はむしろ本場。
  rfd のダイアログもネイティブに出る。排他ロック(`.~lock.名前#`)は
  ただのファイル操作でそのまま動く。`.linklibs/` の回避策
  (libxkbcommon-x11)は Linux 固有で、Mac では不要
- **唯一の本物の穴はサンドボックス。** bubblewrap は Linux 専用で、calc は
  `/usr/bin/bwrap` を直に見ている。いまのまま Mac で組むと、`@名前`
  (ブック搭載コード)と `=PY`/`@計算` は「サンドボックスがありません」で**正しく
  拒否される**(未移植でも嘘はつかず、安全側に落ちる)。一行コードと
  .py 選択実行は動く(深層防御が効かないだけ)

方針: Mac のサンドボックスは Seatbelt(`sandbox-exec`)で**同じ4条件**を組む —
網の遮断・実ファイルは読み取り専用・ホームは不可視・書けるのは交換用の
一時領域だけ。`@名前 net` の段階制(許可は毎回の明示の操作、ブックには
保存されない)もそのまま。実装はサンドボックスの組み立てを1箇所に集め、bwrap と
sandbox-exec を裏で差し替える形にして、4条件は両 OS 共通のテストで
突き合わせる。sandbox-exec は Apple が非推奨と言い続けているが現行
macOS で動く — 使えなくなったらそのときに考える。**サンドボックスが組めない環境では
今までどおり実行を拒否する**(黙ってサンドボックスなしに落とすことはしない)。
