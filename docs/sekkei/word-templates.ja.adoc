= Word のテンプレートを英語版と日本語版で突き合わせる(2026-09-19)

発注者「word のサンプルを英語版と日本語版で全てやってみるのはどうか」「落とす手段と置き場を Fable が考えろ」「実装は Opus に任せろ」「結果は、Web ページでギャラリーとして見せること」。

== 落とす手段(調べた結果)

Word の「新規」の一覧は、Microsoft の公開ギャラリー(`https://word.cloud.microsoft/create/<言語>/<種類>-templates/`)と同じ物を出しています。言語は `en`(英語)と `ja`(日本語)で、ファイルは公開の CDN にあります。

* 一覧の頁(例: `https://word.cloud.microsoft/create/en/resume-templates/`)の HTML に、テンプレートごとの「Word で開く」のリンクがあり、その `src` に docx の URL が入っています。
* docx の URL は `https://createcatalog.public.onecdn.static.microsoft/catalog-assets/<en-us|ja-jp>/<GUID>/TF<GUID><ハッシュ>_wac-<ハッシュ>.docx` の形です。ハッシュは頁から読むしかありません。
* **同じ GUID が英語版と日本語版の両方にあります**(確かめた物: `ce343500-4aff-4dfa-b337-57c78459c6ee` は en-us 100KB、ja-jp 6.4MB)。だから「同じテンプレートの英語版と日本語版」を組で集められます。
* サムネイルも同じ CDN にあります(`…/<GUID>/thumbnails/564/…`)が、使いません(下の「見せ方」)。
* 古い配信(`omextemplates.content.office.net/support/templates/<言語>/tf<番号>.dotx`)は言語ごとに番号が違い、日本語版が無い物が多いので使いません。

== 置き場

`~/Documents/officework-cmp/templates/` の下に、git の外で置きます(Microsoft の著作物なので配りません。試験に使うだけです)。

----
templates/
  目録.tsv            GUID、種類、英語の題、日本語の題、en の URL、ja の URL、落とした日
  en-us/<GUID>.docx   英語版
  en-us/<GUID>.ms.pdf Word で刷った PDF(tools/ms_pdf.py)
  ja-jp/<GUID>.docx   日本語版
  ja-jp/<GUID>.ms.pdf
----

== 道具(Opus が作る)

. `tools/templates_fetch.py` — 一覧の頁を種類ごとに読み、GUID と docx の URL と題を集め、英語と日本語の両方にある GUID だけを落として `目録.tsv` を書く。`--kinds resume,letter,report,...`、`--limit 30`。落とすときは 1 秒に 1 つ、User-Agent を付ける。落とし直しは `--force` のときだけ。
. `tools/templates_round.py` — 目録の docx を Word で PDF にし(tools/ms_pdf.py を使う。開いた物は閉じる)、うちで刷り、頁数と行の位置を比べて `結果.tsv` を書く。役所の様式の集計(スクラッチの pages_sweep.py)と同じ形。これを機に、頁数の集計は tools に入れる(`tools/pages_sweep.py`: 集めのフォルダを引数で受ける)。
. `tools/templates_gallery.py` — 結果からギャラリーの Web ページを作る。`web/gallery/index.html`(普通の HTML。読む頁なので Flet ではない)と、`web/gallery/<GUID>-<言語>-{word,ours}.png`(1 頁目を 60dpi で)。1 枚のカードに、題(英語と日本語)、種類、頁数(Word / うち)、一致の印、Word とうちの絵を横に並べる。並びは「一致していない物が先」。頁の頭に、日付と、一致した数 / 全部の数。

== 見せ方(決めてもらう物)

ギャラリーには Word の描いた絵(Microsoft のテンプレートの見た目)が入ります。**公開してよいかは発注者が決めます。** それまでは手元で見る物として作ります(`web/gallery/` は .gitignore に入れる)。公開するなら、絵を小さくし、各カードから Microsoft の元の頁へリンクを置きます。

== 種類の候補(最初の 30 種)

履歴書(resume)、送付状(cover-letter)、手紙(letter)、レポート(report)、議事録(minutes)、議題(agenda)、メモ(memo)、請求書(invoice)、見積書(quote)、領収書(receipt)、パンフレット(brochure)、チラシ(flyer)、ポスター(poster)、ニュースレター(newsletter)、カレンダー(calendar)、予定表(planner / schedule)、名刺(business-card)、証明書(certificate)、案内状(invitation)、はがき(postcard)、ラベル(label)、しおり(bookmark)、家系図(family-tree)、履歴(timeline)、企画書(proposal)、契約書(contract)、履歴書(CV)、封筒(envelope)、賞状(award)、メニュー(menu)。一覧の頁の URL は `/create/<言語>/<種類>-templates/` で、無い種類は飛ばす。

== 進め方

. Opus が 3 つの道具を作り、英語 30 種・日本語 30 種を落として 1 回目の突き合わせを回す(この Mac。Word が要る)。
. 結果のギャラリーを発注者が見て、公開するかどうかと、直す順を決める。
. 直すのは Fable(原因は OOXML と Word の PDF で確かめる。推測で直さない)。

`open "パス"` ではなく `open file name "パス"` と書くと文書が開きました。`close` は

== 2 回目の結果(2026-09-19)

Word のテンプレートが Word と同じように刷れるように、エンジンを直しました。

=== 直した所

* 大文字にする文字書式(`w:caps`)を読んで、組むときに大文字にします。書き出しでも
  `<w:caps/>` を出します。
* スタイルの `w:rPr/w:spacing`(字間)と、スタイルが指す `w:asciiTheme` /
  `w:eastAsiaTheme` を読みます。テーマの書体は theme1.xml で調べます。
* スタイルに段落前後の空きが書いてあれば、docDefaults の空きで上書きしません。
  スタイルが 0 と言っている段落が、既定の空きで下がっていました。
* 表のセルの中だけで使われているスタイルも、テーマを組み立てるときに集めます。
  表の中でしか使われていない Title が標準に落ちて、36pt が 10pt になっていました。
* 半角英数の run には、スタイルの `w:ascii` の書体を使います(ECMA-376 17.3.2.26)。
* 表の `w:jc`(中央・右)を読んで、本文の幅より狭い表を中央か右に寄せます。
* 表のセルの中の画像を組みます。段落の先頭の画像はその行のベースラインに載せ、
  後ろの画像は自分の行に置きます。
* 画像の関係先が `/word/media/image1.jpeg` のように先頭の `/` から書いてあっても
  読めるようにしました。Word のテンプレートはこの書き方です。
* 1 行の高さを、書体の hhea(USE_TYPO_METRICS があれば OS/2 の typographic)から
  出すようにしました。前は OS/2 の Windows の値の足し方を間違えていて、表に無い
  書体はすべて 1.0em に丸められていました。Word の PDF で測ると Bookman Old Style は
  1.174em、Source Sans Pro は 1.257em で、hhea と一致します。
* Office が後から落としてくる書体の置き場
  (`~/Library/Group Containers/UBF8T346G9.Office/FontCache/4/CloudFonts`)も探します。

=== 今回このセッションで足した直し

行の高さの直しを入れたところ、役所の様式の集計が 258 件から 226 件に落ちました。
原因を 3 つ見つけて直しました。

. **半角の送りを差し替えた run の書体名が、測った表に当たらなくなっていました。**
  この run の書体名には `#hankaku=0.5` という文字列が付きます。これを外さずに調べていたので、
  ＭＳ Ｐ明朝が 1.292em ではなく代替の書体の 1.5em になり、空の段落が文字グリッド 2 行分の
  高さになりました。調べる前にこの文字列を外すようにしました。
. **游明朝と游ゴシックの行の高さを測って表に入れました。** 書体の hhea は 1.602em ですが、
  Word は 10.5pt の行の高さを 15.98pt にします(JETRO の様式。文字グリッドなし、PDF の
  11.04pt に対して 16.8pt)。既定の書体が游明朝の文書に Word 自身が書く `w:docGrid w:linePitch` も
  315(15.75pt = 10.5pt の 1.5 倍)です。表の値は 1.5em にしました。
. **浮いている図は本文の流れの中で場所を取りません。** VML の `position:absolute` と、
  DrawingML の `wp:anchor` + `wp:wrapNone` は、本文の後ろか横に置かれる図です。
  これを行として組んでいたので、履歴書 ce343500 の日本語版は 1 頁目が真っ白になり、
  本文が 2 頁目に押し出されていました。読むときに落とすようにしました。
  `w:object`(表計算の貼り付け)には `position` が無いので、今までどおり場所を取ります。

**空の段落 2 つぶん**(1 つめの前の空き・行・間の空き・行・最後の後の空き)で
3 件とも 1.1pt 以内に合います。行と空きは既定の段落スタイル(Normal)の値です。

`25409d45` を詳しく見ました。この型紙は `headerReference w:type="default"`
を書いていますが、`word/_rels/document.xml.rels` にヘッダーの関係が無く、
部品も入っていません(参照だけが残った形)。Word の PDF のヘッダーの所には
字も図形もありません。必要な押し下げは 15.95pt(Word の 1 行目 96.96pt、
うち 81.01pt)で、既定のスタイルの段落**1 つ**(14.83pt)に近く、2 つ
(51.7pt)では行き過ぎます。参照が無い 3 件は 2 つぶん、参照だけがある
この 1 件は 1 つぶん、という形です。

**空の段落 2 つを取る形を入れて測りました(2026-09-22)。**合う 3 件は
1.1pt 以内に入りますが、ほかが大きく下がります。

本当の原因はこの本文の始まりの方です。47.5pt の出どころが分かったら、
両方まとめて直します。

=== 作り替えが要る物

一度にまとめてやる物です。

* 段落の途中や末尾にある `wp:inline` の絵を、行の中に置く
  (`1138bdc2`。engine/src/layout.rs は段落の頭の絵だけを行に置きます)
* テキストボックスの番号(`0a7ba299`)
* 小数点の止まり位置(`w:tab w:val="decimal"`。ECMA-376 17.3.1.37)。
  中央・右と点線の引き出しは 2026-09-21 に入れました(`4bbce413`、
  `5d5ea8ff`)。小数点は読みますが、置き方は左のままです
* 段落番号の形(`w:numFmt`。ECMA-376 17.9.17)。いまは行頭文字と算用数字の
  2 つだけで、ローマ数字や丸数字は出せません(`e22e6b47`)
* 図形の絵の塗りの差し込み(`a:stretch` の `a:fillRect`。ECMA-376
  20.1.8.30)。箱の外へ広がった絵を図形の形で切り抜く所が要ります
  (`9fd05068`)
* `Line` に行の箱の上端と高さを持たせる。いまは腰(`y_mm`)だけなので、
  フッターの下端を `w:pgMar w:footer` に合わせられません(`7e53ee0d`。
  上の表に 2 つの文書・4 か所の実測があります)。ヘッダー・フッターが本文を
  押す高さ(`hf_push_mm`)も、いま段落ごとに `字の大きさ x em` で出していて
  `w:spacing w:line` を見ていないので、同じ所で直せます
* 図形の中の字を画面にも出す(`0a7ba299`)。紙は `paper::grid::zukei`
  が図形と字の両方を書き、画面は `SheetShape::to_svg` が形だけを書きます。
  画面も紙と同じ道を通すようにします
