== 蒸留の作法

openpyxl のときと同じです。

* 写すのは、記法の意味と試験です。
* Ruby の実装は写しません。asciidoctor を実行時に同梱することもしません。
* 本家は「読む半分」と「出す半分」に分かれています。うちが写すのは読む半分だけです。HTML や DocBook の出し方は写しません。

本家の試験は HTML の文字列で答えを確かめます。
うちは run の並びで確かめます。
たとえば本家のこの試験は、

----
入力:  *a few strong words*
本家:  <strong>a few strong words</strong>
----

うちではこう読み替えます。

----
runs: [ bold "a few strong words" ]
書き戻し: *a few strong words*(入力と同じ字)
----

書き戻しの行は本家に無い確認です。
本家は adoc を読んで出すだけの一方通行ですが、writer は視覚エディタなので、読んだものを adoc に書き戻して字を変えないことが要ります。
写す試験には全部、この書き戻しの確認を足します。

== 本家の約束: 開きと閉じの位置

往復で字が変わる 78 枚の原因は、うちの読み手が `*` と `_` を見つけるたびに強調を入り切りしていることでした。
本家の約束は `lib/asciidoctor.rb` の `QUOTE_SUBS` にあります。
普通の言葉にすると次のとおりです。

一重の印(`*字*` `_字_` `` `字` `` `#字#`)は条件つきです。

* 開きの印の直前は、行の頭か、文字でない字です。`;` `:` `}` も直前には来られません。等幅だけは `"` `'` `` ` `` も直前に来られません
* 中身は空白で始まらず、空白で終わりません
* 閉じの印の直後は文字ではありません。等幅だけは `"` `'` `` ` `` も直後に来られません
* 「文字」は Unicode の word 文字です。日本語の字も文字です

二重の印(`**字**` `__字__` ```` ``字`` ```` `##字##`)は条件がありません。
どこにあっても、次の同じ二重の印までを囲みます。

上付き `^字^` と下付き `~字~` は空白をまたげません。

`\` を印の前に置くと、その印は字になります。

探す順も決まっています。
二重の太字、一重の太字、二重の等幅、一重の等幅、二重の斜体、一重の斜体、二重のマーク、一重のマーク、上付き、下付きの順です。
先に見つかった方が勝ちます。

役割は `[.名前]#字#` の形のほか、`[.名前]*字*` のように他の印にも付きます。
うちの `style_id` に載せます。

== うちの読み手がいま外していること

`engine/src/adoc.rs` の `parse_inline_cont` を本家の約束と比べました。

* 一重の `*` `_` を、直前と直後を見ずに入り切りしている。`README-de_DE` の `_` が斜体の開きになる
* `**` を「`*` が2回」として読み、入り切りが2回になって消える
* `#字#`(マーク)を読んでいない。`CharFormat::highlight` に載せられる
* `"`字`"` `'`字`'`(曲がった引用符の印)を読まず、中の `` ` `` を等幅の開きと取る
* `+++字+++` `++字++` `pass:[字]` を読まない。中の `*` が太字になる
* `\*` の逃がしは読めるが、`\**` の二重の逃がしは1字しか逃がさない
* mailto と裸のメールアドレスを読まない(字として残るので往復は壊れない)

書く側(`should_double` と `esc`)は本家の約束をすでに部分的に入れています。
読む側がそれに追いつけば、往復が閉じます。

== やった結果(2026-09-02)

=== 読み手を本家の順に作り直した

`engine/src/inline.rs` を新しく作りました。
本家の `sub_quotes` と同じで、段落の字をまるごと1つにして、決まった順に置き換えます。
順は passthrough、太字(`**` `*`)、引用符、等幅、斜体、マーク、上付き、下付きです。
置き換えの結果は私用領域の字を印にした文字列で、最後に run の並びへ直します。
マクロ(`footnote:[]` `ruby:[]` `field:[]` リンク `<<>>`)はその最後の段で読みます。

このために、段落の読み方も変えました。
前は1行ずつ読んで強調の状態を次の行へ持ち越していました。
いまは継ぐ行を貯めて、段落の終わりでまとめて読みます。
一重の印の「直前が字でない・直後が字でない」という条件は、行をまたいで効くからです。

=== 書き手は自分で読み直す

本家の `\` は「次の印は字です」と言うためのもので、印として読まれない `*` の前に付けると `\` がそのまま読者に見えます。
なので書き手は、全部の `*` に `\` を付けることができません。
代わりに、書いた1行を自分で読み直し、意図した run の並びと違うところにだけ `\` を足します(`inline::settle`)。
`\` は1つ、だめなら2つ試し、あとで要らなかった物を外します。

印の数も本家の条件で決めます。
外側の隣が字か、中身が空白で始まるか終わるときは、二重の印にします。
役割は、その run だけで開いて閉じる太字か斜体の印に付けます(`[.path]_径路_`)。
太字・斜体・等幅は開いた逆順に閉じます。
蛍光ペンは本家のマーク(`#字#`)で書きます。色は運びません。

== 第2歩: リンクと参照と字の基本(2026-09-02)

=== 本家の試験の入力は、試験を読み込んで記録した

`links_test.rb`(173 本)と `text_test.rb`(29 本)は入力の形が様々で、手で写すと写し間違えます。
そこで Ruby で本家の試験のファイルをそのまま読み込み、`convert_string_to_embedded` などの呼び出しをその場で記録して、入力の文字列だけを取り出しました。
答えは Quotes と同じで、本家を実際に動かして取りました。

写したのは、属性や backend の指定が無く、1つの段落になる入力だけです。
節や複数の段落が要る物(参照の解決・見出しの題を字に使う物など)は `SKIPPED` に名前と理由を残しました。

=== 読み手に足したもの

* 裸の URL(`https://` `http://` `file://` `ftp://` `irc://`)。直前が行頭・空白・`<`・`>()[];"'`・印のときだけリンクです。末尾の `,.?!)` は URL に入れず、`;` `:`(とその前の `)`)も外に出します(本家の `InlineLinkRx` と `sub_macros` の写し)
* `<URL>`(`>` で閉じる物だけ)、`link:対象[字]`(対象は空でもよい)、`URL[字]`
* リンクの `[…]` の中に `=` があれば属性の並びとして読み、最初の名前無しの項目を字に、`role=` を役割にします
* `<<名前,字>>` と `xref:名前[字]`。頭の `#` は名前に入れません
* 段落の中の ` +` の改行。字の中の改行として持ち、書くときに ` +` に戻します

リンクや参照の字の中の書式(`` xref:a[`b` c] ``)は run 1つに書式1つなので持てません。
落とす代わりに、`` `b` `` のような元の形の字として残します。
本家はそれを再び書式として組むので、本家の出力は変わりません。

=== 書き手に足したもの

* 字と URL が同じなら裸で書きます。ただし直前が `<` のときと、次の字が空白か `,.?!);:` でないときは `URL[]` の形です(裸だと後ろの字を飲み込む)
* 参照は `<<名前>>`、字が違えば `<<名前,字>>`。名前が URL やパスの形(`://` `/` `.` `#` `:` `{`)なら `xref:名前[字]` です。`<<page.adoc,字>>` を本家は別の文書への参照と読まないので、元の形を保ちます
* リンクの字の `]` は `\]` に、`\` は `+\+` に包みます
* 自己確認(`settle`)は、`*` などの印の位置に加えて、URL やマクロの頭の位置でも `\` を試します(`\http://…` を字のまま返すため)
