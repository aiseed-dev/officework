= 描画一覧・Flet の部品・PDF と xlsx の出力
:toc:

作る側の資料です。発注者の仕様書「officework 描画一覧・Flet表示部品・PDF出力
仕様書」(2026-09-24)を検討し、決めたことを書きます。

== 目的

様式の決まった文書(履歴書・見積書・請求書)を、画面で見て、欄を直し、同じ見た目の
PDF にできるようにします。aiseed office(gpui)より先に、Flet の部品として出します。

作らない物は仕様書のとおりです。流れる文章の自由な編集、大きな表、スマホでの入力、
gpui と Flet の間の埋め込み、aiseed office の完成です。

== 決め(2026-09-24 発注者)

* 組版はエンジンで一度だけ行い、画面(Flet・gpui)と PDF は同じ描画一覧から描きます。
* 書体は BIZ UD ゴシック・明朝に固定します。こちらで作る様式に使います。受け取った
  docx・xlsx は、今までどおり文書の書体で組みます。
* 履歴書は、厚生労働省の「履歴書様式例」(2021-04-16 公表)を基本にします。
  JIS 様式の履歴書も作れるようにします。
* データは adoc に置きます。出力は xlsx と PDF です。
* Flet の部品は別のパッケージにし、Python だけで作ります(ライセンスは AGPL)。
* 描画一覧の形は当面 0.x とし、変わることを明記します。

== 組み立て

[source]
----
データ(adoc)──────┐
                   ├→ ブックの模型 ─┬→ 描画一覧 ─┬→ Flet の部品(画面)
様式(テンプレート)─┘               │            ├→ PDF
                                   │            └→ aiseed office(gpui)
                                   └→ xlsx
----

欄を直したら、その変更を命令としてエンジンに戻し、返ってきた描画一覧で描き直します。

== 既にある物

描画一覧に当たる物は、エンジンに `paper::pdfw::Leaf` として既にあります。今は、
これから PDF(`paper::pdfw`)、PNG(`paper::e`、vello)、表計算の画面の図形を
描いています。

[cols="1,2,1"]
|===
|仕様書の項目 |今の `Leaf` |状態

|ページの大きさ |`size_mm` |あり
|線と曲線、塗り |`rules`(罫線。破線の刻みあり)、`fills`(四角)、`polys`(多角形)、`paths`(曲線と切り抜き)、`z`(重なりの順) |あり
|文字(折り返しはエンジンが決める) |`pieces`(位置・大きさ・色・書体の番号・太字・下線) |あり
|画像 |`images`(位置・大きさ・中身のバイト列) |あり
|欄の一覧 |無し |足す
|Python へ渡す形 |Rust の中だけ。Python からは PDF と PNG だけが取れる |足す
|===

表計算のエンジンは、セルの格子から `Leaf` を作ります(`paper::grid::sheet_leaf`)。
xlsx の書き出し(`sheet::xlsx::write`)も同じブックの模型から書きます。adoc と
ブックの行き来は `engine/src/book_adoc.rs`、見た目を分けて持つテンプレート
(`.tmpl.adoc`)は `engine/src/booktmpl.rs` にあります。PDF を描画一覧から書く
(仕様書の手順 3)は、今の PDF の作りそのものです。

== 決める物

. *描画一覧を外に出す形。* `Leaf` は PDF と同じく左下からの mm です。外に出す形は
  左上が原点にし、単位は pt(または mm)にします。換算はエンジンでします。描く側が
  計算しない、という仕様書の決まりに合わせるためです。書体は、名前とファイルの一覧を
  載せ、Flet にも同じ書体ファイルを登録させます。
. *文字の置き方。* `pieces` は、行を分けた後の字の並びの始まりの位置です。Flet
  (Flutter)が同じ書体で並べても、字の送りがエンジンと少し違えば、行の終わりが
  ずれます。字ごとの位置も載せられるようにしておき、履歴書 1 枚で「並びの位置だけ」と
  「字ごとの位置」を比べて決めます。
. *欄の一覧の出所。* 欄の名前と位置をどこで決めるかです。データの adoc の欄の名前と、
  テンプレートのセル(結合した範囲)に付けた名前を結びます。docx の記入欄(`sdt`)の
  扱いとそろえます。
. *履歴書のデータの adoc の形。* 決まりました(下の「履歴書のデータの形」)。
. *描く物の数。* 今の履歴書の 1 ページには、罫線が約 580 本あります(セルの辺ごとに
  1 本)。Flet の Canvas で遅いときは、一直線に続く辺をエンジンでつないで渡します。

== 履歴書のデータの形(2026-09-24 発注者)

データは表のブック(`名前.sheet.adoc`)で書きます。見本は
aiai リポジトリの `rirekisho/履歴書.sheet.adoc` です(架空の人です。2026-09-25 に
officework の `sample/rirekisho` から aiai へ移しました)。

* 題は `= 履歴書`。題はブックの題になります
* `:様式:` に `厚労省` か `JIS` を書き、使う様式を選びます
* 表は 4 つです。今のブックと adoc の行き来で、1 つの表が 1 つのシートになります
** 「基本」:2 列(欄の名前、値)。日付、ふりがな、氏名、生年月日、性別、郵便番号、
   現住所ふりがな、現住所、電話、連絡先、写真(画像のファイルの名前)
** 「学歴・職歴」:3 列(年、月、内容)。1 行目は見出し
** 「免許・資格」:3 列(年、月、内容)。1 行目は見出し
** 「自由記入」:2 列(欄の名前、値)。志望の動機など、本人希望。長い文はセルの中で
   改行します(行末の ` +`)
* JIS 様式にだけある欄(通勤時間、扶養家族数、配偶者、配偶者の扶養義務)は、
  「基本」の表に行を足したときだけ使います。性別は、厚労省の様式では書いても
  書かなくてもよい自由記入で、JIS 様式では男・女から選びます
* 年齢は、生年月日と日付から計算するので、データには書きません
* 様式(穴つきの枠)は `履歴書-厚労省.form.adoc` と `履歴書-JIS.form.adoc` の名前に
  します(二重の拡張子の決まり。SEKKEI「ファイルの名前」)

今のエンジンで、この見本が 4 つのシート(11 行、8 行、3 行、2 行)として読めて、
`:様式:` の値とセルの中の改行も残ることを確かめました。その際、文書の題を
「表の外の段落」として落とした数に入れていたのを直しました(題はブックの題に
入るので、落としてはいません)。

== 様式と差し込み(2026-09-24)

様式は表のブックで書きます。値を入れるセルに `{氏名}` のような印を置きます。
罫線や字の大きさなどの見た目はテンプレート(`名前.tmpl.adoc`)が持ち、様式の
`:template:` の行でテンプレートの名前を指定します。

* 印の書き方は `{名前}`、`{名前.年}`(`.月`、`.日` も同じ)、`{名前.元号}`・`{名前.和暦年}`
  (令和、8。元号の最初の年は「元」。2026-09-25)、`{名前.時間}`・`{名前.分}`
  (`1時間10分` と書いた値の時間・分)、`{年齢}`、
  `{表の名前.N.列の名前}`(表の N 行目)、`{名前.N}`(値の N 行目)です。
  年齢は生年月日と日付から計算します
* 選択肢は `{性別:男 ・ 女}` のように、名前の後ろに選択肢を「・」で区切って書きます
  (2026-09-25 発注者)。セルには選択肢を書いたとおりに(空白も含めて)出し、データの
  値と同じ選択肢を楕円で囲みます。囲む位置はエンジンが測ります。埋めたブックを一度
  組み、選んだ字が置かれた四角を紙の組み方から受け取り、その四角を少し広げた楕円の
  図形をセルに留めて足します。図形なので、PDF、描画一覧、xlsx のどれにも出ます。
  描画一覧では種類が `choice` の欄になり、`options` に選択肢が並びます
* チェックボックスは `{送達場所=住所}` のように書きます(2026-09-25)。データの値が
  その選択肢なら ■、違えば □ を出します。☑ は日本語の書体に無いことが多いので
  使いません。同じ名前の □ は、まとめて 1 つの `choice` の欄になります
* 1 つのセルに印をいくつ置いてもかまいません。印の外の字はそのまま残ります
* データに無い印は空になります。名前がデータに 1 つも無いとき(書き忘れや
  打ち間違い)は、空にしたうえで警告を出し、`missing` に並べます。表の行が
  足りないときと、値が空のときは、黙って空にします(2026-09-25 発注者)。
  文書の `render` は印を残して報告します。表の様式は行の数が決まっていて、
  使わない行の印を残せないので、空にします
* Python では `Book.fill(様式, データ)` で埋めたブックができ、`save` で xlsx、PDF、
  PNG に書き出せます。`fields()` は欄の一覧(シート、セル、印の名前)を返します

厚労省の様式は aiai の `rirekisho/履歴書-厚労省.form.adoc` と `.tmpl.adoc` です。
aiai の `python rirekisho/make_forms.py 元の.xlsx` で(2026-09-25 に Rust の例から
Python に書き直して移しました。出る様式は 1 字も変わりません)、
厚労省の xlsx から作り直せます。このスクリプトは次のことをします。

* 書体を BIZ UD 明朝・ゴシックに置き換えます
* 行の高さを 0.881 倍にし(合計 836pt → 729pt。0.75pt 刻み)、印刷の倍率を 100% に
  します。A4 の印刷できる高さ(759.7pt)に収まります。「ページに合わせる」はまだ
  設定していません
* 102 の欄に印を置きます。学歴・職歴は左のページに 15 行、右のページに 7 行です
* 志望の動機などの欄は、折り返して全体を表示し、上に揃えます

文書の様式(Word の申請書・届出書)も、同じ印で埋めます(2026-09-25)。
`kumihan::fill::fill_form` が、段落・表のセル・テキストボックスの印を、データのブックから
埋めます。Word が印を書式の区切りで分けていても、1 つの印として読みます。Python では
`doc.Doc.fill_form(様式, データ)` です。

* 欄の位置:埋めた文書を PDF と同じ組み方で組み(`paper::doc_pages`)、答えの字が
  置かれた四角を `pdfw::text_spots` で受け取ります。本文の段落は本文の中の位置で、
  表のセルは(表の番号, 行, 列)とセルの中の位置で引きます。`Doc.draw_list()` の
  `fields` に入ります。答えが空の欄は、その後ろの 1 字の四角にします
* 文の中の選択肢の丸:選ばれた字の四角を同じように受け取り、少し広げた楕円を、
  そのページに貼り付く図形として足します
* 別紙:データの表の行が、様式に印のある行より多いときは、入らなかった行を別紙に
  同じ列で続けて書きます(2026-09-25 発注者)。別紙に `{表.23.列}` のような印を置いた
  様式を足してから埋めるので、欄の位置も書き忘れの警告も同じに効きます。表の様式では
  「別紙」のシートを足し、列の幅・書式・行の高さを様式のその列のセルから写します。
  文書の様式では、改ページして別紙の表を足し、様式の表の列の幅と段落の書式を写します
* 下線の空欄:Word の様式は、下線を付けた空白で空欄を作ります。様式を作る人は、空欄の
  空白を消さずに、頭に印を打ちます(`{氏名}＿＿＿＿`)。埋めるときは、答えの幅の分だけ
  印の後ろの空白を消し、下線の長さを保ちます。幅は全角を 2、半角を 1 と数えます。
  下線の付いた空白は、run が分かれていても続けて数えます。空白が足りなければ、下線は
  答えの分だけ伸びます。下線の無い run では空白を消しません(「{宛名}　様」の空白の
  ように、わざと空けている所を詰めないため。2026-09-25)

JIS 様式は `履歴書-JIS.form.adoc` と `.tmpl.adoc` です。同じスクリプトが、厚労省の
様式を元に組み替えて作ります(2026-09-25)。

* 性別の欄を `※{性別:男・女}` にします
* 志望の動機の欄を左に寄せ、右に「通勤時間」(`約　{通勤時間.時間}　時間　{通勤時間.分}　分`)、
  「扶養家族数(配偶者を除く)」(右に寄せた「人」)、「配偶者」「配偶者の扶養義務」の欄を
  置きます。配偶者と扶養義務は `※有・無` の選択肢です
* 写真欄に大きさ(縦 36～40mm、横 24～30mm)を書きます
* 1 ページ目の下の注記を、JIS の「記入上の注意」(2 行)に替えます
* 欄は 106 です(厚労省の様式の 102 に 4 つ足しました)

JIS の写しとして、厚生労働省「新たな履歴書の様式例の作成について」の 3 ページ目に
載っている「(参考)従来の履歴書様式例(JIS 規格の履歴書様式例)」を使いました
(https://kouseisaiyou.mhlw.go.jp/assets/pdf/methods/04.pdf)。欄の名前、欄の中の字、
記入上の注意の文と置き方を、この写しと突き合わせて合わせました(2026-09-25)。

見本のデータで埋めて、PDF と xlsx が 2 ページで出ることを確かめました。書き出した
xlsx を開き直して描くと、埋めたブックの描画と同じになります(写真欄の点線の端の
5 画素だけが違います)。このとき、次の不具合を直しました。

* adoc の表で、縦と横の両方に結合したセルの書き方が AsciiDoc の決まり
  (`3.2+|`、横の数.縦の数)と違っていました。読む側も、縦の結合が下の行で占める幅を
  1 列として数えていたので、セルが左にずれていました
* 図形の文字の段落の頭の `{empty}` が、字として残っていました。図形の文字の書式
  (`text-format`)は、字の大きさ、書体、行の高さ、太字、色、内側の余白も書くように
  しました
* 図形の表に `[cols=]` の行があると、`[.shapes]` が表から離れ、別のシートとして
  読まれていました
* 原本の xlsx を渡さずに保存すると、読んだ図形が書かれていませんでした
* 題のある表は、見出しの行が無くても Excel のテーブルとして書かれていました
  (Excel のテーブルは結合したセルを含められません)
* セルが無く高さだけを持つ行が書かれず、既定の高さに戻っていました
* 名前の無い標準の書体を読むと、数字の幅を別の値にしていたので、列が広がって
  いました

== 描画一覧を Python へ渡す形(2026-09-25 発注者)

`Book.draw_list()` は、次の形の辞書を返します。同じ中身を JSON の字にもできます。
形は当面 0.x で、変わることがあります。`version` で見分けます。

[source,json]
----
{
  "version": "0.1",
  "fonts": [
    {"id": 0, "name": "BIZ UD明朝", "file": "/Users/…/BIZUDMincho-Regular.ttf",
     "index": 0, "ascent": 0.88, "descent": 0.12}
  ],
  "pages": [{
    "size": [595.3, 841.9],
    "items": [
      {"type": "fill", "rect": [x, y, w, h], "color": "#FFFFFF", "alpha": 1},
      {"type": "line", "from": [x, y], "to": [x, y], "width": 0.75,
       "color": "#000000", "alpha": 1, "dash": [3, 1]},
      {"type": "path", "d": [["M", x, y], ["L", x, y], ["C", x1, y1, x2, y2, x, y], ["Z"]],
       "fill": "#FFFFFF", "even_odd": false, "stroke": "#BCBCBC", "width": 0.75,
       "dash": [], "alpha": 1, "clip": []},
      {"type": "text", "x": 120.5, "baseline": 210.0, "top": 192.4, "text": "山田 太郎",
       "font": 0, "size": 20, "width": 88.0, "color": "#000000", "bold": false},
      {"type": "image", "rect": [x, y, w, h], "mime": "image/jpeg", "base64": "…"}
    ],
    "fields": [
      {"name": "氏名", "kind": "text", "rect": [x, y, w, h], "value": "山田 太郎"},
      {"name": "生年月日", "kind": "date", "rect": [x, y, w, h], "value": "1990-05-01"},
      {"name": "志望の動機など", "kind": "multiline", "rect": [x, y, w, h], "value": "…"},
      {"name": "写真", "kind": "image", "rect": [x, y, w, h], "value": "photo.jpg"}
    ]
  }]
}
----

* 単位は pt です。原点はページの左上で、y は下向きです。換算はエンジンがします
* `items` は描く順に並べます。描く側は上から順に描くだけです。順は PDF と同じで、
  背景、塗り、図形と画像(重なりの順)、罫線、文字、上に引く罫線、透かしの順です
* 文字は、ベースラインの位置(`baseline`)と上端(`top`)の両方を渡します。Flet の
  Canvas は文字を上端で置くためです。上端は、書体の `hhea` の上の高さ(`ascent`)と
  字の大きさからエンジンが計算します。`width` はエンジンが測った字の並びの幅です
* 書体は、名前とファイルの場所を渡します。Flet には同じファイルを登録させます。
  `font` は `fonts` の `id` です。PDF と同じく、名指しの書体に無い字がある並びは
  1 番目の書体で組みます
* 画像は元のバイト列を base64 で渡します(PNG か JPEG)
* 色は `#RRGGBB`、透明度は `alpha`(0〜1)です。破線の刻みは pt の並びです

欄の決まり:

* 欄はデータの項目ごとに 1 つです。1 つのセルに `{日付.年}` `{日付.月}` `{日付.日}` が
  あっても、欄は「日付」1 つで、種類は `date` です
* `{本人希望.1}`〜`{本人希望.4}` のように行ごとの印は、「本人希望」1 つの欄
  (種類は `multiline`)にまとめます。欄の四角は、その印のセルを全部含む四角です
* `{学歴・職歴.3.年}` のような表の印は、印そのものが欄の名前です(種類は `text`)
* `{年齢}` は生年月日と日付から計算するので、欄にしません
* 折り返して全体を表示するセルの欄は、種類を `multiline` にします
* 欄の四角は、そのセル(結合したセルは結合した範囲)のページの上の四角です。
  同じ欄が 2 ページに分かれたときは、ページごとに 1 つずつ出します
* `value` は、データに書いてある元の値です(日付は `2026-09-24` の形)
* 様式から作った描画一覧は、いちばん上に `missing`(データに 1 つも無い名前の並び)を
  持ちます

写真欄の決まり:

* 様式の図形の表に `field` の項目を足し、`|I3 |field |写真` のように書いた図形を
  写真の欄にします。この項目は adoc の様式にだけ書きます
* 埋めるときは、データの「写真」に書いたファイル(データの adoc と同じフォルダーから
  探します)を、図形の四角の中に縦横の比を保って中央に置きます。写真を置いたときは、
  図形の中の説明の文字を消します。枠の線は残します
* 写真はブックの画像として入るので、xlsx にも PDF にも出ます

欄を直す流れ:

. Flet の部品が、欄の名前と新しい値を受け取ります
. Python で `データ.set_field(名前, 値)` を呼び、データのブックに値を入れます
. `Book.fill(様式, データ)` と `draw_list()` をもう一度呼び、返った描画一覧で描き直します

== 分かっていること

* JIS Z 8303 の履歴書の様式例は、2020 年 7 月に日本規格協会が削除しました。
  代わりに、厚生労働省が 2021 年 4 月 16 日に「履歴書様式例」を公表しました
  (性別は書いても書かなくてもよい欄になり、通勤時間・扶養家族数・配偶者・配偶者の
  扶養義務の欄が無くなりました)。JIS 様式は、特定のファイルを写さず、欄の並びを
  もとにこちらで組みます。
* Flet から officework の PDF と画像を刷る見本が `sample/flet_insatsu` にあります
  (ページごとの画像を並べ、flet-printing で印刷する)。今回の部品は、画像ではなく
  描画一覧を描き、欄の入力を受ける点が違います。
* 厚労省の様式例の xlsx と docx は、2026-09-23〜24 に Word・Excel と細かく比べました
  (`docs/sekkei/excel-tsukiawase.ja.adoc`「厚労省の履歴書様式例(A4)を比べる」)。
* BIZ UD ゴシック・明朝は SIL Open Font License 1.1 です。同梱も PDF への埋め込みも
  できます。Windows 10 の October 2018 Update(1809)から Windows に標準で入って
  いるので、xlsx を受け取った人の Windows でも同じ書体で表示されます。Mac に標準で
  入っているかは、まだ確かめていません。
* Flet の Canvas は、`Path`(`MoveTo`・`LineTo`・`QuadraticTo`・`CubicTo`・`Arc`・
  `Close`)、`Text`(`TextStyle` で字の大きさなど)、`Image`(`src` にパス・base64・
  バイト列)を持つと、Flet の説明にあります。使う版の Flet で動くかは、入れて確かめます。

* 描画一覧だけを Pillow で描いた絵(`sample/drawlist/pil_draw.py`)は、埋めた履歴書の
  PDF と重なりました(4 倍の解像度で描いて縮めたとき)。等倍では、Raqm の無い Pillow が
  字の送りを 1 字ずつ整数の画素に丸めるため、長い字の並びの後ろの字がずれました。
  字ごとの位置を渡すかどうかを決めるときの材料です
* 埋めた履歴書の描画一覧の線は、1 ページ目が 601 本、2 ページ目が 381 本です。
  同じ太さ・色・破線で、一直線に続く線をつなぐと、37 本と 33 本になります
  (2026-09-25 に数えました)。Flet で遅いときにつなぐかどうかを決める材料です
* Flet 1.0.1 の Canvas には `Image` があります(仕様書の未確認事項「Canvas で画像を
  描けるか」)。塗りの偶奇の決まりと切り抜きはありません
* Flet の画面の本体は `flet-desktop` が初めて開くときに `~/.flet/client` へ入れます。
  書体を読ませるには、Flet を起動する時点で assets のフォルダーが在る必要があります
  (無いと、後から写した書体が読まれず、代わりの書体で出ました)

== xlsx で気をつけること

PDF は描画一覧から書くので、画面とそのまま同じになります。xlsx は、受け取った人の
Excel が組み直します。Windows の Excel は、行を縦に約 90% に縮めて印刷することが
あり、罫線の太さも Excel の決め方で印刷します(`docs/sekkei/excel-tsukiawase.ja.adoc`)。

そこで、こちらで作る様式は、行の高さの合計が印刷できる高さに十分収まるように組み、
「ページに合わせる」を 1 ページに設定しておきます。できた xlsx を Excel で開いて
確かめるのは、発注者の許可を得てから行います。
