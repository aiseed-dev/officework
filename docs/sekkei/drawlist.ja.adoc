= 描画一覧・Flet の部品・PDF と xlsx の出力
:toc:

作る側の資料です。発注者の仕様書「officework 描画一覧・Flet表示部品・PDF出力
仕様書」(2026-09-24)を検討し、決めたことを書きます。

== 目的

様式の決まった文書(履歴書・見積書・請求書)を、画面で見て、欄を直し、同じ見た目の
PDF にできるようにします。aiseed office(gpui)より先に、Flet の部品として出します。

作らない物は仕様書のとおりです。流れる文章の自由な編集、大きな表、スマホでの入力、
gpui と Flet の間の埋め込み、aiseed office の完成です。

== 決め(2026-09-24 発注者)

* 組版はエンジンで一度だけ行い、画面(Flet・gpui)と PDF は同じ描画一覧から描きます。
* 書体は BIZ UD ゴシック・明朝に固定します。こちらで作る様式に使います。受け取った
  docx・xlsx は、今までどおり文書の書体で組みます。
* 履歴書は、厚生労働省の「履歴書様式例」(2021-04-16 公表)を基本にします。
  JIS 様式の履歴書も作れるようにします。
* データは adoc に置きます。出力は xlsx と PDF です。
* Flet の部品は別のパッケージにし、Python だけで作ります(ライセンスは AGPL)。
* 描画一覧の形は当面 0.x とし、変わることを明記します。

== 組み立て

[source]
----
データ(adoc)──────┐
                   ├→ ブックの模型 ─┬→ 描画一覧 ─┬→ Flet の部品(画面)
様式(テンプレート)─┘               │            ├→ PDF
                                   │            └→ aiseed office(gpui)
                                   └→ xlsx
----

欄を直したら、その変更を命令としてエンジンに戻し、返ってきた描画一覧で描き直します。

== 既にある物

描画一覧に当たる物は、エンジンに `paper::pdfw::Leaf` として既にあります。今は、
これから PDF(`paper::pdfw`)、PNG(`paper::e`、vello)、表計算の画面の図形を
描いています。

[cols="1,2,1"]
|===
|仕様書の項目 |今の `Leaf` |状態

|ページの大きさ |`size_mm` |あり
|線と曲線、塗り |`rules`(罫線。破線の刻みあり)、`fills`(四角)、`polys`(多角形)、`paths`(曲線と切り抜き)、`z`(重なりの順) |あり
|文字(折り返しはエンジンが決める) |`pieces`(位置・大きさ・色・書体の番号・太字・下線) |あり
|画像 |`images`(位置・大きさ・中身のバイト列) |あり
|欄の一覧 |無し |足す
|Python へ渡す形 |Rust の中だけ。Python からは PDF と PNG だけが取れる |足す
|===

表計算のエンジンは、セルの格子から `Leaf` を作ります(`paper::grid::sheet_leaf`)。
xlsx の書き出し(`sheet::xlsx::write`)も同じブックの模型から書きます。adoc と
ブックの行き来は `engine/src/book_adoc.rs`、見た目を分けて持つテンプレート
(`.tmpl.adoc`)は `engine/src/booktmpl.rs` にあります。PDF を描画一覧から書く
(仕様書の手順 3)は、今の PDF の作りそのものです。

== 決める物

. *描画一覧を外に出す形。* `Leaf` は PDF と同じく左下からの mm です。外に出す形は
  左上が原点にし、単位は pt(または mm)にします。換算はエンジンでします。描く側が
  計算しない、という仕様書の決まりに合わせるためです。書体は、名前とファイルの一覧を
  載せ、Flet にも同じ書体ファイルを登録させます。
. *文字の置き方。* `pieces` は、行を分けた後の字の並びの始まりの位置です。Flet
  (Flutter)が同じ書体で並べても、字の送りがエンジンと少し違えば、行の終わりが
  ずれます。字ごとの位置も載せられるようにしておき、履歴書 1 枚で「並びの位置だけ」と
  「字ごとの位置」を比べて決めます。
. *欄の一覧の出所。* 欄の名前と位置をどこで決めるかです。データの adoc の欄の名前と、
  テンプレートのセル(結合した範囲)に付けた名前を結びます。docx の記入欄(`sdt`)の
  扱いとそろえます。
. *履歴書のデータの adoc の形。* 決まりました(下の「履歴書のデータの形」)。
. *描く物の数。* 今の履歴書の 1 ページには、罫線が約 580 本あります(セルの辺ごとに
  1 本)。Flet の Canvas で遅いときは、一直線に続く辺をエンジンでつないで渡します。

== 履歴書のデータの形(2026-09-24 発注者)

データは表のブック(`名前.sheet.adoc`)で書きます。見本は
`sample/rirekisho/履歴書.sheet.adoc` です(架空の人です)。

* 題は `= 履歴書`。題はブックの題になります
* `:様式:` に `厚労省` か `JIS` を書き、使う様式を選びます
* 表は 4 つです。今のブックと adoc の行き来で、1 つの表が 1 つのシートになります
** 「基本」:2 列(欄の名前、値)。日付、ふりがな、氏名、生年月日、性別、郵便番号、
   現住所ふりがな、現住所、電話、連絡先、写真(画像のファイルの名前)
** 「学歴・職歴」:3 列(年、月、内容)。1 行目は見出し
** 「免許・資格」:3 列(年、月、内容)。1 行目は見出し
** 「自由記入」:2 列(欄の名前、値)。志望の動機など、本人希望。長い文はセルの中で
   改行します(行末の ` +`)
* JIS 様式にだけある欄(通勤時間、扶養家族数、配偶者、配偶者の扶養義務)は、
  「基本」の表に行を足したときだけ使います。性別は、厚労省の様式では書いても
  書かなくてもよい自由記入で、JIS 様式では男・女から選びます
* 年齢は、生年月日と日付から計算するので、データには書きません
* 様式(穴つきの枠)は `履歴書-厚労省.form.adoc` と `履歴書-JIS.form.adoc` の名前に
  します(二重の拡張子の決まり。SEKKEI「ファイルの名前」)

今のエンジンで、この見本が 4 つのシート(11 行、8 行、3 行、2 行)として読めて、
`:様式:` の値とセルの中の改行も残ることを確かめました。その際、文書の題を
「表の外の段落」として落とした数に入れていたのを直しました(題はブックの題に
入るので、落としてはいません)。

== 様式と差し込み(2026-09-24)

様式は表のブックで書きます。値を入れるセルに `{氏名}` のような印を置きます。
罫線や字の大きさなどの見た目はテンプレート(`名前.tmpl.adoc`)が持ち、様式の
`:template:` の行でテンプレートの名前を指定します。

* 印の書き方は `{名前}`、`{名前.年}`(`.月`、`.日` も同じ)、`{年齢}`、
  `{表の名前.N.列の名前}`(表の N 行目)、`{名前.N}`(値の N 行目)です。
  年齢は生年月日と日付から計算します
* 1 つのセルに印をいくつ置いてもかまいません。印の外の字はそのまま残ります
* データに無い印は空になります
* Python では `Book.fill(様式, データ)` で埋めたブックができ、`save` で xlsx、PDF、
  PNG に書き出せます。`fields()` は欄の一覧(シート、セル、印の名前)を返します

厚労省の様式は `sample/rirekisho/履歴書-厚労省.form.adoc` と `.tmpl.adoc` です。
`cargo run -p sheet --example rireki_form -- 元の.xlsx sample/rirekisho` で、
厚労省の xlsx から作り直せます。このスクリプトは次のことをします。

* 書体を BIZ UD 明朝・ゴシックに置き換えます
* 行の高さを 0.881 倍にし(合計 836pt → 729pt。0.75pt 刻み)、印刷の倍率を 100% に
  します。A4 の印刷できる高さ(759.7pt)に収まります。「ページに合わせる」はまだ
  設定していません
* 102 の欄に印を置きます。学歴・職歴は左のページに 15 行、右のページに 7 行です
* 志望の動機などの欄は、折り返して全体を表示し、上に揃えます

見本のデータで埋めて、PDF と xlsx が 2 ページで出ることを確かめました。書き出した
xlsx を開き直して描くと、埋めたブックの描画と同じになります(写真欄の点線の端の
5 画素だけが違います)。このとき、次の不具合を直しました。

* adoc の表で、縦と横の両方に結合したセルの書き方が AsciiDoc の決まり
  (`3.2+|`、横の数.縦の数)と違っていました。読む側も、縦の結合が下の行で占める幅を
  1 列として数えていたので、セルが左にずれていました
* 図形の文字の段落の頭の `{empty}` が、字として残っていました。図形の文字の書式
  (`text-format`)は、字の大きさ、書体、行の高さ、太字、色、内側の余白も書くように
  しました
* 図形の表に `[cols=]` の行があると、`[.shapes]` が表から離れ、別のシートとして
  読まれていました
* 原本の xlsx を渡さずに保存すると、読んだ図形が書かれていませんでした
* 題のある表は、見出しの行が無くても Excel のテーブルとして書かれていました
  (Excel のテーブルは結合したセルを含められません)
* セルが無く高さだけを持つ行が書かれず、既定の高さに戻っていました
* 名前の無い標準の書体を読むと、数字の幅を別の値にしていたので、列が広がって
  いました

== 分かっていること

* JIS Z 8303 の履歴書の様式例は、2020 年 7 月に日本規格協会が削除しました。
  代わりに、厚生労働省が 2021 年 4 月 16 日に「履歴書様式例」を公表しました
  (性別は書いても書かなくてもよい欄になり、通勤時間・扶養家族数・配偶者・配偶者の
  扶養義務の欄が無くなりました)。JIS 様式は、特定のファイルを写さず、欄の並びを
  もとにこちらで組みます。
* Flet から officework の PDF と画像を刷る見本が `sample/flet_insatsu` にあります
  (ページごとの画像を並べ、flet-printing で印刷する)。今回の部品は、画像ではなく
  描画一覧を描き、欄の入力を受ける点が違います。
* 厚労省の様式例の xlsx と docx は、2026-09-23〜24 に Word・Excel と細かく比べました
  (`docs/sekkei/excel-tsukiawase.ja.adoc`「厚労省の履歴書様式例(A4)を比べる」)。
* BIZ UD ゴシック・明朝は SIL Open Font License 1.1 です。同梱も PDF への埋め込みも
  できます。Windows 10 の October 2018 Update(1809)から Windows に標準で入って
  いるので、xlsx を受け取った人の Windows でも同じ書体で表示されます。Mac に標準で
  入っているかは、まだ確かめていません。
* Flet の Canvas は、`Path`(`MoveTo`・`LineTo`・`QuadraticTo`・`CubicTo`・`Arc`・
  `Close`)、`Text`(`TextStyle` で字の大きさなど)、`Image`(`src` にパス・base64・
  バイト列)を持つと、Flet の説明にあります。使う版の Flet で動くかは、入れて確かめます。

== xlsx で気をつけること

PDF は描画一覧から書くので、画面とそのまま同じになります。xlsx は、受け取った人の
Excel が組み直します。Windows の Excel は、行を縦に約 90% に縮めて印刷することが
あり、罫線の太さも Excel の決め方で印刷します(`docs/sekkei/excel-tsukiawase.ja.adoc`)。

そこで、こちらで作る様式は、行の高さの合計が印刷できる高さに十分収まるように組み、
「ページに合わせる」を 1 ページに設定しておきます。できた xlsx を Excel で開いて
確かめるのは、発注者の許可を得てから行います。

== 進め方

. この文書を書く(2026-09-24。済み)
. 履歴書のデータの adoc の形(欄の名前と並び)を決める(2026-09-24。済み)
. 厚労省の様式例のテンプレートを作り、PDF と xlsx が出ることを確かめる(2026-09-24。済み)
. 描画一覧を Python へ渡す形(左上が原点、書体、欄の一覧)を決める
. Flet の部品を作る
. 仕様書の完成の基準(履歴書が表示される、欄を直すと描き直される、写真欄に写真が
  出る、書き出した PDF と画面に違いがない)を確かめる
