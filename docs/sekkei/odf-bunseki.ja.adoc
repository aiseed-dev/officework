= ods と LibreOffice の違いの分析(2026-10-17 から)

ODF を先にする決め(SEKKEI「決め: ODF を先にする」)に沿って、ods を officework と LibreOffice 24.2.7.2 で
PDF にして比べます。見る物は Word・Excel との分析(`chigai-bunseki.ja.adoc`)と同じで、表示されない物、違う物、
読みにくい物の順に重く見ます。

== 進め方

. ods を `tools/lo_pdf.py` で LibreOffice の PDF にします。
. 同じ ods を `cargo run -p ops --example ods_pdf -- 入力.ods 出力.pdf` で officework の PDF にします。
. `tools/pdf_eval.py` で違いの入り口を見つけ、絵を並べて目で確かめます。
. 原因を LibreOffice のソース(`vendor/libreoffice`)で確かめます。ソースに規則があるときはそれに合わせます。
. ods だけに効かせる規則は `Book::print_as_libreoffice`(ods を読むと立つ)で分けます。Excel の規則を
  変えないためです。

比べた ods は 49 個です(`~/ods-corpus`)。2026-10-17 の最初の結果は、見えない字が 22 文書で 13,850 件、
字が無いが 10 文書で 2,064 件でした。

== 分析した違い

[cols="2,3,3,1,2"]
|===
|文書 |違い |原因 |重さ |直し

|Cambria を既定の字体にした ods の全部(見積書・請求書など 24 個)
|セルの字が、読めない黒い塊になる
|Cambria の置き替えの Caladea には日本語が無く、日本語を組める字体を一覧から探す。置き替えの名前からは
字体の系統が分からず、系統が無い物の先頭の Unifont(ドットの字体)を選んでいた
|表示されない
|直した(16e0922f)。系統は、文書が頼んだ名前(Cambria は明朝)から引き継ぐ

|同
|英数字が日本語と同じ字体になる。LibreOffice は英数字を Caladea で描く
|既定の字体が日本語を組めないとき、先頭の日本語の字体 1 つで全部を描いていた
|違う
|直した(16e0922f)。半角は既定の字体の置き替えで描く

|lo_rich、bojsjfy、stat_fies など(見えない字 13,850 件が 17 件に)
|列からはみ出す字が、最後の印刷列で切れる
|LibreOffice は、右が空のセルの文字列がセルの幅を超えると、その分だけ印刷範囲を右へ広げる
(`ScTable::ExtendPrintArea`)。Excel は広げず、最後の印刷列で切る(68bf5c08)
|表示されない
|直した(16e0922f)。ods のときだけ広げる。中央揃えは超えた分の半分、右揃えと折り返しは広げない

|lo_rich
|セルの中の赤い太字、斜体、下線が出ない
|セルの中の字ごとの書式のうち、大きさ・書体・位置だけを描いていた。色・太字・斜体・下線・取り消し線を
描いていなかった(xlsx も同じ)
|違う
|直した(16e0922f)。ods の読み書きも、字ごとの下線と取り消し線を持つ

|見積書など
|金額が入らない欄の `###` が、こちらは欄いっぱいの数(`######`)
|LibreOffice は欄の幅によらず、いつも `###`(3 個)にする(`ScDrawStringsVars::SetHashText`)。
Excel は欄いっぱいに並べる
|違う
|直した(16e0922f)。ods のときだけ 3 個

|lo_furniture
|セルのハイパーリンクが黒い
|LibreOffice は、セルのリンクを濃い青(#000080)の下線つきで印刷する
|違う
|直した(16e0922f)。ods のときだけ

|bojsjfy の 36 頁
|頁番号が「6- -」。LibreOffice は「-1-」
|フッターの `&16`(文字の大きさ)を読まず、`&1` を捨てて `6` を字として描いていた。`&A`(シート名)も捨てていた
(xlsx も同じ)
|違う
|直した。大きさ・太字・斜体・下線・取り消し線・シート名を読む。書体名と色は読まない

|在庫台帳、問い合わせ台帳
|印刷の枠線が、薄い灰色の太い線
|LibreOffice は枠線を黒の 0.1pt で描く(`printfun.cxx` の `COL_BLACK`)。Excel は薄い灰色
|違う
|直した。ods のときだけ

|lo_formats
|時刻(12:59:02)が、欄に入るのに `###` になる
|表示形式が作る字(コロンなど)が幅の表に無く、0.55em と見積もっていた
|表示されない
|直した。表示形式を通した字も表に入れる

|lo_formats
|分数の表示形式(`# ?/?`)の 0.75 が `1`。LibreOffice は `3/4`
|分数の形式に対応していなかった(xlsx も同じ)
|違う
|直した。整数部があれば前に付け、分母は桁数以内で最も近い分数にする。分母が書いてあればその数にする

|lo_formats
|ゼロを隠す表示形式(`#,##0;\-#,##0;;`)で `0` が出る
|3 つ目の区分(ゼロ)を使わず、空の区分も隠していなかった(ECMA-376 18.8.31。xlsx も同じ)
|違う
|直した。3 区分以上のときゼロは 3 つ目を使う。空の区分は何も出さない

|lo_cond
|アイコンセットの矢印が出ない。データバーの周りに赤い枠が出る
|まだ調べていない
|違う
|まだ

|(全般)
|日本語が、こちらは明朝、LibreOffice はゴシック
|字体が日本語を持たないとき、LibreOffice は fontconfig の順で Noto Sans CJK JP を選ぶ。こちらは名前の系統を保つ
|違う(書体)
|直さない。fontconfig の結果は機械で変わるため

|(全般)
|字を傾ける指定で、こちらは傾かない
|斜体の字体が無い書体は傾けない決め(2026-08-31)。LibreOffice は傾ける
|違う
|決めのとおり直さない
|===

== まだ直っていないこと

* アイコンセットとデータバーの枠(lo_cond)。
* 罫線の太さ。ods の 0.74pt の罫線を、LibreOffice は 0.75pt、こちらは 1pt で描く。
* ヘッダーとフッターの字の大きさ。bojsjfy では、LibreOffice の PDF のフッターがシートの縮小と同じだけ小さい。こちらは縮めない。LibreOffice のソースでは確かめていない。
* bojsj 系と stat_fies 系の大きな統計表では、字の違いと「字が無い」が残る。書体が違うための折り返しと
  字送りの差が大半と見ている。
