== 段0: OS の言語に従う道を作る(先にやること)

**これは確認ではなく、新しく作る作業です。** 今の `lang/src/i18n.rs` の
`language()` が見るのは `OFFICE_LANG` → `settings.toml` → 既定 ja の3つ
だけで、OS のロケールはどこにも出てきません。

鍵を裏返すと「無指定 = 英語」になります。発注者の
`~/.config/officework/settings.toml` には `language` の行がありません。
**この段を飛ばすと、次の起動で発注者の画面が英語になります。**

. `language()` の順を `OFFICE_LANG` → `settings.toml` → **OS のロケール**
  → 既定 en にする
. OS のロケールは `LC_ALL` → `LC_MESSAGES` → `LANG` の順。`ja_JP.UTF-8` の
  ような形から `ja` を取り、表にある札だけ受ける(知らない札は既定へ)
. 試験を1つ足す。**`LANG=ja_JP.UTF-8` で ja になること**。i18n.rs の
  言語の節は直列に回す作りなので、そこに入れる
. この段だけで先にコミットする — 裏返す前でも意味のある直しです

== 手順を見直した経緯(2026-08-26)

最初の指示は「t!/tf!/item! の呼び出し 2,616 か所(全部 en の表に載って
いる — 取りこぼし 0)」としていました。実際には **92 か所が機械の目に
入っていません**でした。

`flip_i18n.py` が表とコードを `"((?:[^"\\]|\\.)*)"` で読んでいて、`.` が
改行に当たらないためです。Rust の文字列は行末の `\` で次の行に継げます。

[cols="3,1"]
|===
| 見えていなかった形 | 数

| 行を継いで書いた鍵 | 28
| `crate::t!`(ui クレートが自分を `ui::` と呼べないときの書き方)| 47
| `lang::i18n::tr(`(face は ui に依存しないので直に呼ぶ)| 17
|===

表の側も同じ理由で 19 句を読み落としていました(2,085 と数えていた物が
本当は 2,104)。

**「取りこぼし 0」は、取りこぼした物を数えない目で数えた 0 でした。**
書き替える所と数える所が同じ正規表現なので、見えない呼び出しは
書き替えられもせず、「表に無い鍵」にも数えられません。このまま `--go` を
打つと、表が英語の鍵に変わったあと、その 92 か所だけ日本語の鍵のまま
残って訳が引けなくなります。

直し方は、読む道を `ui/gen_i18n.py` に1本化することにしました。あちらは
行継続も3通りの呼び出しの書き方も既に知っています(註にもそう書いて
あります)。`gen_i18n.py` に `table_pairs()` を足し、`flip_i18n.py` は
それを呼びます。写しの上で `--go` を試して、3種とも書き替わることを
確かめました。

同じ考えで、SRC_DIRS の外の呼び出しも**数えて言う**ようにしました。
黙って外すと「全部やった」に見えます。

== 鍵を記号にしました(2026-08-26)

発注者「どうして番号で管理しているのだ」「キーは英語の省略形で適当に
決めればいい。そうすれば、英語の表現が少々変更されても変更する必要が
ない」。

=== 何が悪かったか

訳のファイルは番号で訳を持っていました。番号は**中身と無関係**なので、
鍵の並びが1つ動くと 13 言語の訳が全部ずれます。しかも数は合ったままなので
見張りは緑です。段1で実際にずらしました。

段1でいったん「英語の文そのもの」を鍵にしましたが、これも駄目です。
英語の言い回しを直すたびに 14 ファイルの鍵を付け替えることになり、
番号と同じ churn が起きます。

=== どうしたか

鍵を**記号**にしました。`formatting_defaults` のような、小文字と `_`
だけの短い字です。英語の文から1度だけ起こし、その後は英語を直しても
動きません。

* `ui/i18n/keys.json` — 記号の一覧
* `ui/i18n/<言語>.json` — `{"記号": "訳"}`。**英語も訳の1つ**で
  `en.json` にあります
* 訳が無ければ**英語に落ちます**。記号をそのまま画面に出すと「save」と
  表示されてしまうので、英語を最後の砦にします

`tools/i18n_remap.py`(番号の付け替え)は要らなくなりました。

=== 記号の起こし方

英語から機械で起こしました。小文字の英数字と `_`、意味の薄い語
(the/a/of…)を落として4語まで、かぶったら語を増やすか2桁を足します。
`can` `not` `no` は落としません — 打ち消しは意味の芯だからです。

中央 17 字、最長 45 字、2,177 個とも一意です。

=== 踏んだ穴

**掃きを2度かけて二重に置き換えた所が2つ**ありました。1度目で
`between` になった所に2度目が当たり、英語の "between" の記号
`between_2` になっていました。見つけたのは「使われていない訳」の見張り
です。数が合っているだけでは分からない類なので、見張りが効きました。

**短い鍵の巻き添え**が9か所。`"+"` が鍵だったので、式を組む
`refs.join("+")` の `+` まで記号になり、`=B5plus_charB7` という式が
出来ていました。`・` の連結も同じです。`format!` の雛形も3つ潰しました。

どれも「文字列の中身は鍵とは限らない」という同じ形です。段3の識別子の
置き換えでも同じ穴があるので、`tools/rename_ids.py` は**文字列と註釈を
先に伏せてから**探す作りにしてあります。

=== 機械の作り

**文字列と註釈を先に伏せてから**識別子を探します。伏せた写しで位置を
決め、元の字を切り貼りします。壊し試験を1つ置いてあります。

伏せた写しでは見えない所が2つありました。どちらも**文字列の中に識別子が
書ける**からです。

* Rust の `format!("{名}")` — 埋め込みの引数
* Python の f-string の `{len(残り)}` — 中身はコード

前者は `{識別子}` の形だけを見て直します。後者は f-string の `{…}` を
伏せずに残す形にしました。
