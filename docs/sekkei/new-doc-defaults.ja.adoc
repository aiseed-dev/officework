== 書体の別の名前(2026-10-12)

Windows 11 の Word で受け入れ試験の docx を開くと、本文が游ゴシックで組まれていました。
テーマは本文の書体を「BIZ UDP明朝」と書いています。Windows に入っている明朝の
名前(name ID 1)は「BIZ UDP明朝 Medium」です。「BIZ UDP明朝」は系列名(name ID 16)
でしかありません。Word は name ID 1 の名前で書体を探すので、見つけられませんでした。
Linux と Google Fonts の版(モリサワの公開版)は「BIZ UDP明朝」です。
ゴシックは、どちらも「BIZ UDPゴシック」です。

決め:

- テーマの書体の名前は「BIZ UDP明朝」のままにします。
- 新しく作る docx に `word/fontTable.xml` を置き、`BIZ UDP明朝` に
  `w:altName`「BIZ UDP明朝 Medium」を書きます。
- 根拠は ECMA-376 Part 1 §17.8.3.1 altName です。元の名前で書体が見つからないとき、
  アプリは別の名前で順に探すべきだと書いてあります。
- 原本が fontTable を持っているときは、原本のままにします。

確かめたこと:altName を書いた送付状を Word 16.0.20430 で PDF にしたところ、
BIZ-UDPMincho-Medium で組まれました。officework の PDF との違いは 6 件から 0 件になりました。
テーマの名前を「BIZ UDP明朝 Medium」に変えても同じ結果でしたが、その方法は Linux の
名前と合わなくなるので採りませんでした。

== 幅を決めていない表の列(2026-10-12)

officework は、幅を決めていない列を `<w:gridCol w:w="0"/>` と書きます。
Word はこの列を中身の幅まで広げます。officework の組版は幅 0 のまま組んでいたので、
受け入れ試験の議事録の表で、字が 1 字ずつ縦に並びました(Word は 1 ページ、
officework は 2 ページ)。

決め:

- autofit の表(`w:tblLayout` が無いか autofit)で、幅がちょうど 0 の列は、
  中身の最大の幅(折らないときの幅にセルの余白を足したもの)まで広げます。
- ページの幅に収まらないときは、広げる分を比で縮めます。
- 複数の列にまたがるセルで足りない分は、またいでいる幅 0 の列で分けます。
- 根拠は ECMA-376 Part 1 です。§17.4.16 gridCol は、幅が無い列の幅を 0 とし、
  格子の幅は最初の幅でしかないと書いています。§17.18.87 の AutoFit の手順は、
  セルを中身の最大の幅まで広げ、表をページの幅まで広げてよいとしています。
- 幅が 0 でない細い列(Word が結合の後に残す 6〜54 twips の列)は広げません。
- 固定の表(`w:tblLayout w:type="fixed"`)と、`w:tblW` で幅を言う表は広げません。
- セルの希望の幅(`w:tcW`)はエンジンが持っていないので、まだ使っていません。
  §17.18.87 では、希望の幅があれば中身の最大の幅の代わりになります。
