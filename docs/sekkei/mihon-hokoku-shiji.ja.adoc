= 指示: 絵の入った見本を、Word と同じに出して紹介ページに載せる(Fable Mac へ)

発注者(2026-09-20)「サンプルももっと絵が入って綺麗なものを載せろ」「これを、Fable Mac に指示する」。

== 目的

紹介ページ(web/main.py)の「同じファイルを両方で開けば、誰でも確かめられます」に、見栄えのよい文書を、Word で開いた写真と aiseed office で開いた写真の対で載せる。載せるのは、頁数と行の位置が Word と一致した物だけ。

対は 2 つ(と、あれば 3 つ目)。**1 つ目は Word のテンプレート**(発注者 2026-09-20「テンプレートが使えるというのは大きい」)。Word の「新規」に出る物から、見栄えのよい物で比較が一致した物を選ぶ。写真が入っていれば Web に公開できる写真に入れ替える。イラストはそのままでよい。2 つ目は官庁の文書(発注者 2026-09-20「日本向けには、Microsoft のテンプレートが使えること、官庁の文書の編集でも使えること。この 2 つをアピールすべき」)。国の省庁が公開していて、誰でも名前を知っている様式(国税庁、厚生労働省、法務省、経済産業省などの申請書・届出書の docx)から、比較で一致した物を選ぶ。物品借用願のようなマイナーな様式は使わない(発注者)。3 つ目は Claude が作った文書で、**AsciiDoc(.adoc)で書いた原稿**(発注者 2026-09-20「3 つ目は事業のご報告、これは Claude が作った物にしろ。特に、adoc 形式を読んで綺麗に印刷できるようにしろ。adoc 形式でないと git が有効に使えない」)。docx ではなく adoc で書く理由は、文字のファイルなので git で差分が取れること。git に入れるのは原稿だけで、デザイン(テンプレート .tmpl.adoc)は git に入れない(発注者 2026-09-20「git で管理するものの中にデザインは入れたくない」)。見本でも、原稿の adoc とテンプレートは別の置き場にし、git で見せるのは原稿の差分だけにする。見せ方は、左に adoc の原稿(文字)、右に aiseed office で刷った紙(PNG)。Word との比較ではなく、「文字の原稿がこう刷れる」の対。docx にも書き出せるので、書き出した docx を Word で開いた写しを 3 枚目に添えてもよい。

Word のテンプレートを載せるときの形(Microsoft の permissions の決まり。docs/sns.ja.adoc の決め 3): Word の窓ごと写す(切り出さない、手を加えない)。aiseed office も窓ごと。添え書き「Microsoft Word のテンプレート『○○』を、Microsoft Word と aiseed office で開いた物です。Used with permission from Microsoft」。テンプレートのファイルは置かない(ダウンロードして試す形は、自分の文書と官庁の様式)。

== Word のテンプレートの写しの扱い(2026-09-20 発注者)

* Microsoft の permissions の原文は「写しは、広告、文書、教材、動画、Web サイトに使ってよい」。Web サイトに使ってよいと書いてあるので、この条件にぴったりで、問題ない。Microsoft に書面で同意を求める必要は無い(発注者)。
* 条件はそのまま守る: Word の窓ごと写す、手を加えない、切り出さない、「Used with permission from Microsoft」、製品名は「Microsoft Word」、悪く言わない、推薦や提携を匂わせない。
* 写真の入ったテンプレートは、写真を入れ替えてから開く。写真は、Web に公開できる物であれば何でもよい。商用でも問題ない約束の物はいくらでもあり、相手の要求を満たすのは簡単(発注者)。写真は人に渡す物ではなく、この Web で見せるだけ(発注者)。イラストはそのままでよい(発注者)。

== いまある物

* `sample/gen_hokoku.py` — 事業のご報告.docx を作る。中身は架空。棒グラフと円グラフを Pillow で描いて `add_picture`、見出し 4 つ、表 1 つ。`.venv/bin/python sample/gen_hokoku.py` で `sample/事業のご報告.docx` ができる(コミット済み)。
* Word の側: `.venv/bin/python tools/ms_pdf.py sample/事業のご報告.docx out.pdf`(Word を AppleScript で動かす。開いた文書は閉じる)。PDF の 1 頁目を PNG にするのは pypdfium2(`PdfDocument(...)[0].render(scale=110/72).to_pil().save(...)`)。
* うちの側: `doc.Doc.open(path).save("office.png", dpi=110)`(頁ごとに office.png、office-2.png)。
* 紹介ページの写真は `web/assets/word.png` と `office.png`、`shot()` で並べている。docx のダウンロードは `buppin202411.docx` と同じ形で置ける。

== 分かっている違い(2026-09-20 に 1 度比べた)

* 両方とも 2 頁。ただし Word は「地域の内訳」の見出しで 1 頁目が終わり、円グラフは 2 頁目。うちは円グラフが 1 頁目に入る。
* うちの本文が太字に見える。docx は書体を指定しておらず、`w:docDefaults` がテーマの書体(`minorHAnsi` / `minorEastAsia`)、`w:lang` は en-US。Word はテーマを Times New Roman と明朝の系統に解いていて、うちは太いゴシックに解いている。**テーマの書体の解き方の違い**が原因と見ている。
* 見出しの書体も Word は明朝、うちはゴシック。

== やること

. 原因の側を直す。第一目標(docx を Word と同じに出す)に当たるので、生成スクリプトで書体を明示して逃げるのではなく、エンジンのテーマの書体の解き方(minorHAnsi / minorEastAsia / majorHAnsi / majorEastAsia を、theme1.xml の `a:latin` / `a:ea` と、無ければ Word の既定に解く)を Word に合わせる。theme1.xml が docx に無いときの Word の既定も確かめる(この docx に theme があるかを先に見る)。
. 直したら、上の手順で両方を出し直して、頁数と円グラフの位置と本文の太さが合うことを見る。合うまで繰り返す。
. 合ったら、`web/assets/` に `hokoku-word.png` と `hokoku-office.png` と `事業のご報告.docx` を置き、web/main.py の compare の節に対として足す(見出しの文は「株式会社みほん商事の『事業のご報告』(docx、中身は架空)を、Word と aiseed office で開いた物です。グラフと表と見出しが同じに出ます」の形)。物品借用願の対と、その docx のダウンロードは、紹介ページから外す(web/assets の word.png・office.png・buppin202411.docx も消す)。
. 3 つ目(adoc)を作る。`sample/事業のご報告.adoc` を Claude が書く(中身は gen_hokoku.py の物と同じで、架空。棒グラフと円グラフは PNG を `image::` で入れる)。同じフォルダに `.tmpl.adoc` を置いて、見出しの色・書体・余白を整え、**綺麗に刷れる所まで**エンジンを直す(adoc の読み込みと組版で足りない物があれば、それを直すのがこの項目の本体。docs/ja/genkou-manual.adoc が仕様)。`doc.Doc.open("事業のご報告.adoc").save("x.png", dpi=110)` で紙にし、adoc の原稿の写し(エディターか writer の画面)と並べて 3 つ目の対として載せる。adoc のダウンロードを置く。テンプレートは原稿と分けて、アプリのテンプレートの置き場に入れる形で見せる。
. 官庁の文書の対を作る。~/Documents/officework-cmp/corpus の中から、国の省庁の様式で誰でも名前を知っている物のうち、頁数と行の位置が合っている物を選び、Word と aiseed office の写しを撮って 2 つ目の対として載せる。見出しの文は「○○省が公開している『○○申請書』(docx)を、Word と aiseed office で開いた物です」の形。役所の様式は公開の物なので、docx のダウンロードも置いてよい。
. Word のテンプレートの対を作る。web/gallery(英語版と日本語版の比較の結果)から、見栄えのよい物で頁数と行の位置が合っている物を選ぶ。写真が入っていれば Web に公開できる写真に入れ替える。Word の窓ごとの写しと aiseed office の窓ごとの写しを撮って `web/assets/` に置き、1 つ目の対として載せる。添え書きは上の形。合っている物が無ければ、合わせる作業(SEKKEI「Word のテンプレートを英語版と日本語版で全部通す」)を先にやる。
. `flet run --web --port 8550 web/main.py` で開いて、2 つの対が出ることを見てからコミットする。SEKKEI.adoc に、直したテーマの書体の解き方を 1 節書く。

== やらないこと

* 数字(288 枚のうち 246 枚)や細かい経緯を紹介ページに書かない(発注者「こういう細かいことは書かない」)。
* Microsoft のテンプレートのファイルを置いたり、切り出したりしない。写し方は上の形で。
* Word で開いた文書を開いたままにしない(閉じられなければ止まる)。
