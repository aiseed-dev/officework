=== 画面の大きさ — GNOME の文字倍率は使わない(発注者確定 2026-08-14)

*採らない*: `org.gnome.desktop.interface text-scaling-factor` に追随する案。
**あれは「字だけ」を大きくする設定**で、箱(ボタン・リボンの高さ・セルの幅・行の高さ)は元のまま — 字が枠からはみ出して切れる。
帳票ではさらに悪く、*画面と紙が食い違う*(セルの幅は文字数で決まるのに字だけ膨らむ)。
GTK のアプリが耐えられるのは箱が字から組み上がる作りだから。
うちは px で組んでいるので同じ手は効かない。

*同じ理由で Tweaks の「フォントの大きさ」も使わない。* 2026-08-14 に発注者の機械がこの形だった(インターフェイスのフォントを 11 → 16 に上げてあり、GTK のアプリだけ 1.45 倍で表示されていた)。
高 dpi の画面で字が小さいのをフォント名で底上げする回避策で、*GTK でないアプリ(officework)だけが小さく見える*。
解いて OS の画面倍率 2倍にしたところ揃った(162.6dpi ÷ 2 = 81dpi 相当。
96dpi 設計が実寸の 1.18 倍で出る。
整数倍なので滲みも無い)。

*画面が小さいときの正しい順*: ① OS の画面倍率(設定 → ディスプレイ →拡大/縮小。
箱ごと拡大されるので崩れない。
整数倍が滲まない) ②それでも足りなければ Ctrl+= と Ctrl+ホイール。
*字だけ大きくする設定は使わない*(GNOME の文字倍率・Tweaks のフォント)。

*代わりに在る2本*(どちらも箱ごと動くので崩れない):

* `Ctrl+=` / `Ctrl+-` — 画面の文字(リボンから状態行まで)。settings の``ui_scale``(0.8〜1.5)
* `Ctrl+ホイール` — 格子の拡大縮小(`zoom`)

*画面の dpi は 96 に固定する*(発注者確定 2026-08-14)。
pt→px は 96/72、mm→px は 96/25.4 の1本(calc は util::cell\_font\_px、writer は PX\_PER\_MM)。

*実 dpi を読む案は採らない。* 測ることはできる(EDID: `xrandr` の``600mm x 340mm``、Mutter の D-Bus、Wayland の wl\_output)。
実際この機械は**実 162.6dpi** で、X の申告 96dpi は XWayland の作り値だった。
だが実 dpi で描くと**同じブックが機械ごとに違う紙面になる** — 紙は A4=210mm と物理で決まっており、PDF は 72dpi の pt で出るので、画面だけ機械ごとに動かすと印刷と合わせられない。
「画面と紙が一致する」は**1cm が実寸という意味ではなく、画面の紙面と印刷の紙面が同じという意味**。
実寸で見たい人はCtrl+ホイールで拡大して合わせる。

EDID が嘘をつく機械(プロジェクタ・テレビ・仮想画面で 0mm や出鱈目)がある事も、読まない理由の後押し。

=== 主従の逆転 — Python が主、calc は従(発注者確定 2026-08-15)

*マクロは基本的に無くなる。* calc の中に「Python を呼ぶ口」を並べるのは、データとプログラムを分けた決めと矛盾していた(Python タブに「手続きを実行」「一行のコード」「計算し直す」が並び、**いま開いているブックに何かをする**発想のままだった)。

正しい形はこう:

* *Python が主*。台本を(Zed でも端末でも Jupyter でも)走らせると、*calc が画面つきで起ち上がって操られる*。`xw.Book()` が calc を起こす(pysheet の launch。実装済み)
* *openpyxl はファイルしか触れず画面が無かった。xlwings は Excel とWindows が要った。* officework は自前の画面を持つので、Python から呼べば画面が出て、そこを操れる — ここが売り
* *calc に残るのは「操作の記録」だけ*。手で操作すると Python の行として記録され、台本の下書きになる(何を書けばいいか分かる)
* *UDF は calc の付属物*(セルの関数)。これはこのまま残る。writer では同じ仕組みを**差し込み**として使う
* Python タブは**編集の口だけ**(新しい .py・一覧・置き場を開く)。編集そのものは外の道具へ渡す — settings の `editor`(zed でも何でも)→隣の writer → 機械の既定、の順(ui::open\_for\_edit)

*まだ無い物*: writer の差し込み。

=== 左右のパネル

* *規則: 右=選んでいる物の設定、左=対話する相手*
* 右パネルは選択に追従する設定の盤。writer は種あり(panels.rs「設定 — いる場所を直す」)— 画像・表・数式で切り替わるように。calc は新設 — *既定の面はセルの設定*(塗り・罫線・向き・条件付き書式の入り口)。*罫線の面は場所×ペンで組む* — パレットでは窮屈だった2軸が、開きっぱなしのパネルで生きる(ペンを選んだまま連打)
* 何度も直す設定を小窓からパネルへ移すほど、「小窓中はリボン無効」で止まる場面が減る(補い合い)
* calc の表示タブに「左パネル」「右パネル」を writer と同じ id・同じ札で足す(訳は14言語に既にある)
* 左パネルは細いアイコンの列(ナビ・検索・コメント・チャット・AI)。優先は右が先
* *AI はタブごと廃止*。9つの動詞も廃止 — 対話の面で「これを要約して」と打てば済む。残すのは文脈: 選んでいる範囲が対象・結果を見てから適用・空の欄に例文を薄く。廃止時は 14言語再生成と、要らない鍵の引退を同じ回で
