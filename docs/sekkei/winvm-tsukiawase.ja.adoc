= Windows 11 の Word・Excel との突き合わせ(2026-10-12)

Debian の PC に Windows 11 の仮想マシンを作り、Microsoft 365 の Word と Excel
(16.0.20430)で受け入れ試験の 10 枚を PDF にして、officework の PDF と比べました。
道具は `tools/winvm_pdf.py` で、使い方は HIKITSUGI にあります。

発注者の決め(2026-10-12)「OOXML で基準を確認。なければ Word に合わせる」に従いました。
xlsx は Excel に合わせました。

== 直したこと

[cols="2,3,3"]
|===
|違い |OOXML |決め

|議事録の表の字が 1 字ずつ縦に並び、2 ページになった
|§17.4.16 gridCol(幅の無い列は 0、格子は最初の幅)、§17.18.87 AutoFit
|autofit の表で幅がちょうど 0 の列は、中身の幅まで広げる。設計は new-doc-defaults に書いた

|新しく作る docx に fontTable を置き、「BIZ UDP明朝」に「BIZ UDP明朝 Medium」を付ける

|テンプレートで保存し直すと theme1.xml が 2 つになり、保存が失敗した
|(部品の名前の重複は zip として不正)

|xlsx の余白が Excel と違った
|§18.3.1.62 pageMargins は省いてよく、省いたときの値は無い
|Excel に合わせる。読むときは 0.7・0.75・0.3 インチ。書くときは、余白の無いシートにも紙の 20mm を書く

|上付き・下付きが PDF で小さくならず、上げ下げもされなかった

|Word に合わせ、和文の字と半角の英字・数字の間に 0.25em を入れる。段落とスタイルの指定を読み、書き戻す

== Word で測った値

上付き・下付きは、Word に字の大きさと書体を変えた文書を作らせて測りました。

* 大きさ:和文の書体は 0.6 倍、欧文の書体は 0.65 倍で、0.5pt 単位に丸めます
  (10.5pt は 6.5pt と 7pt、12pt は 7pt と 8pt)。
* 上げ下げ:書体ごとに違いました。上付きは元の大きさの 0.33〜0.42、下付きは 0.04〜0.21 です。
  officework の既定の書体の BIZ UDP明朝 Medium(10.5pt)は、上へ 3.9pt、下へ 1.6pt でした。
  これを小さくした字の大きさの 0.6 倍と 0.25 倍として、どの書体にも使います。
  書体ごとの違いには、まだ合わせていません。

和文と英字・数字の間の空きは、次のとおりでした。

* 漢字・かなと半角の数字の間(DN)、漢字・かなと半角の英字の間(DE)に 0.25em。
* 全角の数字(１)、記号(%、括弧、ハイフン、ピリオド)、和文の句読点(。、)、
  「〜」の前後には入りません。
* 本文に半角の空白を書いた所には、空白の幅だけがあります。

== 確かめたこと

受け入れ試験の docx の 5 枚は、Word の PDF と行ごとに比べて違いが無くなりました。
xlsx は、出勤簿と棚卸表で違いが無くなりました。

== xlsx の残り 3 つ(2026-10-13)

見積書・申込書・月次売上報告の違いを、OOXML で確かめてから直しました。OOXML に基準が
無い所は、Excel に試験用のブックを PDF にさせて測った値を使いました。

[cols="2,3,3"]
|===
|違い |OOXML |決め

|Excel でグラフの図形が基準のセルに寄り集まった
|§20.5.2.11 colOff と §20.5.2.27 rowOff は「セルの中の」ずれ
|書くときに、ずれがセルの中に収まるまで基準のセルを進める(`Cells::within`)

|グラフの目盛りの字が 2 行に折れた
|§21.1.2.1.1 bodyPr の余白の既定は左右 0.1 インチ、上下 0.05 インチ
|グラフの字は余白 0 で置く。図形の字の余白を xlsx に書くようにした(読むだけで書いていなかった)

|ヘッダーとフッターの字が 9pt の灰色だった
|§18.3.1.46 に大きさの指定の書き方はあるが、指定の無いときの大きさが無い
|Excel に合わせ、ブックの既定の書体の大きさで黒く描く。位置はヘッダーとフッターの余白から(下の表)

|データバーが紙に出なかった
|§18.3.1.28 dataBar:長さは minLength + 位置 ×(maxLength − minLength)、既定は 10% と 90%
|紙にもグラデーションで描く。長さの求め方は画面と紙で同じ(`kumihan::look::bar_share`)

|組み込みの表のスタイルの色が出なかった
|§18.8.40 tableStyleElement に当てる順。定義は ECMA-376 の presetTableStyles.xml
|`tools/gen_table_styles.py` で定義を表にし、紙と画面が同じ関数(`book::table_style`)で当てる

|テーマの無い xlsx の色が Excel と違った
|(テーマの無いときの色は書かれていない)
|Excel に合わせ、既定を 2023 年版のテーマにする。officework が書く xlsx には、テーマを必ず書く

|行の高さと列の幅が、Excel の印刷と違った
|§18.3.1.13 は列の幅を数字の幅で数えるが、印刷のことは書いていない
|Excel に合わせる(下の表)。Windows の数え方で読んだ xlsx の紙だけに当て、画面と ods には当てない

|「#」で埋める数が 1 つ多かった
|(Excel の書体の字の幅による)
|Excel の書体の「#」の幅で数える。測った游ゴシック(0.587em)だけを表に入れた
|===

Excel 16.0.20430 で測った値は、次のとおりです。

* 列の幅:幅の数 × 既定の書体の数字の本当の幅で印刷されます。画面は数字の幅を画素に丸めるので、
  游ゴシック 11pt の幅 14 は、画面で 84pt、紙で 85.68pt です。
* 行の高さ:指定した高さ × 書体ごとの係数を、600dpi の点に丸めて印刷されます。係数は
  游ゴシック(名前の無い書体も)が 0.98376、ＭＳ Ｐゴシックが 0.90549 です。10〜45pt の
  12 通りで、どれも 1 点以内に合いました。測っていない書体は、係数を 1 にしています。
* ヘッダーのベースラインは、ヘッダーの余白から 1.236em 下にあります。フッターは、
  フッターの余白から 0.61em 上にあります(11pt で 13.6pt と 6.7pt)。
* データバーは、セルの左と上下から 1.9pt 内側に描かれ、色から白へのグラデーションです。
* Excel の新しいブックのテーマは 2023 年版で、アクセント 1 は #156082 です。既定の書体は
  游ゴシック 11pt、既定の行の高さは 18.75pt です。

LibreOffice 25.2(Collabora と同じ core)で同じ 3 冊を PDF にすると、列の幅は 79.8pt、
行は 18.7pt で、どちらにも合いませんでした。表のスタイルの色も描いていませんでした。

== 残っていること

* 行の高さの係数は、游ゴシックとＭＳ Ｐゴシックしか測っていません。
* 「#」の幅も、游ゴシックしか測っていません。
* 上付き・下付きの上げ下げを、書体ごとの違いに合わせていません。
* 行末に来た 0.25em の空きも行の長さに数えるので、Word より 1 字早く折れることがあります。
