= Word と Excel のテンプレートへの差し込み(sashikomi)

作る側の資料です。検討と決めたことを書きます。作った後の「いまの真実」は
link:../dev/README.ja.adoc[開発者マニュアル]と利用者向けの手引きに移します。

== 目的(2026-09-29 発注者)

Word の差し込み印刷を、Word なしでできるようにします。

昔は、変わる所以外を写した用紙を持っていました。それを Word でやるようになりました。
ただ、Word と Excel の料金は高くなりすぎ、サーバーでは動かせません。これができると、
素人でもシステムを作りやすくなります。

== 決めたこと(2026-09-29 発注者)

* aiseed office(writer と calc をすべての機能を持つ Office にする開発)は、一旦止めます
* 画面は gpui + Vello です。左で adoc を直し、右はテンプレートを当てた結果を見せるだけです
* テンプレートは docx か xlsx で、Word と Excel で作ります。使う人の AI も作れるように
  しておきます
* 右の表示は、今のエンジン(paper)で絵にします
* 差し込みは、うちのエンジン(Rust)で行います。python-docx や openpyxl には任せません
* Python からは、同じエンジンを python-docx と openpyxl と同じ書き方で使えるようにします
* 差し込んだ docx と xlsx の書き出しも、機能に含めます
* AI が書くのは adoc だけです。AI に docx を作らせる必要はありません
* docx と xlsx は、読み込み専用で開けます。人が docx と xlsx を直す機能は、一旦止めます
* adoc にテンプレートの指定が無ければ、今の標準(見た目を書いた toml 形式)を使います
* 印は、Word が名前、Excel が A1 です。Excel は、A1 の代わりに名前(名前の定義)も使えます
* この作業が終わったら、次は Excel と Word の拡張数式を使えるようにします

== 流れ

. 人か AI が、Word か Excel でテンプレートを作り、差し込む所に印を置きます
. 人か AI が、adoc に中身を書きます
. うちのエンジンが、テンプレートを読み、印の所に adoc の中身を入れます。テンプレートの中で
  うちが触らない部品は、元のまま残します(`ooxml::write_with` と `sheet` の xlsx の書き出し)
. 差し込んだ結果を、paper で右に絵にします。書き出しは同じ結果を docx か xlsx に書きます。
  PDF も paper で書きます

画面に見える物と、書き出したファイルは、同じ処理から作ります。

== 印

=== docx:名前

次の 2 つを読みます。どちらも名前で指します。

* `{名前}` と字で書いた物。SEKKEI の決め(2026-08-20、差し込みの穴は `{名前}`)と、
  xlsx の様式(`book::form`)と同じ書き方で、`kumihan::fill::fill_form` が既に読みます。
  Word が字を別々の run に分けていても、つなげてから読みます。前の書き方の `{{名前}}` も読みます
* Word の差し込み印刷のフィールド(`MERGEFIELD 名前`、ECMA-376 Part 1 17.16.5.35)。
  Word の差し込み印刷のために作ったテンプレートを、そのまま使えます。うちはまだ読めないので、
  作ります。読み込みでは字に変えず、相互参照(REF)と同じように「フィールドの印を付けた run」
  として持ちます。開いて保存し直しても、フィールドのまま残ります。見えている字(`«氏名»`)も
  そのまま出します。差し込みのときに、値に置き換えます

=== xlsx:A1 と名前

adoc の側で、セルを A1 の番地で指します(例 `B5`、ほかのシートは `履歴書!B5`)。
テンプレートには何も書き足しません。

A1 の代わりに、Excel の名前の定義(例 `氏名` = `履歴書!$B$5`、ECMA-376 Part 1 18.2.5)の
名前でも指せます。名前は、テンプレートに行や列を足しても Excel が番地を直します。うちの xlsx の
読み込みは、名前の定義を既に読んでいます(`sheet/src/xlsx/read.rs`)。

テンプレートに行や列を足すと、番地がずれます。adoc の側の番地を直さないと、違うセルに入ります。
最初は、人が確かめます(2026-09-29 発注者)。

== データの書き方

既にある `.sheet.adoc` の形を使います。aiai の履歴書のデータ(`履歴書.sheet.adoc`)と同じ形で、
`Book.fill` が読んでいます(`book::form`)。

* 2 列の表(項目と値)が、1 つだけの値です。`{氏名}` は、この表の「氏名」の値になります
* 見出しのある表が、繰り返す行です。`{学歴・職歴.3.内容}` は、3 行目の「内容」の値です
* 日付の年・月・日、和暦、年齢、選ぶ欄などの書き方も、そのまま使えます(`book::form` の説明)

xlsx のテンプレートのときは、2 列の表の項目に、A1 の番地か、名前の定義の名前を書きます。

....
= 履歴書
:template: 履歴書.xlsx

.基本
[cols="1,3"]
|===
|B5 |山田 花子
|氏名ふりがな |やまだ はなこ
|===
....

== 入れるのは値だけ(2026-09-29 発注者)

(a) 値だけを入れる形から始めます。申請書、履歴書、請求書のように、形の決まった書類です。
Word の差し込み印刷と同じです。

adoc の本文(見出し、段落、箇条書き、表)をテンプレートの見た目で組む形(b)は、作りません。
python-docx でできます(発注者)。SEKKEI の 2026-08-20 の決め(名前の付いた段落を丸ごと
差し替える形は作らない)とも合います。

== 書き出しの形:テンプレートに直に書き込む(2026-09-29)

差し込んだ結果は、うちのモデルから作り直さず、テンプレートのファイルに直に書き込みます。
うちのモデルが持たない書式も、差し込んだ後にそのまま残すためです。値を入れた所の無い部品は、
縮めたままのバイトで写します。

* xlsx(`sheet::xlsx::patch`):値の変わるセルだけを、そのシートの XML に書きます。字は
  セルの中に直に書く形(`t="inlineStr"`)で、数は数で入れ、セルの書式の番号は残します。
  厚生労働省の履歴書で、値を 4 つ入れると、変わる部品はシート 1 つだけでした(モデルから
  書き直すと、9 つの部品を書き直し、文書の情報を落としていました)
* docx(`ooxml::patch`):本文・ヘッダー・フッターの、印と差し込み印刷のフィールドの字だけを
  変えます。Word が印を書式の違う run に分けていても、段落の字をつなげて探します。値は、印の
  始まる run の書式で入ります。差し込み印刷のフィールドは、値を持つ run 1 つになります。Word の
  テンプレート 2 つで、変わる部品は本文だけでした
* 画像(xlsx):テンプレートの図形に、Excel の名前ボックスでデータの項目と同じ名前(`写真`)を
  付けておくと、データに書いた画像がその図形の中に入ります。いまは PNG と JPEG です
  (2026-09-29 発注者「画像を急ぐよりも、基本を大切にして」。SVG とほかの種類は後にします)

Python からは `sheet.Book.fill_template(テンプレート, データ, 書き出す先)` と
`doc.Doc.fill_template(テンプレート, データ, 書き出す先)` で使います。

== 画面

新しいアプリは作らず、今の writer を残して、要らないメニューを隠します(リボンの設定ファイル)。
隠すだけでは、キーやソケットの命令から隠した機能に届くので、差し込みの形で使える操作は
コードの側(`usable_here` と `run_cmd`)でも絞ります。

* データの adoc を開くと、左にコード、右に差し込んだ結果のページ(hyouji-e で作ったコードの
  画面を元にします)
* docx と xlsx を開くと、ページの絵で見せるだけです。カーソルも入力も受けません。編集の仕組みは
  消さずに、この形では使えないようにします

2026-09-29 の見直しで見つかった、ファイルを壊す道は直してから使います。

* ファイルのタブを移って戻ると、コードの画面の状態が戻らない
* 開けなかったファイルがあると、コードの画面の状態が消える
* 落ちたときの控えを、adoc の書き出しで書いている
* 名前を付けて保存の既定の拡張子が docx になる
* 表や画像を入れても、保存で消える

== 右の表示を Word と Excel に合わせる(2026-09-29)

右の表示は、差し込んだ結果を paper で絵にした物です。Word と Excel が PDF にした物と比べて、
違いを直しました。

=== 比べ方

* Word と Excel に PDF を作らせるのは `tools/ms_pdf.py` です。Word や Excel の画面にダイアログが
  出ていると、応答しなくなります。そのときは画面のダイアログを閉じてから、もう一度回します。
* うちの絵と Word や Excel の PDF を並べるのは `tools/screen_compare.py` です。docx と xlsx の
  両方を読みます。Mac の Excel で作った PDF と比べるときは `--platform mac` を付けます。
* 行ごとの位置は、PDF の字の位置(pdfplumber)で比べます。
* メイリオ UI の文書は、書体を游ゴシックかヒラギノ角ゴシックに替えた写しで比べます
  (2026-09-29 発注者「メイリオ UI は、できるだけ使わないで」)。Word for Mac は、ヒラギノを
  英語の名前「Hiragino Sans W3」でしか見つけません。ほかの名前では游ゴシックで描きます。

=== Mac の Excel と Windows の Excel の違い

同じ xlsx でも、Mac の Excel と Windows の Excel では刷り上がりが違います。

* 列の幅:ECMA-376 の 18.3.1.13 は、数字 1 字の幅と文字数から、96 dpi の画素で列の幅を
  出す式を書いています。Mac の Excel は、同じ式を 72 dpi で使うようです。厚生労働省の履歴書
  (標準の書体は ＭＳ Ｐゴシック 11pt)では、幅 10 の列が Windows の式では 52.5pt、Mac の Excel
  では 60pt でした。列が約 14% 広くなるので、Mac の Excel では左半分が 1 ページに入らず、
  8 ページになります。
* 行の高さ:Mac の Excel は、行の高さを pt の整数に切り下げます(28.5pt が 28pt)。
* うちは、指定が無ければ Windows の読み方です。Mac の読み方は
  `sheet.Book.open(パス, platform="mac")` です。Mac の読み方で比べると、ページ数と列の境目が
  Mac の Excel と合いました(列の境目の差は 0.2pt 以内)。
* 厚生労働省が出している履歴書の PDF(Windows の Excel)は、元の xls から作られています。
  この xlsx とは行の高さや列の幅が違うので、この xlsx の比べる相手にはなりません。

=== 規定と Word が違った所

* 句読点のはみ出し(`w:overflowPunct`):17.3.1.21 は、書いていなければはみ出してよい、と
  しています。Microsoft の実装の説明(MS-OI29500)も、日本語で行末からはみ出してよい字に
  「、」を挙げています。Word for Mac は、レターヘッドの本文で「、」をはみ出させずに、1 字前で
  折りました。うちは規定どおりに組みます(2026-09-23 の方針「何でも Office の真似をしない」)。
* 下線の位置(`w:u`):17.3.2.40 は「字の高さのすぐ下」とだけ書いています。Word は、欧文の
  書体では書体の推奨値(post 表の underlinePosition と underlineThickness)で引きます。和文の
  書体では、推奨値とも字の下がりとも合わない位置に引きます。

=== Word で測った値

どれも Word for Mac の PDF で、書体だけを変えた小さな文書を作って測りました。

* ヒラギノ角ゴシック W3 の 1 行の高さは 1.30em です(10.5pt、12pt、20pt で同じ)。書体の
  値(hhea)は 1.5em で、Windows 用の値は 1.234em です。17.3.1.33 は 1 行の高さの出し方を
  決めていないので、測った値を表に入れました。
* ヒラギノ角ゴシック W3 の基準線は、行の上から 1.03em の所です。0.9 倍の行では、その 0.9 倍
  です。
* 太字の書体を持たない書体を太字にすると、Word は 1 字ごとに 0.02em 広げます(ヒラギノ角ゴシック
  W3、ヒラギノ明朝 W3、ＭＳ 明朝、ＭＳ ゴシック、Century)。半角スペースは広げません。
  全角スペースは測っていません。
* 游ゴシックの 1 行の高さは、Word for Mac では 1.44em でした。表には 1.5em(前に別の文書で
  測った値)が入っています。Windows の Word と違うのかは確かめていません。

=== 決めてもらったこと(2026-09-29 発注者)

* 下線は、書体の推奨値(post 表)の位置と太さで引きます。値を持たない書体は、今までどおり
  基準線の 0.18em 下に、字の大きさの 20 分の 1 の太さで引きます。
* 右揃えのセルは、文の終わりの全角スペースを幅に数えません。文頭の全角スペースは数えます。
* 改ページをまたぐ図形は、Excel と同じく、届くページのそれぞれにそのページの範囲で切って描きます。
* 極細線(`hair`)は、2026-09-24 の決めどおり、Windows の Excel の PDF に合わせた 0.12pt の
  実線です(Mac の Excel は点線で描きます)。

=== Windows で確かめること

次のことは、Windows の Word と Excel が無いと決められません。

* 游ゴシックの 1 行の高さ
* 和文の書体の下線の位置
* 右揃えのセルの末尾の全角スペースを、Windows の Excel がどう扱うか
* Mac で保存された xlsx を、指定が無いときにどちらの読み方にするか

== 段取り

== sashikomi ブランチに持ってきた物(2026-09-29)

hyouji-e から、新しい目標に使える物だけを、ファイル単位で持ってきました。

* セルの大きさの決まり(`booktmpl.rs` の `sized_by_runs`)
* adoc の誤りを、ファイルの行の番号で出す(`adoc.rs`)
* paper:ページのデータを作る処理の共通化、絵を PDF と同じ順で描く、PNG に図形とヘッダーを出す
* 比べる道具 `tools/screen_compare.py`

持ってくるときに、見直しで見つかった誤りを直しました。

* 蛍光ペンの色の名前が黒になっていた
* PDF で、半透明が後ろの線と字に残っていた
* ページの絵の字に、下線、取り消し線、字の間隔、書体に無い字の補いが無かった
* 比べる道具が、薄い網掛けの違いを数えなかった
