= Word と Excel のテンプレートへの差し込み(sashikomi)

作る側の資料です。検討と決めたことを書きます。作った後の「いまの真実」は
link:../dev/README.ja.adoc[開発者マニュアル]と利用者向けの手引きに移します。

== 目的(2026-09-29 発注者)

Word の差し込み印刷を、Word なしでできるようにします。

昔は、変わる所以外を写した用紙を持っていました。それを Word でやるようになりました。
ただ、Word と Excel の料金は高くなりすぎ、サーバーでは動かせません。これができると、
素人でもシステムを作りやすくなります。

== 決めたこと(2026-09-29 発注者)

* aiseed office(writer と calc をすべての機能を持つ Office にする開発)は、一旦止めます
* 画面は gpui + Vello です。左で adoc を直し、右はテンプレートを当てた結果を見せるだけです
* テンプレートは docx か xlsx で、Word と Excel で作ります。使う人の AI も作れるように
  しておきます
* 右の表示は、今のエンジン(paper)で絵にします
* 差し込みは、うちのエンジン(Rust)で行います。python-docx や openpyxl には任せません
* Python からは、同じエンジンを python-docx と openpyxl と同じ書き方で使えるようにします
* 差し込んだ docx と xlsx の書き出しも、機能に含めます
* AI が書くのは adoc だけです。AI に docx を作らせる必要はありません
* docx と xlsx は、読み込み専用で開けます。人が docx と xlsx を直す機能は、一旦止めます
* adoc にテンプレートの指定が無ければ、今の標準(見た目を書いた toml 形式)を使います
* 印は、Word が名前、Excel が A1 です。Excel は、A1 の代わりに名前(名前の定義)も使えます
* この作業が終わったら、次は Excel と Word の拡張数式を使えるようにします

== 流れ

. 人か AI が、Word か Excel でテンプレートを作り、差し込む所に印を置きます
. 人か AI が、adoc に中身を書きます
. うちのエンジンが、テンプレートを読み、印の所に adoc の中身を入れます。テンプレートの中で
  うちが触らない部品は、元のまま残します(`ooxml::write_with` と `sheet` の xlsx の書き出し)
. 差し込んだ結果を、paper で右に絵にします。書き出しは同じ結果を docx か xlsx に書きます。
  PDF も paper で書きます

画面に見える物と、書き出したファイルは、同じ処理から作ります。

== 印

=== docx:名前

次の 2 つを読みます。どちらも名前で指します。

* `{名前}` と字で書いた物。SEKKEI の決め(2026-08-20、差し込みの穴は `{名前}`)と、
  xlsx の様式(`book::form`)と同じ書き方で、`kumihan::fill::fill_form` が既に読みます。
  Word が字を別々の run に分けていても、つなげてから読みます。前の書き方の `{{名前}}` も読みます
* Word の差し込み印刷のフィールド(`MERGEFIELD 名前`、ECMA-376 Part 1 17.16.5.35)。
  Word の差し込み印刷のために作ったテンプレートを、そのまま使えます。うちはまだ読めないので、
  作ります。読み込みでは字に変えず、相互参照(REF)と同じように「フィールドの印を付けた run」
  として持ちます。開いて保存し直しても、フィールドのまま残ります。見えている字(`«氏名»`)も
  そのまま出します。差し込みのときに、値に置き換えます

=== xlsx:A1 と名前

adoc の側で、セルを A1 の番地で指します(例 `B5`、ほかのシートは `履歴書!B5`)。
テンプレートには何も書き足しません。

A1 の代わりに、Excel の名前の定義(例 `氏名` = `履歴書!$B$5`、ECMA-376 Part 1 18.2.5)の
名前でも指せます。名前は、テンプレートに行や列を足しても Excel が番地を直します。うちの xlsx の
読み込みは、名前の定義を既に読んでいます(`sheet/src/xlsx/read.rs`)。

テンプレートに行や列を足すと、番地がずれます。adoc の側の番地を直さないと、違うセルに入ります。
最初は、人が確かめます(2026-09-29 発注者)。

== データの書き方

既にある `.sheet.adoc` の形を使います。aiai の履歴書のデータ(`履歴書.sheet.adoc`)と同じ形で、
`Book.fill` が読んでいます(`book::form`)。

* 2 列の表(項目と値)が、1 つだけの値です。`{氏名}` は、この表の「氏名」の値になります
* 見出しのある表が、繰り返す行です。`{学歴・職歴.3.内容}` は、3 行目の「内容」の値です
* 日付の年・月・日、和暦、年齢、選ぶ欄などの書き方も、そのまま使えます(`book::form` の説明)

xlsx のテンプレートのときは、2 列の表の項目に、A1 の番地か、名前の定義の名前を書きます。

....
= 履歴書
:template: 履歴書.xlsx

.基本
[cols="1,3"]
|===
|B5 |山田 花子
|氏名ふりがな |やまだ はなこ
|===
....

== 入れるのは値だけ(2026-09-29 発注者)

(a) 値だけを入れる形から始めます。申請書、履歴書、請求書のように、形の決まった書類です。
Word の差し込み印刷と同じです。

adoc の本文(見出し、段落、箇条書き、表)をテンプレートの見た目で組む形(b)は、作りません。
python-docx でできます(発注者)。SEKKEI の 2026-08-20 の決め(名前の付いた段落を丸ごと
差し替える形は作らない)とも合います。

== 画面

新しいアプリは作らず、今の writer を残して、要らないメニューを隠します(リボンの設定ファイル)。
隠すだけでは、キーやソケットの命令から隠した機能に届くので、差し込みの形で使える操作は
コードの側(`usable_here` と `run_cmd`)でも絞ります。

* データの adoc を開くと、左にコード、右に差し込んだ結果のページ(hyouji-e で作ったコードの
  画面を元にします)
* docx と xlsx を開くと、ページの絵で見せるだけです。カーソルも入力も受けません。編集の仕組みは
  消さずに、この形では使えないようにします

2026-09-29 の見直しで見つかった、ファイルを壊す道は直してから使います。

* ファイルのタブを移って戻ると、コードの画面の状態が戻らない
* 開けなかったファイルがあると、コードの画面の状態が消える
* 落ちたときの控えを、adoc の書き出しで書いている
* 名前を付けて保存の既定の拡張子が docx になる
* 表や画像を入れても、保存で消える

== 段取り

. 印を読む:docx の `MERGEFIELD`(`{名前}` は既に読める)、xlsx の A1 と名前の定義
. 差し込み:データの値をテンプレートに入れ、docx と xlsx に書く(テンプレートの部品は元のまま)
. Python から使う形(python-docx と openpyxl と同じ書き方)
. 画面:writer の差し込みの形。右の表示は差し込んだ結果を paper で絵にする
. 書き出し:docx、xlsx、PDF
. AI にテンプレートを作らせる手順(スキル)と、見本のテンプレート

== sashikomi ブランチに持ってきた物(2026-09-29)

hyouji-e から、新しい目標に使える物だけを、ファイル単位で持ってきました。

* セルの大きさの決まり(`booktmpl.rs` の `sized_by_runs`)
* adoc の誤りを、ファイルの行の番号で出す(`adoc.rs`)
* paper:ページのデータを作る処理の共通化、絵を PDF と同じ順で描く、PNG に図形とヘッダーを出す
* 比べる道具 `tools/screen_compare.py`

持ってくるときに、見直しで見つかった誤りを直しました。

* 蛍光ペンの色の名前が黒になっていた
* PDF で、半透明が後ろの線と字に残っていた
* ページの絵の字に、下線、取り消し線、字の間隔、書体に無い字の補いが無かった
* 比べる道具が、薄い網掛けの違いを数えなかった
