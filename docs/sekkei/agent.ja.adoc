= エージェントパネルの設計
:toc:

2026-08-31 起こし(Fable)。決めの出どころは SEKKEI の続き14・続き19・
続き20とその続き(発注者の指示)。これは作る側の文書です。利用者向けの
説明は、動くようになってから手引きに書きます。

== 何を作るか

**マクロとデータを直接扱えるエージェントと対話しながら、文章や表や
コードを書けるアプリにする**(2026-08-31 発注者)。エージェントは
アプリの中に住み、左のエージェントパネルで対話する。設定なしで、
開いたらもう隣にいる。

Microsoft 365 との違いはここに出る。Copilot は文書について話す
(要約と下書きを出す)だけで、文書とデータとマクロを操作できない。
こちらのエージェントは、セルとデータフレームを直接読み書きし、
マクロを書いて動かし、その結果を見て続きを考える。モデルは手元の
物でよく、データは機械から出ない。

== 立ち位置 — 同じ語彙に入り口が3つ

操作の語彙(ops)は1つで、入り口だけが違う。

[cols="1,2,2"]
|===
|入り口 |誰のためか |道

|エージェントパネル |普通の利用者。設定なし |語彙を**直に呼ぶ**(ソケットも MCP も経由しない)
|Python |コードを書く人 |officework.sheet / doc / calc
|MCP |外の AI を繋ぐ人 |officework-mcp(標準入出力)
|===

エージェントが使える道具を増やすときは、まず ops の語彙に足す。
そうすれば3つの入り口に同時に増える。エージェント専用の隠れた道具は
作らない。

== ループ — oh-my-pi の蒸留

ループの骨は oh-my-pi(MIT。pi の fork)から蒸留する。写すのは
設計だけで、作法どおり実装は写さない。

- **往復**: モデルに道具の一覧を渡し、返ってきた道具呼びを実行し、
  結果を渡して続きをもらう。道具呼びが無くなったら1つの答え
- **提供元の切り替え**: 宛先は**名前つきの一覧**で持ち、対話の途中でも
  替えられる(下の「提供元の一覧」)。OpenAI 互換の API
  (`lang::model::Endpoint`)。序列は付けない — 手元のモデルも
  クラウドも同じ扱い(決め 985aa858)
- **セッション**: 対話と道具呼びの記録を綴りの中に持つ(後述)
- **写さない物**: omp の32道具(コード用)・LSP・デバッガ。道具は
  うちの語彙。サブエージェントは v1 では作らない

機能の追いかけっこはしない。「機能では勝負しない」はエージェントにも
効かせる — ループの骨だけ写し、あとは事務の道具として育てる。

== 置き場 — 新クレート agent

- **agent/(新クレート)**: ループの本体。gpui を持たない(face と
  同じ決め — 試験できて、他の機械でも組める)。lang に依存して
  Endpoint を使う。道具の実行は trait で受け取る — アプリの側が
  語彙への結線を渡す(calc の Host と同じ形)
- **lang::model に道具呼びを足す**: いまの chat(system, user) に、
  tools の一覧と tool_calls の往復を足す(OpenAI 互換の形のまま)
- **画面**: 左のエージェントパネル(いまの「AI に相談」の面を育てる)。
  描きは writer / calc が共用できる形で ui に置く

== 道具 — v1 は MCP と同じ一覧

最初に繋ぐ道具は、MCP がいま渡している一覧と同じにする(表: ブックの
情報・範囲の読み書き・数式・書式・自動調整・保存。文書: 本文の
読み書き・記入欄・差し込み・PDF)。実装済みの語彙なので、結線だけで
動く。

それに1つだけ足す: **マクロを書いて動かす**。エージェントが Python を
書き、見える .py として置き、サンドボックスで走らせ、結果(出力か
エラー)を受け取る。エージェントの賢さの中心はこれ — 定型の道具に
無い仕事は、コードを書いて解く。

== 提供元の一覧(2026-09-02 発注者 — ここは oh-my-pi を参考に)

宛先は settings.toml に**名前つきの一覧**で持つ。

[source,toml]
----
[[ai]]
name = "手元"
url = "http://127.0.0.1:8000/v1/chat/completions"
model = "local"

[[ai]]
name = "会のサーバー"
url = "https://ai.example.org/v1/chat/completions"
model = "gpt-oss-120b"
key_env = "OFFICE_API_KEY_KAI"
----

- パネルに今の宛先の名前を出し、押すと一覧から選べる。**対話の
  途中で替えても履歴は続く**(履歴は OpenAI 互換の形で持つので、
  提供元に依らない)
- 鍵は `key_env` に**環境変数の名前だけ**を書く。鍵そのものを
  設定ファイルに書かない決めはそのまま
- 既定は最後に使った宛先。まだ無ければ一覧の1番目。一覧が空なら
  「未設定」
- 今までの `ai_url` / `ai_model` は一覧の1行として読み続ける
  (後方互換)。校正などの既存の AI 機能も後からこの一覧に乗せる —
  エージェント専用の設定にはしない

=== Claude と直接話す(2026-09-04 発注者「パネルで直接 Claude と話すのも大丈夫」)

公式の資料で確かめた事実(2026-09-04):

- 今の4つ: Claude Fable 5.1(`claude-fable-5-1`、$10/$50 per MTok)、
  Claude Opus 5(`claude-opus-5`、$5/$25)、Claude Sonnet 5(`claude-sonnet-5`、
  $2/$10)、Claude Haiku 4.5(`claude-haiku-4-5`、$1/$5)。上の3つは文脈 100 万、
  出力 128K。Haiku は 200K と 64K。パネルの既定は Sonnet 5(速さと値段)
- Anthropic は **OpenAI 互換の口も持つ**: `https://api.anthropic.com/v1/chat/completions`、
  鍵は `Authorization: Bearer`、道具呼びは全部通る。ただし公式は「試験と比較の
  用途で、多くの場合は本番向けではない」と書き、prompt caching と thinking の
  細部と structured outputs は native の口だけ。**だから今日でも `[[ai]]` に
  この url を書けば、いまの実装のままパネルで Claude と話せる**
- native の口(messages)は `POST /v1/messages`、`x-api-key` と
  `anthropic-version: 2023-06-01`、`max_tokens` 必須、道具は `input_schema`、
  返りは `tool_use` の塊、結果は user の `tool_result`(`tool_use_id`、
  `is_error`)、`stop_reason` は end_turn / tool_use / max_tokens / stop_sequence
- モデルの一覧は `GET /v1/models`(新しい順。`max_input_tokens` `max_tokens`
  `capabilities` 付き)。選ぶ画面はこれを引く

決め(2026-09-04 発注者): **開発の間は OpenAI 互換の口で繋ぐ**(「テスト・
比較用途限定で本番非推奨、これで問題ない。開発は本番ではない」)。ただし
「今は動作しているけど、いつ禁止されるかわからない。本番に組み込むと困る」
ので、**アプリを公開する(本番)までに native の口(messages)を足し、表の
anthropic の行はそちらに切り替える**。表の「当面は openai-completions でも可」は
開発の間の話。この機械の settings.toml には Claude の行を書いた。

**API キーは定額とは別の従量の課金**(2026-09-04 発注者の指摘)。さらに
`ANTHROPIC_API_KEY` は Claude Code も読むので、シェルに置くと Claude Code
まで従量に切り替わる。うちの表の既定の変数名は `ANTHROPIC_API_KEY` のまま
(本家の作法)だが、**Claude Code を使う人は `key_env` を別の名前
(`OFFICE_API_KEY_CLAUDE` など)にする**。手引きにもそう書く。定額を使いたい
なら道は Claude Code 経由(上の「条件付きで可」)しか無い。

=== Claude の定額(2026-09-04 発注者「claude 定額は使えるようにしておいて」)

本家は Claude Pro / Max の定額を使えるが、その作りは **Claude Code に
なりすます**物だった。Claude Code の版番号と User-Agent、請求用の指紋、
本文の照合値、「You are Claude Code」の system 文まで写し、Anthropic の
側に Claude Code だと見せている。Anthropic は定額を自社のアプリに限って
いるので、これはその制限をすり抜ける形になる。**この部分は写さない**
(Fable の判断。相手がどの会社でも同じ)。

定額を活かす道は2つある。

. Claude Code(定額に含まれる)に `officework-mcp` を登録し、Claude Code の
  側から officework を操る。今もある道(手引き「自分の AI から calc を操る」)
. パネルから手元の `claude` コマンド(Claude Code)を呼び、officework の
  道具を MCP で渡す。技術的には作れる。規約は確かめた(下)

パネルの中で Claude と直接話すなら、API キー(従量)が正規の道。表の
anthropic の行がそれ。

==== 「本番非推奨」と「禁止」は別の物(2026-09-04 発注者の問い)

公式の資料(code.claude.com/docs/en/legal-and-compliance、2026-09-04 に読んだ)で
3つに分かれる。

[cols="1,2,2"]
|===
|区分 |何が |守らされる物

|非推奨(使ってよい)
|OpenAI 互換の口を API キーで使う。公式は「試験と比較の用途で、多くの場合は
本番向けではない」と書くだけ。「壊す変更はしない」とも書いてある
|機能が一部無い(prompt caching・structured outputs)。将来の変更に自分で
追いつく。規約の問題は無い

|禁止(規約違反)
|Free / Pro / Max の OAuth トークンを他のアプリで使う(Agent SDK も含む)。
Claude.ai のログインを自分のアプリに付ける。認証の情報を預かる・仲介する。
oh-my-pi の「Claude Code へのなりすまし」はこれ
|Consumer Terms の違反。2026-04-04 から遮断されている。利用者の
アカウントが止まる。officework の名にも傷が付く

|条件付きで可
|**改変していない Claude Code の実行ファイル**を、利用者自身のログインで
動かす(「プラットフォームが Claude Code を載せる」形を公式が明記)
|Commercial Terms への同意。実行ファイルを改変しない・認証の方法を
外さない。利用者が自分で認証し、費用は利用者に付く。名前とロゴを自分の
製品名に使わない。Pro / Max の上限は「個人の普通の使い方」を前提
|===

つまり道2(パネルから `claude` を呼ぶ)は、officework が `claude` を
改変せずに子プロセスとして起動し、ログインは利用者が Claude Code 自身の
流れで済ませ、officework は認証の情報に触らない、という形なら規約の内に
入る。Commercial Terms への同意が要るので、**やるかどうかは発注者の決め**。
道具は MCP(`officework-mcp`)で渡せるので、作りは今ある物の組み合わせ。

=== 宛先「Claude Code」— `claude -p` を子プロセスで呼ぶ(2026-09-04 発注者「この形で設計して」)

定額(Pro / Max)を規約の内で使う唯一の形。officework は Claude Code を
改変せず、子プロセスとして起動し、道具は MCP で渡す。ログインは Claude Code
自身の流れで済ませ、officework は認証の情報に触らない。Anthropic の側からは
Claude Code の普通の利用として見える。

事実は公式の資料で確かめた(2026-09-04。code.claude.com の headless・
cli-reference・mcp・agent-sdk/streaming-input)。手元の `claude` は 2.1.259。

==== 起動の形

[source,text]
----
claude -p
  --output-format stream-json --input-format stream-json --verbose
  --model sonnet                         # 選んだ物。sonnet / opus / haiku / fable
  --tools ""                             # Claude Code 自身の道具(Bash・Read・Edit…)を全部止める
  --mcp-config '{"mcpServers":{"officework":{"command":"<綴りの .venv>/bin/officework-mcp","args":["--panel"]}}}'
  --strict-mcp-config                    # これ以外の MCP を読まない
  --allowedTools "mcp__officework__*"    # うちの道具は確認なし(読みは黙って、書きは1手)
  --permission-mode dontAsk              # それ以外は断る(問い合わせの画面は無い)
  --system-prompt "<AGENT_SYSTEM と同じ文>"
  --max-turns 30
----

- **`--bare` は使わない。** bare は OAuth の資格を読まないので定額が効かない
  (公式に明記)。代わりに `--strict-mcp-config` と、作業ディレクトリを綴りの
  フォルダでなく `~/.config/officework/agent/` にすることで、プロジェクトの
  hooks や CLAUDE.md を読ませない
- **1つの会話 = 1つのプロセス。** 標準入力に
  `{"type":"user","message":{"role":"user","content":"…"}}` を1行書くと1往復。
  標準出力の JSON 行を読み、`result` の行が来たら答え。「新しい会話」で
  SIGINT を送って終え、次の会話で起動し直す
- 読む行: `system/init`(モデル・MCP の状態。`mcp_server_errors` があれば
  officework-mcp が立っていない)、`assistant`(文と `tool_use`)、`user`
  (`tool_result`)、`result`(答え・`session_id`・費用の見積り)、
  `system/api_retry`(繋ぎ直し中)。道具呼びの行は今の決めどおり
  `read_range B2:D4` のように小さく出すだけ
- `result` の `session_id` を記録(`.agent.txt`)に残す。アプリを開き直した後に
  「続きから」を選べば `--resume <id>` で続く(Claude Code が自分の記録を持つ)

==== 道具

officework-mcp は**動いている本体に AF_UNIX のソケット(ops の命令)で
話しかける**作りなので、パネルからの書き替えも ops を通り、1手として入る。
つまり道具の実体は今の物のまま。足すのは2つ。

. `officework-mcp --panel`: パネルから起動された印。今の MCP は「任意の
  コードを走らせる道具は置かない」決めで run_macro を持たないが、パネルの
  マクロは見える .py + bubblewrap で本体の機能なので、`--panel` の時だけ
  `run_macro` を差し出す(実体は ops に `macro` の命令を足し、本体の側で
  今の agent::tools と同じ道を通す)。外の AI に登録した officework-mcp
  (`--panel` なし)は今までどおり持たない

==== 起動の形

[source,text]
----
codex exec --json -
  -c model="gpt-5.6-terra"                       # 選んだ物
  -c features.shell_tool=false                   # Codex 自身のシェルを止める
  -c sandbox_mode="read-only"
  -c approval_policy="never"                     # 問い合わせの画面は無い
  -c web_search="disabled"
  -c 'mcp_servers.officework.command="<綴りの .venv>/bin/officework-mcp"'
  -c 'mcp_servers.officework.args=["--panel"]'
  -c mcp_servers.officework.startup_timeout_sec=30
  --ignore-user-config --ignore-rules            # 利用者の ~/.codex の設定と規則を読まない
----

- 頼みは標準入力(`-`)で渡す。1回の `codex exec` が1往復。**続きは
  `codex exec resume <SESSION_ID>`**(Claude Code の `--input-format stream-json`
  のようにプロセスを生かしたまま続ける形は無いので、1往復ごとに起動する)
- 読む行: `thread.started`(session の id)、`turn.started` / `turn.completed`、
  `item.completed`(`agent_message` が文、`mcp_tool_call` が道具呼び)。
  道具呼びは今の決めどおり小さく1行
- `--ignore-user-config` は利用者の設定を読まない印なので、必要な設定は全部
  `-c` で渡す(上の形)。`--ephemeral` は続きが効かなくなるので使わない
- 状態は `codex login status`。ログインしていなければ「未設定」で、
  状態行に「端末で `codex login` を実行してください」と出す。ログインの画面は
  officework が作らない(Claude Code と同じ)
- モデルは表の既定(gpt-5.6-terra)と、公式の一覧にある gpt-5.6 の3つ
  (sol / terra / luna)。`/v1/models` は引かない

`codex exec` の2つが増える)。3つ目の CLI(Gemini CLI など)が出ても同じ形で足せる。

=== writer にも同じパネル(2026-09-04 発注者「Word の方にもいれて。こちらの差がもっと大きくなる」)

==== なぜ差が大きいか

Word の Copilot は文書について話す(要約・下書き・書き直しの提案)だけで、
文書の中身を意味の単位で読み書きしない。officework の文書は本文が AsciiDoc
(意味エディタの決め)なので、エージェントは見出し・段落・表・記入欄という
単位でそのまま読み、そのまま書ける。様式の記入欄を埋める・差し込む・PDF に
する・マクロで一括で直す、が全部道具として揃う。表計算より「文書の構造を
道具で扱える」ことの差が大きい。

==== トークンの量(2026-09-04 発注者の問い「docx と adoc で差は大きくならないか」)

大きくなる。手元の docx 7 枚を engine で AsciiDoc にして測った(字の数からの
目安。日本語は1字≈1トークン、英数字と XML の記号は4バイト≈1トークン)。

[cols="2,>1,>1,>1,>1"]
|===
|文書 |document.xml のトークン目安 |AsciiDoc のトークン目安 |倍 |本文の字

|報告書(sample) |1,171 |226 |5.2 |241
|議事録(sample) |920 |227 |4.1 |255
|カタログ(sample) |6,766 |801 |8.4 |1,034
|送付状(sample) |718 |166 |4.3 |188
|操作手順書(test) |952 |191 |5.0 |159
|開催通知(test) |821 |134 |6.1 |149
|プロジェクト報告書(python-docx 製) |4,046 |687 |5.9 |671
|===

これはどれも生成した素直な docx で、rsid も run ごとの書式もほとんど無い。
Word で人が書いた docx は run が字ごとに割れ、rsid と rPr が付くので差は
もっと開く(様式の docx は 18,802 要素のうち本文は 154 だった — 決めの記録)。
さらに XML 全体(styles・numbering・theme)は 1 枚あたり約 800KB ある。

だからエージェントに docx を見せない。writer は docx を開いた時点で模型に
読み、道具が返すのは AsciiDoc のブロックだけなので、**docx で来ても adoc で
来てもエージェントが払うトークンは同じ**。outline と read_blocks で触る所だけ
読むので、長い文書でも量は「触った分」で決まる。

==== いまの writer

- 左パネルに「AI と相談」の面はあるが道具が無い。直した文を囲みで受け取り、
  人が「入れる」を押す形(writer/src/lib.rs の AiJob::Chat)
- ソケット(writer/src/rpc.rs)の命令は text / set_text(本文の丸ごと)・
  fields / merge_fields / fill_field / fill_one・open / save / to_pdf。
  officework-mcp の `doc_*` はこれを包んでいる
- マクロは既にある: bubblewrap の中の python-docx(AiJob::Macro、doc.rs)

==== 決め

. **パネルは calc と同じ物を使う。** リボンを1つにする決めと同じで、
  描きは ui に1つ、状態(4語)・道具呼びの1行・1手の印・記録の形・宛先の
  一覧と切り替え、全部共通。違うのは道具の一覧と system の文だけ
. **calc と同じく、相談の面はエージェントになる。** 「囲みで受けて入れる」
  形は廃止し、書き替えは道具で直接入り、1手で戻す
. **文書の道具は意味の単位で。** 本文の丸ごとの読み書きでは、長い文書で
  1か所直すのに全文を往復することになる。ブロック(段落・見出し・表・
  塊)の番号で読み書きする道具を ops の語彙に足す。中身は AsciiDoc の
  そのままの字
+
[cols="1,2"]
|===
|道具 |何をするか

|doc_info |題・テンプレート・ブロックの数・記入欄の数・選んでいる範囲
|outline |見出しの一覧(段と番号)。長い文書の地図
|read_blocks(from, to) |その範囲のブロックを AsciiDoc の字で返す(番号付き)
|replace_blocks(from, to, adoc) |その範囲を書き替える。1手
|insert_blocks(at, adoc) |その前に差し込む。1手
|delete_blocks(from, to) |消す。1手
|find(text) |字を探してブロックの番号で返す
|fields / fill_fields(values) |記入欄の一覧と記入(今の fill_field を値の組で)
|to_pdf(path) / save |今の物のまま(保存は確認のボタン)
|run_macro(code) |サンドボックスの Python。**渡すのは AsciiDoc の字、返すのも AsciiDoc の字**(下)
|===
+
**マクロは docx を通さない**(2026-09-04 発注者「docx で渡して docx でもらうのは
効率が悪い」)。今の AiJob::Macro は python-docx に docx を渡して docx を受け取る
形だが、これは docx を作って読む往復が毎回入る上に、モデルが python-docx の
書き方(run・段落・表のオブジェクト)を書かなければならない。パネルのマクロは
`src`(文書の AsciiDoc の字)を受け取り、直した字を返す普通の Python にする。
本体はそれを adoc として読み直して1手で入れる。ブロックの番号を付けた形で
渡せるので、「3番から 40 番の見出しを一段下げる」のような一括の直しが
字の処理で書ける。docx は開く時と保存する時の端にだけ現れる(writer は
意味エディタ + レンダラの決め)。python-docx のマクロは、docx そのものを直す
特殊な用途として残すかどうかを別に決める(Python の文書 API officework._doc も
python-docx の上にあるので、同じ問いになる — 決め待ちに追加)
+
ブロックの番号は `Document.blocks` の添字で、読んだ時の字を持たせて
(表のセルと同じ照合の考え)書き替えの前にずれを見る。**選んでいる範囲が
相談の相手**(calc の範囲と同じ)。選んでいれば doc_info にブロックの
番号で入る
. **3つの入り口に同時に増える。** ops(rpc.rs)に足せば、officework-mcp の
  `doc_*` と Python(officework._doc)からも同じ物が呼べる。エージェント専用の
  道具は作らない(決め)
. **宛先は共通。** settings.toml の `[[ai]]`・提供元の表・Claude Code /
  Codex の子プロセス、全部 writer からも同じ。記録は文書の隣の
  `<名前>.agent.txt`
. system の文は writer 用に1つ(「あなたは文書を作るアプリの中で働く助手です。
  本文は AsciiDoc で、道具でブロックごとに読み書きできます。まず outline で
  地図を見てから触ります…」)。calc の AGENT_SYSTEM と対にする

== 対話の画面の決め

- モデルの状態は**4語で出す**: 未設定・接続中・接続済・接続失敗
  (2026-09-02 発注者)。説明の文は付けない。横に今の宛先の名前を出す
- 道具呼びの行は**文章にしない**(2026-09-02 発注者「もっと自由に
  対話ができるように」)。呼んだ事実を `read_range B2:D4` のように
  小さく1行出すだけで、道具ごとの文言も訳の表も作らない。会話の文は
  すべてモデルが自分の言葉で書き、利用者の言語に合わせるのも
  モデルに任せる。ブックや文書を書き替えた行には「1手」の印だけ
  付ける(Ctrl+Z で戻せる印)。黙って動かさない、は変わらない
- **読みは確認なし。書きは実行してから1手として見せる** — アプリへの
  変更はすべて1手で入り、Ctrl+Z で戻せるから、事前の「よろしいですか」は
  出さない(作り直せる物に重い警告を付けない — 決め)
- **確認を取るのは3つだけ**: ファイルの保存・削除・機械の外への送信
- 会話の欄の焦点はプロジェクトパネルと同じ作法(押したら移る・
  本文を押すか Esc で戻る)

== 安全 — 既存の決めで足りる

- エージェントが書くマクロは**見える .py**(見えないコードは運ばない)
- 実行は**サンドボックスの中**(勝手にネットやファイルへ出ない)
- アプリへの変更は**1手**で入り、Ctrl+Z で戻せる
- 見せるのは**開いているフォルダとファイルだけ**。全社の索引は作らない
- モデルの選択は自由。手元のモデルならデータは機械から出ない
