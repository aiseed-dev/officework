# SEKKEI — calc(表計算)

設計の正本の一部(5つの直し・本家ガイド突き合わせ・calc/src の部屋割り)。2026-08-08 に SEKKEI.md から部屋割りで
**純移動**した(文言は変えていない)。書き込みの規則は SEKKEI.md の頭を見よ。

## calc の5つの直し(2026-08-06 発注者報告)

1. **窓の縁のつかみ**(`ui::resize_edges` — writer と共通): GNOME の
   Wayland は SSD 非対応で外枠が出ず、大きさを変えられなかった。
   Client 装飾のとき縁8箇所の透明なつかみを根の最後に描き
   (後に描く=先にマウスを受ける)、`start_window_resize(edge)` を呼ぶ。
   タイル済みの辺には出さない(Zed と同じ判断)。
   **続報(同日)**: 変えられるようになったら、格子が窓に合わせて
   伸縮していた(発注者)。原因は2つ — 見える行数・列数が固定の定数
   (ROWS=30/COLS=9)で、かつ taffy の flex は既定で子を縮める。直しは
   「**セルの大きさは設定どおり固定、窓に合わせるのは見える範囲**」:
   行・セル・見出しに flex_none(伸縮させない。はみ出しは器の
   overflow_hidden が刈る)+ 窓の大きさを描画のたびに控え
   (view_w/h_px)、rows_fit/cols_fit が幅・高さを積んで見える数を出す。
   端の追従とページ移動は額縁を差し引いた rows_snug/cols_snug で
   (描画前・試験は従来の既定に落ちる)
2. **パネルは表の中央**: prompt(名前の定義・検索ほか全部)とソルバーの小窓を、
   左上固定から `inset_0 + flex 中央` の受け皿に。受け皿は聞き手を持たない =
   後ろのセル操作を遮らない
3. **はみ出しと縮小(Excel の流儀)**: 折り返し OFF の文字セルは1行
   (改行は空白に畳む)。伸びる方向(揃えで決まる。中央は流さない)の隣が
   空なら、そのセルの上にも描く — 格子の後の重ね描き1枚(spill_texts)で、
   セル側は文字を出さない。**縮小して全体を表示**(shrinkToFit)も読み書き+
   画面(幅に収まるまで文字を小さく)。幅の見積りは全角=1em・半角=0.5em の近似
4. **書式は本当に据え置きに**(方針の破れ目を塞いだ): 保存が styles.xml を
   モデルから作り直していて、読みで拾えない書式(indexed 色・罫線の太さ・
   斜線など)が**開いて保存しただけで**消えていた。直しは3点:
   - 読み: セルの書式索引(`<c s=…>`)を `Sheet.style_of` に控える。
     indexed 色の 64 色パレット・shrinkToFit・patternType="none" も正しく読む。
     自己完結の書式だけのセル(`<c r s/>`)も落とさない
   - 保存: 原本の styles.xml を**据え置き、末尾に追記**(styles::append_to。
     節の count を増やし、numFmtId は原本の最大+1 から)。触っていない
     セルは照合(読みと同じ parse 同士なので必ず一致)して**原本の索引の
     まま**書き戻す。dxfs は二重にならないよう置き換え
   - 試験: 実物の様式7で「開いて保存 → styles.xml が1字も変わらない・
     全セルの索引が原本のまま」「A1 だけ太字 → 原本の xf はそのまま残り
     追記で受ける」を実走
5. **新規は空白のブック**: 見本の請求書を入れるのをやめた(試験は自前で
   表を作る。触れる見本は sample/*.xlsx)
6. **打ち始めは置き換え(同日追加報告)**: セルを選んで打ち始めたら、
   既存の中身は消して置き換える。追記になるのは**同じセルで編集を
   続けている間だけ** — Excel の作法。`edit_armed` の旗で持つ:
   F2(新設。ui::EditCell)・ダブルクリック・1打目で立ち、セルを移る
   (sync_input)・Esc で降りる。IME の変換途中は消さない。
   F2/ダブルクリック中は ←→ が文字カーソルになる(editing() と同格)。
   **数式バーは編集モード(同日)**: クリックで押した位置に文字カーソルを
   立てて編集に入る(置き換えにならない)。編集中はバーに | のキャレットと
   緑の枠。カーソルのアイコンはバー=文字(I ビーム)、セル面=Excel と
   同じ十字(手のひらをやめた)
6b. **終了確認の線引きの改訂(2026-08-06 発注者「保存しないで終了しようと
   した時に警告を消したのはどうしてですか?」)**: 2026-08-03 の
   「確認は実ファイルに限る」(名前なしは常に黙って終了)は、新規に見本が
   入っていた頃の線引きだった。新規が空白になり実の仕事が始まる場所に
   なったので引き直す — **未保存の変更があれば、名前が無くても確認を出す。
   本当に空のままの新規だけ黙って閉じる**(writer・calc とも)
6c. **終了確認は窓の中のパネルに(同日「警告はスクリーンの中央にでます。
   離れすぎ」)**: rfd の OS ダイアログは親窓を持てず、スクリーンの中央に
   出て窓から離れる。他のパネルと同じ**窓の中の中央のパネル**に置き換えた
   (writer・calc とも)。保存して終了(Enter が既定)/ 保存せず終了 /
   キャンセル(Esc)。「はい」で保存できなければ終了しない、は従来どおり
   (save(then_quit) の道は不変)。rfd の確認はこれで全廃 —
   残る rfd はファイル選択の窓だけ
6d. **ホームの帯は「組ごとの上下の対」(2026-08-06 発注者スクショ
   「よくみて、単純に2列ではないです」)**: 本家のホームは2行割りではなく、
   組の中で上下が対 — コピーの下に貼り付け、書体の下に B I U…、
   縦揃えの下に横揃え。calc の帯を HOME_PAIRS(組ごとの上段・下段の表)で
   組み直し、組の間に縦の区切り線。対の表に無いボタンは右端に半々で出す
   (黙って落とさない)。あわせて calc のホームに コピー/切り取り/貼り付け
   (run_cmd へ配線 — 実体は copy_now/cut_now/paste_now に括り出し)と
   左揃え/右揃えを追加。ribbon.rs 手編集後の各言語の追随は
   gen_lang.py <loc>(en だけ gen_ribbon_locale.py)で再生成 —
   **gen_ribbon_locale を直接他言語に使うと OVERRIDES 不足で空になる**(踏んだ)
7. **数式バーの三点構成(同日)**: 名前ボックス / fx(関数を挿入)/
   数式編集、の本家の並びに。
   - **名前ボックス**: 押すと打てる。番地(B12)・範囲(A1:C9)・
     定義済みの名前で移動・選択し、**知らない名前はいまの選択に付ける**
     (Excel の名前ボックスと同じ)。Enter で決定・Esc で取消
   - **関数を挿入**(fx と数式タブのボタンが同じ実体): 本家の FormulaDialog の
     形の小窓 — 検索(打つと絞り込み)/ 分類の耳 / 一覧(↑↓で選ぶ・
     ダブルクリックで入る)/ 引数と説明 / OK・キャンセル。
     **一覧・引数・説明は本家の現物から生成**(calc/gen_funcs.py が
     vendor/web-apps の formula-lang/ja_desc.json から calc/src/funcs.rs を
     起こす。SmartArt と同じ流儀)。載るのは**計算できる関数だけ** 188 個。
     和製4関数(YEN/JIS/DATESTRING/PHONETIC)は手書きの説明。
     決定すると =名前( で編集が始まる(編集中なら差し込み)
   - **関数の引数(第2段。同日「もっと詳しく。OKでなく次へ」)**:
     一覧の決定は「次へ」になり、本家と同じ**引数の画面**へ —
     引数ごとの欄(Tab/↑↓/クリックで渡る。省略可の印つき)、
     いまの欄の説明(本家 ad の ! 区切りを引数順に。可変長は最後が代表)、
     **関数の結果=下見**(引数を打つたび、**表の複製**の空きセルで計算 —
     ゴールシークと同じ流儀で本物は触らない)。
     **セルをクリックすると、いまの欄に参照が入る**(本家の引数ダイアログの
     作法)。**ドラッグすると範囲(A1:C9)が入る**(pick_from が起点を持ち、
     なぞった矩形を正規化して欄へ。離した所で終わり)。
     OK で式に、戻るで一覧へ、Esc/キャンセルで取消

## 本家ガイドとの突き合わせ点検(2026-08-06 発注者発注)

ONLYOFFICE の公式利用者ガイド(日本語)を上から辿り、calc の現状と
突き合わせた食い違いの一覧。**1件=原因究明→修正→試験→コミット**で消し込む。
右の印: ✔=この点検で直した / 控=一覧に控えて後日 / 送=判断が割れるので
発注者の実機確認に回す。

**インターフェース(タブの構成)** — 原因はほぼ2種:
gen_ribbon.py の id 正規表現(`slot-(btn|field|chk|cmb)-`)に掛からない
**class 注入スロット・別綴りの id**(`slot-add-pivot`, `slot-comment`,
`slot-editheader`, `slot-sortasc/desc`, `slot-img-*`, `slot-shapes-merge`)と、
テンプレートに無い**動的タブ**(表示・保護)の手書きの漏れ。

1. ✔ ホーム: 昇順/降順の並べ替えが無い。フィルター/解除の位置が末尾
   (本家は 消去 と 数値の書式 の間、並べ替えの下の対)
2. ✔ 挿入: ピボットテーブル・コメント・ヘッダー/フッターの3ボタンが無い
3. ✔ レイアウト: ヘッダー/フッター、前面へ移動/背面へ移動/配置/
   グループ化/図形を結合 が無い(オブジェクト操作は未実装 → 灰色で場所だけ)
4. ✔ データ: 昇順/降順が無い(実体は右クリックに済 — 配線だけ)
5. ✔ 表示: 標準/改ページ プレビューが無い(プレビューは未実装 → 灰色)。
   送: ツールバー常時表示・シートとステータスバーの結合・左右パネルの切替は
   web の画面構成のボタンなので入れていない(額縁はデスクトップ版合わせの方針)
6. ✔ 描画: 「選択」が無い(本家は 選択・ペン・蛍光ペン・消しゴム)。
   実体は「道具を措く」で、ペンの解除と同じ — 実装して足した
7. ✔ 保護: 本家 SSE は 暗号化/ブックの保護/シートの保護/範囲の保護。
   calc は writer の形(暗号化/署名/保護)のままだった。「保護」の実体は
   シート保護なので名前を「シートを保護する」に。ブック/範囲は灰色で場所だけ。
   署名は独自のボタンとして末尾に残す(本家 SSE の保護タブに署名は無い)
8. 控: ピボットタブのスタイル系(行/列見出しの強調・縞・スタイル一覧)、
   表のデザインのスタイル一覧とスライサー/ピボット挿入ボタン
9. 控: 常時表示の「スタイルのコピー」(書式のコピー/貼り付け。刷毛)が無い

**基本操作・関数ほか(挙動)**

10. ✔ シートの管理: 耳の右クリックメニューが無く、名前の変更・削除・
    移動/コピー・タブの色が**機能ごと無かった**(あるのは追加・切替・
    表示タブ経由の隠す/戻すだけ)。本家の並び(挿入/削除/名前の変更/
    移動またはコピー/非表示/タブの色)で実装。ダブルクリックで名前の変更
11. 控: 検索と置換の選択肢(大文字小文字/セル全体/行・列方向/範囲/
    値・数式の別)が無い — いまは素朴な全シート順送りだけ
12. 控: 貼り付けオプションが本家13種+演算(加減乗除・空白スキップ)に対し
    4種(値/式/書式/転置)。独自の割り切りとして SEKKEI 済だが、
    演算貼り付けは表の仕事で実際に使うので候補
13. 控: オートフィルの右ドラッグメニュー(セルをコピー/連続/日/平日/月/年/
    線形/成長)。フィルはボタン(fill-num)のみ
14. 控: スペルチェック・オートコレクトは calc に無い(writer と共通化できる)
15. ✔ 文字の書式の最初から違っていた(発注者指摘 2026-08-06
    「最初のフォントから実装が間違っていませんか?」)。
    - フォント/サイズ: 本家はホーム先頭の**今の値が見える欄**
      (slot-field-fontname/fontsize)なのに、calc はただの絵のボタンだった —
      枠付きの欄にして今のセルの書体名と大きさを出す(押すと一覧)
    - フォントの色・塗りつぶしの色: 本家はパレットなのに、calc は
      **2色を順繰りに切り替えるだけの仮実装**だった — 色見本つきの一覧に
      (文字 11色+自動 / 塗り 薄い色を先に 11色+色なし)
    - 書体の一覧が **16個で黙って切り捨て**(方針違反)、サイズも13択 —
      切り捨てをやめ、一覧のパネルは長ければ中でスクロール。サイズは
      Excel の標準の並び(6〜72)
    - 控: サイズの自由入力(本家は欄に打てる)・上付き(モデルに
      subscript しか無い)・色名の一覧が全言語で日本語のまま
      (図形や SmartArt の一覧と同じ割り切り)

読んだ節: インターフェース各タブ(紹介・ファイル・ホーム・挿入・描画・
レイアウト・数式・データ・ピボット・コラボ・保護・表のデザイン・表示)、
基本操作(コピー/貼り付け・元に戻す)、シートの管理、検索と置換。
数式バー・ステータスバー(耳+選択の生きた値)・ファイルのページ・
クイックアクセス(保存/印刷/戻す/やり直し)は既に本家の形と一致を確認。
残りの節(オブジェクト・保護の各論・ツール・ショートカット)は次の便で。

あわせて文言の門番(gen_i18n)を緑に戻した: 前の便(数式バー・終了確認)

## .py を calc の中で編集する(2026-08-09 発注者「zed と ONLYOFFICE の合体」)

発注者の言い直し: これは「VS Code と Excel」ではなく **zed と ONLYOFFICE の
合体**(前の2つは数年変わっていない)。土台は既にそうなっている — 描画は
**GPUI**(zed の UI 基盤。ui/Cargo.toml が zed-industries/zed の git 依存)、
本家合わせの相手は ONLYOFFICE。

**zed の editor クレートは借りない。** 16 万行あって project / lsp /
workspace / multi_buffer / dap / rpc を引き連れてくる — zed をほぼ丸ごと
持ち込むことになる。借りるのは GPUI まで。

**編集の芯は kumihan::Editor**(engine/src/edit.rs)。セル入力・数式バー・
writer の本文が既にこれを使っている。足すのは**論理行の勘定と見せ方**だけ
(行番号・上下の行・Home/End・字下げ・色分け)。

**置き場は ui/src/pyedit.rs — writer と calc で共有する**(2026-08-09 発注者
「ui/ に置いて両方から使えるようにしましょう。.py ファイルなので両方から

## LET(2026-08-08 実装)。LAMBDA は見送り

## セルの文字はマークダウン(2026-08-09 発注者確定)

文字列のセルを**マークダウンとして描く**(`sheet/src/markdown.rs`)。
発注者の言い方: 「セルで文字列のときにはマークダウンが使えるようにして。
そうするとセル内での編集機能が不要になる」。

**要**: セルが持つのは平文のまま。書式は文字の中に記号として書かれていて、
解釈するのは描くときだけ。だから

- **セル内の一部だけを太字にする編集 UI を作らなくてよい**(リッチテキストの

- **xlsx へは平文で入る** — 往復で絶対に化けない。リッチテキストの run には

- 数式バーに出るのも Python が読むのも、いつも同じ平文

**描く場所は2つある**(踏んだ穴): 格子の中の普通のセル(view.rs の

- 無ければ `markdown::DEFAULT_HEADINGS`(1.6 / 1.35 / 1.15 倍・太字)に落ちる
- **書式は帳票の側にある**という方針(原本据え置き)と同じ筋。保存は原本の

- **見出しを打つと行が広がる**(`Calc::fit_row_to_markdown`)。**狭めはしない** —

  「キーの嘘」と同じ型の穴(押しても何も起きない)。配線して塞いだ

## INDIRECT の文字列は改名に追随させない(2026-08-08 判断)

台帳 第3便に「シート名の変更が `INDIRECT("古い名前!A1")` を追わない」を
不具合として立てたが、**直さないと決めた**。理由:

1. **Excel も追随させない。** INDIRECT は「動かない参照」を作る道具で、
   行の挿入でもずれないのが値打ち。追随させるとその使い方を壊す
2. **筋を通せない。** 文字列の直書きは直せても、`INDIRECT(A1&"!B2")` や
   `INDIRECT(B3)` は実行時に決まるので直しようがない。
   「たまに追随する」は「決して追随しない」より分かりにくい
3. **文字列は data であって参照ではない。** 打った文字を書き換えるのは
   「黙って別の意味にしない」に反する
4. そもそも痛かったのは INDIRECT が**別シート参照の唯一の道**だった頃の話。
   直書きの `=4月!B2` が入った今、普通の道はちゃんと追随する

**代わりに黙って壊さない** — 改名のとき、文字列の中に残る「古い名前!」を
数えて「N 箇所は追随しません(手で直してください)」と言う
(`stale_in_strings`)。**直せないなら、せめて知らせる**という方針の形。

## 書式の一覧は画面の言語に合わせる(2026-08-10 発注者確定)

数値書式の一覧(`calc/src/util.rs` の `number_formats()`)に、**日本語を
焼き付けた項目が2つ**あった。

    長い日付 (2026年8月6日) → yyyy"年"m"月"d"日"
    通貨 (¥1,234)          → ¥#,##0

見出しは `ui::item!` を通るので訳される。**中身だけが日本のまま**なので、
独語で「Langes Datum (6. August 2026)」を選んだ人のセルには
`2026年8月6日` が出る。**見出しが嬉しい嘘をつく**という、この家がいちばん
嫌う形。訳者4人が独立に指摘してきた(2026-08-10 の12言語の対訳の回)。

**確定(2026-08-10、発注者の言葉): 通貨も長い日付も選べるようにする。
長い日付は各言語に既定を1つ置く。**

つまり「言語から自動で決める」ではなく、**選ばせたうえで、既定を言語ごとに
用意する**。日付は既定が言語で変わってよい(読む人の作法だから)。
通貨は既定も言語に引かせない(次節)。

引き受けた制約:

- **書式はファイルに保存される。** 独語で作った帳票を日本で開けば独語の
  月名が出る。xlsx が書式を文字列で持つ以上これは避けられない。
  隠さない — 「その帳票が独語で作られた」という事実がそのまま残るだけで、
  嘘にはなっていない
- 短い日付 `yyyy/m/d` も同じ扱い(米なら `m/d/yyyy` を既定に)

### 月名・曜日名は書式コードの地域から引く(2026-08-11 実装)

**壁だった所は片付いた。** 前は描き手が月名を持たず、`m` は何文字並べても
数字(`mmmm` → `08`)、`aaa`/`aaaa` はどの言語でも「木」「木曜日」だった。
`YOBI` の配列が engine に焼き付けてあった。

いまはこう出る:

    [$-407]dddd, d. mmmm yyyy  → Donnerstag, 6. August 2026
    [$-419]d mmmm yyyy "г."    → 6 августа 2026 г.
    [$-40c]dddd d mmmm yyyy    → jeudi 6 août 2026
    [$-412]yyyy"년" m"월" d"일" dddd → 2026년 8월 6일 목요일

**どの言語で描くかは書式コード自身が運ぶ。** xlsx には元から
`[$-407]`(独)`[$-409]`(米)という仕組みがあり、Excel もこれで決めている。
おかげで:

- **engine は画面の言語を知らないままでよい**(`sheet` に依存が増えない)
- **呼ぶ側は1行も変わらない**(`format_value` の口はそのまま)
- 書式はファイルに保存されるが、入るのは `[$-407]` という**地域の指定**で
  あって `"August"` という字ではない。8月以外の日付にも使い回せる

**読む人の言語では描かない。** `[$-407]` のセルは日本語で開いても独語で
出る。これは通貨で決めた分け方と同じで、**その札は「何語で書かれたか」で
あって「誰が見ているか」ではない**。「その帳票が独語で作られた」という
事実が残るだけ。

**地域指定が無ければ日本語。** 推測ではない — 実物26枚を数えたら、
月名・曜日名を使う書式は2件あって**2件とも地域指定を持っていた**
(無しは0件)。指定なしは実質「こちらで作った書式」なので素の言語でよい。

材料は `vendor/sdkjs/common/NumFormat.js` の `cultureInfo`(本家
ONLYOFFICE、AGPL-3.0)から `sheet/gen_datetime_names.py` が起こす。
247 語を人が打たずに済み、**露語などの属格**(「8月」と「8月の」で形が
違う)も落ちない。LCID の対応表も同じ材料から起こす — 暗記だと
pt の 416(ブラジル)/816(欧州)を必ず踏み外す。

#### 既定を対訳表(`ui::t!`)で持たない

対訳の回で `ui::t!("yyyy\"年\"m\"月\"d\"日\"")` の形が試されたが、
**書式コードは文ではなく表に置く**:

- 書式コードは**こちらの小さな言語**で、訳者が知っているとは限らない。
  仏の Excel は `jj/mm/aaaa` と綴る — 訳者が善意でそう書いたら描き手が
  読めない。実際、英語に `mmmm d, yyyy` が入りかけて `08 6, 2026` に
  なっていた(気づいて戻された)
- 穴埋め `{}` の数のような**検算が効かない**。文なら門番が守るが、
  書式コードの妥当性は誰も見ない
- 文言の門番が13言語ぶんの「訳」を要求する。**訳す物ではない**

いまは `datetime_names::Names::long_date` に**本家が決めた既定**が
言語ごとに1つ入っている。発注者の「各国で一つに決めて置いたほうがいい」に
そのまま当たる。

#### 残っているのは選択式のほう

月名は出るようになったが、**長い日付・短い日付を選ばせる口はまだ無い**
(通貨は入った)。書式の一覧の「長い日付」はいまも日本語の書式コード固定で、
押すと `yyyy"年"m"月"d"日"` が掛かる。二段の一覧にして、各言語の既定を
先頭に置くのが次。

### 通貨だけは言語に引かせない — 選ばせる(2026-08-10 発注者確定)

はじめ「通貨も言語に合わせる」と書いたが、**発注者が選択式に変えた**。
こちらが正しい。

**通貨記号は読む人の言語ではなく、その帳票のお金**である。日本の会社が
€建ての請求書を作るのは普通で、そのとき独語圏の相手に送るとは限らない。
言語から決めると、**円の帳票をドイツ語で開いた人に € と見せる**ことに
なりかねない — これは書式の見た目の話ではなく、**金額の意味を書き換えて
見せる**ことなので、日付のずれより重い。

分け方はこうする:

- **記号はその帳票のお金** — 人が選ぶ。¥ を既定に、$ € £ ₩ 元。
  帳票でよく使う順(記号の一覧 `symbol_groups()` と同じ考え方)
- **並びは読む人の言語** — `¥#,##0` か `#,##0 €` かは言語の作法。
  記号を選んだうえで、置き場所は画面の言語が決める
- **小数の桁も通貨で決まる** — 円は `#,##0`、ドル・ユーロは `#,##0.00`。
  「¥1,234.00」は日本の帳票では見ない

つまり「通貨」の項目は1つではなく、**押すと通貨を選ぶ一覧が開く**形に
なる(改ページやデータテーブルと同じ二段)。

**この分け方は他にも効くはず** — 「その物の性質」と「読む人の作法」は
別物で、混ぜると必ずどちらかが嘘になる。日付は後者、金は前者。

**実装は未了**(2026-08-10 時点)。`calc/src/util.rs` を別の作業が
持っているため、空いてから入れる。

## ポルトガル語は pt(ポルトガル)と pt-BR に分ける(2026-08-11 発注者確定)

一度こちらは逆をすすめた — vendor の `pt.json` はブラジルで、CLDR も素の

## ブックの情報 — 著者は何人でも、カスタムプロパティは3つでひと組(2026-08-13 実装。台帳 第2便の [小] 2件)

台帳の「プロパティを追加」と「著者の複数入力」は**別の札だが1つの仕事**。
同じ板の同じ場所で、模型も読み書きも1本になる。

**著者は列で持つ。** `BookProps.creators: Vec<String>`。xlsx の
`dc:creator` は**1つの要素に `;` 区切りで何人でも**入る(Excel の慣習)ので、
読みで割り、書きで繋ぐ。**綴りの都合を xlsx の層から外に出さない** —
板も Python も「著者の列」だけを見る。並びには意味がある(先頭が主著者)
ので集合ではなく列にした。

空の断片は数えない(「山田;」は1人。名無しの2人目はいない)。
名前そのものに `;` が入っていたら**繋ぐ前に落とす** — 開き直して1人が
2人に化ける方が、記号が1つ消えるより悪い。

**カスタムプロパティは部品・宣言・関係の3つでひと組。**
`docProps/custom.xml` は core.xml とは別の部品で、`[Content_Types].xml` の
Override と `_rels/.rels` の Relationship が要る。3つのうち1つでも欠けると
Excel は「修復しました」と言って開く。**全部消したときは3つとも畳む** —
無い先を指す関係を残す方が、部品が消えるより重い。

`fmtid` は規格がこの部品に1つと定めた値、`pid` は2から連番。原文の番号は
持ち歩かず**書くときに振り直す**。ただし `linkTarget`(Excel の「内容に
リンク」)は意味を持つので抱える — こちらは繋ぎ直さないが、**外しもしない**
(板では鎖の印を出す)。落とすと繋がっていた札が黙って静かな値に変わる。

**知らない型は `CustomVal::Other(タグ, 中身)` で抱える。** `vt:i4` や
`vt:cy` を `vt:lpwstr` に均すのは、黙って型を変えること。画面では値だけ
見せ、打ち直しはさせない。

**先に確かめた**: この直しの**前から**、custom.xml を持つ xlsx は開いて
保存しても消えていなかった(知らない部品を持ち越す方針が効いていた)。
今回それをモデル経由の書き直しに変えたので、同じことを試験で縛り直した。

**板を巻けるようにした**(`file-pane` に `overflow_y_scroll`)。項目は
何件でも増えるので、巻けないと足した先から「プロパティを追加」が画面の
外へ出て押せなくなる。**実機で下端が切れているのを見て気づいた** —
試験は位置を見ていない。

追加は**名前 → 型 → 値の3段の小窓**(小計・ゴールシークと同じ運び)。
専用の板を作らずに済み、型を綴りで訊けるので「型を選ばせない代わりに
中身から当てる」推測を入れずに済んだ。**値まで打って初めて足す**。

検分は LibreOffice への往復で行った — 5件とも読め、著者2人が
`山田 太郎; 鈴木 花子` で通る。`vt:bool` は向こうが `1` で書き戻すが、
こちらの読みは `true`/`1` の両方を受ける。

## 塗りは色1つでは足りない — 柄とグラデーション(2026-08-13 第1版。台帳 第2便の [中])

`CellFormat.fill: Option<String>` は**べた塗りしか表せない**。xlsx の
`<fill>` は柄(`patternFill@patternType`)とグラデーション(`gradientFill`)も
取るので、色1つに潰すと情報が落ちる。

**落ち方が見えにくかった。** 開いて保存するだけなら、原本の styles.xml を
据え置きの土台にしているので柄は残る。壊れるのは**そのセルの書式を1つでも
触ったとき** — 太字にした途端に xf が作り直され、模型が持っている「べた塗りの
前景色」で新しい `<fill>` が積まれる。網目が赤いべたに化ける。読んで気づける
種類ではなく、実測で見つけた(`fillId` が lightGrid から新しい単色へ移る)。

**決め**:
- `fill` は**べた塗りの色、柄のときは前景色**(fgColor)という意味にする。
  `fill_pattern` は**柄の名前だけ** — `solid` と `none` は入れない
  (べた塗りは `fill` が色を持つこと、塗り無しは `fill` が `None` である
  ことで表す。同じことを2箇所で言わない)
- `fill_bg` は**柄があるときだけ**読む。べた塗りの `bgColor` は
  `indexed="64"`(自動)で意味を持たず、拾うと差分が濁る
- グラデーションと柄は**排他**(xlsx も `<fill>` の中身は一つ)
- `Gradient` の数は**すべて整数**(角度=度×100、位置=千分率)。
  `CellFormat` は `Ord` を導出していて `f64` には付かない —
  文字の大きさ(`size_c`)が先に踏んだのと同じ穴
- 知らない放射の型(`type="path"`)も**型名ごと抱える**。落として線形に
  均すと、円形の塗りが黙って横縞になる

**`FillDef` に束ねた。** `styles.rs` の `fills: Vec<Option<String>>` は
読み・書き・追記・名前付き様式の4箇所で使い回されていたので、色1つのまま
欄を足すと4箇所が食い違う。1つの型にして `from_fmt` / `is_none` を持たせ、
「塗り無しは 0 番」という xlsx の予約も1箇所で言うようにした。

**LibreOffice は物差しにならない。** 往復させると LO 自身が柄も
グラデーションもべた塗りに潰す(Calc がセルの柄を持たない)。こちらの
往復のほうが保つので、ここでの検分は**自分の往復試験と XML の機械検分**で行う。

## 図形は名前で往復し、絵で嘘をつく(2026-08-13 第1版。台帳 第2便の [中])

`SheetShape.kind` は xlsx の `prstGeom@prst` の名前そのもの。書くときも
`prst="{kind}"` と返すだけなので、**知らない形でもファイルは壊れない**。
壊れるのは画面のほうで、作図を持たない名前は四角で描いていた —
Excel の星や吹き出しの入った帳票が、四角の列に見えていた。

**「ファイルが無事」と「画面が正しい」は別の話。** 往復の試験は前から
通っていて、それでも見える物は違っていた。往復が緑なことは、絵が
合っていることを何も言わない。

**決め**:
- 描けるかどうかの判断は **`can_draw` の1箇所**。描く側(`body_svg` の
  match と `preset_svg`)と数える側(読みの Report)で名前の表が割れると、
  四角に化けた物が数から漏れる
- 知らない形は四角で描く。ただし**黙ってやらない** — 読みが
  「図形(描けない形。四角で見せます。保存では元の形のまま)」と数える。
  「保存では元の形のまま」まで言うのは、**消えたと誤解させないため**
- 形の比は Office の既定の調整値(adj)に寄せるが、**一致させることは
  目的にしない**。目的はその形に見えること

**試験で SVG の well-formed と NaN を見る。** 座標の式を1つ間違えると
`points="NaN,NaN"` が出て、画面から図形が**消える**。絵は「出ない」と
しか言わないので、机上では原因に辿り着けない。幅も高さも 0(ドラッグの
途中で来る)も同じ理由で縛った。

**既存の試験が1本落ちて教えてくれた。** 「知らない種類は四角で描く」の
例に `hexagon` を使っていた — 描けるようになったので落ちた。例に使う名前は
「まだ描けない物」でなければならないので `cube` に替え、その旨をコメントに
残した(次に誰かが cube を描けるようにしたら、また落ちて気づける)。

## 並べるのは描き分けられる物だけ(2026-08-13 第2版。塗りの柄と図形の一覧)

模型と往復を通した2件に、画面から選ぶ道を付けた。そこで効いたのは
**「できないものを、できるように見せない」を一覧の品揃えに掛ける**こと。

**柄は6つに絞った。** xlsx の patternType は 18 あり、読みはどれも受ける
(往復は保つ)。だが GPUI が持つ背景は**単色・線形グラデーション・斜線・
市松の4つ**で、横線・縦線・斜め格子は描き分けられない。並べれば
「選べるのに同じに見える」— 選んだ物と見える物が食い違う。だから
**出すのは6つ**(網 6.25/12.5/25/50%・斜線・市松)にした。

網の %% は**濃さの混色**で見せる。これは手抜きではなく、セルの大きさでは
細かい点は目に解けず、Excel も同じ見え方になるため。**方向を持つ柄だけが
別物**で、そこは混色に落とすと嘘になるので一覧から外した。
グラデーションの「放射」も同じ理由で外した(GPUI に放射が無く、線形で
代用すると選んだ物と違う物が出る)。

**色を選ぶ = べた塗り。** 柄と虹はそこで外す。単色を選んだのに前の網目が
残っていたら、押した意味が通らない。逆に柄を選ぶと、いまの塗りの色が
前景になる(色が無いときは灰に落とす — 白地に白の柄は何も見えない)。

**柄の地の色は柄が無いと効かない。押したらそう言う。** 押して何も起きないと、
鍵が効かないのか柄が無いのか分からない(スライサーの Alt+S と同じ作法)。

**図形は2段の一覧**(分類 → 形)。1段に 30 以上並べると探せない。
2段目は1段目と同じ場所に重ねる — 目が飛ばない(SmartArt と同じ運び)。
**一覧に並ぶ形はすべて `can_draw` が真**であることを試験で縛った。
描けない名前を並べると、押した人の前に四角が置かれる。分類をまたいだ
鍵の重なりも縛る(フローチャートの「処理」と基本図形の「四角形」は別物で、
鍵が重なると2段目の引き当てが取り違える)。

## テキストボックスの中の組み方(2026-08-13。台帳 第2便の [中])

図形の中の文字は `text: Option<String>` の生文字列だけだった。揃えも
箇条書きも持てないので、Excel で組んだテキストボックスを開くと**全部
左上の素の文字**になっていた(保存では txBody を作り直すので、
組み方はそこで失われる)。

`TextFmt` を足した — 横の揃え・縦の揃え・縦書き・箇条書き・取り消し線・
上付き/下付き。**縦の揃えはセルの `VAlign` と別の型**(`TextAnchor`)にした。
既定が違うため(セルは下、図形の中は上)で、同じ型を使い回すと既定が
どちらかで狂う。

**タブ位置は持たない。** 本家の段落設定にはあるが、こちらは文字を
重ね描きの div 1枚で出していて、タブの位置を守って描けない。
持てば「設定はあるのに効かない」欄が1つ増える — 塗りの柄で
「描き分けられない柄は並べない」と決めたのと同じ線。

**上付きと下付きは同時に立たない。** xlsx の `baseline` は1つの属性なので、
両方立てても書けるのは片方だけ。画面でも片方を押したらもう片方を降ろす。

**試験が2つ穴を出した**:
1. `bodyPr` と `rPr` は Empty、`pPr` は中身(箇条書きの印)を持つと Start で
   来る。**Start と Empty の両方から拾う** — 片方だけ見ていると、
   「箇条書きを付けた途端に揃えが読めなくなる」種類の穴になる
   (`sheet_view` で一度踏んだのと同じ道理)。拾うのは `text_fmt_attr` 1箇所
2. **読みの途中の控えを図形ごとに畳んでいなかった。** 前の箱の揃えや
   箇条書きが次の箱へ漏れる。**1つだけの往復試験では出ない** —
   6つ並べた実物の見本を作って画面で見て、初めて出た。
   往復試験は「1つが往復すること」しか言わない

## コメントは筋で持つ — 写しだけ直すと Excel に映らない(2026-08-13。台帳 第2便の [中])

近代の Excel はコメントを `xl/threadedComments/` に置き、`xl/comments1.xml`
はその**古い読み手向けの写し**になっている。こちらは写しだけを読み書き
していたので、**スレッドを持つブックを開いて直すと、写しだけが変わって
Excel が見る本体は元のまま**だった。返信もこちらから見えず、報告も出て
いなかった — 静かに食い違う。

これも**開いて保存するだけなら無事**で、直したときに出る類の穴だった。
今日3件目の同じ形(塗りの柄・図形の作図・これ)。**「往復が緑」は
「見える物が合っている」を意味しない**という同じ教訓に戻る。

**決め**:
- `CommentThread`(解決の印 + 発言の列)。発言は (書いた人, いつ, 文)。
  解決は**筋ごと**に立つ — 返信1つだけを解決済みにはできない(Excel も同じ)
- 日付は `dT` の綴りのまま持つ。暦の計算はしない — 往復で崩さないことが先
- 書いた人が分からなければ**空**。「不明」のような名前を作らない
- **写しと本体は同じ回で必ず一緒に書く。** 原本の古いスレッド部品と
  `xl/persons/` は持ち越さず作り直す(残すと新しい写しと食い違う)
- `guid()` は**乱数を使わない**。番号から決まった形を作る — 同じブックを
  2回書いたら同じ物が出てほしい(差分が読めなくなるし、試験も書けない)。
  Excel は中身を見ず、一意であることしか要求しない
- 古い写しには**筋を一続きにして**書く。頭だけ書くと、古い読み手には
  返信が無かったことになる

## スパークラインの点の印(2026-08-13。台帳 第2便の [小])

本家の設定は「色・太さ・点の印・空セルの扱い・縦軸のそろえ」。このうち
**前の3つだけを持つ**。

分かれ目は**元データを引き直すかどうか**。空セルの扱い(隙間/ゼロ/線で継ぐ)も
縦軸のそろえ(自動/共通/固定)も、元の範囲から線を引き直さないと決まらない。
こちらのスパークラインは挿したときの数を焼き付けた折れ線で、元の範囲を
覚えていない(台帳の既存の割り切り)。**持っても効かない設定になるので置かない。**

点の印は違う。高点も低点も最初も最後も、**焼き付けた点だけで決まる**ので
引き直さずに出せる。だから持てるし、持った。

**画面にその境目を書いた** — 「空セルの扱いと縦軸のそろえはありません
(この線は挿したときの数を焼き付けています)」。無い物を黙って無いままに
しない。理由まで書けば、次に触る人が同じ調べ直しをしなくて済む。

札は `jo:種類:底:印` の3欄。**印の欄は後から足した**ので、2欄しか無い古い
札も読めなければならない(試験で縛った)。自作の札を伸ばすときの作法。

## 形の点は制御点まで含めて1つの型(2026-08-13。台帳「図形の編集」)

`points: Vec<(f32,f32)>` を `Vec<PathPoint>`(点 + 入りの制御点 + 出の制御点)
へ移した。**どちらも None なら直線**なので、スパークラインもペンの線も姿は
変わらない。

**点の列と制御点の列を別々に持つ案は採らなかった。** 片方だけ足したり消したり
できてしまうためで、今日「塗り」と「コメント」で2度戒めた
「同じことを2箇所で言わない」に従った。移す先が 26 箇所あっても、
表現が1つである方が後で安い。

**取っ手は描く側と押す側で同じ表から出す**(`point_handles`)。別々に持つと、
見えている丸と当たり判定がずれる — 回転の取っ手で一度その形を踏んでいる。

**札の付け替えが行き過ぎていた記録。** 2026-08-09 にこの項目は
「ベジェの制御点をつまむ操作は…図形の作りごと変わる」を理由に [小] → [大] へ
移されたが、実物を見ると土台(正規化した点・custGeom の往復・掴んでの
ドラッグ・回転の取っ手の当たり判定)は既にあり、足りないのは制御点だけだった。
**作りは変わっていない。** 見積もりも実物で数え直す。

**clippy が「押す口の無い機能」を捕まえた。** `point_toggle_curve` を書いた
まま UI へ繋ぎ忘れ、「使われていない」で赤になった。`-D warnings` で回して
いなければ通り抜けていた — **できない物を作らないのと同じくらい、
作った物に口を付け忘れないことも門で見る**。

## 図形の足し引きは格子で解く(2026-08-13。台帳「図形のブール演算」)

結合・交差・減算を入れた。**交点をつないで輪郭を追う方式は採らなかった。**
Greiner-Hormann のような方式は、重なった辺・接する頂点・自己交差でどれも
別の場合分けが要り、帳票の図の品質に対して割に合わない。

採った道は3手:

1. 両方の形を細かい格子(256×256)で「中か外か」に落とす(偶奇判定)
2. 求める演算で中外を組み直す
3. 中と外の境目の辺をつないで輪郭に戻す(輪郭追跡)

**近似であることは隠さない。** 曲線は折れ線に割ってから計算し(区間あたり
16)、結果は自由な形になる。元の形と回転は戻らないので、それを状態行で言う。

**穴のあく形は輪郭2本で表す。** `PathPoint.start`(SVG の `M`、xlsx の
`moveTo` に当たる切れ目)を足した。輪郭を別の列に分けて持つ案は採らなかった —
**書式そのものが「moveTo で切れ目を入れた1本の列」**なので、同じ形にして
おく方が読み書きで取り違えない。塗りは even-odd で抜く。

**輪郭を点で取れない形は断る**(吹き出しなど)。黙って四角で計算しない。
これは図形ギャラリーの `can_draw` と同じ線 — できない物をできるように
見せない。

**出していないもの**: 「結合(ハイライト)」は見た目だけの別物、
「フラグメント」は結果が複数の図形に割れる操作で、いまの「2つが1つになる」
流れと別の作りが要る。台帳にその旨を書いた。

**一直線の点は畳む。** 格子をたどると1辺ごとに点が立ち、四角1つで 1000 点を
超える。畳まないと保存も描画も重くなる。

## 名前の適用範囲は名前が持つ(2026-08-13。台帳「名前の適用範囲」)

`names: Vec<(String, String)>` を `Vec<DefinedName>`(名前・参照・適用範囲)へ。

**推測をやめたのが要点。** 前は xlsx の `localSheetId` を「同じ名前が2枚の
シートにあるかどうか」から当てていた。そのため ①重なっていないシート限定の
名前が作れず、②偶然重なったブック全体の名前がシート限定に落ちていた。
いまは名前が自分で持っている印のとおりに書く。

**重なりの見張りは残した。** ブック全体の名前が2つあると Excel は開けないので、
そうなる組み合わせは書き出しで限定に落とす。**印は人の意図、見張りは
壊れたファイルを出さないための最後の砦**で、役割が違う。

画面は名前を打った後に段を1つ挟む(ブック全体 / このシートだけ)。
**範囲まで選んで初めて名前が入る** — 途中でやめたら何も残らない。
カスタムプロパティの3段と同じ運び。

**Python の口は組のまま残した。** `sheet.names` は `[(名前, 参照)]` のままで、
適用範囲は `names_scoped` で別に引く。既に使っている台本を壊さないため —
足すときに壊さない道があるなら、そちらを取る。

**踏み跡(自分の失敗)**: 52 箇所を一括置換で直そうとして、
`packaging/flatpak/.flatpak-builder/`(ビルドの使い捨てキャッシュ。vendor した
serde まで)を書き換えた。**rglob は作業空間のクレートに限る。** また
「(n, _)」のような組の分解は名前以外の所にも当たるので、正規表現の一括置換は
**必ず対象を絞る**。今回は git で戻して手で直した。
