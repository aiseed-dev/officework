= マニュアルの書き方(作る側の手引き)

利用者向けの冊子(docs/ja/・docs/en/)を書く人のための手引きです。
何を守るか・出す前に何を回すかは `.claude/skills/manual/SKILL.md` にあります。
ここに書くのは、**どう書くか**です。

== マニュアルは開発のもと — コード化できる内容を全部書く

このプロジェクトは**マニュアルをベースに開発します**。実装はこの頁を
読んで作られ、検査はこの頁と実物を突き合わせます。だから、コード化できる
内容が全部入っていなければなりません。

コマンド1つなら、少なくとも次が要ります。

* 欄と選択肢の**全部**(言い換えず、画面に出す実文で)
* 既定の値。数なら範囲と単位
* 押した後に何が起きるか(状態行に出る文言まで)
* 断るとき(できない・危ういとき)に、何と言って断るか
* Python の口があるなら、その名前と引数

書き切れているかの目安は1つです: **この頁だけを読んで、実装と試験が
作れるか**。

簡潔に書くことと、内容を省くことは別です。省いてよいのは経緯と内輪の
事情だけで(下の「書いてはいけない物」)、動きの中身は省きません。

== 文体 — 1つの文に1つのこと

* です・ます で書きます。主語と述語をそろえます
* 1つの文に入れることは1つです。「〜し、〜なので、〜ですが」と
  つないだ文は、切ってから出します
* 造語・比喩・格言調を使いません。迷ったら Excel / Word のヘルプが
  使う言い方を選びます
* 太字は1段落に多くて1つです。全部が太字なら何も太字ではありません
* 体言止めとダッシュでつなぐ書き方は、主語と述語をあいまいにするので
  使いません

用語は、Excel / Word と Euro-Office の**両方を引いて見比べてから**選びます。
順に機械的に落ちる決めではありません — どちらにも誤訳や癖があるためです。
迷ったら「使う人がヘルプや検索で探すのはどちらの言葉か」で決めます。
例: 式 → 数式、真偽 → 論理値、様式(docx)→ スタイル、入力規則 →
データの入力規則。

独自の機能(どちらにも無い物)は、両方とも参考にできません。
普通の言葉で名前を決めてから使い(決めるのは発注者)、決めた名前は
リボン・手引き・対応表で揃えます。

== 構成の型

=== 冊子

頭に「何の本で、誰が読むか」を1〜2文。あとは仕事の順に節を並べます。
できることだけを書きます。「〜できます(予定)」は書きません。

=== コマンドの手引き(1枚の型)

----
= <リボンのラベルと同じ題>

<どの段にあるか>。キーは `<あれば>` です。

*状態: 実装済み* — いま使えます

== 何をするか

<1〜3文。押すと何が起きるか>

== ダイアログ

<出ないなら「(ダイアログは出ません)」の1行>

== プログラムから

<実在の口の名前。無ければ「(まだありません)」>
----

ダイアログの節は「欄の名前 → 選べる値(全部)→ 既定」の順で書きます。
選べる値は言い換えずに、画面の実文を写します
(調べは link:dialog-parameters.ja.adoc[パラメータの台帳])。

=== 本家と違う所の書き方

無い物は「無い」と1行で言い切り、理由があれば短く添えます。

* 良い: 「任意の角度は指定できません。様式で使う向きは6つの型で足ります」
* 悪い: 「現時点では未対応です(将来のバージョンで検討予定)」

同じボタンが押す場所で違う働きをするときは、表で書き分けます
(罫線・大文字小文字の頁が見本です)。

== 例の作法

* **実測してから書きます。** 例のコード・数値・選択肢は、この機械の
  実物に当てて確かめた物だけを載せます
* 例は事務の実物に寄せます — 見積書・台帳・報告書・電話番号。
  foo や bar は使いません
* 危ない手順は、良い手順の隣で「しない理由」ごと書きます
  (例: ラベルの文字を探して隣に書く走査 — macro-manual の書き方)

== 書いてはいけない物

* 決めた人・決めた日付・経緯の注記。「(2026-08-03 発注者確定)」は
  設計文書の物です。理由だけを残します —
  「〜ため撤去(2026-08-03 発注者確定)」→「〜ため、ありません」
* 管理の話。一覧(docs/ja/README.adoc)も利用者の物です
* 作る側への注意(「手で直さないでください」の類い)

== 両言語

英語版が正本です。頭の断り書きは定型を写します。

* 英語版: `_日本語版(secondary): link:../ja/<名前>.adoc[<名前>.adoc]_`
* 日本語版: `_元は英語版(link:../en/<名前>.adoc[<名前>.adoc])です。こちらは日本語訳です。_`

訳すときは文の形ごと日本語にします。英語の語順のまま訳した文
(「あなたは〜することができます」)は書き直します。

== 直した実例

この手引きの決まりは、実際の指摘から来ています。同じ形を繰り返さないために
残します。

[cols="1,1"]
|===
|悪い(実際に書いた) |直した後

|当面、管理するのは利用者向けの冊子の日本語と英語の対だけです(発注者 2026-08-26。設計や台帳は作る側の資料で、この管理の外です)
|読みたいことから冊子を選んでください。

|境界ダブルクリックの自動調整 — 事故を防ぐため撤去(2026-08-03 発注者確定)
|掴み直しのドラッグを自動調整が横取りする事故を防ぐため、ありません
|===
