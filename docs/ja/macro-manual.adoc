= officework マクロの手引き(Python)

_元は英語版(link:../en/macro-manual.adoc[macro-manual.adoc])です。こちらは日本語訳です。_

officework のマクロは、置き場に置いた Python のスクリプトです。
方針は3つだけです。

* **コードはファイルの外。** ブックにも文書にもコードは載りません。受け取ったファイルを開いても、何も実行されません
* **アプリの中でマクロは書きません。** 書くのは AI(下の「AI に書かせる」)か、VS Code などのエディタです。officework は使う場です
* **人が置いて、人が押します。** 置き場に `.py` を置き、一覧やボタンから走らせます。走るのはサンドボックスの中です

== 置き場は3つ

全部 `~/.config/officework/` の下です(Windows は `%USERPROFILE%\.config\officework`)。

[cols="1,2,2"]
|===
|置き場 |なにになるか |使い方

|`funcs/` |セルから呼ぶ関数 |`=倍(A1)` のように、普通の式として
|`ribbon/` |リボンのボタン |ファイルの頭に書く(下記)
|`plugins/` |一覧から選ぶマクロ |マクロタブ > 一覧
|===

リボンのボタンにするときは、ファイルの頭にこう書きます。

[source,python]
----
リボン = {"ラベル": "月次の締め", "アイコン": "py-run", "タブ": "マクロ"}
----

ボタンは指定したタブの、組み込みのボタンの後ろに並びます(並びは日によって変わりません)。
前の版のキーの名前で書いた `.py` も、そのまま読めます。

== 表のマクロ — 選択に効く定型処理

表のマクロは `officework.calc` を通して、動いているアプリに話します。xlwings と同じ流儀です。
**いま画面で選んでいる範囲**に働くのが基本の形で、VBA の `Selection` と同じ入り方です。

選んだセルの字の後ろに「(済)」を足す:

[source,python]
----
# ~/.config/officework/ribbon/済みを付ける.py
リボン = {"ラベル": "済みを付ける", "タブ": "マクロ"}
from officework import calc as xw

r = xw.selection()          # いま選んでいる範囲
for c in r:                 # 1セルずつ
    if c.value:
        c.value = f"{c.value}(済)"
print(f"{len(r.value)} 行に付けました")
----

選んだ範囲を黄色く太字に:

[source,python]
----
r = xw.selection()
r.color = (255, 255, 0)     # 塗り
r.font.bold = True
----

選んだ列の右隣に、1.1倍した値を入れる:

[source,python]
----
r = xw.selection()
r.offset(0, 1).value = [[x * 1.1 for x in row] for row in r.value]
----

作法が2つあります。

* **大きい範囲は `r.value` でまとめて読み書きします。** 1セルずつの往復は行の数だけ橋を渡るので、数千行では待たされます(読み → 作り直し → 書き、の3手が速い形です)
* **できない・危うい頼みは `raise SystemExit("理由")` で断ります。** 理由は画面に出ます。黙って空振りしません

橋の口の全部(`Range` の書式・シート・保存など)は link:python-manual.adoc[Python の手引き]にあります。

== 文書のマクロ — 記入欄と雛形

文書のマクロは、**開いている文書の複製**をサンドボックスの中で python-docx で直します。
成功すると直った複製が読み戻され、**Ctrl+Z 一回**で丸ごと戻せます。
失敗したら文書は無傷です。

次のものは用意済みです。スクリプトに書かないでください。

[source,python]
----
# 用意済み:                    書かない:
d          # 文書              import docx / docx.Document(...) / d.save(...)
----

`print()` の最後の行がステータスバーに出ます。何をしたかを一行で報告して終わるのが行儀です。

=== 名前つき記入欄 — 様式の背骨

まず欄に名前を付けます: フォームタブで記入欄を挿し、欄の中にカーソルを置いて「名前」ボタン。
名前は docx の `w:tag` に入るので、Word と往復しても生きています。
同じラベルが繰り返される様式では、`代表・住所` `協力1・住所` のように**節つきの名前**で区別します。

[cols="1,1"]
|===
|関数 |はたらき

|`fill(名前, 値)` |その名前の欄**すべて**に書く(2枚目に同じ欄がある様式のため)
|`fill_one(名前, 値)` |最初の一つだけに書く
|`extract(名前)` |欄の値を読む
|`fields()` |(名前, 値) の一覧 — 様式のデータ台帳
|===

どれも、無い名前ははっきり断ります。打ち間違いが黙った空振りになることはありません。

*ラベルの文字を探して隣のセルに書く方法は、使わないでください。*
結合セルは同じセルを二度返します。均等割付はラベルに空白を挟みます。同名のラベルは別の相手に当たります。
そうしなくて済むように、名前があります。

=== 雛形 — 出して終わりの量産文書

通知書・契約書・送付状のような「作って送って終わり」の文書は、記入欄ではなく **`{{差し込み口}}` の雛形**で作ります。

[cols="1,1"]
|===
|関数 |はたらき

|`render(辞書)` |雛形に辞書を差し込む。結果がそのまま文書になる
|`tpl_fields()` |差し込み口の名前一覧 — 雛形の仕様書
|===

明細のくり返しは `{%tr %}` を専用の行に置きます。
雛形を実際に壊すのは、`{%tr %}` を明細と同じ行に書くことと、IME の全角の `{{ }}` の2つだけです(編集で `{{ }}` が中で割れるのは、たいてい無害です。開くときに繋ぎます)。

=== python-docx を直接使う

`d.paragraphs`・`d.tables`・`d.sections` など全部使えます。実際に確かめた作法が2つ:

* *表は行ごとに読みます。* `tb.cell(i, j)` は、呼ぶたびに結合の格子を組み直します。1,920 セルの帳票では、`for row in tb.rows: for c in row.cells:` なら 91ms、`cell(i, j)` のループだと 12.7秒でした
* *書式を保って差し替えます。* `c.text = "…"` は run の書式を潰します。最初の run に書くのが安全です

== AI に書かせる

アプリの中にマクロを書く画面はありません(そう決めました)。道は2つです。

* **左パネルの会話に頼む。**「選んだセルに(済)を付けるマクロを書いて」— コードが囲みで返るので、自分で置き場に `.py` として置き、一覧から実行します
* **外の AI(Claude など)に頼む。** MCP を繋げば、AI は開いている文書の記入欄の名前や表の中身を自分で読んでから書けます

どちらも**自動では走りません**。読んで、置いて、押すのは人です。
機械が書き、人が読み、サンドボックスが走らせます。これが安全の仕組みの全部です。

== サンドボックス

マクロはサンドボックスの中で走ります: **ネットは無し**、ホームは空に見え、書けるのはマクロの作業場だけ。`.venv` のライブラリ(python-docx・docxtpl・polars…)は使えます。

* `~/名簿.csv` は読めません。データはスクリプトに直に書くか、`render()` の辞書で渡すか、文書や表から取ります
* 表のマクロの橋(このパソコンの中のソケット)は、サンドボックスの中からも通ります

=== サンドボックスが使えるのは Linux だけです

これは正直に書いておきます。

[cols="1,2"]
|===
|OS |マクロの走り方

|Linux |bubblewrap のサンドボックスの中で走ります(上のとおり)
|macOS |*サンドボックスがありません。* ご自分で置いたマクロは、囲いの外で走ります
|Windows |同じく*サンドボックスがありません*
|===

macOS と Windows には、この仕組みに当たるものがありません。
そのため、置いたマクロは**あなたのファイルを読み書きでき、ネットにも出られます**。
Python を直接動かすのと同じだと考えてください。

*どの OS でも変わらないこと*は3つあります。

. **自動では走りません。** 置いて、押したときだけ走ります
. **ブックや文書はコードを運びません。** 受け取ったファイルを開いても、何も実行されません
. **他所から来たコードは、サンドボックスが無ければ実行しません。** macOS と Windows では、この種のコードは走らないと表示されます

したがって、macOS と Windows では**置く前に中身を読んでください**。
書いた人が分からないマクロは置かないでください。

== 困ったとき

[cols="1,1"]
|===
|表示 |意味

|`officework に繋がりません` |アプリが動いていない — 起こしてから実行(`xw.Book()` は自分で起こします)
|`python-docx がありません` |`pip install python-docx`(`.venv` があればそちらへ)
|`docxtpl がありません` |`pip install docxtpl` — `render` / `tpl_fields` のときだけ要る
|`記入欄「X」が見つかりません` |X という名前の欄が無い — フォームタブ「名前」で付けるか、`fields()` で確かめる
|`雛形が壊れています: …` |`{%tr %}` の行の置き方と、全角の `{{ }}` を確かめる
|`マクロ: <エラーの最後の行>` |スクリプトが例外で止まった — 文書もブックも変わっていません
|===
