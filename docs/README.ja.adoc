== 記事(articles/)— 三帳簿にもマニュアルにも入らない

link:articles/[articles/] は**公開用の書き物**の置き場。
マニュアルではないので、下の管理の規則は掛からない:

* *その時点の事実と見立てを残すもの。* 挙動が変わっても遡って直さない(直すのはマニュアルの方)。日付が中身の一部
* 発注者の一人称で書く。「これから作る」にも触れてよい(規則3の外)
* 各ファイルの頭に、その旨の注記が HTML コメントで入っている

== 管理の規則

. *嘘は欠落より悪い。* 挙動を変えるコミットは、**同じ回で**マニュアルの該当箇所も直す(2026-08-08 の「手続きはブックから動かない」でcalc/python の手引きと templates/sample の README が一斉に嘘になった —この規則はその反省)
. **新機能の追記は遅れてよい**が、遅れは下の「追随待ち」に一行で控える。黙って古いままにしない
. *できることだけ書く*(リボンの灰色と同じ方針)。「〜できます(予定)」は書かない
. 両言語とも直すのが原則。急ぐときは正本(英語)を先に直し、日本語は追随待ちに載せる — どちらか一方だけが直っている状態を規則の外に置かない
. 実測で書く(python-manual の流儀 — 「全部この機械で実測してある」を守る)
. *蒸留の作法*(2026-08-08 発注者「Excel のマニュアルを蒸留して」):本家(Excel)のヘルプは**課題の並びの教師** — 使う人が知っている仕事の一覧として構成だけ借り、*文章は写さない*(vendor を挙動の教師にした台帳と同じ流儀)。成果物は from-excel(課題→ここでの道/やらない理由)
